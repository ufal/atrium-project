# [\#73 Issue](https://github.com/ufal/atrium-project/issues/73) `open`: Discovery enrichment and document-quality outputs
**Labels**: `enhancement`, `development`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-30 08:29](https://github.com/ufal/atrium-project/issues/73):

Implement the remaining record-level outputs required by the agreed S3 discovery scope, without expanding the pilot into broader experimental NLP/LLM work.

Scope:
- add a dedicated statistical-keyword block owned by `nlp-enrich`;
- use KeyBERT as the default statistical keyword method;
- keep YAKE as the selectable alternative;
- preserve the method and score with each statistical keyword;
- keep statistical keywords distinct from controlled vocabulary keywords;
- add the optional document-level quality summary only after the page/line quality baseline is stable;
- derive the document summary from existing page/line quality information rather than introducing a second quality model;
- keep page-level quality as the authoritative stored signal.

Acceptance criteria:
- the record clearly distinguishes controlled and statistical keywords;
- statistical keywords carry method and score;
- discovery consumers can use the keyword block without depending on LLM-generated vocabulary;
- the optional document-level quality summary is deterministic and derived from the existing record;
- no new quality-gating behaviour is introduced;
- the work remains compatible with the agreed S3 discovery scope: lemma search, entity facets, keywords and configurable OCR-quality bands.

Deferred from this issue:
- custom NER and annotation tooling;
- broader document-understanding / LLM applications;
- vocabulary-gap experiments.

One change after the meeting: the block's owner is **keyword-extractor**, not nlp-enrich (ufal/atrium-keyword-extract#1 moves both keyword kinds there). The scope and acceptance above stay as written.

Two design details, so that the Digital Archive can use the block:
- Scores mean different things per method (KER counts occurrences, YAKE's score is normalised per document, KeyBERT's is a cosine). So every keyword carries its method and a rank, and scores are only compared within one method.
- The quality summary carries numbers (page-quality statistics and line counts per category), not bands, because AMČR computes the bands at index time.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-10-02 18:35](https://github.com/ufal/atrium-project/issues/73#issuecomment-5958867875):

**Update on #73 after the repository split and latest thread decisions**

The implementation direction is now:


* **`atrium-keyword-extract` owns the new `keywords` block**, not `nlp-enrich` ([[#1](https://github.com/ufal/atrium-keyword-extract/issues/1)](https://github.com/ufal/atrium-keyword-extract/issues/1)).
* Its current `v1.0.0-beta` already produces **statistical keywords for both the document and each page**, with `method`, `score` and `rank`.
* **Controlled vocabulary keywords remain separate in `enrichment`** and must never be merged with statistical keywords.
* The hub schema still needs to add the record-level `keywords` block; this should be handled as the additive schema round alongside the already-landed #71 contract changes.
* The **document-level quality summary remains last/optional**: it should be derived deterministically from the established page/line quality data, carry numeric statistics rather than index bands, and introduce no new gating behaviour. `ocr-postprocess` remains the quality baseline.
* `nlp-enrich` remains the **NLP + TEITOK projection stage** and should consume/project the record keywords after `keyword-extract`; it is no longer the producer.


For the other contributors: the main interfaces affected by this issue are therefore the **hub schema/record contract, `keyword-extract`, `nlp-enrich`'s projection, and the existing `ocr-postprocess` quality data**. The parked AMČR ideas (negation flags and editor-facing generated text) are awareness-only and are **not part of #73**.

Two things since the last update:
- **The quality summary's prerequisite now holds on both branches.** Born-digital lines that decode are scored by ocr-postprocess's model (`POST /score_record`, `v1.9.0-beta`), and OCR'd pages of a born-digital record get the same quality fields (`v1.9.1-beta`). A summary can therefore read the same fields on every record the route has scored.
- **keyword-extract will stop extracting from undecodable text.** On `test` it skips the converter's `Garbage`/`Inverted` lines as well as `Trash`/`Empty`; this ships with its next tag.
