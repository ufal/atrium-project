Implementation notes from the first pass — three findings that change this issue's scope.

**1. Kubernetes does not read Docker `HEALTHCHECK`.** The kubelet uses `livenessProbe` /
`readinessProbe` / `startupProbe` from the pod spec and ignores the image's directive
entirely. `HEALTHCHECK` is still worth adding (docker/compose/podman read it, it documents
the contract in-image, and CI can now assert it), but it cannot by itself make `/health`
visible to a K8s probe. The partner-facing half is a probe contract plus a reference
manifest: `docs/k8s_deployment.md` + `docs/templates/k8s/atrium-service.deployment.yaml`.

**2. Four of the five services had no runnable API image.** Only nlp-enrich published one.
alto-postprocess, translator and page-classification reached FastAPI *only* through a
`docker-compose entrypoint:` override on the batch image; llm-enrich's `api` stage was
declared but excluded from `build-targets` (roadmap B5). Since the handoff boundary is "a
Docker image, run at ARÚP/ARÚB's own Kubernetes" (#40, 2026-08-02), there was nothing to
pull — the acceptance criterion was unreachable by configuration. All four now publish an
`api` target.

**3. Two prerequisites had to land first.** Three services called blocking inference inline
in `async def` handlers; uvicorn's SIGTERM handler is an event-loop callback, so it could
not run until the request returned and `--timeout-graceful-shutdown` had nothing to
measure. And nlp-enrich's shallow `/health` ran `run_pipeline.py --dry-run` as a subprocess
on *every* probe, before checking `?deep=`, unbounded — the worst possible target for a
30s-interval HEALTHCHECK.

**On "a rolling restart kills in-flight work"** — this was literally true of `POST /jobs`:
it returned `queued` and left the job in a bare `asyncio.create_task(...)` with the result
discarded, so uvicorn saw zero in-flight requests and exited mid-job. Neither
`--timeout-graceful-shutdown` nor in-flight-request middleware can reach that. Jobs now
register with `ServiceState.track()`, which the drain awaits — verified against a real
uvicorn subprocess sent a real SIGTERM.

**Design note:** readiness is a **separate `/ready`** route; shallow `/health` stays 200
even while draining. A liveness probe that fails during a graceful shutdown gets the pod
SIGKILLed before the drain finishes — this issue's own failure mode, one layer up.

**Scope/estimate:** this came to 53 files across six repos, past "days of work" and past
the Q3 milestone's 2026-09-30 due date. Suggest moving the milestone rather than missing it.

Also: roadmap **B8** needed no fix — `service/text_api.py:475` already env-gates `reload`,
default false. Six documents described it as open; corrected in `docker_gha_roadmap.md` §8.
