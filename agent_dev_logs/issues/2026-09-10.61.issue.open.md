# [\#61 Issue](https://github.com/ufal/atrium-project/issues/61) `open`: LOGS: as an event stream — no basicConfig() in library modules, no per-job log file
**Labels**: `enhancement`, `development`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-10 12:13](https://github.com/ufal/atrium-project/issues/61):

alto-postprocess is the model here and documents the rule explicitly. `atrium-alto-postprocess/service/text_inference.py:51-55` carries the comment "(12-factor XI) No basicConfig() here" — the root logger is configured in exactly one place, `service/text_api.py:537`, inside `__main__`, writing to `sys.stdout` at `os.getenv("LOG_LEVEL", "INFO")`.

Two counter-examples:

1. **`atrium-page-classification/service/inference.py:22`** calls `logging.basicConfig(level=logging.INFO)` at **import** time, in a library module — the exact pattern alto documents against. Whoever imports it inherits a root-logger configuration they did not ask for, at a level they cannot set, and the first import wins over any later `basicConfig` in a real entrypoint.
2. **`atrium-nlp-enrich/service/enrichment.py:234`** sets `LOG_FILE` to `<workspace>/out/processing.log` — a file on container-local disk, not an event stream. It is also, per the Factor VI sub-issue, on disk that no other replica can read and that dies with the pod.

`LOG_LEVEL` is read in exactly **one** place ecosystem-wide, so four of five services cannot have their verbosity changed at deploy time at all.

### Scope

- Remove `basicConfig` from `service/inference.py:22`; leave `logger = logging.getLogger(__name__)`. Configure the root logger in page-classification's `__main__` instead, in the shape of `text_api.py:537-547` — which the Factor VII sub-issue is already editing, so land them together or in that order.
- Have every service honour `LOG_LEVEL` at its single configuration point.
- Decide what nlp-enrich's per-workspace `processing.log` is for. If it is the pipeline's own artifact for the caller to download, keep it **and** mirror the same records to stdout; if it is service logging, it should be stdout only.

### Acceptance

- `grep -rn "basicConfig" --include=*.py` across the five tool repos matches only `__main__` blocks (and test fixtures).
- `LOG_LEVEL=DEBUG docker run …` visibly changes output volume for all five services.
- Nothing a partner needs in order to diagnose a failed request is written only to a file inside the container.
