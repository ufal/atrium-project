# [\#40 Issue](https://github.com/ufal/atrium-project/issues/40) `open`: CI/CD: Enforce Branch Protection (GH) & Enable GPU Runner (GHA)
**Labels**: `enhancement`, `development`, `ci`, `github_actions`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-08-02 09:53](https://github.com/ufal/atrium-project/issues/40):

The centralized CI/CD hardening across the repositories is largely complete, but we have two critical infrastructure gaps remaining. First, the external GPU runner must be properly configured and unblocked to allow the execution of test suites marked as `slow`. Second, strict branch protection rules need to be applied to the `main` and `test` branches of the hub repository to secure the converged pipeline against unreviewed or accidental merges.

## Context & Rationale
* The GPU crons were previously removed because the ecosystem was advertising test coverage it did not possess (due to the lack of an active GPU runner). Activating this runner is a prerequisite for closing the testing gap on ML-heavy processes.
* The hub repository holds the canonical CI templates and shared `atrium_document` standard files. Protecting these branches prevents a bad push from cascading across the five tool repositories.

## Tasks
- [ ] Configure the external GPU runner and update GitHub Actions workflows to target it for `pytest -m slow` jobs - @rharasim
- [ ] Verify that the E2E E2E pipeline smoke test successfully executes the GPU-dependent phases.
- [ ] Apply branch protection rules to `main` and `test` requiring pull request reviews, status checks to pass, and preventing force pushes - @stranak

## Acceptance Criteria
- **Security:** Commits cannot be pushed directly to `main` or `test` without an approved PR and passing CI checks.
- **Coverage:** Workflows targeting the GPU runner successfully spin up, execute `slow` tests, and tear down without hanging.

A request that belongs next to the branch protection here, as a proposal for Wednesday (see [atrium-project#67](https://github.com/ufal/atrium-project/issues/67)).

AMČR will build its production images from a release tag, after its own checks. For that, a tag has to mean one thing, permanently:

- [ ] **Immutable releases** in the five tool repositories. Their releases are published as mutable today, so a tag can still be moved or its release changed after we have checked it.
- [ ] **Reusable workflows referenced by commit**, not by the moving `@v1` tag. A version comment beside the SHA is fine.

*Done when:* new releases in the five repositories are immutable, and every `uses:` line that points to this repository names a commit.

We don't depend on this, because our checks run on our side, but it makes a released tag trustworthy for everyone who uses it. On the GPU runner, my comment of 2 August still stands: it is outside what AMČR needs, so we propose to defer it.

- **Branch protection** on the default branch and `test` in all six repositories, plus tag rules for `v*`, `v1` and `doc-schema-v*`.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-10-01 05:52](https://github.com/ufal/atrium-project/issues/40#issuecomment-5925597844):

The release-trust tooling is on the hub (#72):
- `scripts/release_trust.py` switches on and reads back immutable releases, a tag ruleset and a branch ruleset.
  - Tags: `v*` in the tools, `v1`/`doc-schema-v*` in the hub; no update, no deletion.
  - Branches: default and `test`; no deletion, no force push, PR required, optional required checks.
  - Admins can bypass; GitHub logs each bypass.
- `scripts/pin_hub_reusables.py` pins the 35 caller jobs to the commit `v1` points to, with a matching `hub-ref`. The linter accepts both forms now; `--require-sha-pins` makes pins mandatory after the sweep.

The five `release.yml` need no change for immutable releases: softprops v3 attaches the assets while the release is still a draft. Order: [`docs/release_trust.md`](https://github.com/ufal/atrium-project/blob/test/docs/release_trust.md). The GPU runner stays deferred.
