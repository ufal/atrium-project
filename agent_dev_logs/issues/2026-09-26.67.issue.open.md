## Requests from the AMČR pilot

Each request is meant to be checkable. Most are additive under `doc-schema-v1`.

- [ ] **Seeded baseline record.** AMČR creates the record before the first stage, with `doc_id` = the AMČR file id, and `source` with `sha512` (the Fedora digest), the file name and the media type. It leaves `source.origin` to the tool that reads the document.
  - Every service accepts this baseline on its first call and keeps `doc_id` and `source.sha512` unchanged.
  - *Tools:* all five, and `digital-convert`.
  - *Done when:* the E2E smoke runs from a seeded baseline.
- [ ] **Paradata from every service.** Each service returns the paradata of its run as one RO-Crate Process Run Crate `CreateAction`:
  - `instrument`: the tool, with `version`, and its container image;
  - `object`, `result`, `agent`, the start and end times, and `actionStatus`;
  - the paradata 2.0 fields as properties of the action.

  *Tools:* page-classification, alto-postprocess, translator, llm-enrich; nlp-enrich aligns what it already returns. *Done when:* each service's response carries it.
- [ ] **Record-only mode.** Each tool can merge an output that already exists into the record without running its models, for example the PSNC ALTO in alto-postprocess, which we will import in bulk.
  - *Tools:* all five.
  - *Done when:* a record is built from existing outputs alone.
- [ ] **`atrium_rocrate.py` aligned with the AMČR record crate:**
  - RO-Crate 1.2 with Process Run Crate 0.5;
  - `version` on each `SoftwareApplication`, not `softwareVersion`;
  - stable run and tool identifiers;
  - tool authors as `creator` of each tool, not of the root;
  - a mode that emits the crate as a fragment without its own root entity, so we can embed it.

  *Done when:* its output passes rocrate-validator with the `ro-crate-1.2` and `process-run-crate-0.5` profiles, run separately.
- [ ] **A `keywords` block owned by nlp-enrich,** for the statistical keywords with their method and score (KeyBERT by default, YAKE selectable), next to the controlled keywords from llm-enrich.
- [ ] *Optional:* **a document-level quality summary** in the record, next to the page aggregates.
- [ ] **Tool architecture cleanup,** as a short list you shape:
  - one production service per stage;
  - shared layers governed like the contract modules under `para-drift`: one document reader, one LLM engine and client, one versioned vocabulary artifact;
  - nlp-enrich without its `llm` stage and vocabulary code;
  - llm-enrich research kept off the release line.

  *Done when:* `para-drift` covers the shared layers, and each image does only its stage.

Thanks, Kate and Pavel. See you on Wednesday.

### Subtask from Opus 5.5

Found while planning #67 R1 (seeded baseline). Read in the code, not yet reproduced.

The shared module keeps the seed's `doc_id` (`atrium_document.py` `_inherit_doc_id`, `:494-534`), and `finalize()` writes `<seed doc_id>.document.json` (`:1002`). Two tools then read back the file named after the id they derived from the upload's file name:

| Where | Effect when the ids differ |
|---|---|
| alto-postprocess `service/text_api.py:502` saves the seed as `<derived id>.document.json` and reads it back at `:527-528` | `/process` returns the seed without alto-postprocess's blocks |
| alto-postprocess `run_pipeline.py:346-377` | the CLI collects the seed copy |
| llm-enrich `llm_client_shared.py:1248` (`baseline`), returned at `:1319`, loaded by `service/api.py:351-398` | the API returns the seed without `enrichment` |
| llm-enrich `service/api.py:516` hardcodes `doc_id="inline_text"` | a seed sent to `/extract_keywords_text` is never enriched |

An AMČR seed has the AMČR file id as `doc_id` and the upload has another name, so every call hits this.

**Fix:** use the path `finalize()` returns. In llm-enrich, return that path from the helper, and key `/extract_keywords_text` by the seed's `doc_id` when a record is sent.

**Done when:** in all five tool repositories, a test sends a seed whose `doc_id` differs from the upload's name, and the response record carries both the tool's block and the seed's `doc_id`. page-classification, translator and nlp-enrich write to an explicit path and should pass already; the test keeps it that way.
