## 📌 ATRIUM WP4 Roadmap (2026–2027): UFAL & Tasks 4.1 / 4.2

**Overview:** Our goal in Work Package 4 (WP4) is to build highly composable, reusable digital workflows (rather than reinventing tools) that integrate seamlessly into the European Open Science Cloud (EOSC). All outputs will strictly adhere to FAIR principles and be published to the SSH Open Marketplace.

## 🛠 UFAL's Core Technical Stack

Charles University (UFAL) is driving the NLP and text-processing pipelines, normalizing unstructured historical texts and OCR outputs into machine-actionable data.

- **UDPipe** – Tokenization, PoS tagging, lemmatization, and dependency parsing.
- **NameTag** – Advanced Named Entity Recognition (NER) for extracting geographic and historical data.
- **MorphoDiTa** – Morphological analysis for highly inflected historical languages.
- **NeuralMonkey & Treex** – Advanced machine learning and sequence learning.
- **atrium-translator** – Custom repo for automated in-place translation of XML/ALTO/AMCR files to English.

## 🔄 Workflow Architectures

### Task 4.1: Text-Based Workflows

This pipeline handles the transition from raw visual capture to enriched semantic data:

1. **Ingestion** – Take raw text transcribed via OCR/HTR (formatted in ALTO XML, Page XML, or TEI).
2. **Normalization** – Run text through UDPipe and MorphoDiTa to resolve historical orthography and extract base lemmas.
3. **Enrichment** – Use NameTag for NER, run `atrium-translator` for localization, and map outputs to controlled vocabularies (e.g., Getty AAT, PeriodO).

### Task 4.2: Image-Based Workflows

Focuses on visual data integration, heavily relying on the IIIF protocol. Workflows will utilize WADM (Web Annotation Data Model) for standardized spatial annotations and integrate with deep learning models (e.g., ResNet) for automated motif recognition. Task 4.2 intersects with 4.1 to align high-res IIIF scans with our deep NLP analyses.

1. The Core Deliverables (The Pipeline)

From the formal perspective, UFAL MFF is responsible for a 4-step processing pipeline titled "From Relics to Active Data: An Integrated Meaning-Making Pipeline for Archaeological Archival Collections".

This directly maps to the 4 repositories you mentioned:

    Page Classification (atrium-page-classification)

        The Promise: A vision model (ViT/CNN) to classify input PNG images from scanned PDFs.

        Features: Must distinguish between graphical elements (drawings, photos), text types (handwritten, printed, typed, mixed), and tabular layouts/forms so the data can be routed to the correct OCR subtasks.

    Text Lines Categorization (atrium-alto-postprocess)

        The Promise: Post-processing OCR outputs (ALTO XML format) to structure, parse, and clean the text lines before downstream translation or enrichment.

    Vocabularized XML Translation (atrium-translator)

        The Promise: The translation task you are currently working on. It specifically involves translating the parsed XMLs while respecting domain vocabularies.

    NLP-Enrichment of Documents (atrium-nlp-enrich)

        The Promise: Applying Natural Language Processing models to the translated/processed text (e.g., Named Entity Recognition, dependency parsing, or metadata extraction) to make the archival collections searchable and "active."
