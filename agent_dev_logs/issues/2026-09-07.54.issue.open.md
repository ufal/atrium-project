This is our WP3/T3.3 deliverable. `SCHEMA_VERSION="1.0"` and the migration guard already exist; two things remain:

(1) tighten top-level `required` — currently only `["schema_version","doc_id"]` against 17 properties, so a stage that produces nothing still validates;
(2) add the RO-Crate export the DMP names for WP3 (zero occurrences across all six repos today — a new commitment, not continuity).

After this, the schema is a compatibility obligation, not a design surface.

Relevant issue: https://github.com/ufal/atrium-llm-enrich/issues/13

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-09-09 17:06](https://github.com/ufal/atrium-project/issues/54#issuecomment-5605743920):

Both halves drafted and verified locally; nothing pushed.

**(1) `required`** → `["schema_version","record_type","doc_id","provenance","assembled"]`, plus `anyOf` (a record must carry **either `source` or ≥1 stamped block**) and `allOf` (every name in `assembled.blocks` needs a top-level payload, 11 clauses).

The `anyOf` is the non-obvious part. Requiring `assembled.blocks` non-empty — the literal reading of "a stage that produces nothing" — breaks the pipeline at stage 1: `set_source()` deliberately doesn't stamp, so `page_split.py:540` emits a source-only record with no `blocks` key at all, straight into a hard gate.

Verified with `jsonschema` 4.26.0 over every per-stage record shape traced from production code: **16 cases, 0 mismatches** — 11 real shapes still valid, 5 defect shapes now refused (including today's `{schema_version, doc_id}` minimum, and a stamp with no payload).

**Not zero-touch.** An invalid *baseline* demotes the own-output gate from `raise` to `warn` in five repos, so a fixture pass has to land first: **10 hand-built baselines across 6 repos**, plus `tests/test_e2e_assert.py` — its `del record["pages"]` orphans a stamp, the only such case anywhere, while the 7 sibling deletions in that same file already remove both.

**(2) RO-Crate** — `atrium_rocrate.py`, hub-canonical, stdlib-only and deterministic (no RDF library, per `skos_strategy.md`'s stated non-goal). `document_crate()` + `run_crate()`. The record's reference discipline maps 1:1 onto RO-Crate's own rule: `derived_from` → `hasPart`, `regenerable` → contextual and **never** `hasPart`, `source` → `isBasedOn`. Intro doc for anyone new to the format: `docs/rocrate_export.md`.

Found in passing: `fixtures/atrium_document.example.json` carries four controlled values the registry doesn't know (`Text`, `Plate`, `kostel`) — V-4's second home, since that pass fixed the schema's `examples` and left the fixture. And `forms` has no writer in any of the six repos.

Rollout order: fixture pass → hub edit → `revendor_shared.sh` → commit all six in one window → **then** move `v1`. The freeze tag has to be separate from `v1`.
