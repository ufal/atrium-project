**Request: an llm-enrich tool record.** llm-enrich is the only tool in the chain without a record, and two steps link to it:

- step 8, vocabulary keywords. This replaces KER in the workflow: the text is mapped onto the AMČR and TEATER vocabularies, with the output constrained to the vocabulary;

We put it inside `0xSpVP` instead, as step 6, which replaces steps 4–5 for files with a usable text layer. T4.1.2 names digital-born extraction as part of the basic workflow. The GROBID note from `atrium-llm-enrich#11` is in that step.

<summary><b>Step 5 · <code>YParYU</code></b> → <code>ufal/atrium-ocr-postprocess</code>, v1.9.1-beta</summary>

**Label:** OCR output post-processing and quality control (text-line categorization)

**Formats:** input ALTO, PAGE XML, hOCR, JSON, PDF, DOCX, HTML, TEI, TXT · output ALTO, CSV, TXT, JSON

> Turns OCR output into clean, classified text lines. The pipeline splits documents into pages, builds page statistics tables, extracts each page's text in reading order, from the ALTO geometry or with a layout-aware model, and labels every text line by language and OCR quality: Clear, Noisy, Trash, Non-text or Empty. The quality score combines structural checks, a small language model's perplexity and character-level measures; the language comes from a language-identification model.
>
> Input: ALTO XML and other OCR output (PAGE XML, hOCR, ABBYY FineReader XML, OCR JSON), and text-bearing files such as PDF, office documents, HTML, TEI or plain text. Output: per-page ALTO and plain text, page statistics and per-line tables (CSV), and the ATRIUM document record (JSON), with a paradata JSON log per run.
>
> Command-line pipeline, or REST API container image (`ghcr.io/ufal/atrium-ocr-postprocess-api`): `/process` for a file, `/score_record` for the lines of an existing ATRIUM document record. The tool continues atrium-alto-postprocess under a new name.

<details>
<summary><b>Step 6 · new record</b> → <code>ufal/atrium-digital-convert</code>, v1.1.1-beta</summary>

**Label:** Born-digital document converter: PDF and office files into structured text without OCR

**Properties:** licence MIT · input PDF, DOCX, ODT, ODS, XLSX, RTF, DOC, XLS · output JSON, Markdown · activities Converting, Extracting · keyword `ATRIUM catalogue` · related `0xSpVP`, `RER7Fw`, `YParYU`, `j9fqxo`

> Reads documents that were created on a computer rather than scanned, and writes their text with its structure into the ATRIUM document record (JSON), without OCR: pages, text lines in reading order grouped into blocks, and the headings, running headers and footers, footnotes and tables the format carries; for PDF also the position of every line. It reads PDF, DOCX, ODT, ODS, XLSX and RTF, and the legacy DOC and XLS through LibreOffice; the type is recognised from the file's content, not its extension.
>
> The text layer of every page is checked. A page without a text layer, with one that does not decode, or with one left by an earlier OCR run is flagged as needing OCR, with the reason, so that only such pages go to OCR; a PDF that is mostly an earlier OCR run is refused as not born-digital. On request the record is also rendered as annotated Markdown in reading order.
>
> REST API container image (`ghcr.io/ufal/atrium-digital-convert-api`): `/reformat` returns the record; `/describe` adds a per-page assessment with the suggested next step (NLP, OCR or handwritten text recognition), asking the ATRIUM page classifier and OCR post-processor when they are available. A command-line tool does the same conversion, and an optional layout-model engine (Docling) can be built locally for complex PDFs. The API returns the provenance of every run (paradata); the command line writes it on request.

<summary><b>Step 7 · <code>EMhu3X</code></b> · <code>ufal/atrium-nlp-enrich</code>, v1.0.0-beta</summary>

**Label:** NLP enrichment of text lines into TEITOK (UDPipe 2, NameTag 3)

> Adds linguistic annotation and named entities to the text lines of archival documents: the line tables written by ATRIUM OCR post-processing (CSV or XLSX with a `text` column), or plain text. The lines go to the LINDAT UDPipe 2 service for tokens, lemmas, part-of-speech tags, morphological features and dependency syntax, and to the NameTag 3 service for named entities such as people, places and organisations.
>
> The main output is TEITOK XML, the TEI-based format of the TEITOK corpus platform; when the OCR's ALTO files are supplied, every word keeps its box on the page image. CoNLL-U files, entity tables per page and per document, a collection summary (CSV) and the ATRIUM document record (JSON) are also written, with a paradata JSON log per run. Documents that are not ALTO, such as PDF, office files, PAGE XML or hOCR, can first be converted into TEITOK with flexiconv on the command line.
>
> Command-line pipeline, or REST API container image (`ghcr.io/ufal/atrium-nlp-enrich-api`: `/enrich`, `/enrich_text`, background `/jobs`). Keywords are extracted by a separate tool, ATRIUM keyword extraction.

<details>
<summary><b>Step 8 · <code>j9fqxo</code></b> → <code>ufal/atrium-keyword-extract</code>, v1.0.0-beta</summary>

**Label:** Keyword extraction from archival documents (statistical and vocabulary-controlled)

**Formats:** input JSON, TXT, TEI, CoNLL-U (no longer PDF or DOCX) · output JSON, CSV

> Finds keywords in archival documents. Two kinds are kept apart, and every keyword says which method produced it, with its score and rank.
>
> **Statistical keywords** characterise a document and each of its pages: KeyBERT (embedding-based), YAKE, or the legacy KER method (lemma frequency). The REST API reads the ATRIUM document record, or plain text, and returns keywords per document and per page; a batch command line reads CoNLL-U or TEITOK files and writes CSV tables.
>
> **Vocabulary-controlled keywords** are terms of the AMČR keyword lists and the TEATER thesaurus, with Czech and English labels and a thematic category, chosen by a large language model whose output is constrained to the vocabulary's terms. This kind is at the research stage: it runs as a separate batch job on a GPU with a locally hosted model, and the API returns statistical keywords only.
>
> Container images for the REST API (`ghcr.io/ufal/atrium-keyword-extract-api`, `/extract_keywords`) and for both batch tools; every run records its provenance (paradata). The tool continues the keyword extraction of atrium-nlp-enrich and atrium-llm-enrich.
