# [\#58 Issue](https://github.com/ufal/atrium-project/issues/58) `open`: Honour `$PORT`, following the `alto-postprocess` pattern in all 5 repos
**Labels**: `bug`, `development`, `integration`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-10 12:04](https://github.com/ufal/atrium-project/issues/58):

Our own partner-facing manifest advertises a configuration knob that four of five services silently ignore.

`docs/templates/k8s/atrium-service.deployment.yaml:54-56` — the manifest ARÚP/ARÚB deploy from under #55 — sets:

```yaml
env:
  - name: PORT
    value: "8000"
```

Only alto-postprocess honours it. Its `api` stage declares `ENV PORT=8000` (`Dockerfile:106`) and its entrypoint is `python service/text_api.py` (`Dockerfile:107`), whose `__main__` reads the environment (`service/text_api.py:549-550`: `host=os.getenv("HOST", "0.0.0.0")`, `port=int(os.getenv("PORT", "8000"))`).

The other four bake the port into an **exec-form** `ENTRYPOINT` array, where no shell exists to expand a variable even if one is set:

| Repo | Line | Entrypoint |
|---|---|---|
| atrium-nlp-enrich | `Dockerfile:62` | `["uvicorn", "service.api:app", "--host", "0.0.0.0", "--port", "8000", …]` |
| atrium-translator | `Dockerfile:67` | same shape |
| atrium-llm-enrich | `Dockerfile:147` | same shape |
| atrium-page-classification | `Dockerfile:113` | same shape |

A knob that reads as supported and fails silently is worse than no knob: the probes keep working at 8000 while the declared setting does nothing, so nothing surfaces the mismatch until a partner sets it to a real value.

### Scope

For each of nlp-enrich, translator, llm-enrich, page-classification:

1. Add (or complete) a `__main__` block in `service/api.py` shaped exactly like `atrium-alto-postprocess/service/text_api.py:529-559` — `HOST`, `PORT`, `RELOAD` and `GRACEFUL_SHUTDOWN_S` all read from the environment with the current values as defaults. Two repos already have a partial block to replace: `atrium-llm-enrich/service/api.py:519-522` (`host="0.0.0.0", port=8000` hardcoded) and `atrium-page-classification/service/api.py:348+`.
2. Change the `api`-stage `ENTRYPOINT` to `["python", "service/api.py"]` and add `ENV PORT=8000 GRACEFUL_SHUTDOWN_S=20` beside the existing `EXPOSE 8000`.
3. Keep `--timeout-graceful-shutdown 20` behaviour intact — it moves from the CLI flag into `timeout_graceful_shutdown=int(os.getenv("GRACEFUL_SHUTDOWN_S", "20"))`. #55's drain contract must not regress.
4. Note the import-string difference: page-classification's `__main__` deliberately passes the app **object** rather than `"service.api:app"` (see the comment at `service/api.py:349-358`) because the README runs it from `service/`. Preserve that reasoning rather than pasting alto's string verbatim.

### Acceptance

- `docker run -e PORT=9000 -p 9000:9000 ghcr.io/ufal/atrium-<tool>:<tag>-api` listens on 9000, for **all five** services, and `service/healthcheck.py` passes against it.
- The default (no `PORT` set) still listens on 8000, so the reference manifest and every probe in it keep working unchanged.
- `HOST` is under the same treatment in all five.
- A CI probe covers it: extend #55's `docker-build-smoke` (`load: true` + `probe-targets`) with one non-default-port start, so this cannot silently regress. Verify by **breaking it** — set the entrypoint back on one repo and confirm the job goes red.

### Files

Two corrections from the verification pass before anyone starts — details in `agent_dev_logs/digests/58.digest.md`, per-repo shape in `plans/58.plan.md`.

**1. The prescribed entrypoint crashes all four containers.** `python service/api.py` puts `sys.path[0]` at `/app/service` with no package context. nlp-enrich and llm-enrich use relative imports (`from .atrium_service import …`) → `ImportError: attempted relative import with no known parent package`; translator imports from the repo root (`from main import …`) → `ModuleNotFoundError`. Both reproduced. alto only works because of the `sys.path` bootstrap at `text_api.py:21-45`, which the entrypoint line doesn't carry. Use **`ENTRYPOINT ["python", "-m", "service.api"]`** — fixes both classes, needs no `__init__.py` and no import rewrites.

**2. This is not an inert knob.** `service/healthcheck.py:49` (para-drift-guarded, all six repos) builds its probe URL from `PORT`. In the four non-conforming repos `PORT=9000` moves the *probe* and not the listener, so the container reports **unhealthy permanently**. Latent only because the manifest sets the default. Acceptance must run `healthcheck.py` inside the container at a non-default port, not just curl it.
