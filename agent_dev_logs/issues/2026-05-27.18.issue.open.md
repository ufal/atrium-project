The repos are already **pre-wired for this**: the shared `atrium_paradata.py` provenance logger reads `ATRIUM_RUNNER_IMAGE`, `ATRIUM_RUNNER_REPO`, `ATRIUM_RUNNER_REF` env vars and records them in every output JSON, with the documented example `ghcr.io/ufal/atrium-translator:v0.5.2`. The maintainers clearly intended GHCR-published, self-identifying containers — this plan delivers exactly that.

**Outcome:** anyone can `docker compose run <tool>` over a mounted data dir with zero manual setup; tagged releases auto-publish a provenance-stamped image to GHCR; PRs are gated by the existing fast test suite.

#### Decisions (confirmed with user)

- **Scope:** the **4 component repos only**. `atrium-project` gets just a short strategy/index doc — no umbrella orchestration compose.
- **GH Action** (no preference given → recommended): **build & publish to GHCR** on tag/release, feeding the paradata `ATRIUM_RUNNER_*` hook; **`pytest -m "not slow"`** gate on PRs.
- **Run mode:** batch CLI (one-shot, mounted in→out, then exit) by default; an optional `api` Compose profile only for the two repos that ship a FastAPI `service/` (alto-postprocess, page-classification). translator & nlp-enrich are batch-only (confirmed: no `service/` dir).
- **Rollout:** pilot **atrium-translator** (lightest — no GPU, no API), verify end-to-end, then replicate the proven template to the other three.
- **Branch:** all work on `claude/determined-hypatia-fi57y4` (already exists in every repo; remote `origin` → `ufal/<repo>`).

#### Reuse — existing things to wire into, not reinvent

- **Provenance contract:** `atrium_paradata.py` (every repo) reads `ATRIUM_RUNNER_IMAGE/REPO/REF` (translator lines 54-58, 144-148, 253-255). Dockerfile build-ARGs → ENV must set these; nothing in app code changes.
- **Version source:** `para_config.txt` `[tool] version` (e.g. page-classification `v1.1.1-beta`) — drives image tags.
- **Test gate:** existing `pytest.ini` with the `slow` marker in all repos → CI runs `pytest -m "not slow"` (network/GPU-free).
- **Setup logic to translate into Dockerfile steps (not re-run at runtime):** `atrium-alto-postprocess/setup_api_server.sh` (LayoutReader `v3/` sparse-checkout + `lid.176.bin` download), `atrium-page-classification/setup_api_service.sh`.
- **Existing `.gitignore`s** (present in 3 of 4; absent in alto-postprocess) inform the `.dockerignore`.

#### The templated pattern (identical vs parameterized)

Every repo gets the same 4 files: `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `.github/workflows/docker.yml`. The two service repos also get `docker-compose.gpu.yml` and an `api` profile.

**Identical across all four:** the `ARG ATRIUM_RUNNER_* → ENV` block; `PYTHONUNBUFFERED`/
`PYTHONDONTWRITEBYTECODE`/pip env; `HF_HOME=/cache/huggingface`; non-root user `atrium` (uid 10001) owning `/app /cache /data`; layer order (copy requirements → `pip install` → copy source); volume convention (`./data:/data` bind + `hf-cache` named volume); the whole CI workflow except `IMAGE_NAME` and the test-deps apt line; the `.dockerignore`.

**Parameterized per repo:**

| Knob | translator (pilot) | alto-postprocess | nlp-enrich | page-classification |
|---|---|---|---|---|
| Image | `ufal/atrium-translator` | `ufal/atrium-alto-postprocess` | `ufal/atrium-nlp-enrich` | `ufal/atrium-page-classification` |
| Base | `python:3.11-slim` (all repos — satisfies 3.8+/3.10+) | same | same | same |
| apt build deps | `g++ libxml2-dev libxslt1-dev` (fasttext, lxml) | `g++ git wget` | none beyond base | `g++ libgl1 libglib2.0-0 poppler-utils` |
| Extra build steps | — | clone LayoutReader `v3/`, fetch `lid.176.bin` | — | — |
| torch in default image | no | **yes** | no (LLM variant: yes) | **yes** |
| ENTRYPOINT / default CMD | `python main.py` / batch args | `python run_pipeline.py` / `[]` | `bash -lc` / 4-script chain | `python3 run.py` / `-d /data/input --hf -rev v5.3` |
| GPU | no | optional override | optional (LLM only) | optional override |
| `api` profile | no | yes (`service/text_api.py`) | no | yes (`uvicorn service.api:app`) |
| Runtime secret | none | none | `HF_TOKEN` (gated LLM) | `HF_TOKEN` (gated/push only) |

#### Pilot: atrium-translator (reference template — full contents)

##### `Dockerfile`

```dockerfile
# syntax=docker/dockerfile:1.7
FROM python:3.11-slim AS base

ARG ATRIUM_RUNNER_IMAGE=""
ARG ATRIUM_RUNNER_REPO="https://github.com/ufal/atrium-translator"
ARG ATRIUM_RUNNER_REF=""
ENV ATRIUM_RUNNER_IMAGE=${ATRIUM_RUNNER_IMAGE} \
    ATRIUM_RUNNER_REPO=${ATRIUM_RUNNER_REPO} \
    ATRIUM_RUNNER_REF=${ATRIUM_RUNNER_REF} \
    PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 \
    PIP_NO_CACHE_DIR=1 PIP_DISABLE_PIP_VERSION_CHECK=1 \
    HF_HOME=/cache/huggingface

RUN apt-get update && apt-get install -y --no-install-recommends \
        build-essential g++ libxml2-dev libxslt1-dev ca-certificates \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY requirements.txt requirements-test.txt ./
RUN pip install -r requirements.txt -r requirements-test.txt
COPY . .

RUN useradd --create-home --uid 10001 atrium \
    && mkdir -p /cache/huggingface /data \
    && chown -R atrium:atrium /app /cache /data
USER atrium

ENTRYPOINT ["python", "main.py"]
CMD ["/data/input", "--alto", "--formats", "alto.xml", "--target_lang", "en", "-o", "/data/output"]
```

##### `docker-compose.yml`

```yaml
services:
  translator:
    image: ghcr.io/ufal/atrium-translator:${ATRIUM_VERSION:-dev}
    build:
      context: .

        ATRIUM_RUNNER_REPO: https://github.com/ufal/atrium-translator
        ATRIUM_RUNNER_REF: ${ATRIUM_RUNNER_REF:-dev}
    environment:
      ATRIUM_RUNNER_IMAGE: ghcr.io/ufal/atrium-translator:${ATRIUM_VERSION:-dev}
      ATRIUM_RUNNER_REPO: https://github.com/ufal/atrium-translator
      ATRIUM_RUNNER_REF: ${ATRIUM_RUNNER_REF:-dev}
      HF_HOME: /cache/huggingface
    volumes:
      - ./data:/data
      - hf-cache:/cache/huggingface
      - ./config.txt:/app/config.txt:ro
volumes:
  hf-cache:
```
Usage: `docker compose run --rm translator` (defaults), or override args after the service name, e.g. `... translator /data/input --alto -tgt en -o /data/output`; aux script via `docker compose run --rm --entrypoint python translator load_vocab.py --help`.

##### `.github/workflows/docker.yml`

```yaml
name: docker
on:
  pull_request:
  push:
    branches: ["claude/determined-hypatia-fi57y4", main]
    tags: ["v*"]
  release:
    types: [published]
env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ufal/atrium-translator
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: sudo apt-get update && sudo apt-get install -y --no-install-recommends build-essential g++ libxml2-dev libxslt1-dev
      - run: pip install -r requirements.txt -r requirements-test.txt
      - run: pytest -m "not slow"
  build-and-push:
    needs: test
    if: startsWith(github.ref, 'refs/tags/v') || github.event_name == 'release'
    runs-on: ubuntu-latest
    permissions: { contents: read, packages: write }
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with: { registry: "${{ env.REGISTRY }}", username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}" }
      - id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=semver,pattern={{version}}
            type=sha
            type=raw,value=latest,enable=${{ startsWith(github.ref, 'refs/tags/v') }}
      - uses: docker/setup-buildx-action@v3
      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          build-args: |
            ATRIUM_RUNNER_REPO=https://github.com/${{ github.repository }}
            ATRIUM_RUNNER_REF=${{ github.sha }}
            ATRIUM_RUNNER_IMAGE=${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.ref_name }}
```
Build-args → Dockerfile ARG → ENV → paradata, so a published `:v0.5.2` image self-reports `docker_image=ghcr.io/ufal/atrium-translator:v0.5.2` and `runner_ref=<sha>`.

#### Shared conventions

- **HF cache:** `HF_HOME=/cache/huggingface` + named volume `hf-cache` — models never baked, downloaded once, reused.
- **Model dirs:** `alto-models:/app/models` (holds `lid.176.bin`), `page-model:/app/model`.
- **I/O:** single bind `./data:/data`; convention `input/` + `output/` subdirs; paradata JSON lands under the output dir's `paradata/`.
- **Secrets:** `HF_TOKEN` supplied at runtime only (compose `environment:` from a git-ignored `.env`, or compose secrets) — **never** a build ARG, never committed.
- **`.env`** (git-ignored): `ATRIUM_VERSION`, `ATRIUM_RUNNER_REF`, `HF_TOKEN`.
- **GPU (alto, page, nlp-llm):** default images are CPU. Ship `docker-compose.gpu.yml` adding `deploy.resources.reservations.devices` (driver `nvidia`, `capabilities:[gpu]`) + `NVIDIA_VISIBLE_DEVICES`; used via `-f docker-compose.yml -f docker-compose.gpu.yml`. Requires NVIDIA Container Toolkit on host. We keep the slim base + torch's bundled CUDA rather than an `nvidia/cuda` base (smaller, no CUDA-version coupling).
- **atrium-project:** add `docs/containerization.md` (this strategy, condensed) + a links table; no code.

#### Risks / notes
- **Image size:** torch repos (alto ~5–7 GB, page ~6–8 GB CPU wheels). Pin the **CPU torch wheel index** in CI/Dockerfile to avoid accidentally pulling multi-GB CUDA wheels into the default image.
- **GHCR is private by default** — after first publish, repo admins must make the package public or have consumers authenticate.
- **Network:** full batch runs and API startup need outbound access to `lindat.mff.cuni.cz` and `huggingface.co`. The network-free checks are `pytest -m "not slow"` and alto's `run_pipeline.py --dry-run`.
- **alto-postprocess has no `.gitignore`** — add one alongside the `.dockerignore`.

## Per-repo Docker integrations — current state (similarities & differences)

All four component repos now carry a draft Docker integration built from one shared template, so
they already behave like interchangeable building blocks for the composer/wrapper this issue
tracks. Summary of what's in place and where they diverge.

### Shared foundation (identical by design)

- **Base & build:** `python:3.11-slim`, BuildKit (`# syntax=docker/dockerfile:1.7`), a single
  `base` stage (nlp-enrich adds a second — see below).
- **Provenance contract:** `ARG → ENV ATRIUM_RUNNER_IMAGE / ATRIUM_RUNNER_REPO / ATRIUM_RUNNER_REF`,
  consumed by the shared `atrium_paradata.py` and stamped into every output paradata JSON as
  `docker_image` / `repository` / `runner_ref`. CI injects them as build-args
  (`github.repository`, `github.sha`, `IMAGE:ref_name`), so a published image self-reports its origin.
- **Runtime env:** `PYTHONUNBUFFERED`, `PYTHONDONTWRITEBYTECODE`, `PIP_NO_CACHE_DIR`,
  `PIP_DISABLE_PIP_VERSION_CHECK`, `HF_HOME=/cache/huggingface`.
- **Layer order:** copy requirements → `pip install` → `COPY . .` (cache-friendly).
- **Non-root user** `atrium` (uid 10001) owning `/app`, `/cache`, `/data`.
- **Compose:** `image: ghcr.io/ufal/atrium-<tool>:${ATRIUM_VERSION:-dev}`, build passes the
  provenance args, `environment:` mirrors them + `HF_HOME`, volumes = `./data:/data` + a named
  `hf-cache` volume + a read-only bind of the tool's config file. HF models are **never baked** —
  pulled at runtime into `hf-cache`.
- **CI (`.github/workflows/docker.yml`):** a `test` job runs `pytest -m "not slow"` on every
  PR/push; a `build-and-push` job runs **only on `v*` tags / releases** and pushes
  `ghcr.io/ufal/atrium-<tool>` tagged `{semver, sha, latest}` via `docker/metadata-action` +
  `docker/build-push-action` (GHA cache), with provenance passed as build-args.

### Per-repo differences

**Cross-cutting notes**

- **GPU overlays:** alto, nlp, and page each ship a `docker-compose.gpu.*` adding NVIDIA device
  reservations; translator has none (CPU-only tool). page-classification is the only image that
  *requires* a GPU; the others are CPU-first with optional GPU.
- **API services:** alto and page expose an opt-in FastAPI on `:8000` behind an `api` profile;
  translator and nlp are batch-only (nlp instead has an `llm` profile for semantic enrichment).
- **Runtime secrets:** `HF_TOKEN` is wired for `nlp-llm` (gated models) and page (commented;
  gated / push) — supplied at runtime only, never as a build arg.
- **Heaviest images** are page-classification (CUDA torch) and alto-postprocess (CPU torch +
  LayoutReader); translator and base nlp are slim.

### Minor inconsistencies worth aligning during integration

- nlp-enrich uses `docker-compose.yaml` / `docker-compose.gpu.yaml`; the others use `.yml`.

its differences.

Newly added files collectively implement a centralized, DRY (Don't Repeat Yourself) CI/CD architecture for the four ATRIUM project repositories. ## E2E pipeline smoke test: `e2e-pipeline-smoke.yml` rewritten to actually thread a document JSON through all five stages - report by Sonnet

A prior rewrite of `e2e-pipeline-smoke.yml` moved the workflow from per-repo checkouts to published `docker run ghcr.io/ufal/atrium-*` images and threaded `--document-json`/`--document-json-out` through all five stages structurally — but the real file inputs each tool's CLI still needs underneath that baseline had been dropped in the process, so every stage failed for a different reason. This pass fixes the actual chain, stage by stage, verifying each fix against real fixture data (not just plausible-looking flags) before moving to the next.

### Stage 1 — Page Classification: wrong input type
Raw ALTO XML was being passed to `-f`, which expects a raster image → `PIL.UnidentifiedImageError`. Added a pre-step that renders a PNG from the fixture ALTO (`tools/e2e/render_alto_page.py`, which already existed in `tools/e2e/` but wasn't wired into the workflow) before Stage 1 runs. That script imports Pillow, which the workflow never installed — added `tools/e2e/requirements.txt` (`pillow>=12.3.0`) and a `pip install -r` step.

### Container-vs-runner permission mismatch (hit every stage in turn)
Every image runs as its own non-root user baked in at build time (e.g. `atrium`, uid 10001) — unrelated to the GitHub Actions runner's own uid that owns the `work/` directory after `mkdir -p`. The first stage to write into it (`doc_json/1_pc.json.tmp`) hit `PermissionError: [Errno 13]`; every later stage would have hit the identical wall on its own output directory. Fixed with `chmod -R a+rwX` on the workspace right after creating it — acceptable here since it's a throwaway CI workspace holding only fixture data, never secrets.

### Stage 2 — ALTO Postprocess: two separate gaps
1. `run_pipeline.py` has no `-f` single-file flag at all — it's config/directory-batch oriented (`--input-dir`, `--config`). Restored a scoped `config_e2e_alto.txt`, matching how the pre-rewrite (checkout-based) version of this workflow always did it, rather than inventing new CLI-only wiring the tool doesn't support.
2. `alto_stats_create.py` shells out to the external `alto-tools` CLI **unconditionally** — it's the stats stage, not an extraction-method choice, so this happens for every `--method`. The dependency was documented (`setup/para_config.txt`: `alto_tools ... ; always ;`, and the README's own dependency table) but never actually declared anywhere the published image installs from — it only ever worked where a caller happened to install it out of band (the README's manual clone step, or the pre-rewrite workflow's own extra `pip install`). Declared it in `atrium-alto-postprocess/setup/requirements.txt`, pinned to a commit (not a floating branch) — verified directly that the **PyPI** release (0.1.0) has no `-s`/statistics flag at all, only the git version implements it.

Also fixed `--document-json`/`--document-json-out` themselves in this repo: same class of bug as nlp-enrich below — declared in argparse, never wired to the working `--document-json-dir` mechanism every stage script already honors.

### Stage 3 — Translator: baseline is not a substitute for the real input
The rewrite dropped translator's required positional `input_path`/`--alto`/`--formats`/`-o` entirely, assuming the document-json baseline alone was enough. It isn't — `main.py` hard-checks `input_path` exists and prints `[ERROR]` + **exits 0** on failure, so this was failing silently green. Restored the real chain: translator now runs against alto-postprocess's actual per-page split output (`PAGE_ALTO/<doc>/<doc>-1.alto.xml`).

### Stage 4 — NLP Enrich: same config-file requirement as Stage 2, plus a document-identity bug
Needed its own scoped config file (bridged via the committed `DOC_LINE_CATEG` fixture CSV, since the real `classify` stage hard-requires CUDA). Once the config/flags were right, a live run surfaced a genuine accretion bug, root-caused with the run's own intermediate JSON artifacts: `page_categories`, `content`, `source`, and `translations` all survived stages 1–3 and vanished entirely at this stage.

Cause: `atrium-translator` names its output after the per-page split filename it's actually given (`"CTX000000003-1"`, not `"CTX000000003"`) — a `doc_id` mismatch that made nlp-enrich's document-json bridge seed its scratch directory under the wrong filename, silently missing its own baseline and falling back to "own contribution only," while a second, correctly-named-but-empty file was written alongside it. The collector then non-deterministically grabbed one of the two files sitting in the scratch dir. Full details and the fix (nlp-enrich now derives its own authoritative doc_id instead of trusting the baseline's declared field) are in [atrium-llm-enrich#13](https://github.com/ufal/atrium-llm-enrich/issues/13).

### Stage 5 — LLM Enrich: wrong image, wrong entrypoint, no gating
Three separate issues:
- `build-targets` for this repo is `["remote", "llm"]` — it excludes `"base"`, so the bare `ghcr.io/ufal/atrium-llm-enrich` image the old workflow pulled was **never published**. Switched to `-remote` (OpenRouter/CPU path — `-llm` is the local/HF-hosted GPU path and the wrong choice on `ubuntu-latest` regardless).
- The `-remote` image's `ENTRYPOINT` is bare `python`, not baked-in `openrouter_client.py` — a `docker run` without explicitly naming the script just starts the Python REPL. Added `openrouter_client.py` as the first argument.
- Restored `OPENROUTER_KEY` secret gating with a hard failure on `schedule` runs specifically — the exact "dark stage stays green for weeks" pattern this issue's earlier CI-hardening work already fixed once (see the original T1–T8 tracking above); a stage that quietly skips on PR/push (no secret available to forks/contributors) but is invisible-but-broken on the nightly schedule is the one outcome that must never happen silently again.

Also added the TEATER vocabulary fixture (`fixtures/e2e/VOCAB/teater_nested_vocab.json`, byte-identical copy from `atrium-nlp-enrich/data_samples/`) — the new image-based architecture has no per-repo checkout to source it from directly the way the old workflow did.

### `tools/e2e/e2e_assert.py`: two contract bugs, both now fixed
- The entity check looked for entities nested under `doc["lines"][i]["entities"]`, but `atrium_document.schema.json` defines `entities` as its own top-level array block (owner: nlp-enrich) — never merged into `lines`. The assert script's assumption was wrong, not the block placement.
- It also required a `"type"` key on every entity, which the schema never defines (only `type_onto`/`type_cnec`/`type_teitok`) — and which `merge_block`'s declared field-ownership list would silently drop even if a producer tried to write it. Fixed to check `type_onto`/`type_cnec` presence instead.

### Fixture switched back to the documented one
`E2E_DOC` was `CTX000000001` (2 pages, undocumented) — switched to `CTX000000003`, the fixture `fixtures/e2e/README.md` actually describes (single page, well-characterized), matching what the pre-rewrite workflow always used.

### Known caveat, worth restating here
`docker-tool.reusable.yml` only publishes the `:latest` tag on a `refs/tags/v*` build — this workflow only ever exercises each tool repo's latest **tagged release**, not every default-branch push. Several of the fixes above needed either a fresh release tag or a temporary "checkout latest source, run it inside the published image for its Python environment" workaround to actually get exercised in CI before a formal release existed. Worth a fresh look at whether this smoke test should track a floating pre-release tag instead, now that it's actually threading real data through every stage.
