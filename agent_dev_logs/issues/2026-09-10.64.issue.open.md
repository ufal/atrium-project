# [\#64 Issue](https://github.com/ufal/atrium-project/issues/64) `open`: Dev/prod parity: same Python version for CI lanes
**Labels**: `enhancement`, `development`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-10 12:26](https://github.com/ufal/atrium-project/issues/64):

Two small, mechanical divergences between what CI runs and what ships.

**One 3.12 lane in a 3.11 ecosystem.** All five images are `python:3.11-slim` and every CI lane is 3.11 — except `atrium-translator/.github/workflows/scheduled-smoke.yml:51`, which pins `python-version: '3.12'`. That same job also runs the whole suite (`pytest tests/ -rs`) rather than the slow subset it exists for (roadmap **D1**). So the one lane that differs from production is also the one with the widest blast radius: a 3.12-only failure reads as a product bug, and a 3.12-only pass hides one.

**B7, still live.** `atrium-nlp-enrich/docker-compose.gpu.yaml:1-3` instructs:

```
#   docker compose -f docker-compose.yml -f docker-compose.gpu.yml run --rm nlp
```

while both files on disk are `.yaml` (`docker-compose.yaml`, `docker-compose.gpu.yaml`). The documented command fails with "no such file" — a copy-paste path that cannot work.

### Scope

- `scheduled-smoke.yml:51` → `'3.11'`, matching the image and every other lane. Decide separately whether the suite selection there should narrow to `-m slow` (roadmap D1) or stay broad; if it stays broad, say why in a comment.
- Fix the four path references in the nlp-enrich GPU compose header.
- Sweep for the same `.yml`/`.yaml` mismatch in the other four repos' compose files and READMEs while in there.

### Acceptance

- `grep -rn "python-version" **/.github/workflows/*.yml` across all six repos returns 3.11 only.
- Every compose command printed in a comment, README or doc runs verbatim from that repo's root — verify by running them, not by reading them.
