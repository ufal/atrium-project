#### According to https://github.com/ufal/atrium-llm-enrich/issues/13 issue, the following preliminary decisions were made:

### 1. JSON

Contains all of the possible information about the document (page of a document) from all of the processing steps

- OCR text (and HTR text)
- page content category predicted
- text line quality categorization
- NER + UDPipe + KeyBERT enrichment with NLP processing
- LLM + vocabulary from TEATER tagging with predefined topic-related keywords
- anything else for connection of this JSON to other information records in the database

### 2. MD+(HTML-CSS)

Contains the textual content (plain text in full) - but not trash text lines (misrecognized handwriting, etc.) - including tables with simplified layout, and figure regions (width+height only)

- not strict alignment with the source visual layout of the page
- ordered OCR/HTR information with comments of visual context references
- comments about page number, paragraph type, table cells formatting

### 3. TEITOK XML

Contains visually correct XML elements of text strings and figure regions (ideally) that can be rendered on top of the PNG/JPG page image

- by default has NLP enrichment information from NER + UDPipe
- keywords, topic-based words, page content classification, and text line quality are not recorded by default (at the moment)
- bounding boxes of textual and graphical elements should be aligned with the relevant pieces of the image by coordinates that can be calibrated for the specific page image used for rendering

### Status of the 2026-08-01 TODO — 2026-09-24 by Opus 5.5

> Make sure JSON-2-MD and TEITOK-2-MD pipelines work correctly with the fully (and partially) enriched JSONs of documents and complex XMLs of pages

- **JSON-2-MD** — `atrium-llm-enrich/api_util/json_to_md.py`: page-sectioned Markdown with box, page-size and paragraph cues. It falls back to the record's `content.text` when there are no lines, and it never reads the `enrichment` block. 20 tests.
- **TEITOK-2-MD** — `atrium-llm-enrich/api_util/xml_to_md.py --format layout`: rebuilt on 2026-09-24 on TEITOK format 2's page model (a sentence that crosses a page break becomes one line per page part, page labels head the sections, print-space boxes are labelled). 25 tests; nlp-enrich's real sample `CTX000000002` is a pinned fixture.
- **Not yet:** a stress suite on fully enriched inputs. It is tracked as ufal/atrium-llm-enrich#11 (its 2026-08-02 task; a shape is proposed there). Its "nothing lost" criterion is being re-scoped: entities and keywords live in the JSON record, not in the Markdown.

**The TEITOK part of the decision, as built** (nlp-enrich, format 2):
- boxes calibrated to the displayed page image (`INPUT_PAGES_DIR` or `IMAGE_DPI`); the writer now warns when an image is missing or ALTO units stay unscaled;
- UDPipe + NameTag inside; keywords, topics, page categories and line quality not written;
- a contract gate before the file is used;
- the hub E2E checks the record against the TEITOK file ([run 35990199050](https://github.com/ufal/atrium-project/actions/runs/35990199050), green).

What can still produce a valid but misaligned file is listed in nlp-enrich's README § "TEITOK XML" → *Pitfalls*.
