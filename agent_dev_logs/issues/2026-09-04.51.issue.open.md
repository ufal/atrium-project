### Status update by Opus 5

Direction is unchanged and unchallenged: no namespace is requested from here, and the current IDs stay as they are. This is about the internal-alignment half he called "definitely desirable", which shipped on 2026-09-08. Five of the eight follow-ups in `docs/skos_strategy.md` §7 are now taken:

- **V-1 (F1) — fixed, and it changes what the model reads.** `DROP_CATEGORIES` was  `digital-convert`'s two labels only; alto-postprocess emits a disjoint set, so on the OCR path the filter matched *nothing* and every garbage line reached the model. It now filters on `UNTRUSTWORTHY_LINE_CATEGORIES`. Flagging it explicitly because it is the one change here with a downstream quality effect — it is in its own commit so any shift is attributable.
- **V-2 (F2) — fixed.** `collect_images()` raised on this repo's own sample data; the quieter half was that a stray *directory* would silently shift every class index out of step with `model_registry.CATEGORIES`.
- **F6 — built.** `enrichment.items[].teater_category_uri` carries the source concept's own URI, so the 707 captured `skos:exactMatch` URIs finally have somewhere to go. Populated via `concept_index()`, never via `nested_keep` — that path serialises into the system prompt, and a provenance field must not change model behaviour.
- **F8 — done.** Deleted an orphan fixture the README had called removed since August.
- **F3 — half.** `load_vocab.py --from-flat` rebuilds the translator's vocabulary from nlp-enrich's committed artifacts, so reproducing it no longer requires running the duplicate harvester. Full retirement still needs a release plan.

⚠️ **Two things worth your eye.**

**The regenerated translator CSV is 159 terms lighter** (5,087 → 4,952; 24 gained, 11 retranslated). Those are TEATER ethnology terms the live GraphQL API returns and the *pinned* snapshot does not — the reproducibility-vs-coverage trade V-3 names. If the coverage matters more, the lever is the snapshot ref, not this path.

**New defect V-5.** `enrichment.items[].teater_category` holds a **source** label (`kostel`), not one of the eleven ATRIUM harmonisation themes — but `atrium_vocab`'s `fields` entry and the crate's `CONTROLLED_TERMS` both read it as a theme. So the exporter was minting
`w3id.org/atrium/theme/kostel`: an ATRIUM-authored identifier for an **AMCR** concept, against `skos_strategy.md` §3, dangling beside the real one. The crate now prefers the source URI and mints nothing, which removes the false claim. **The contract question is not mine to settle**: should the field carry the source label (theme derived via `HESLAR_TO_THEME`), or the theme with the label moved to a sibling? The schema's own description agrees with production today, which puts the registry and `validate_labels` out of step rather than the pipeline.

Still open: **F4** (needs the CNEC reference), **F5** (register the `w3id.org/atrium` redirect — external, blocks nothing), **F7** (needs network; the parser is ready and tested).
