# [\#72 Issue](https://github.com/ufal/atrium-project/issues/72) `open`: Production architecture, dependency and release hardening
**Labels**: `enhancement`, `development`, `dependencies`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-30 07:19](https://github.com/ufal/atrium-project/issues/72):

Complete the production-side cleanup needed to turn the current tool set into a stable set of independently deployable ATRIUM services.

Scope:
- one production service per processing stage;
- establish the governed shared layers for document reading, LLM access and versioned vocabulary artifacts;
- remove the duplicate LLM/vocabulary implementation from `nlp-enrich`;
- keep research code in `llm-enrich` outside the production release line;
- extend `para-drift` coverage to the governed shared layers;
- replace the undeclared AGPL `PyMuPDF` dependency in page-classification with the agreed alternative after comparison;
- correct the AMČR vocabulary / TEATER licence declarations in `nlp-enrich` and `llm-enrich`;
- retain the already-established common `/health`, `/info`, limit and error-contract conventions;
- harden production release handling through branch protection and immutable release tags;
- keep the GPU runner as a later/deferred item rather than a pilot dependency.

Acceptance criteria:
- production images contain only their intended stage plus approved shared components;
- shared components are checked for drift;
- no production image depends on the undeclared AGPL dependency;
- vocabulary and licence metadata match the agreed AMČR baseline;
- production release tags cannot be silently retargeted;
- the resulting service layout is the baseline consumed by the processing/trust gate.

Dependencies:
- #32 typed contracts;
- #53 limits;
- #55 health/shutdown behaviour;
- #58 port handling;
- #40 for release governance.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-09-30 16:21](https://github.com/ufal/atrium-project/issues/72#issuecomment-5915288300):

The repository moves agreed on Wednesday take over most of this issue's architecture items:
- **Duplicate LLM/vocabulary code:** both copies move to keyword-extractor (ufal/atrium-nlp-enrich#40). Nothing is kept twice, and nlp-enrich becomes a CPU-only LINDAT client.
- **Research off the release line:** llm-enrich's images currently ship everything in the repository. That ends when its LLM code leaves (ufal/atrium-llm-enrich#29) and the converter gets its own `api-digital` image (ufal/atrium-llm-enrich#28).
- **One document reader:** ocr-postprocess owns it; the converter vendors it with pinned hashes.
- **One vocabulary artefact:** keyword-extractor publishes it as a release asset, and the translator reads it instead of harvesting the vocabularies itself.

What stays here: the service map, a check that each production image contains only its stage, PyMuPDF → pypdfium2, the flexiconv licence, immutable releases and workflow pins, and one gate change. The release gate fails any release whose service id changed, so the ocr-postprocess rename needs a declared-rename rule first.

Proposed order, since the report asks for one: immutable releases first; `api-digital` and the PyMuPDF comparison in parallel; the gate change and the schema round; then the three moves. S2 pins the result.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-10-01 05:51](https://github.com/ufal/atrium-project/issues/72#issuecomment-5925583708):

Round 1 is ready to land in the hub and all five tools. The repository moves (nlp#40, llm#28/#29, alto#56) are not part of it.

- **Service map:** [`docs/k8s_deployment.md` → *Which image to deploy*](https://github.com/ufal/atrium-project/blob/test/docs/k8s_deployment.md#which-image-to-deploy--one-production-image-per-stage-72). Each stage has one production image (`-api`) with its endpoints, program id and GPU. The other published targets are batch CLIs, never pinned.
- **What an image may contain:** each tool repo has `.github/production-image.json`, the list of first-party files its production image can run. CI checks it on every push (`tools/ci/image_closure.py`): an undeclared file, a stale entry or an unpinned copy of another repo's code fails. For the gate's diff review ("only the files that go into the image we use"), the scope is this file at the tag plus the hub's shared-module manifest. nlp-enrich's keyword/LLM files are marked `moving` until nlp#40 takes them out.
- **Shared layers:** para-drift has a new `vendored-parity` job that compares a vendored copy with its owner's `test`. llm-enrich runs it against nlp-enrich's TEITOK reader.
- **PyMuPDF:** replaced in page-classification (details on #6). CI now fails any probed image that has it installed.
- **Renames:** the release gate accepts a changed `x-atrium-service` only if the spec declares the old id in `x-atrium-service-previous`. This unblocks alto#56.
- **Release dates (report item 7):** immutable releases and the tag rules go on **after** the next five tags (page-classification 1.9.1-beta, alto 1.7.0-beta, translator 1.3.1-beta, llm 0.9.0, nlp 0.23.0), so every release AMČR reviews from then on is immutable. The workflow pins follow those tags. Order and scripts: [`docs/release_trust.md`](https://github.com/ufal/atrium-project/blob/test/docs/release_trust.md). The `status` output will follow here.

Still open: the flexiconv licence (upstream), the moves, and the single vocabulary artefact.
