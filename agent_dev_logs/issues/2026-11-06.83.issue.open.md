## Decision models in the ATRIUM workflow: experiments in four tools (for review before 11 November)

Pavel's suggestion in ufal/atrium-page-classification#58 has grown into experiments in four tools. A decision model reads an input with a fixed list of answers, and returns a probability for each answer. It writes no text, so it cannot answer outside the list. The candidates are Clef 27B, Clef-Flash 9B and Strands Decider 2B, all with open weights under Apache-2.0. Pavel (@stranak) already serves Clef on an internal ÚFAL machine, so the first runs can start next week.

Nothing in the pilot set changes. The work runs offline or behind opt-in flags, and the results are reported on each issue.

| Tool | What the model is asked | Judged against | Issue |
|---|---|---|---|
| page-classification | the page category when the classifier is unsure; which processors a page needs | 4,795 held-out pages | ufal/atrium-page-classification#58 |
| ocr-postprocess | the category of the lines the rules are least sure of | the 2,067-line gold set | ufal/atrium-ocr-postprocess#10 |
| digital-convert | the type of each PDF page and document, from AMČR's `dokument_typ` | the 15 AMČR PDFs | ufal/atrium-digital-convert#8 |
| keyword-extract | the vocabulary term for a line, chosen level by level | the R3 runs now, the gold set later | ufal/atrium-keyword-extract#3 |

One small client, `decision_client.py`, is written in page-classification. It is copied into the other three with a pinned checksum, like the other shared files (`docs/shared_components.md`).
