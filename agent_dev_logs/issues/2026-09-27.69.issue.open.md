Split from #18, which closes because AMČR no longer needs wrappers in the ARUP-CAS forks (#67). The roadmap in `docs/docker_gha_roadmap.md` (findings register §2, waves §4) is our own CI work; #18's comment of 7 September asked to execute or retire it.

**Findings re-checked on `test` (2026-09-27).** B1, B4, B5, B7, B8 and B9 are fixed. Still open:
- **B2:** compose files ask for `atrium-<tool>:<version>-api`, but CI publishes `atrium-<tool>-api:<version>` (nlp-enrich `docker-compose.yaml:35,86`; llm-enrich `docker-compose.yaml:4,32,74,98`).
- **B3:** `ATRIUM_RUNNER_IMAGE` is built from `github.ref_name` (`v…`), but GHCR carries the tag without the `v` (`docker-tool.reusable.yml:738,803`). Paradata therefore names an image tag that does not exist.
- **B6:** no repository has a `data/` folder. The compose bind mount creates it owned by root, so the uid 10001 container cannot write to it.

- [ ] **W1, guardrails (hub):** linter rules for `timeout-minutes`, `concurrency`, workflow-level `permissions` and the action floor; tests for `workflow_lint.py`; `hub-self-check` running the linter from the PR, not from `@v1`.
- [ ] **W2, the open live breakages:** B2, B3 and B6, with the §3.1 image-naming decision.
- [ ] **W3, an `:edge` channel,** so CI can test HEAD; parameterise the E2E.
- [ ] **W4, collapse the duplicated workflow families** (`release`, `scheduled-smoke`, `shellcheck`); split the `slow` and `gpu` markers.
- [ ] **W5, supply chain:** pinned tooling installs; the alto weight fetch pinned to a revision plus a checksum; `pip-audit` as a real gate; lockfiles; test and research dependencies out of the production images.
- [ ] **W6, convergence:** `HEALTHCHECK` and readiness in compose, asserted against a running container; page-classification's shellcheck gap. The GPU overlays wait with the GPU lane (deferred, #40).
- [ ] **Hygiene:** secret scanning on all six repositories; the placeholder token in `update_issues.sh`; the `line-length` 120 reformat in nlp-enrich and llm-enrich (from #10).

**For the AMČR pilot** (proposed in #67):
- B3 goes with R2, since every `CreateAction` names the image as its `instrument`.
- B2 and B6 go in, because AMČR runs these images.
- From W5, the items that change production images go in, together with R7's slimmer images.

Everything else waits until after the pilot, unless it is cheap.

Not here: branch protection, immutable releases and commit-pinned reusable workflows (#40); the GPU runner (deferred with #40).

**Done when:** each wave is executed or explicitly retired, and the roadmap says which.
