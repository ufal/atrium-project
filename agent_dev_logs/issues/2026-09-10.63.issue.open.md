# [\#63 Issue](https://github.com/ufal/atrium-project/issues/63) `open`: Backing services: make the UDPipe and LINDAT endpoints attachable resources
**Labels**: `enhancement`, `development`, `integration`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-10 12:21](https://github.com/ufal/atrium-project/issues/63):

Backing services are attachable where someone did it on purpose, and hardcoded right next door in the same repos. Both cases have the correct pattern already present a few files away, so this is two small changes, not a factor-wide refactor.

**atrium-nlp-enrich** — `api_util/call_nametag.py:202-206` takes a `--url` argument defaulting to `os.environ.get("NAMETAG_URL", NAMETAG_URL)`. Its sibling `api_util/call_udpipe.py:73` posts straight to the module constant `UDPIPE_URL` with no flag and no env read. `config_api.txt:19-20` already declares **both** URLs; only the shell path reads them.

**atrium-translator** — `processors/lemmatizer.py:40` holds `URL = "https://lindat.mff.cuni.cz/services/udpipe/api/process"` and `processors/translator.py:129` holds `BASE_URL = "https://lindat.mff.cuni.cz/services/translation/api/v2"` as class constants; `service/api.py:215` re-hardcodes the same URL into paradata. The same repo already treats its LLM backend as fully attachable (`LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`), and already env-tunes LINDAT's *transport* (`LINDAT_MIN_INTERVAL_S`, `LINDAT_MAX_RETRIES`, `LINDAT_BACKOFF_BASE_S` at `processors/translator.py:119-123`) — every dial except which host it talks to.

### Scope

- `call_udpipe.py`: add `--url`, defaulting to `os.environ.get("UDPIPE_URL", UDPIPE_URL)`, and thread it to the `session.post` at `:73`. Mirror `call_nametag.py` exactly.
- translator: read `UDPIPE_URL` / `LINDAT_BASE_URL` (names to match nlp-enrich's) with the current constants as defaults, and have `service/api.py:215` report the **effective** URL in paradata rather than a literal — a paradata record that names a host the request did not go to is worse than one that omits it.

**Explicitly out of scope**: converting algorithmic parameters to environment variables. Factor III is about *deployment-varying* config; thresholds, model registries and chunk sizes are correct in files, and moving them would make five config surfaces worse.

### Acceptance

- `UDPIPE_URL=http://localhost:9999 python api_util/call_udpipe.py …` attempts localhost:9999 and fails there — verify by pointing it at a local stub and reading the stub's log, not by reading the code.
- The same for the translator's two endpoints, including the paradata field.
- Defaults unchanged: with no variables set, all four call sites reach the same LINDAT hosts they reach today.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-09-11 16:25](https://github.com/ufal/atrium-project/issues/63#issuecomment-5637457253):

**Done.** `UDPIPE_URL`, `NAMETAG_URL`, `TRANSLATION_URL` (`LINDAT_BASE_URL` as alias), `KOREKTOR_URL`.
Precedence: `--url`/arg > env > config file > constant. **Empty counts as unset.**

Four more surfaces were broken beyond the four named here:

- **`source config_api.txt` silently defeated the env var** — bash keeps the export attribute, so a bare assignment overwrote *and re-exported* the deployment's value. Pre-fix: 0 stub hits on both stages, and `api_3_nt.sh` **exited 0** while calling the wrong host. This is also why **NameTag was not already correct** — its Python half was, but it sat behind the same clobber and `api_3_nt.sh` never passed `--url`, so `config_api.txt:20` was inert too.
- **`main.py:58`** wrote the LINDAT URL into CLI paradata **unguarded** — every LLM/CT2 run already claimed an endpoint it never contacted.
- **Compose never forwarded the variables**, so none of them could reach a container. `translator-batch` had no `environment:` block at all.
- **`KOREKTOR_API`** (alto-postprocess) was the same defect in a third repo.

⚠️ The acceptance test here invokes `call_udpipe.py` **directly**, bypassing the shell — it passes while the deployed pipeline stays unattachable.

**Verified**: `verify_issue63.py` 34/34, asserted from stub logs; 6 fail pre-fix. Defaults byte-identical. Suites unmodified: 860 / 497 / 1102.
**For #60**: `.env.example` added for nlp-enrich and translator (verified supersets of `service/` reads); three repos remain. `ATRIUM_<XX>_URL` is *not* a competing convention — it's inbound, these are outbound.
