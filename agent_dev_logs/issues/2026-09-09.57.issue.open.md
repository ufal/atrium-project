#### Status update by Opus 5

Design refreshed against the tree; nothing built this round, by decision. Premises all still hold —
`has_pages` false on all six, no scaffolding anywhere, **223 markdown files / ~50,900 lines / ~2.9 MB**.

Five corrections are folded into `agent_dev_logs/plans/57.plan.md` (marked ⚡):

1. **Reuse #59's `MANIFEST.json` pattern for `docs/site.yml`.** #59 landed after this plan was
   written and already solves the same problem — one registration drives every consumer, and a test
   asserts they agree. Inventing a second registration convention would re-create the defect #59
   exists to prevent.
2. **The `vit` default branch is a prerequisite, not a footnote.** Pages publishes from the default
   branch, so it gates page-classification's site rather than following it. Needs an owner.
3. **Permissions are tighter than the plan recorded**: `admin: false` on **all six** (not two), and
   `maintain: false` on `atrium-project` and `atrium-llm-enrich`. `actions/configure-pages` is the
   only path — for every repo, including the hub.
4. **The hub has no `CONTRIBUTING.md` of its own**, only the template the five tool repos vendor.
   Its Contributing page renders the family standard, not a local file.
5. **`atrium-page-classification/README.html`** (178 KB, stale, at repo root) needs a
   delete-or-exclude decision before a generator emits a competing HTML tree.
