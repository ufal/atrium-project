# [\#68 Issue](https://github.com/ufal/atrium-project/issues/68) `open`: Seeded record: alto-postprocess and llm-enrich return the seed, not their result, when its doc_id differs from the file name
**Labels**: `bug`, `integration`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-27 05:46](https://github.com/ufal/atrium-project/issues/68):

Found while planning #67 R1 (seeded baseline). Read in the code on `test` (alto-postprocess `b0341b3`, llm-enrich `7074643`), not yet reproduced; the test below reproduces it first.

The shared module keeps the seed's `doc_id` (`atrium_document.py` `_inherit_doc_id`, `:494-534`), and `finalize()` writes `<seed doc_id>.document.json` (`:1002`). Two tools then read back the file named after the id they derived from the upload's name:

| Where | Effect when the ids differ |
|---|---|
| alto-postprocess `service/text_api.py:503` saves the seed as `<derived id>.document.json` and reads it back at `:527-528` | `/process` returns the seed without alto-postprocess's `pages`/`lines` |
| alto-postprocess `run_pipeline.py:346-380` (`_prepare_document_json_bridge`, `_collect_document_json_output`) | `--document-json-out` gets the seed copy |
| llm-enrich `llm_client_shared.py:1247` (`baseline`), returned at `:1319`, loaded by `service/api.py:351-398` | the API returns the seed without `enrichment` |
| llm-enrich `service/api.py:516` hardcodes `doc_id="inline_text"` | a seed sent to `/extract_keywords_text` is never enriched |

An AMČR seed carries the AMČR file id as `doc_id`, and the upload has another name, so every pilot call hits this. It fails silently: the response is a valid record, just without the tool's block.

**Fix:** read back the path `finalize()` returns, not the derived name. In llm-enrich, return that path from the helper, and key `/extract_keywords_text` by the seed's `doc_id` when a record is sent.

**Done when:** in all five tool repositories, a test sends a seed whose `doc_id` differs from the upload's name, and the response record carries both the tool's block and the seed's `doc_id`. The test fails on the current code in alto-postprocess and llm-enrich and passes after the fix. page-classification, translator and nlp-enrich write to an explicit path and should pass already; the test keeps it that way.

Part of #67 (R1), first in its order.

#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-09-27 06:39](https://github.com/ufal/atrium-project/issues/68#issuecomment-5853461143):

**Fixed on `test` in all five tool repositories.** A seed now comes back with each tool's block, and it keeps its `doc_id`.

**The cause reached one step further than the table above.** Reproducing it first also showed that alto-postprocess's CLI lost work between stages. `run_pipeline.py --document-json` runs each stage as a separate process that finds the record by name. Each stage re-read the untouched seed and wrote `<seed id>.document.json`, so every stage overwrote the one before it, and only the last block survived.

Reading back "the path `finalize()` returns" cannot reach across those processes. So the fix is to **write back in place**: a tool writes the record to the file it read, returns that path, and its callers read that path. nlp-enrich already worked this way. The record keeps the seed's `doc_id`, and no shared module changed.

| Repository | Commit | Change |
|---|---|---|
| alto-postprocess | ufal/atrium-alto-postprocess@c37d610 | `write_document_block()` writes in place and returns the path; `/process` reads it back |
| llm-enrich | ufal/atrium-llm-enrich@32e3bac | `write_document_record()` returns the path it wrote, which fixes the API and `--document-json-out`; `/extract_keywords_text` is keyed by the sent record's `doc_id` when that is a safe file name; `enrichment` citations name that `doc_id` |
| page-classification | ufal/atrium-page-classification@26237c1 | test only |
| translator | ufal/atrium-translator@88a926b | test only |
| nlp-enrich | ufal/atrium-nlp-enrich@d681f9c | test only |

**Done when, checked:**

- [x] In alto-postprocess and llm-enrich, the tests fail with the fix reverted and pass with it.

The full suites pass (alto-postprocess 1761, llm-enrich 1033, page-classification 515, translator 829, nlp-enrich 1133), and every test job on `test` is green.

The fix reaches your images with the next alto-postprocess and llm-enrich releases. The seed profile, `source.sha512` and the seeded E2E follow under #67 R1.

Noticed along the way, not changed here: the translator builds its output path from the baseline's `doc_id` without checking it (`service/api.py:344`). That is harmless for AMČR ids, and we'll harden it with the translator's next change.
