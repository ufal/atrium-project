### 🔴 Cross-cutting missing pieces (highest value)

**1. `nlp-enrich/tests/tets_udpipe.py` — dead test file, never collected.** 🐛 pytest.ini uses `python_files = test_*.py`, so `tets_udpipe.py` (typo: `tets_`) is silently skipped — its `test_udpipe_smoke` never runs. Impact is low because `call_udpipe` *is* covered by the collected `test_conllu_processing.py` and `test_remote_apis.py`, so this file is redundant. Fix: rename to `test_udpipe.py` or delete it. Either way it's a latent trap.

**2. `llm-enrich` has no `test_paradata.py`.** It's the only repo of the five missing one, yet it ships the byte-identical shared `atrium_paradata.py` (md5 `4ad6df67…` across all 5). Note `test_paradata.py` is *not* a byte-identical drop-in (all four differ) — so the fix is to adapt a sibling's (nlp's is the closest fit), not copy blindly. The drift-CI won't catch this: it enforces the *module* + the shared `test_para_licenses.py` (identical `22a9753d…` everywhere ✅), but not per-repo paradata tests.

**3. `llm-enrich` carries three api_util modules that are byte-identical to nlp's and already tested there — but untested in llm.** 🎯 Straight test-port opportunity:

| Module (identical nlp↔llm) | LOC | Tested in nlp | Tested in llm |
|:--|--:|:--:|:--:|
| `api_util/teitok_alto.py` | 817 | ✅ | ❌ |
| `api_util/bbox_scale.py` | 104 | ✅ | ❌ |
| `api_util/flexiconv_convert.py` | 93 | ✅ | ❌ |

**4. `page-classification` — `REVISION_TO_BASE_MODEL` prefix-resolution has no regression guard.** 🐛 This is the latent bug flagged earlier. The `v*.4` block was fixed (specific-before-generic, with a comment), but the older generic block still lists `"v4."` **before** `"v4.3"` (and `"v3."` before `"v3.3"`, `"v5."` before `"v5.3"`). Exact keys are safe via the `if version in …` fast path, but any *non-exact sub-revision* falls to the first-match loop in `service/inference.py::_get_base_model_id` (also `run.py:985`):

- `"v4.3.1"` → matches `"v4."` first → returns `tf_efficientnetv2_l` ❌ (should be `regnety_160` via `"v4.3"`).

The two tests that touch this both dodge the ambiguity: `test_inference.py` patches a single-key dict, and `test_folds_split.py` only exercises the correctly-ordered `v*.4` keys. No test pins sub-revision resolution through the generic block.
