## Context

The 2026-07-29 audit reoriented this issue from *build it* to *harden it*. That hardening pass has now
**landed on `test` in all six repos and is green** — 33 workflow runs since the push, zero failures,
zero timeouts. Two of the changes are provably working rather than merely present: the concurrency
groups cancelled translator's superseded 03:49 runs when 03:50 landed, and the release-bundle closure
guard was verified failing on the old copy list and passing on the new one.

**What is left is activation, not code.** The two remaining P0s are both about reach:

1. The E2E's stage 5 is still dark — not because the gate is wrong, but because `OPENROUTER_KEY` was
   never added to `atrium-project`. Proven in run `30512204306`: `Gate on OPENROUTER_KEY` succeeded,
   then all 11 downstream steps skipped.
2. **GitHub fires `schedule` only from the default branch**, and this work is on `test`. So the nightly
   E2E gate, the GPU cron removals and the smoke failure reporting are all inert in 5 of 6 repos.
   Translator — already merged to `master` — is the only place the hardening is fully effective.

That second point is why **Wave A′ is now the highest-value, lowest-effort step in the whole plan**: a
branch merge unlocks work that is already written, reviewed and green.

## Wave A′ — activate what is already written

Nothing here needs new code. This is the whole reason the plan was re-cut.

| #       | Action                                                                                                                                                                                                                                                                                                |
|---------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **A′1** | Merge `test` → default branch in the five lagging repos: `atrium-project`→`main`, `alto-postprocess`→`master`, `llm-enrich`→`main`, `nlp-enrich`→`master`, `page-classification`→**`vit`**. This single step activates the E2E hard-fail gate, the GPU cron removals and the smoke failure reporting. |
| **A′2** | Add `OPENROUTER_KEY` to `ufal/atrium-project` repository secrets. It exists in llm-enrich and page-classification, but the E2E runs in the hub.                                                                                                                                                       |
| **A′3** | Confirm each repo's default branch is the one the team intends. `page-classification` defaults to `vit`, which is surprising given how often `master` appears in trigger lists.                                                                                                                       |

**Verify in this order — the order is the test:**
1. After A′1 but *before* A′2, the nightly E2E must go **red** at `Require the secret on scheduled runs`.
   A green nightly at this point means the merge did not reach `main`.
2. After A′2, the nightly must go green **with stage 5 actually executing** `Enrich the fixture lines
   (OpenRouter)` — check the step list, not just the run conclusion, since a skipped stage still
   reports `success`.
3. Confirm no `gpu-inference` scheduled run appears after the merge, and that llm-enrich/nlp-enrich
   smoke failures now open an issue.

## Wave B — remaining coverage gaps

- **Sequence Trivy after publish.** Move `image-scan`/`sbom` behind `needs: build-and-push` in
  `docker-tool.reusable.yml`, or gate on `workflow_run` completion of Docker Build & Publish. Then set
  `exit-code: "1"` for CRITICAL. Today they scan the *previous* release or fail to pull.
- **Decide one lint policy** — recommend blocking everywhere after one cleanup PR per repo.
- **Settle the gitleaks question** — adopt `secret-scan.caller.example.yml` or delete the template.
- **GPU runner provisioning** (rharasim) stays the standing external blocker. Until it lands, every
  `slow`-marked test is unexecuted and the E2E `alto → nlp` boundary keeps using the committed fixture
  CSV instead of a live `--start-from classify` run.

## Wave C — harden the reusable architecture

Still needs a decision before implementation.

- **Version the reusables.** Cut `v1` in `atrium-project`, migrate all 20 caller refs to `@v1`, keep
  `@test` as the pre-release channel. Protect `test` and `main`.
- **Replace `secrets: inherit`** with explicit `secrets:` declarations in each `workflow_call`, passing
  only `CODECOV_TOKEN`/`HF_TOKEN` where actually consumed.
- **SHA-pin third-party actions** holding write scope — `softprops/action-gh-release`,
  `anchore/sbom-action@v0` (floating major-zero), `aquasecurity/trivy-action`.
- Move `${{ inputs.* }}` out of `run:` bodies into `env:` (`docker-tool.reusable.yml:61,65,69`); fix the
  HF cache key, which hashes `**/*.py` and therefore always misses.

## Wave D — consolidate duplication

- **`version-guard` → one vendored `tools/check_version.py`**, held byte-identical by the existing
  `para-drift` mechanism. Keeps the release gate inline — it must not depend on a cross-repo `uses:`
  resolving at tag time — while removing ~300 lines of copy-paste.
- **`codeql.reusable.yml` and `pre-commit.reusable.yml`** in the hub; tool repos drop to ~12-line callers.
- **Complete the template set** — caller examples for `security`, `api-contract`, `para-drift`.
- Align dependabot configs: grouping in llm-enrich/nlp-enrich (one PR per dep today), and correct
  `directory:` in page-classification (watches `/`, manifests are in `setup/` and `service/`).
- Sweep stale comments and the vestigial `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24`.

## Done-criteria for the issue

- Nightly E2E exercises all five stages, and fails loudly when it cannot.
- No workflow targets a branch that does not exist; PR checks match push checks everywhere.
- Release artifacts start standalone, proven per tag by the closure guard.
- All 20 caller refs resolve to an immutable ref; no caller passes `secrets: inherit`.
- `slow`-marked tests execute somewhere on a real schedule.
