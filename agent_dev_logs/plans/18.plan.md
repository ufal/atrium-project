# Strategy — Issue #18: Docker compose + GH-action wrapper for CU forks

> Issue [#18](https://github.com/ufal/atrium-project/issues/18) · Labels: `enhancement`, `help wanted`, `development`, `a big one` · **Status: 🛠️ Harden**
> _Refreshed 2026-07-29 from a full GHA audit of all six repos (53 workflow files, 20 cross-repo refs, live run history)._

## Context

The build-out phase this issue was opened for is **done**. The reusable-workflow architecture is
in place and working: five reusables in `atrium-project`, thin callers in each tool repo, GHCR
publishing on tags, paradata drift-checking that genuinely holds (all shared modules byte-identical
across all five repos), and a five-stage end-to-end pipeline smoke test that has been green since
2026-07-16. All bugs tracked in the previous revision of this plan are closed, including the three
translator P0/P1 items, now verified in-repo.

**The problem is no longer breakage — it is false confidence.** The 2026-07-29 audit found that the
green dashboard is partly green because several checks assert nothing: the E2E's final stage gates
on a secret name that was never created, two committed workflows are empty placeholders, no GPU
runner exists so no `slow`-marked test has ever run, and container scans race the image they scan.
Separately one shipped release artifact cannot start, and the whole ecosystem executes code from an
unprotected branch in another repo while inheriting every secret.

This plan therefore reorients #18 from *build it* to **harden it**, in four waves ordered by blast
radius.

## Wave B — close the coverage gaps

- **Normalize triggers per repo.** `push` and `pull_request` must cover the *same* branch list;
  tags `v*` and `release: [published]` everywhere. Today PRs targeting `master` skip api-contract
  and para-drift in **all five** repos, and page-classification's active `vit`/`clip` branches skip
  both entirely. Per-repo lists: alto/nlp/translator `[test, master]`, llm-enrich `[test, main]`,
  page-classification `[test, vit, clip, master]`. Also align translator's `v*.*.*` to `v*`.
- **Resolve the GPU-runner dependency.** No `[self-hosted, gpu]` runner is registered, so the three
  `gpu-inference.yml` workflows have never run and every `slow`-marked test in the ecosystem is
  unexecuted (`docker-tool.reusable.yml` runs `pytest -m "not slow"`). Until rharasim provisions
  one, drop the `cron` and keep `workflow_dispatch` only, so the ecosystem stops advertising
  coverage it does not have. **This is the single largest real coverage hole.**
- **Uniform smoke-failure reporting.** Port the `if: failure()` → `github-script@v9` open-an-issue
  step into llm-enrich and nlp-enrich; align cadence to daily across all five.
- **Sequence Trivy after publish.** Move `image-scan`/`sbom` behind `needs: build-and-push`, or gate
  on `workflow_run` completion of Docker Build & Publish; then set `exit-code: "1"` for CRITICAL.
- **Decide one lint policy** — recommend blocking everywhere after one cleanup PR per repo.
- **Settle the gitleaks question** — adopt `secret-scan.caller.example.yml` or delete the template.

## Wave C — harden the reusable architecture

- **Version the reusables.** Cut `v1` in `atrium-project`, migrate all 20 caller refs to `@v1`, keep
  `@test` as the pre-release channel. Protect `test` and `main`.
- **Replace `secrets: inherit`** with explicit `secrets:` declarations in each `workflow_call`,
  passing only `CODECOV_TOKEN`/`HF_TOKEN` where actually consumed.
- **Least privilege** — `permissions: { contents: read }` as the default, widened per job only where
  needed (missing today on api-contract, para-drift, pre-commit, shellcheck, gpu-inference callers
  and three hub reusables).
- **`timeout-minutes` on every job** (currently 0 of 53) and `concurrency` with
  `cancel-in-progress: true` on every PR-triggered workflow (currently 2 of 53).
- **SHA-pin third-party actions** holding write scope — `softprops/action-gh-release`,
  `anchore/sbom-action@v0` (floating), `aquasecurity/trivy-action` (its own comment recommends this
  after the 2026-03 incident).
- Move `${{ inputs.* }}` out of `run:` bodies into `env:` (`docker-tool.reusable.yml:61,65,69`); fix
  the HF cache key, which hashes `**/*.py` and therefore always misses.

## Wave D — consolidate duplication

- **`version-guard` → one vendored `tools/check_version.py`**, held byte-identical by the existing
  `para-drift` mechanism. Keeps the release gate inline — the stated reason it was inlined is that it
  must not depend on a cross-repo `uses:` resolving at tag time — while removing ~300 lines of
  copy-paste across five `release.yml` files plus `security.reusable.yml`.
- **`codeql.reusable.yml` and `pre-commit.reusable.yml`** in the hub; tool repos drop to ~12-line
  callers (5 × ~35 and 5 × ~30 near-identical lines today).
- **Complete the template set** — add caller examples for `security`, `api-contract` and
  `para-drift`, the three active reusables that have none.
- Align dependabot configs: grouping in llm-enrich/nlp-enrich (one PR per dep today), and correct
  `directory:` in page-classification (watches `/`, manifests are in `setup/` and `service/`).
- Sweep stale comments (page-classification `release.yml` says "Bumped from v4 to v5" on a `@v7`
  line; alto-postprocess `security.yml` says "Pin @main" over an `@test` ref) and the vestigial
  `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24`.

## Verification / done-criteria

- Page-classification's release zip starts standalone; a CI step proves it on every tag.
- A scheduled E2E with a missing secret goes **red**, not green; with the secret, all five stages run.
- Every repo's PR checks match its push checks; no workflow targets a branch that does not exist.
- No workflow can run longer than its `timeout-minutes`; superseded PR runs cancel.
- All 20 caller refs resolve to an immutable `@v1`; no caller passes `secrets: inherit`.
- 5/5 tool repos plus the hub stay green after each wave merges to `test`.
