## T1 — P0: push the `docker.yml` permission fix

**Done locally, needs pushing.** The five `docker.yml` callers now grant `security-events: write`
(job-level in four repos; workflow-level in translator, which has no job-level block).

Root cause worth remembering: **a reusable workflow's job permissions are capped by the calling job's
grant.** Wave B gave the reusable's `build-and-push` `security-events: write` for the Trivy SARIF
upload; the callers granted only `contents: read` + `packages: write`, so GitHub rejected the file at
parse time — `startup_failure`, not a step failure, which is why local YAML validation missed it.

A caller-vs-callee permission check now exists and passes for all 20 pairs. Keep running it whenever a
reusable's `permissions:` block changes; that check's absence is what let this through.

**Verify:** any push to `test` re-runs the workflow, since the failure is a parse error — no tag
needed. Docker Build & Publish must leave `startup_failure` in all five repos. The Trivy/SARIF steps
themselves only execute on a `v*` tag, so they stay unexercised until the next release.

## T3 — `@v1` reusable pin + branch protection

All 20 refs point at `…@test`, an unprotected mutable branch in another repo. Cut `v1` in
`atrium-project`, migrate every caller to `@v1`, keep `@test` as the pre-release channel, and protect
`test` and `main`.

Do it as **one atomic operation**: migrating callers before the tag exists breaks every repo's CI.

## T4 — `codeql.reusable.yml` / `pre-commit.reusable.yml` — **only after T3**

Would collapse ~325 duplicated lines (CodeQL 5 × ~35, pre-commit 5 × ~30). Deliberately **not** done
yet: it moves 10 more workflows behind a `@test`-pinned cross-repo ref, raising mutable-branch
coupling from 20 refs to 30 *before* the pin is immutable. That inverts the blast-radius ordering this
plan is built on — and T1 is a concrete demonstration of what one hub-side change can do to five repos
at once. Sequence it after T3, not before.
