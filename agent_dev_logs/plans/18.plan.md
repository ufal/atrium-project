## Refinement & expansion waves (proposed 2026-08-04)

| Wave   | Theme                        | Blast radius       | Headline                                                                                                                                                                                                               |
|--------|------------------------------|--------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **W1** | Make the guardrails real     | hub only           | The linter has no rule for `timeout-minutes`, `concurrency`, workflow-level `permissions` or the action floor — and `hub-self-check` runs the linter **from `@v1`**, so a linter change is never tested by its own PR. |
| **W2** | Live breakages               | 5 tool repos       | Two API images cannot start (`uvicorn` absent); 6 compose image refs unpullable; paradata names an unpublished tag; the E2E's secret-less path can only fail.                                                          |
| **W3** | `:edge` image channel        | hub + 5 callers    | Images publish only on `v*`, so CI can only ever test the last release, never HEAD.                                                                                                                                    |
| **W4** | Finish the DRY collapse      | hub + 5 tool repos | ~1,020 lines of `release`/`scheduled-smoke`/`gpu-inference`/`shellcheck` with no reusable; already drifted into 3 nightly semantics.                                                                                   |
| **W5** | Supply chain & image hygiene | 5 tool repos       | No lockfiles or hash pinning; 2 floating VCS refs; a ~1.2 GB unpinned build-time weight fetch; test+research deps in production images.                                                                                |
| **W6** | Convergence & new targets    | 5 repos + hub      | No `HEALTHCHECK` anywhere, though "reachable via API" is this issue's requirement; plan the `digital` target before the PDF/DOCX converter lands.                                                                      |

**Sequencing rationale:** guardrails before refactor. The 2026-07-30 round landed timeouts on 45 jobs and
concurrency on 33 workflows; two days later `all-repos-smoke.yml` shipped with neither, plus no
`permissions:` block, and CI stayed green — because no rule checks any of them. Collapsing another ~1,000
lines before the linter can hold the result repeats that at five times the blast radius.

## Decisions settled 2026-08-04

1. **Documentation-only round** — findings need owner review before five-repo diffs land.
2. **All four expansion themes in scope** — they are interdependent: `:edge` is what lets the collapsed
   workflows be validated without cutting a release.
3. **Retire `test`; protect the default branch** — `test` is byte-identical to default in all six repos, so
   it doubles CI spend per push and protects nothing.
4. **GPU lane becomes runner-agnostic**, and `slow` splits into `slow` (network, runnable on
   `ubuntu-latest` today) + `gpu` (needs CUDA) — so three currently-vacuous nightly lanes become
   substantive with no runner at all.
