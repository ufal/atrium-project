## T2 — `@v1` pin migration — ✅ COMPLETE

**42 caller jobs** across six repos resolve `@v1`; zero `@test` pins remain anywhere, including the
five `agent-skill` branches migrated 2026-07-31.

Those five were the last gap and they matter more than their count suggests. The original 26-ref
migration walked default branches only, so `agent-skill` kept a `@test` pin — and a `test`-branch
change is precisely what silently broke them (T6). The lesson generalises: **a pin migration must
enumerate branches, not repos.**

`para-drift.reusable.yml` takes a `hub-ref` input (default `v1`) so `@test` callers stay
self-consistent — otherwise the pin would be half-done, taking workflow *logic* from the immutable
tag while the *files it enforces* still came from a mutable branch.

**Two channels**, documented in `docs/docker_gha.md` §1: `@v1` is what every caller pins (a moving
major tag only a maintainer advances); `@test` validates a hub change before `v1` moves.

## T4 — Supply chain + Trivy policy — ✅ DECIDED

**SHA pins.** The precedent is in this repo's own history: `security.reusable.yml` documented that
`aquasecurity/trivy-action` tags ≤ 0.34.2 were force-pushed to credential-stealing malware on
2026-03-19 (GHSA-69fq-xp46-6x23, 76 of 77 tags) and recommended pinning to the release commit. Live on
`main`: `docker/build-push-action` ×3, `trivy-action` ×2, `peter-evans/create-pull-request` ×1.
`softprops/action-gh-release` ×5 is committed but **not yet on any default branch** — see T8.

Read-only and upload-only actions (`setup-buildx`, `metadata`, `login`, `codecov`) stay on tags
deliberately. Dependabot maintains SHA pins and their trailing `# v3` comments, so this hardens
without freezing.

**Trivy `exit-code`.** Settled as a *separate* gate rather than by flipping the existing step, which
keeps two concerns apart: the SARIF step still runs on every build and never blocks, so the full
CRITICAL+HIGH picture always reaches code scanning; the new step blocks. It sits **after** the SARIF
upload deliberately — if it fails, the findings are already in the Security tab.

| Narrowing                                  | Effect                                                  |
|--------------------------------------------|---------------------------------------------------------|
| `if: startsWith(github.ref, 'refs/tags/')` | pushes and PRs untouched; it stops a *release*          |
| `severity: CRITICAL`                       | HIGH stays report-only — too noisy to hold a release on |
| `ignore-unfixed: true`                     | an unpatchable CVE cannot wedge releases indefinitely   |

The weekly `security.reusable.yml` scan stays report-only. **Caveat:** the code scanning alerts were
not readable from the session that made this change, so the design fails safe rather than deriving
from a triaged list, and it cannot fire without a tag. Reverting is one value.

## T6 — Templates and the `skill-validate` clobber — ✅ RESOLVED

**Caller-example templates.** `codeql.caller.example.yml` was a byte-identical copy of the docker
example. A sweep then found worse in `docker.caller.example.yml`: an *explicit* permissions block of
only `{contents: read, packages: write}` while `docker-tool.reusable.yml` requests
`security-events: write` — so copying it reproduced the Wave B `startup_failure` verbatim. Fixed,
along with a leftover `secrets: inherit` and a missing tag-exempt `concurrency` block.

The distinction to keep: an **explicit** block omitting a scope fails at parse time; **no** block at
all inherits the repo default and is fine.

**The clobber.** Commit `39a9edd` applied one round's `security.reusable.yml` edits into
`skill-validate.reusable.yml`, destroying 348 lines and leaving `security.reusable.yml` unpinned. All
five `agent-skill` callers pass `client-script`; the replacement declared different inputs, so they
were **already broken** — latently, since nobody had pushed to those branches. Restored from
`7fa727b`; verified at `v1` and against all five callers.

## T7 — Hub self-coverage — ⚠️ HALF-LANDED

The hub is the source of truth for 42 caller jobs and six vendored files and had **no caller
workflows at all**. Nothing in CI parsed, linted or policy-checked it — which is why two clobbers and
a missed pin were each caught only by a human reading files.

**Live and green** on `main` (`34f5ccd`, 07:59:24Z): `codeql.yml` and `pre-commit.yml`, calling the
hub's own reusables by **local `./` path** so the self-check validates the ref being pushed rather
than the last released tag. `ruff.toml` `extend`s `docs/templates/ruff.toml` rather than copying it,
so the hub is held to the config it publishes and the two cannot drift.

**Next step — one file.** A workflow with two jobs closes all three: run
`python tools/ci/workflow_lint.py --repo-root .`, and run pytest over `tests/` and
`docs/templates/shared/`. `contents: read`, no secrets, plus a weekly cron since the pin check
resolves real tags that can move while nothing here changes.

The linter's six checks, each matching a defect this issue hit: every workflow and template parses ·
write-scoped actions SHA-pinned with a version comment **whose tag really resolves to that SHA** ·
caller/callee permissions agree (explicit under-grant fails, no block inherits) · no structural
`secrets: inherit` · no duplicate `name:` within a directory · no template passing an input its callee
does not declare. The last two are the clobber detectors; both real incidents are caught when
replayed. Every check was proven able to fail on its own defect, and seven mutations of
`check_version.py` are each detected by the tests.
