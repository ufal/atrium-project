## T1 — Exercise the release path (top priority)

Latest tags are `v1.4.0-beta`, `v0.4.0`, `v0.18.0`, `v1.7.0-beta`, `v0.10.0` — all from **2026-07-26 or
earlier**, and each `para_config.txt` already matches its tag, so nothing is mid-bump. These five
guards have therefore never executed:

1. `check_version.py` invoked from `release.yml` with `--require-tag`
2. page-classification's release-bundle closure guard
3. the post-publish Trivy digest scan and its SARIF upload
4. the buildkit `sbom: true` / `provenance: true` attestations
5. `build-and-push` under the caller's new `security-events: write` grant

**One patch release exercises all five at once.** Pilot with **atrium-translator**: lightest repo, no
GPU, no torch, single `base` build target — the same pilot choice this issue settled on originally.

Sequence: bump `CITATION.cff` and `para_config.txt` together, tag `v0.10.1`, push the tag. Then check
- `version-guard` passes via `check_version.py --require-tag`
- `build-and-push` completes (this is the first exercise of the new permission grant)
- the Trivy digest scan runs and SARIF lands in the Security tab under `trivy-publish-base`
- `docker buildx imagetools inspect ghcr.io/ufal/atrium-translator:0.10.1` shows the SBOM and
  provenance attestations
- the release zip attaches

**Run the negative test too** — tag once with `CITATION.cff` deliberately out of step and confirm
`version-guard` blocks the release. That gate exists to stop a mistagged publish (it would have caught
`v1.0.0.-beta` and `v1.16.2`) and it has never had occasion to fire. Cheap to prove, expensive to
discover broken during a real release.

Then replicate in **page-classification**, whose bundle closure guard covers a defect that actually
shipped.

## T2 — `@v1` reusable pin + branch protection

All 20 refs still point at `…@test`. This became **more** valuable with the merges, not less: `test` is
now the default branch, so a bad hub push lands directly on every repo's production branch rather than
an integration branch.

Cut `v1` in `atrium-project`, migrate all 20 callers to `@v1`, keep `@test` as the pre-release channel,
and protect the default branches. **One atomic operation** — migrating callers before the tag exists
breaks every repo's CI simultaneously.

Two properties of the current pin worth carrying into the design:
- **Enforcement crosses branches.** `para-drift.reusable.yml` checks the hub out at `ref: test` while
  its callers fire on default-branch pushes, so the newest templates are enforced against branches
  that may lack the matching vendored file. This nearly bit when the `check_version.py` parity step
  landed before any default branch had the file; the merge happened to deliver both together.
- **Blast radius is demonstrated, not theoretical.** The Wave B permission change took down
  `docker.yml` in all five repos at once, from a single hub-side edit.

## T4 — Remaining decisions

- **Trivy blocking severity.** `exit-code: "0"` in both the post-publish and periodic scans. T1

  a release.
- **gitleaks.** Adopt `secret-scan.caller.example.yml` or delete it — no repo calls it.
- **SHA-pin write-scoped third-party actions** (`softprops/action-gh-release`,
  `aquasecurity/trivy-action`) via `pin-github-action` or Dependabot digest support, so the pins are
  verifiable rather than hand-written.

## T5 — GPU runner (external, rharasim)

Until a `[self-hosted, gpu]` runner is registered, no `slow`-marked test executes anywhere and the E2E
`alto → nlp` boundary keeps using the committed fixture CSV instead of a live `--start-from classify`
run. Crons are removed so the ecosystem stops advertising coverage it lacks; restore instructions are
inline in each `gpu-inference.yml`.
