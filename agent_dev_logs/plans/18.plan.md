## Context

The 2026-07-29 audit reoriented this issue from *build it* to *harden it*. That hardening pass has now
**landed on `test` in all six repos and is green** — 33 workflow runs since the push, zero failures,
zero timeouts. Two of the changes are provably working rather than merely present: the concurrency
groups cancelled translator's superseded 03:49 runs when 03:50 landed, and the release-bundle closure
guard was verified failing on the old copy list and passing on the new one.

**What is left is activation, not code.** The two remaining P0s are both about reach:

1. The E2E's stage 5 is still dark — not because the gate is wrong, but because `OPENROUTER_KEY` was
   never added to `atrium-project`. Proven in run `30512204306`: `Gate on OPENROUTER_KEY` succeeded,
   then all 11 downstream steps skipped.
2. **GitHub fires `schedule` only from the default branch**, and this work is on `test`. So the nightly
   E2E gate, the GPU cron removals and the smoke failure reporting are all inert in 5 of 6 repos.
   Translator — already merged to `master` — is the only place the hardening is fully effective.

That second point is why **Wave A′ is now the highest-value, lowest-effort step in the whole plan**: a
branch merge unlocks work that is already written, reviewed and green.

## Wave A′ — activate what is already written

Nothing here needs new code. This is the whole reason the plan was re-cut.

| #       | Action                                                                                                                                                                                                                                                                                                |
|---------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **A′1** | Merge `test` → default branch in the five lagging repos: `atrium-project`→`main`, `alto-postprocess`→`master`, `llm-enrich`→`main`, `nlp-enrich`→`master`, `page-classification`→**`vit`**. This single step activates the E2E hard-fail gate, the GPU cron removals and the smoke failure reporting. |
| **A′2** | Add `OPENROUTER_KEY` to `ufal/atrium-project` repository secrets. It exists in llm-enrich and page-classification, but the E2E runs in the hub.                                                                                                                                                       |
| **A′3** | Confirm each repo's default branch is the one the team intends. `page-classification` defaults to `vit`, which is surprising given how often `master` appears in trigger lists.                                                                                                                       |

**Verify in this order — the order is the test:**
1. After A′1 but *before* A′2, the nightly E2E must go **red** at `Require the secret on scheduled runs`.
   A green nightly at this point means the merge did not reach `main`.
2. After A′2, the nightly must go green **with stage 5 actually executing** `Enrich the fixture lines
   (OpenRouter)` — check the step list, not just the run conclusion, since a skipped stage still
   reports `success`.
3. Confirm no `gpu-inference` scheduled run appears after the merge, and that llm-enrich/nlp-enrich
   smoke failures now open an issue.

## Wave B — coverage gaps — ✅ DONE except the standing blocker

- ✅ **Container-scan race removed.** The post-publish Trivy scan now runs inside
  `docker-tool.reusable.yml`'s `build-and-push`, against the digest that step just
  pushed, with a per-target SARIF category so multi-target repos (nlp-enrich:
  base/api/llm) do not overwrite each other's findings.
  `security.reusable.yml` keeps only the periodic `:latest` re-scan — the thing it
  is actually good at, and which cannot race anything. `exit-code` stays `"0"` in
  both: flipping it to block a release is a triage policy call, not a mechanical
  one, so it is left to maintainers.
- ✅ **SBOM job removed.** Release SBOM + provenance are now buildkit attestations
  pushed with the image (`sbom: true`, `provenance: true`). That also retired
  `anchore/sbom-action@v0`, the last floating major-zero third-party pin.
- ✅ **One lint policy.** All five repos now run pre-commit blocking. llm-enrich's
  only finding was a B008 on FastAPI's `arg: T = Body(...)` idiom — a false
  positive, fixed by adding `fastapi.*` to bugbear's `extend-immutable-calls`
  (the allowlist alto-postprocess already had), not by restructuring the code.
  nlp-enrich was already clean.
- 🚧 **GPU runner** (rharasim) remains the standing external blocker. Until it
  lands, no `slow`-marked test executes and the E2E `alto → nlp` boundary keeps
  using the committed fixture CSV.
- 📝 **gitleaks** still undecided — adopt `secret-scan.caller.example.yml` or
  delete it.

## Wave C — reusable hardening — ✅ DONE except the pin itself

- ✅ **`secrets: inherit` eliminated.** `docker-tool.reusable.yml` now declares the
  one secret it consumes (`CODECOV_TOKEN`); the other four reusables consume none,
  so their callers pass no secrets at all. Previously every caller handed the hub
  every secret in the repo.
- ✅ **Expressions out of `run:` bodies.** `apt-packages`, `pre-install-torch` and
  `requirements` now arrive via `env:` and are quoted.
- ✅ **`torch-index-url` input** — the CPU wheel index was hardcoded, so a CUDA
  build could not be requested by a caller. alto-postprocess's bare `torch` now
  passes `torch>=2.1,<3.0`, matching its own manifest.
- ✅ **HF cache key** keys on a caller-supplied model revision
  (`hf-cache-key: v4.3`) instead of `hashFiles('**/*.py')`, which changed on every
  source edit and so almost never hit.
- ✅ **Lagging pins levelled** — `checkout@v5`, `setup-python@v5`,
  `upload-artifact@v4` in the hub reusables brought onto the majors the rest of the
  hub already runs green. `checkout` is now uniformly `@v7` ecosystem-wide.
- ❌ **Still open: `@v1` tagging and branch protection.** Requires cutting a tag in
  `atrium-project` and 20 caller edits, plus repo-settings changes. Migrating
  callers before the tag exists would break every repo's CI, so this needs to be
  done as one deliberate operation.
- 📝 **SHA-pinning third-party actions** deferred: resolving trustworthy commit
  SHAs means reading repos outside this session's allowed scope, so any SHA written
  here would be unverified — worse than a tag. Do it with `pin-github-action` or
  Dependabot's digest support, which now runs on the hub.

## Wave D — consolidation — ✅ DONE except one deliberate deferral

- ✅ **`version-guard` → `check_version.py`.** One canonical script in
  `docs/templates/shared/`, vendored into all five tool repos and held
  byte-identical by a new `para-drift.reusable.yml` step. Replaced ~360 lines of
  copy-paste that had already drifted between the five `release.yml` files and the
  hub's own three-way variant. Both call sites now run the same code: `release.yml`
  with `--require-tag`, `security.reusable.yml` without. It stays a vendored file
  rather than a reusable workflow because the release gate must not depend on a
  cross-repo `uses:` resolving at tag-push time.
- ✅ **Template set completed** — caller examples added for `security`,
  `api-contract` and `para-drift`; every active reusable now has one.
- ✅ **Dependabot aligned** — every ecosystem in every repo is grouped (llm-enrich
  and nlp-enrich were opening one PR per dependency). page-classification's pip
  entry watched `/`, where the only manifest is a forwarding stub, so its real
  dependency surface under `setup/` and `service/` was unmonitored; now split per
  directory like alto-postprocess.
- ✅ **Stale comments swept** — the "Bumped from v4 to v5" note on a `@v7` line, the
  "Pin @main" header over an `@test` ref, the duplicated build-targets paragraph,
  and the five `release.yml` headers that still described an inline heredoc.
- ⏸️ **Deliberately NOT done: `codeql.reusable.yml` / `pre-commit.reusable.yml`.**
  These would collapse ~325 duplicated lines, but they also move 10 more workflows
  behind a `@test`-pinned cross-repo reference — raising the mutable-branch
  coupling from 20 refs to 30 **before** the `@v1` pin exists. That inverts the
  blast-radius ordering this plan was built on. Do it immediately after the `@v1`
  migration, not before.

## Done-criteria for the issue

- Nightly E2E exercises all five stages, and fails loudly when it cannot.
- No workflow targets a branch that does not exist; PR checks match push checks.
- Release artifacts start standalone, proven per tag by the closure guard.
- All 20 caller refs resolve to an immutable ref; no caller passes `secrets: inherit`
  (second half done).
- `slow`-marked tests execute somewhere on a real schedule.
