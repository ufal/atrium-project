## A — Governance policy and map in `docs/shared_components.md` `(a)`

Create a single, concise governance page at `docs/shared_components.md` (and expose it in `docs_site/` via `mkdocs.yml`) structured into three parts:

### A.1. The seven governance rules

1. **Single canonical owner:** Every shared file or data artifact has exactly one canonical owner repository (`atrium-project` for the 24 files in `docs/templates/shared/MANIFEST.json`, or a single named tool repo for sibling files and data artifacts). Consumers never hand-edit vendored copies; changes always land in the owner first.
2. **Runtime self-containment:** Services must be 100% self-contained at image build time (`COPY . .`). No container or service may fetch shared source files, schemas, or vocabularies from GitHub at startup or request time.
3. **Immutable consumer pins:**
   - **Hub-canonical files (24):** Pinned via the caller workflow's `hub-ref` input, which `#72` E.4 (`scripts/pin_hub_reusables.py`) pins to an immutable 40-hex hub commit SHA. Nothing new to build per file.
   - **Tool-to-tool sibling files (12 owner files, 14 copies):** Pinned in each consumer's `tests/test_vendored_*_parity.py` via `VENDORED` (per-file SHA-256) beside `ADOPTED = {"owner": "<repo>", "commit": "<40-hex>", "release": "<optional-tag>"}`.
   - **Data artifacts (vocabulary):** Pinned by immutable owner release version tag + release zip asset SHA-256 + extracted CSV SHA-256.
4. **Two-tier parity enforcement:** Blocking CI verifies that a consumer's working tree matches its own `VENDORED` hashes and the owner repository **at `ADOPTED["commit"]`**. Comparing against the owner's moving `test` branch runs as a **non-blocking advisory step** that writes `"owner ahead: files, commits"` to `$GITHUB_STEP_SUMMARY` (`#81`'s monitoring tier).
5. **Cumulative impact classes for shared changes:**
   - **Class (a) — Internal / byte-only** (docstrings, comments, typing, internal refactors with unchanged I/O and schemas): requires owner tests + revendor + byte-parity checks (`hub-parity` / `vendored-parity`).
   - **Class (b) — Additive / backward-compatible contract change** (new optional schema property, new originator shape, additive OpenAPI field): requires Class (a) **plus** the contract tests: `VALID_SHAPES` (`test_document_originators.py`), a new `POST_FREEZE_CHANGES` entry (`test_schema_freeze.py`) with a matching row in `docs/document_schema.md`, and an additive OpenAPI compare (`test_openapi_contract.py`).
   - **Class (c) — Breaking or record-meaning change** (field removal/rename, tightened validation, or any change to archival record/paradata/RO-Crate/licensing semantics): requires Class (b) **plus** the MAJOR schema procedure (`docs/document_schema.md:475-484`), review by maintainers of all affected tool repos, an E2E smoke run on a recorded fixture set (`#81` B.3), and **AMČR's explicit agreement before merging**.
6. **Coordinated vs. routine rollout:** Routine owner changes merge to `test` without breaking consumers; consumers adopt via PR on their own schedule. For urgent or coordinated fixes, the owner opens the consumer adoption PRs directly rather than forcing red CI on unrelated consumer branches.
7. **Licensing and provenance:** All shared components across the seven repositories are MIT-licensed (`SPDX-License-Identifier: MIT`) and carry a top-of-file provenance header naming the canonical owner repository and path.

## B — Recommendation: pin to the adopted owner commit `(a, then b)`

**Recommendation:** Pin every consumer's sibling parity check to the immutable owner commit SHA that the consumer actually adopted (`ADOPTED["commit"]`), and make comparisons against the owner's moving `test` branch non-blocking advisory notices.

1. **B.1 — `ADOPTED` metadata in pin tests `(a)`:** Beside `VENDORED` in `digital-convert/tests/test_vendored_reader_parity.py`, `digital-convert/tests/test_vendored_teitok_parity.py`, and `keyword-extract/tests/test_vendored_teitok_parity.py`, add:
   ```python
   ADOPTED = {
       "owner": "atrium-ocr-postprocess",
       "commit": "<40-hex-sha>",
       "release": "v1.12.1-beta",  # optional informational tag
   }
   ```


This follows the `UPSTREAM_COMMIT` pattern already proven in `ocr-postprocess/alto_tools.py:70-73` and `tests/test_alto_tools.py:168`.
2. **B.2 — AST reader and blocking pinned checkout `(a)`:** Add a small, unit-tested hub helper `tools/ci/vendored_pins.py` (with `tests/test_vendored_pins.py`) that parses `tests/test_vendored_*_parity.py` via Python's stdlib `ast` module (importing nothing) and emits the `(owner, commit, files)` records. Update `vendored-parity` in `.github/workflows/para-drift.reusable.yml` to clone each owner **at `ADOPTED["commit"]**`. Keep both this check and the local `test_vendored_copy_matches_its_pin` test **blocking**.
3. **B.3 — Non-blocking `"owner ahead"` step summary `(a)`:** Add a second, non-blocking step in `vendored-parity` that compares the pinned file paths against the owner's `test` branch (`origin/test`) and appends an `"owner ahead: <files>, <commits>"` table to `$GITHUB_STEP_SUMMARY` (`#81`'s monitoring tier).
4. **B.4 — Urgent/coordinated updates `(a)`:** Document in `docs/shared_components.md` that when an owner lands an urgent or coordinated fix, the owner immediately opens the consumer adoption PRs updating `VENDORED` and `ADOPTED["commit"]`; no artificial CI failure is forced on unrelated consumer work.
