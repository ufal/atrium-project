## Context

The 2026-08-01 TODO asked for three axes per repo — **JSON pipelines**, **`atrium_document` adaptation**, **GHA workflows**. That round is done: five P0s fixed, the two hub-built safety mechanisms (`canonical_doc_id()`, `validate_document()`) adopted ecosystem-wide, the §1a origin guard armed, the service half of rule 1 implemented, and the hub's own governance closed.

**The defining result of the round is not the fix list — it is what the gates found the moment they were switched on.** Three defects surfaced *after* the pass, each caught by a mechanism installed during it, and each invisible to every test that existed before:

1. `ruff-format` at differing `line-length` split a byte-identical shared file → para-drift red in three repos.
2. The Layer D schema gate rejected a **released** image (`type_cnec: null` in nlp v0.18.2), which no source fix could clear because `:latest` moves only on a tag.
3. The cross-stage `doc_id` assertion caught a fork from a derivation that was **correct for its input file** — forcing an architectural change: `DocumentRecord` now **inherits** the baseline's `doc_id` instead of re-deriving it.

That pattern is the strategy's centre of gravity going forward: **the remaining risk is concentrated in paths nothing exercises**, not in code nobody has read.

## Strategic actions

### Phase 0–4 — ✅ EXECUTED

Correctness, mechanism adoption, dormant guards, service parity, hub governance. See the digest for per-finding evidence. Nothing outstanding.

### Phase 5 — `digital-convert` originator (now unblocked, and the next substantive build)

`api_util/digital_to_json.py` still does not exist; `digital_born/` is Phase-0 exploration with no `DocumentRecord` usage. It was gated on Phases 1–2 being live — **they now are**, so this is the next real feature.

Do it in this order, because §1a only earns its keep once a *second* originator exists:
1. Write the converter against the field grants already declared for `digital-convert` (`pages`, `content`, `lines`, `tables` — note `lines` **must** include `text`/`bbox`; the earlier draft granting only `group_id` is exactly the silent-drop bug §1b exists to catch).
2. Set `source.origin` to a `digital-born*` / `pdf` / `docx` value so `resolve_originator()` actually routes — an unrecognised origin makes the check **abstain**, which is how §1a silently stops applying.
3. Exercise the documented **digital→OCR hand-off** (`pages[].needs_ocr`), the one case where alto may re-originate a digital-born record.
4. Add it as a sixth E2E stage, or the contract stays untested on the path that has two possible writers.

### Phase 6 — close the "nothing exercises this" class

The round's three follow-ons were all *unexercised paths*, not bad code. Attack that directly:
1. **Flip the E2E to `image-tag: test`** once all five `:test` tags exist, so the gate judges what is about to ship rather than what shipped last. Keep a `latest` run for released-artifact verification.
2. **Assert idempotency** where it has already bitten: a suite run must leave `git status` clean (nlp rewrote committed fixtures).
3. **Fire `issue-log-refresh.yml` once** — a workflow with three fixed defects and zero executions is an untested path by definition.
4. **Ratchet `fail_under`** to just under measured, so coverage cannot silently regress.

### Phase 7 — hygiene tail

`line-length` still differs (100 in nlp/llm, 120 elsewhere). Harmless for shared files now that they are format-excluded, but it means those two repos reformat file-by-file as they are touched. Either unify on the template's 120 or record the divergence as intentional — do not leave it undecided.

## Working rules (earned this round, keep them)

* **Do not re-derive what you were told.** doc_id inheritance is the general form: a stage's local filename is a *guess*; the baseline carries the answer. Prefer inheriting over re-computing wherever a record already states a fact.
* **A fix without a gate is not done** — but equally, **a gate is only worth what it exercises**. All five P0s existed under green CI; each was caught by adding the assertion CI structurally could not make (in-process `TestClient` cannot see a missing `uvicorn`; `docker-build-smoke` never runs the image it builds; no per-repo suite can compare five stages).
* **Vendored canonical files have exactly one authority — the hub.** Anything a repo does automatically (format, fix, autoupdate) must be excluded from them, and `force-exclude` is required for that exclusion to survive pre-commit's explicit paths.
* **Released ≠ current.** `:latest` moves only on a tag. When a gate judges images, say which set it judged, or a red run gets misread as a broken pipeline.
* **Report every violation at once** when each one costs a release cycle to discover.
* **Never edit a vendored copy.** Edit the hub canonical, re-vendor all five, land, *then* move `v1` — moving the tag mid-window makes identical SHAs fail para-drift non-deterministically (observed 08-03/04 in two repos).

## Risks

* **Doc staleness** — re-proven twice this round; these files can be hours behind. Re-check live state before acting on any table.
* **The `:test` flip is a two-step** — publishing the tag and switching the default must not be conflated, or the E2E fails on missing images.
* **Refactors without a runtime** — modularization stays GPU-gated; do not eyeball it.
* **Endless-refactor guardrail holds** — architectural fixes, tests and bug resolution only; not stylistic sweeps.
