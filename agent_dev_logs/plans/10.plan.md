**The organising insight has sharpened.** The 08-06 round's lesson was *"the risk is unexercised paths."* This round narrows it to something more useful:

> **A gate that only checks existence is not a gate.**

Six of the round's nine findings were mechanisms that were present, green, and checking something other than the thing that mattered:

| Mechanism                      | What it checked                     | What it missed                                                                           |
|--------------------------------|-------------------------------------|------------------------------------------------------------------------------------------|
| `set_source()` immutability    | that no key *collided*              | that a key was never *written* — so `origin` could never arrive and §1a deferred forever |
| `concurrency` blocks           | that a block *existed*              | that its group let a push cancel the nightly, which then reports no failure at all       |
| Layer D schema validation      | that the record's *shape* was legal | that any stage had actually *done* anything — every content block is optional            |
| `importorskip` guards          | that a dep was *importable*         | that no CI lane installs it, so the test never runs anywhere                             |
| `pytest -m slow` nightlies     | that the command *succeeded*        | that zero tests carry the marker, so exit 5 is tolerated forever                         |
| Test-suite `sys.modules` stubs | that imports *resolved*             | that they resolved to fakes, so skip reasons blamed the environment                      |

Every one was green the whole time. That is the class to keep hunting.

## Phase 8 — the publish channel

The only phase with real momentum, and the one the `e2e-digital-smoke.yml` header has been waiting on since 08-18. **Four steps, in order. Never conflate them** — the workflow's own header says so, and the 08-06 round already paid once for treating "publish the tag" and "switch the default" as one move.

1. **Confirm `:test` on the next `test` push for all five.** `v1` now carries the gate, so this should be automatic; verify it rather than assume it. llm-enrich publishes under suffixed names (`-remote`, `-digital`, `-llm`) — check those, not the bare `atrium-llm-enrich`, which is not a package.
2. **Flip `e2e-pipeline-smoke.yml`'s `image-tag` default to `test`**, keeping a `:latest` run for released-artifact verification. One line. This is what makes the gate judge what is *about to* ship rather than what shipped last.
3. **Publish `atrium-llm-enrich-digital` on a release.** `:test` exists; `:latest` is 404 by design, because `:latest` moves only on a version tag. Until that release, the digital cron will keep failing on `:latest` even after step 4 goes green on dispatch.
4. **Land the sixth E2E stage.** The workflow is built and wired; it has run 7 times and failed 7 times, never reaching an assert step, and **has not been re-run since its blocker cleared**. One `workflow_dispatch` with `image-tag: test` would exercise the two-originator path — the one §1a exists to arbitrate — end to end for the first time.

**Do step 4's dispatch early.** It is one click, it is independent of steps 2–3, and it converts the ecosystem's least-tested contract from "believed to work" into evidence.

## Phase 9 — the release wave

All five versions are unchanged since 08-06. `:latest` therefore describes the 08-06 release while `test` carries two rounds of fixes on top, and **the nightly E2E runs `:latest`**. So the gate with the broadest reach in the ecosystem is currently validating artifacts that predate both rounds entirely.

This is the counterweight to Phase 8: flipping the default to `:test` (step 2) makes the nightly meaningful again *without* a release, which is why it should not wait on one. But the release wave is what makes `:latest` worth validating, and what unblocks step 3.

## Tail

* **Prove the two workflows that are fixed but never observed green.** `issue-log-refresh.yml` ships a `dry-run` input for exactly this; use it, read the step summary, then run it for real. A workflow holding `contents: write` + `pull-requests: write` + a repo secret should not first be trusted unattended on a cron.
* **Close the "did the stage do work" gap.** Add per-block non-emptiness and `assembled.blocks` stamping to `e2e_assert.py`, mirroring what `entities` and `_assert_enrichment` already do. Then add born-digital cases to `tests/test_e2e_assert.py` — in-process, no image, no network, and it takes the file from 74 % to near-complete.
* **Reconcile `@pytest.mark.slow` with `importorskip`.** In nlp-enrich and llm-enrich the two mechanisms never meet: the tests that should be slow-marked are gated on deps no CI lane installs, so `pytest -m slow` collects nothing and exit 5 is tolerated. Both workflow headers already say so; the note has stood in for the fix long enough.
* **`line-length`: execute the decision.** Unify nlp-enrich and llm-enrich on 120 in one dedicated reformat commit each, so the change is reviewable as formatting rather than leaking into unrelated diffs.
* **alto modularization is unblocked** — extract the shared rule-state module first, then split `text_util.py`, keeping `test_pipeline_parity.py` green *without regeneration* at every step.

## Working rules (keep these — each was paid for)

* **Do not re-derive what you were told.** `doc_id` inheritance is the general form: a stage's local filename is a guess; the baseline carries the answer.
* **A fix without a gate is not done — and a gate is only worth what it exercises.** All five 08-06 P0s lived under green CI.
* **A gate that only checks existence is not a gate.** This round's own lesson: assert the property, not the presence of the mechanism. The concurrency fix is the model — it landed as a linter check that accepts either correct remedy, not as five hand-edits.
* **Run the repo's whole gate, not the part you were thinking about.** Both defects this round introduced were caught by a gate the author had not run: `pre-commit run --all-files` for the pc breakage, Dependabot's own run for the hub one. Running the narrow check you have in mind is how a change ships that the broad check would have stopped.
* **Measure in a clean venv, built from the repo's own `requirements-test.txt`, every time.** A floor set from a hand-augmented environment fails in CI and nowhere else.
* **Never `git add -A` after a test run** without reading `git status`.
* **Vendored canonical files have exactly one authority — the hub.** Anything a repo does automatically must be excluded from them, and `force-exclude` is required for that exclusion to survive pre-commit's explicit paths.
* **Released ≠ current.** `:latest` moves only on a tag. A gate judging images must say which set it judged.
* **Edit the hub canonical, bring all five into compliance, land, *then* move `v1`.** This round did exactly that for the new linter check — compliance commits at 09:07–09:15 UTC, tag move at 09:37 — and that ordering is why no tool repo went red. The rule was written for vendored files; it applies just as hard to a widened *rule*, because tool repos resolve both through `@v1`.
* **A claim about live state must be measured, not derived.** Both corrections this round came from reasoning about state instead of checking it — a stale checkout, and an inference about a tag's history from its current target. Neither is knowable by derivation; both were one command away.

## Risks

* **Doc staleness — proven three times.** The 08-06 tables described a block that no longer exists, and both of this round's corrections came from acting on a stale reading. Re-check live state before acting on any table here; the working copy you are holding is probably not `origin/test`.
* **`:latest` predates the round.** Until Phase 9, the nightly's verdict is about old artifacts. A green run there is not evidence about current source.
* **The converter is still unproven on real documents.** `digital_born/sample.pdf` (6 pages) and `sample.docx` are committed and exercised by nothing — `pytest.ini`'s `norecursedirs` excludes the directory, and all 29 converter tests run against sub-4 KB generated fixtures. One test reading the real PDF would exercise several open questions at once.
* **Refactors without a runtime** — pc's stays GPU-gated; alto's does not, but do not eyeball either.
* **Endless-refactor guardrail holds** — architectural fixes, tests and bug resolution only; not stylistic sweeps.
