## Strategic actions

### Phases 0–5 — ✅ EXECUTED

Correctness, mechanism adoption, dormant guards, service parity, hub governance, and now the second originator. Per-finding evidence in the digest.

**What Phase 5 deliberately did not do**, so it is not re-litigated: no silent text repair (the converter reports; rewriting would make `source.sha256` describe a document whose text no longer matches it), no `docling` dependency (nothing needs it and it is the heavy one), and no deletion of `digital_born/` or deprecation of `pdf_to_md`/`docx_to_md` — those are `18.plan.md`'s PR 7, and they should follow the converter proving itself on real documents, not precede it.

### Phase 6 — close the "nothing exercises this" class — 🔄 IN PROGRESS

Two of four done. The remainder, in value order:

1. **Sixth E2E stage for `digital-convert`.** Until a born-digital document is threaded end to end, the two-originator path — the one §1a exists to arbitrate — is tested only by unit tests inside one repo. Needs a published image, so it is release-ordered, not source-ordered.
2. **Flip the E2E to `image-tag: test`** once all five `:test` tags exist, so the gate judges what is about to ship rather than what shipped last. Keep a `latest` run for released-artifact verification. Two steps, never conflated: publish the tag, *then* switch the default.
3. **Assert idempotency** where it has already bitten — a suite run must leave `git status` clean (nlp rewrote committed fixtures).
4. **Fire `issue-log-refresh.yml` once**. A workflow with three fixed defects and zero executions is, by definition, an untested path.

**And the generalisation Phase 6 earned:** a skipped test is not a cheaper test, it is an untested module wearing a green tick. `docx_to_md.py` sat at **15 %** coverage behind a passing build for as long as it existed. Worth a one-off sweep of every `importorskip`/`skipif` in the ecosystem, asking of each: *does this ever run anywhere?* Where the answer is no and the dependency is light, declare it.

### Phase 7 — hygiene tail

`line-length` differs (100 in nlp/llm, 120 elsewhere). Harmless for shared files now they are format-excluded, but those two repos reformat file-by-file as they are touched, so the divergence leaks into unrelated diffs. Either unify on the template's 120 or record it as intentional — the cost of leaving it undecided is a steady trickle of formatting noise in otherwise-clean reviews.

## Working rules (earned in this round — keep them)

* **Do not re-derive what you were told.** doc_id inheritance is the general form: a stage's local filename is a *guess*; the baseline carries the answer. Prefer inheriting over re-computing wherever a record already states a fact.
* **A fix without a gate is not done — and a gate is only worth what it exercises.** All five P0s lived under green CI. Each was caught by adding the assertion CI structurally could not make: an in-process `TestClient` cannot see a missing `uvicorn`; `docker-build-smoke` never runs the image it builds; no per-repo suite can compare five stages of one document.
* **Measure in a clean venv, built from the repo's own `requirements-test.txt`, every time.** A floor set from a hand-augmented environment is a floor that fails in CI and nowhere else — this pass did exactly that and reddened llm-enrich.
* **Never `git add -A` after a test run** without reading `git status`: this pass committed `__pycache__` and `.coverage` twice that way.
* **Vendored canonical files have exactly one authority — the hub.** Anything a repo does automatically (format, fix, autoupdate) must be excluded from them, and `force-exclude` is required for that exclusion to survive pre-commit's explicit paths.
* **Released ≠ current.** `:latest` moves only on a tag. A gate judging images must say which set it judged, or a red run gets misread as a broken pipeline.
* **Edit the hub canonical, re-vendor all five, land, *then* move `v1`.** Moving the tag mid-window makes identical SHAs fail `para-drift` non-deterministically.

## Risks

* **Doc staleness** — proven repeatedly; these files can be hours behind on a multi-commit day. Re-check live state before acting on any table here.
* **The converter is unproven on real documents.** Its tests use 700-byte fixtures where every glyph position was chosen deliberately — readable in review, but not evidence about a 40-page excavation report. The `digital_born/sample.pdf` A/B is the next honest check.
* **Refactors without a runtime** — modularization stays GPU-gated; do not eyeball it.
* **Endless-refactor guardrail holds** — architectural fixes, tests and bug resolution only; not stylistic sweeps.
