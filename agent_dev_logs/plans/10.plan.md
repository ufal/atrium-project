## Context

**The July backlog is done.** Release plumbing, the `@v1` pin, version consistency and the forward-merge lag — the four items that dominated the June and July rounds — are all closed and verified against live state, not against a commit message. The release path in particular had been carried as "written and waiting" through three consecutive digests; it has now run successfully on three real translator tags plus two ecosystem-wide waves.

**The centre of gravity has moved again.** In June it was code quality; in July it was release plumbing and cross-repo governance. It is now the **`atrium_document` accretion layer** — the per-document JSON record that threads the whole pipeline, introduced 2026-07-26 and hardened 2026-08-03 (Issue #18 §1a/§1b). That layer is four weeks old, is being edited daily, and this round found **5 P0 defects** in it.

The shape of the problem is specific and worth stating precisely, because it determines the fix order:

* **The contract itself is sound**, and the tools honour it where they exercise it. Nobody writes a block they do not own. `set_block()` vs `merge_block()` is chosen correctly everywhere. Field grants match `BLOCK_FIELD_OWNERS` exactly.
* **The two mechanisms the hub built to make the contract self-enforcing are adopted by nobody.** `canonical_doc_id()` and `validate_document()` have zero production call sites in all five repos. Both were written in direct response to earlier incidents; both currently protect nothing.
* **Every P0 found is an instance of the class those mechanisms exist to prevent.** D1 and D2 are doc_id forks — exactly what `canonical_doc_id()` retires. J1 is a silent-empty-block write — exactly what `validate_document()` plus `assert_fields_survived()` would surface.

So this is not five unrelated bugs. It is **two unadopted safety mechanisms and their predictable consequences**, and the strategy below fixes the mechanisms *and* the instances, in that causal order — otherwise the same class returns with the next service endpoint anybody writes.

A second, structural theme: **CI cannot currently see any of it.** J1's endpoint parameter has no tests. D1's code path has no tests. G3's broken deployment path is invisible because the contract tests use an in-process `TestClient` and `docker-build-smoke` never runs the image it builds. The hub's own `Hub Self-Check` cannot detect a regression in the origin logic it publishes (G6/D9). Every phase below therefore ends with a **gate** — the specific check that makes the fix stay fixed.

## Strategic actions (phased execution)

Phases 0–4 are all CPU-only and executable in a normal session. **Phase order is causal, not cosmetic**: Phase 1 removes the *cause* of the Phase 0 P0s, so doing Phase 0 alone guarantees a repeat.

### Phase 1 — Adopt the two safety mechanisms (retires the whole class)

This is the phase that matters most, and the one most likely to be skipped because Phase 0 will feel like "done". Phase 0 fixes four symptoms; **Phase 1 removes the cause.**

**1.1 — D3: route every doc_id derivation through `canonical_doc_id()`** (~11 sites, 5 repos)

| Repo       | Sites to replace                                                                                                                    |
|------------|-------------------------------------------------------------------------------------------------------------------------------------|
| pc         | `run.py:757-762`, `utils.py:32-51` — **special case**, see below                                                                    |
| alto       | `page_split.py:37-42` (`_doc_id_from_filename`), `run_pipeline.py:258-269` (`_single_input_doc_id`), `alto_stats_create.py:128-133` |
| nlp        | `api_util/build_manifest_row.py:106`, `api_util/summarize_nt_udp.py:467,601`, `run_pipeline.py:511`, `api_util/teitok_alto.py:499`  |
| translator | `main.py:243`, `main.py:452`, `utils.py:152`, `utils.py:491`, `service/api.py:109`                                                  |
| llm        | `api_util/teitok_read.py:7-14` (`doc_id_from_path`), `service/api.py:203-208` (`_doc_id`), + the Phase-0.4 sites                    |

Two nuances that must not be steamrolled:

* **pc is a genuine exception, not laziness.** Its regex splits a trailing *page number* off a per-page image filename (`CTX01_0007.png` → doc `CTX01`, page `0007`). `KNOWN_PIPELINE_SUFFIXES` lists no image extensions, so `canonical_doc_id()` cannot do this today. The right fix is to **compose**, not replace: call `canonical_doc_id()` for suffix stripping, then apply the page-split regex to its result — and de-duplicate the two copies (`run.py` and `utils.py` carry the same regex independently).
* **llm's `teitok_read.doc_id_from_path` is subtly wrong beyond the obvious.** It strips `.teitok.xml` and `.conllu` as *literal-length slices*, so a `.udpipe.conllu` name leaves `…udpipe` attached, where `canonical_doc_id()` matches the longer suffix first (that ordering is deliberate — see `KNOWN_PIPELINE_SUFFIXES`'s comment). Latent only because the current input filter never feeds it a `.conllu`; the function is public and documented for it. Retire it rather than patch it.

*Gate:* per repo, a parametrised test over multi-dot filenames (`X.alto.xml`, `X.teitok.xml`, `X.udpipe.conllu`, `X.document.json`, `X.v2.csv`) asserting one identical `doc_id` across every entry point in that repo. Additionally a **cross-repo assertion in the E2E**: after each stage, `doc_id` is unchanged from stage 1 (see 4.3).

**1.1b — D11: for every stage after the originator, the rule is INHERIT, not derive** (landed 2026-08-06)

1.1's cross-repo E2E assertion (the "Additionally" clause above) fired on its first real disagreement — run [31076188660](https://github.com/ufal/atrium-project/actions/runs/31076188660) — and what it caught was **not** a hand-rolled derivation: the translator called `canonical_doc_id()`, correctly, on `PAGE_ALTO/CTX000000003/CTX000000003-1.alto.xml`. That is the file alto-postprocess hands it; `CTX000000003-1` is the right answer about that file and the wrong key for the record.

So 1.1 as written is necessary and not sufficient. Routing every site through one derivation makes the derivations agree with each other; it cannot make them agree with a document none of them was shown. The pc "compose, don't replace" nuance above is the same shape (a page label in a filename), which is why it was foreseen there and nowhere else — but the general form is not a page-suffix rule at all, and cannot be: `sbn.2019-1` is a legal document name.

* **`DocumentRecord` now inherits.** `__init__` kept the caller's `doc_id` over the baseline's unconditionally (`atrium_document.py:436` — flagged inside D1's own text, actioned by nothing). The baseline's now wins, with a non-fatal `_note()`; `derived_doc_id` keeps the caller's value for its own per-file output names. Ecosystem-wide, so no tool can fork the key by being careless at one call site.
* **Translator** applies the same rule to the two values computed outside the record (CSV `file` column, paradata key), which `DocumentRecord` cannot reach.
* **This is a shared-file change**, so it carries 4.2's atomic discipline: hub edit + five re-vendorings + `v1` retag in one window, or `para-drift` goes red in five repos. Landing it *before* the translator's `main.py` change reaches its default branch is harmless but pointless — the E2E runs each tool's checked-out `main`, so both halves must land together to green the gate.


**1.2 — D4: wire the Layer D validation gate**
Per repo: add `jsonschema` to the appropriate requirements file (**it is currently undeclared in pc and nlp**, so the call would raise its own fail-loud `RuntimeError`), then call `validate_document(doc.to_dict())` immediately before `finalize()` at each write site — the natural chokepoints are the per-repo hooks, not the many callers: alto `document_hook.write_document_block()`, nlp `api_util/document_hook.run_document_hook()`, pc `atrium_document_adapter.py:117-125`, translator `main.py:302`, llm `llm_client_shared.write_document_record()` (+ `service/api.py:_run_extraction()`).

Decide **one** ecosystem-wide failure policy and document it in `docs/document_schema.md`. Recommended: **hard-fail on the tool's own output, warn on an inherited baseline.** Rationale — a tool must never *emit* an invalid record (that is what Layer D says), but refusing to run because an upstream tool wrote something invalid turns one bad record into a whole stalled pipeline, and rule 6 already commits to passing unknown content through.

*Gate:* a test per repo that feeds a deliberately-invalid record and asserts the chosen behaviour (raise vs warn) — not merely that the call exists.

**1.3 — D8: make `merge_block()` filtering visible**
After each `merge_block()` in the per-repo hooks, call `assert_fields_survived()` for the fields that repo owns, or at minimum log `dropped_fields()`. This is the §1b mechanism added on 08-03 and used by nobody. Prefer the assertion in the hooks (where the field set is known) over the blunt global `warn_dropped_fields=True`, which the module's own docstring notes needs a call-site cleanup pass first.
While here, remove nlp's `entity_record["pid"]` placeholder (**D10**, `api_util/document_hook.py:148`) — `pid` is llm-enrich's field and is silently dropped every call.

*Gate:* a test that a field outside the repo's grant triggers the assertion rather than vanishing.

### Phase 2 — Re-arm the dormant §1a guard (alto)

**2.1 — D5: set `source.origin` in `page_split.py`**
`page_split.py:442-447` — add `origin` to the `source={...}` dict. Values must match an `ORIGIN_ORIGINATORS` prefix or the check silently abstains: `"ABBYY-ALTO"` for the alto-tools XML path, and an appropriate `ocr:<engine>` / `vlm:<engine>` where the engine is known. For the JSON path, choose the value that reflects how the *original input* was acquired — not how this stage read it.
This single change switches on the mixed-plane refusal for every real alto run. It is deliberately **after** Phase 1, because turning on a check while ~11 doc_id derivations still disagree would produce noise attributable to the wrong cause.

**2.2 — D6: fix the latent `run_id` landmine in the same file**
`page_split.py:441` — `_logger` → `_logger.run_id`, matching all seven sibling call sites, and thread `document_hook.paradata_ref_for(_logger)` through for parity. Harmless today *only* because this site writes `source=` with no block; the moment a block is added, `_stamp()` embeds the object, `json.dump()` raises `TypeError`, `__exit__` swallows it, and **the entire record including `source` is silently never written** — leaving a stray `.tmp`.

*Gate:* extend `tests/test_page_split.py` (currently zero coverage of the document-json path) to exercise `write_document_block` *the way the real call site does* — with `source=` **and** a block — and assert both the file exists and `origin` resolves to the expected originator. `tests/test_document_hook.py` only tests the already-correct string form, which is why D6 went unnoticed.

### Phase 4 — Hub self-governance (the hub is now the weakest link)

## Risks

* **Fixing Phase 0 and declaring victory.** The five P0s are symptoms; Phase 1 is the disease. Four of the five are instances of exactly what `canonical_doc_id()`/`validate_document()` prevent, so skipping Phase 1 guarantees the class returns with the next endpoint written. If time is short, prefer **1.1 + 1.2 over any Phase 3 item**.
* **Turning on a guard before the data agrees.** Enabling §1a (2.1) or hard-fail validation (1.2) while doc_id derivations still disagree produces failures attributable to the wrong cause. Hence the strict Phase 1 → Phase 2 order.
* **Gates that cannot see the thing they gate.** In-process `TestClient` tests cannot catch a missing `uvicorn`; `docker-build-smoke` cannot catch a broken entrypoint; `Hub Self-Check` cannot catch an origin-logic regression. Every phase above specifies its gate for this reason — a fix without one is a fix with a scheduled recurrence.
* **A moving `v1` masking or manufacturing drift.** Until 4.2 lands, any `para-drift` red on a `test` branch during a template pass must be re-checked against the default branch before being believed — and, worse, a *genuine* drift could be dismissed as this known artefact.
* **Doc/code cadence.** Execution outpaces the write-ups within hours on multi-commit days; this round again corrected several claims in current documents. Reconcile at the end of every round, and treat every state table as a lower bound.
* **Endless-refactoring drift.** Keep changes to architectural fixes, tests and bug resolution — not stylistic sweeps. The print→logging deprioritisation is the standing precedent.
