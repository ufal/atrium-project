## Context
#72 was written the morning of 30 September as "clean up the five tools". The meeting that afternoon did most of the
architecture by moving repositories instead: the keyword stage gets its own repository, which takes **both** copies of
the LLM and vocabulary code; llm-enrich becomes the born-digital converter; alto-postprocess becomes ocr-postprocess.
This issue therefore stops being a list of deletions and becomes **the frame that says what the six production images
are, what they may contain, how shared code is governed between them, and how their releases are trusted** — with the
moves as its three largest work items, each tracked in its own issue.

The acceptance criterion that matters most to AMČR is the last one: *"the resulting service layout is the baseline
consumed by the processing/trust gate"* (aiscr-docs-pipeline#8). Everything below is ordered so that the images S2 pins
are the final ones.

## Strategic actions

### A — The service map (the frame)
1. **Record it** in `docs/k8s_deployment.md` and the docs site's *Pipelines* page — one row per stage: repository,
   image, endpoint, program id, blocks written, GPU:

   | Stage                   | Repository → image                       | Endpoint                     | GPU                                  |
   |-------------------------|------------------------------------------|------------------------------|--------------------------------------|
   | born-digital            | digital-born-convertor → `…-api-digital` | `/reformat`                  | —                                    |
   | OCR output, scoring     | ocr-postprocess → `…-api`                | `/process`                   | GPU 1                                |
   | page categories         | page-classification → `…-api`            | `/predict_document`          | GPU 1                                |
   | morphology, NER, TEITOK | nlp-enrich → `…-api`                     | `/enrich`, `/project_record` | —                                    |
   | keywords                | keyword-extractor → `…-api`              | `/extract_keywords`          | GPU 1 (KeyBERT); LLM server on GPU 2 |
   | English metadata        | translator → `…-api`                     | `/translate`                 | —                                    |

2. **One production image per stage.** Every other target is either the batch/CLI form of the same stage (kept,
   published, never pinned by the pilot) or research (not published). Each repository's `docker.yml` says which is which
   in one comment; `probe-targets` names the production image.
3. **The production core** of each image: the endpoint AMČR calls, its record hook, its paradata (report item 6). An
   image-closure test per repository lists the first-party modules the production app imports and fails on any module
   outside that list — the machine check of *"only their intended stage plus approved shared components"*.

### B — The three shared layers, with owners
| Layer                      | Owner                                                  | Consumers                        | Mechanism                                                                                                          |
|----------------------------|--------------------------------------------------------|----------------------------------|--------------------------------------------------------------------------------------------------------------------|
| Contract modules           | hub                                                    | all six                          | para-drift, as today (`MANIFEST.json`)                                                                             |
| Document reader            | ocr-postprocess (`text_formats.py`)                    | the converter                    | vendored with SHA-256 pins (the `tests/test_vendored_teitok_parity.py` pattern)                                    |
| Record → Markdown renderer | the converter (`json_to_md`, `layout_md`, `xml_to_md`) | keyword-extractor                | the same pinned vendoring                                                                                          |
| TEITOK reader              | nlp-enrich                                             | the converter, keyword-extractor | the same pinned vendoring (exists today)                                                                           |
| LLM access layer           | keyword-extractor (`llm_client_shared.py`)             | — (one stage uses it)            | **no copy left anywhere**: nlp-enrich#40 moves it                                                                  |
| Vocabulary artefact        | keyword-extractor (`vocab_build.py`)                   | translator, the E2E              | a **versioned release asset** (CC0) the consumers download; the translator's own harvest (`load_vocab.py`) retires |

**para-drift's extension** (the issue's item): the pinned-vendoring tests are the drift check for tool-to-tool layers;
para-drift gains one job that runs them against the owner's current `test` head, so a pin that falls behind shows red in
the consumer. No new package, no second governance mechanism.

### C — The moves (each in its own issue)
1. **keywords** — atrium-nlp-enrich#40: keyword-extractor with history; nlp-enrich 1.0.0 LINDAT-only (CPU, no torch).
2. **born-digital** — atrium-llm-enrich#28 (the service, now) and #29 (the repository becomes the converter; the LLM
   code leaves first). The `COPY . .` problem disappears with the LLM code; the converter's images get an explicit
   `.dockerignore` for `digital_born/` and the Docling path.
3. **ocr-postprocess** — atrium-alto-postprocess#56, after the time-box release.

### D — Dependencies and licences
1. **PyMuPDF → pypdfium2** in page-classification (`service/api.py:237-240`, the one function that opens PDFs):
   compare the labels of the current model over the AMČR samples with both rasterisers (same DPI, same colour space);
   record the comparison as a small table in the repository; replace; drop `PyMuPDF` from `service/requirements.txt:41`.
   *Done when* no production image installs PyMuPDF (`pip show pymupdf` fails in it).
2. **CC0**: done, and announced on #6 (09-30 12:33, *"This also covers the licence item of #72"*). That comment still
   carries the placeholders `<NLP_COMMIT>` and `<LLM_COMMIT>`: they are `ufal/atrium-nlp-enrich@d46239a` and
   `ufal/atrium-llm-enrich@b0e384c` (drafts file: an edit, not a new comment).
3. **flexiconv**: ask upstream for a licence file; record the answer in `para_config.txt` and #6. flexiconv stays off
   the AMČR production chain either way (nlp-enrich#10).
4. **Per-run licences** stay as they are: the accretion rule (most-restrictive union) is not touched by any move.

### E — Release trust
1. **Immutable releases** on in the six repositories (repository setting) **before** the next tool releases, so every
   release the gate reviews from then on is immutable; branch protection on `main` and `test` in the hub (PRs, required
   checks, no force pushes). A date for AMČR (item 7).
2. **Reusable workflows by commit** with a matching `hub-ref`, in one hub-driven sweep (35 references); `v1` keeps
   moving for development, the pins move by a reviewed PR.
3. **The gate learns renames**: `atrium_openapi.py compare` accepts a changed `x-atrium-service` only when the new spec
   declares `x-atrium-service-previous` equal to the baseline's id (alto#56 §A.1). New images (`api-digital`,
   keyword-extractor) start as bootstraps under new asset names or repositories.
4. **ARUP-CAS forks**: one per production repository under its final name, mirrors of release tags (#18's decision).

## Verification / done-criteria
Mapped onto the issue's acceptance criteria:
1. *Production images contain only their stage plus approved shared components*: the image-closure test (A.3) green in
   the six repositories; `python -c "import llm_utils"` fails in every image but keyword-extractor's.
2. *Shared components are drift-checked*: para-drift for hub modules; the pinned-vendoring job (B) for tool-to-tool
   layers.
3. *No production image depends on the undeclared AGPL dependency*: `pip show pymupdf` fails in every production image.
4. *Vocabulary and licence metadata match the AMČR baseline*: CC0 in every `para_config.txt` that lists the
   vocabularies; the translator reads the released artefact.
5. *Release tags cannot be silently retargeted*: immutable releases on in six repositories (screenshot or API read in
   the issue); `@v1` replaced by commit pins in release paths.
6. *The layout is the trust gate's baseline*: the map (A.1) reviewed by Ronald Harasim for aiscr-docs-pipeline#8.
