## Context
#72 is the frame for the six production stages, their image contents, their shared-layer ownership, and release trust.

The 30 September meeting changed the implementation shape:

- the keyword stage gets its own repository and takes **both** copies of the LLM/vocabulary code;
- `llm-enrich` becomes the born-digital converter after the LLM implementation leaves;
- `atrium-alto-postprocess` becomes `atrium-ocr-postprocess`;
- the resulting six production stages are page classification, OCR post-processing, born-digital conversion, NLP enrichment, keyword extraction and translation.

The main acceptance criterion is still the last one: **the resulting service layout is the baseline consumed by the processing/trust gate**. Every action below is ordered so S2 pins only the final immutable service identities.

## Strategic actions

### A — Land the authoritative six-stage service map

1. Update `docs/k8s_deployment.md` and the docs-site Pipelines page so the map is the **six-stage** production baseline:
   | Stage | Repository → production image | Endpoint | Program id |
   |---|---|---|---|
   | page categories | `atrium-page-classification` → `…-api` | `/predict_document` | `page-classification` |
   | OCR output / scoring | `atrium-ocr-postprocess` → `…-api` | `/process` | `ocr-postprocess` |
   | born-digital | final digital-convertor image | `/reformat` | `digital-convert` |
   | morphology / NER / TEITOK | `atrium-nlp-enrich` → `…-api` | `/enrich`, `/project_record` | `nlp-enrich` |
   | keywords | `keyword-extractor` → `…-api` | `/extract_keywords` | `keyword-extractor` |
   | English metadata | `atrium-translator` → `…-api` | `/translate` | `translator` |
2. Mark the production target in each repository explicitly; every other target is batch/CLI or research and is never the image the pilot pins.
3. Keep the image-closure mechanism as the machine-readable proof that the production image can reach only its intended stage plus approved shared components.
4. Do not close A until the **hub docs and the trust-gate asset list agree** with the six-stage table.

### B — Govern the three shared layers

| Layer | Owner | Consumers | Mechanism |
|---|---|---|---|
| Contract modules | `atrium-project` hub | all production services | `para-drift` / shared manifest |
| Document reader | `atrium-ocr-postprocess` | born-digital converter + consumers as needed | pinned vendoring + parity test |
| Record → Markdown renderer | born-digital converter | keyword-extractor | pinned vendoring |
| TEITOK reader | `atrium-nlp-enrich` | converter + keyword-extractor | pinned vendoring |
| LLM access | `keyword-extractor` | keyword stage | move, do not copy; no LLM implementation remains in nlp |
| Vocabulary artefact | `keyword-extractor` | translator + E2E | versioned CC0 release asset |

5. Extend `para-drift` with the tool-to-tool vendor parity check: a consumer must be red when its pinned copy differs from the owner's current `test` head.
6. Keep the existing hub/shared-module drift machinery as the only governance mechanism; do not introduce a second framework.

### C — Complete the repository moves

1. **Keyword extractor — `atrium-nlp-enrich#40`**
   - Move the shared LLM/vocabulary implementation with history.
   - Leave `nlp-enrich` as the CPU/LINDAT NLP stage.
   - Publish the canonical vocabulary asset from the new owner.
2. **Born-digital — `atrium-llm-enrich#28` + #29**
   - Establish the `/reformat` production service under the final image/repository identity.
   - Move the converter after the LLM implementation leaves.
   - Ensure Docker build context and `.dockerignore` contain no research LLM stack in the production image.
3. **OCR — `atrium-alto-postprocess#56`**
   - Treat the new `atrium-ocr-postprocess` repo as the successor, but do not call the move complete yet.
   - Replace old repo/provenance defaults and developer-facing references.
   - Set the correct service program id and release repository identity.
   - Declare `x-atrium-service-previous: alto-postprocess` in the new OpenAPI info so the release gate accepts the rename.
   - Keep legacy `alto-postprocess` accepted only through the shared successor map until the contract freeze.
   - Make the new repository's production release tag the immutable artifact S2 will actually pin.

### D — Dependency and licence closure

1. **PyMuPDF → pypdfium2**
   - Compare the two rasterisers on the AMČR sample pages at equal DPI and colour settings.
   - Record the comparison in page-classification.
   - Remove `PyMuPDF` from service/runtime requirements.
   - Prove by production-image scan that `pip show pymupdf` fails.
2. **CC0**
   - Consider this DONE for the relevant nlp/llm vocabulary metadata.
   - Keep the exact commits recorded in #6 as evidence.
3. **flexiconv**
   - Ask upstream for the licence file/statement.
   - Record the answer in `para_config.txt` and #6.
   - Keep flexiconv out of the AMČR production chain independently of the licence answer.
4. Preserve the existing per-run most-restrictive licence aggregation rule.

### E — Release trust

1. **Immutable releases first.** Enable release-tag immutability in every production repository **before the next production tool release**.
2. Enable branch protection on hub `main`/`test` with PRs, required checks and no force-pushes.
3. Update reusable workflow references from moving `@v1` to reviewed commit pins in the release path, accompanied by the matching `hub-ref`.
4. Keep development flexibility (`@v1`) only where explicitly allowed outside the release path.
5. The release gate must recognize service renames through `x-atrium-service-previous`; new repositories/images start with their own final identities.
6. Finalise one ARUP-CAS fork/mirror per production repository under the final name and mirror only immutable release tags.

## Verification / done-criteria

1. **Production image closure**: the image-closure test is green in all six production repositories; production images do not carry research-only modules.
2. **Single shared layers**: hub modules pass `para-drift`; tool-to-tool vendored layers pass the pinned-parity checks.
3. **No PyMuPDF**: every production image fails `pip show pymupdf`.
4. **Vocabulary/licence baseline**: all production configs reflect the AMČR CC0 baseline and consumers use the released canonical vocabulary artefact.
5. **OCR successor identity**: `atrium-ocr-postprocess` production metadata names the new repo/program id and declares `alto-postprocess` as the previous id; legacy references are intentional compatibility metadata only.
6. **Service map**: hub deployment/trust documentation contains the same six-stage map as the production assets.
7. **Release immutability**: immutable release settings are demonstrably enabled in all six repositories before their next tags.
8. **Workflow trust**: release-path workflow calls are commit-pinned with matching `hub-ref`.
9. **Trust-gate baseline**: the final six immutable image identities are exactly the ones consumed by the processing/trust gate.
