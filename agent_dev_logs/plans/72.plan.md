## Context

The 30 September meeting moved most architecture items into three repository moves. All of them are released, and the six stages run as `-api` images with declared contents.

The answers motyc gave on 13 October settle the two open questions:
- **The vocabulary list.** The translator takes keyword-extract's curated list, not its own merge.
- **The translator's LLM backend.** It stays a second LLM client by design. It is a translation alternative to LINDAT that should be fed the vocabulary with its descriptions. R7's single LLM client is the keyword stage's.

## Execution plan

### B.2 — the translator reads keyword-extract's list (answer 1)
1. **`load_vocab.py --from-release`:** after `records_from_release` merges the flat rows, keep only the pairs present in the asset's `vocabulary.csv`, so the five columns and the source ids stay. Make the release the documented way to build the CSV. The API harvest (no flag) stays for rebuilding without a release.
2. **The CSV:** regenerate `data_samples/vocabulary.csv` from `v1.2.0-beta`; expect about 4,715 rows against today's 5,087. Record the diff in the commit message.
3. **Docs:** the README's release-path section, `docs_site/pipelines.md` and `para_config.txt` (the asset version).
4. **Tests:** the filter, a pair missing from the flat rows, and the checksum path (the existing `AssetError`).

### B.3 — the LLM translation path with vocabulary (answer 2)
These steps are carried out under translator#4.
1. **Descriptions in the glossary.** `processors/llm_translator.py` gets glossary entries with a description, taken from the flat JSON's `note_cs`/`note_en` and capped like the pairs (`:219-247`).
2. **A vocabulary for `/translate`.** `service/api.py:317` passes `vocab_path=None`. Add `VOCABULARY_PATH` (default: the bundled CSV, or none), so `/translate` can use a vocabulary for both backends. Declare it in the spec's `/info` and `.env.example`.
3. **The bake-off** (translator#4) measures LINDAT, ct2 and the LLM path with and without descriptions on the same AMČR sample.

### C.4 — archive the predecessors (b)
Archive atrium-alto-postprocess and atrium-llm-enrich in their GitHub settings. Their "moved" README notices are in place.

### D — dependency and licence closure
1. **The PyMuPDF label run** (b): `python3 data_scripts/compare_pdf_rasterisers.py <amcr_pdfs>/ --labels --version all --out amcr_labels.md` in page-classification. It fills the empty table. If labels move, the fallback proposed on #6 applies: declare the training renderer.
2. **flexiconv** (c): ask upstream (ufal/flexiconv) for a LICENSE file. Its `pyproject.toml` says GPL-3.0-or-later, and nlp-enrich declares it (`para_config.txt:33`). It is off the AMČR chain either way.

### E — release trust (decides closure)
1. **Clean up.** `git rm docs_site/workflows/llm-enrich.md fixtures/e2e/VOCAB/teater_nested_vocab.json`, the two deletions the 10-13 round lost.
2. **Immutable releases** in page-classification, translator and nlp-enrich, before their next tags. Then tag all six; every spec changed on 10-13. digital-convert's next is `v1.1.2-beta` (digital-convert#5/#6), page-classification's carries `f6c1aeb`.
3. **Record the state.** Run `scripts/release_trust.py status`, then `tag-rules` and `branch-rules`, and attach the output here and on #40.
4. **Pin.** Move `v1` to the hub commit of this round, then run `scripts/pin_hub_reusables.py --sha "$(git rev-parse 'v1^{commit}')"` over the six. The sweep sets `require-sha-pins` in each workflow-lint caller.
5. **ARUP-CAS** mirrors only immutable release tags; that is the AMČR side.
