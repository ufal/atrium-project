## Context

Factor XI asks for logs on stdout, configured once, at the entrypoint, at a level the operator sets. The issue framed this as two counter-examples and a one-line fix.

Since the issue was written, #58 landed and created the `__main__` root-logger block in four of the five services. The issue's framing no longer fits: **the configuration half is done.** `LOG_LEVEL` is now read in five places rather than one.

What the measurement shows instead is that wiring the knob was the easy half. `LOG_LEVEL` is **effective in two of five services**. In two others nothing ever reaches the logger; in the fifth a single library-module line silently overrides the entrypoint that was written to satisfy this very issue. A partner setting `LOG_LEVEL=DEBUG` today sees no change in three of five containers, and no error telling them why.

The work is still small — six `print` conversions, one deleted line, one subprocess relay — but it is in different files than the issue names, and skipping any one of the three leaves the acceptance criterion failing.

## Strategic actions

Do them in this order. S1 is two lines and makes an existing test observable; S2 is what the acceptance criterion actually measures; S3 is the only one with design content.

### S1 — Delete the override that is killing an already-written fix (page-classification)

`service/inference.py:22` — delete `logging.basicConfig(level=logging.INFO)`, keep `logger = logging.getLogger(__name__)`.

That is the whole change. `service/api.py:360-365` already contains the correct block, already commented `(issue #61)`; it is a no-op today only because `api.py:16` imports `inference.py` at module scope and `basicConfig` does nothing once the root logger has handlers. Deleting line 22 makes the existing block live. **Do not add `force=True`** as a shortcut — it would paper over the import-time side effect rather than remove it, and leave the next library module free to do the same thing.

Replace the deleted line with alto's rule comment (`text_inference.py:51-55`), adapted. The rule belongs in the file that has to obey it, which is the entire reason alto's version works as documentation:

```python
# (12-factor XI) No basicConfig() here. This module is imported as a library by
# api.py and by tests; configuring the ROOT logger at import time is a side effect
# that silently overrides whatever the host application chose — and because
# basicConfig() is a no-op once the root logger has handlers, the first import
# wins over the real entrypoint. Emit to a named logger; let __main__ decide
# handlers and level. (issue #61)
logger = logging.getLogger(__name__)
```

Two things to check while there:

1. **Does anything lose output?** 18 `logger.*` sites in `service/` have been logging "for free" through the root config this line installed. After the fix they route through `api.py`'s `__main__` — under `python -m service.api` that is strictly better. Under `pytest` the root logger is unconfigured; `caplog`-based tests are unaffected, but confirm none of `tests/` asserts on captured stream output.
2. **Both import names.** `inference.py:15-20` is a `try/except` import block, so the module loads under two different names depending on the path. Both must reach a configured root; only `service/api.py` and `tests/` import it (the batch CLI path — `run.py`, `entrypoint.py` — does not), so the risk is contained.

**Expected observable change**: page-classification's records move from stderr to stdout, gain timestamps and logger names, and start responding to `LOG_LEVEL`. Anyone grepping container logs for the old `INFO:service.api:` prefix will need the new format — worth a line in the issue.

### S2 — Convert the six in-server `print()` calls (4 files, 4 repos)

Without this, S1 does not satisfy the acceptance criterion: two services would still have a correctly configured logger that no record enters.

**First, add the logger.** `translator/service/api.py` and `nlp/service/enrichment.py` do not `import logging` at module scope at all. Add `import logging` and `logger = logging.getLogger(__name__)` near the top of each — nothing else in those files changes.

**Then convert, at these levels:**

| File:line                           | Now                                                                         | Becomes                                                                                                                      |
|-------------------------------------|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------|
| `alto/service/text_inference.py:30` | `print("CRITICAL: 'v3' folder not found …")`                                | `logger.critical(…)`                                                                                                         |
| `alto/service/text_api.py:285`      | `print(f"[document] WARNING – …", file=sys.stderr)`                         | `logger.warning(…)` — drop the `[document] WARNING –` prefix and the `file=` kwarg; the level and logger name now carry both |
| `nlp/service/enrichment.py:340`     | `print("[warmup] KeyBERT model loaded.")`                                   | `logger.info("KeyBERT model loaded.")`                                                                                       |
| `nlp/service/enrichment.py:342`     | `print(f"[warmup] KeyBERT warmup failed: {exc}. Will degrade gracefully.")` | `logger.warning("KeyBERT warmup failed: %s. Will degrade gracefully.", exc)`                                                 |
| `translator/service/api.py:68`      | `print(f"[INFO] Warming up translation backend …")`                         | `logger.info("Warming up translation backend (%s)", backend or "lindat")`                                                    |
| `translator/service/api.py:78`      | `print("[INFO] Shutting down service...")`                                  | `logger.info("Shutting down service")`                                                                                       |

Use `%s` lazy formatting, not f-strings, in the converted calls — it matches llm-enrich's existing `api.py:204,208` and skips the interpolation when the level is filtered out, which is the point of having a level.

Two of these deserve naming in the commit message, because they are the ones that justify the change:

- **`text_inference.py:30`** sits 21 lines above the comment at `:51` that documents the factor-XI rule. A `CRITICAL` condition — layout reordering unavailable for the process's whole life — announced by an un-timestamped, un-named `print` at import time, in the repo the issue holds up as the model. Fixing it makes alto's own documentation true.
- **`translator/service/api.py:78`** is #55's drain record.

**Leave the other 41 `print()` calls alone.** They are in three standalone CLI scripts whose stdout *is* their output contract, run as their own process: `service/healthcheck.py` (×5, invoked by Docker `HEALTHCHECK` — converting these breaks the health contract), `page-classification/service/api_client.py`, and `nlp-enrich/service/test_api.py`. **Say this in the PR description.** A later reader sweeping for `print` in `service/` will otherwise "finish the job" and break five healthchecks.

llm-enrich needs no changes in this step.

### S3 — Relay the subprocess's output instead of discarding it (nlp-enrich)

The issue asks what `processing.log` is for and offers three answers. The measurement settles it without a policy call: **the records are already mirrored to stdout by the shell, and the Python parent throws them away.**

`api_util/api_common.sh:41` already does `… | tee -a "$LOG_FILE"` — file *and* stdout. The loss is at `service/enrichment.py:472-480`, where `subprocess.run(..., capture_output=True)` pipes the child's streams and nothing forwards them, keeping only `(stdout + stderr)[-4000:]`.

**The change**: replace the capture-and-discard with a relay. Stream the child's output line by line to `logger.info` as it arrives, while still accumulating the tail:

- keep a bounded deque (or a running 4000-char slice) so `PipelineError`'s message and `EnrichmentResult.stdout_tail` keep their current contracts exactly — **do not change the 4000-char tail semantics in this issue**, several error paths and at least one API response field depend on them;
- merge stderr into the same stream (`stderr=subprocess.STDOUT`) or relay it separately — but **cover it either way**: `api_4_stats.sh:145` tees to `>&2`, so a stdout-only relay silently drops the stats stage's failure records;
- apply the same treatment to the dry-run health path at `enrichment.py:402-413`, which has the identical pattern;
- preserve the `timeout=30` on the health path — a relay loop must not become an unbounded read.

**`processing.log` then needs no decision.** It stays as a per-job artifact the caller can download, the event stream is complete without it, and it is documented as an artifact rather than inherited as an accident.

**Worth recording in the issue**: `enrichment.py:532` `shutil.rmtree`s the workspace on exception unless `API_KEEP_WORKSPACES` is set (off by default), so today `processing.log` survives successful runs and is **deleted on failed ones**. That is the clearest single argument that the file was never a diagnostic channel. The relay fixes the diagnosis; whether the workspace should outlive a failure is [nlp#35](https://github.com/ufal/atrium-nlp-enrich/issues/35)'s call — coordinate, do not decide it twice.

- **`.env.example`**: alto's omits `LOG_LEVEL`; page-classification and llm-enrich have no `.env.example` at all. **Flag for [\#60](https://github.com/ufal/atrium-project/issues/60), do not absorb** — #60 owns the env contract, and it can now publish `LOG_LEVEL` honestly for the first time.
- **Correct #60's premise.** [`60.plan.md`](../plans/60.plan.md)'s status line states "#58, #61 and #63 all landed". #58 did; #61 has not. Post this on #60 or fix the line — #60's sequencing depends on it.
- **Batch CLIs**: state explicitly that `run.py`, `run_pipeline.py`, `main.py`, `llm_run.py` and `entrypoint.py` are **out of scope** — one-shot processes whose stdout already is the event stream. Left unsaid, the `grep` criterion passes vacuously for them and someone re-opens the question in six months.

## Verification / done-criteria

- [ ] `grep -rn "basicConfig" --include=*.py` across the five tool repos matches only `__main__` blocks, alto's rule comment, page-classification's new rule comment, and test fixtures. (Today: one violation, `pc/service/inference.py:22`.)
- [ ] **`LOG_LEVEL=DEBUG` and `LOG_LEVEL=WARNING` both visibly change output for all five services.** Test **both** directions — a level that is read but ignored passes a one-directional test, which is exactly how three services pass today.
- [ ] Removing `basicConfig` from `inference.py` does not make page-classification's logs **disappear**: start the service, exercise an endpoint, confirm records still reach **stdout** (not stderr) with timestamps.
- [ ] All five emit `%(asctime)s %(levelname)s %(name)s %(message)s`. Diff one line of real output per service.
- [ ] `grep -rn "print(" --include=*.py <repo>/service` returns only `healthcheck.py`, `api_client.py` and `test_api.py`.
- [ ] A failing nlp-enrich job's **early**-stage records appear in `docker logs` — not just the last 4000 characters. Run a multi-stage job that fails late and confirm stage-1 output is present.
- [ ] `docker inspect --format='{{.State.Health.Status}}'` still reports `healthy` for all five — proof the healthcheck prints were left alone.
- [ ] #55's shutdown record appears on stdout for **translator** specifically — the one that is a `print` today.
- [ ] Nothing a partner needs to diagnose a failed request is written only to a file inside the container.

## Out of scope

- **Structured/JSON logging.** Factor XI asks for an event stream on stdout, not a schema. Named here so it is not proposed as the natural extension mid-implementation.
- **Log aggregation, retention, shipping.** Explicitly the execution environment's job under factor XI — the app writes to stdout and stops caring.
- **Batch CLI entrypoints.** See S4.
- **The 4000-char tail contract** in `enrichment.py`. Changing it is a separate, API-visible change.
- **The `API_JOBS_ROOT` workspace design and workspace lifetime on failure.** [nlp#35](https://github.com/ufal/atrium-nlp-enrich/issues/35).
- **Publishing `LOG_LEVEL` in the env contract.** [\#60](https://github.com/ufal/atrium-project/issues/60) — unblocked by this issue, not part of it.
