## Strategic actions

There is one action, and then three things to get right while doing it.

### A — Close the issue, with a closing comment that states the evidence

Issue #61 has been substantively finished since 2026-09-12 and fully finished (docs included) since
2026-09-14. Its one comment, posted 09-12 07:10, describes the landed state but predates the doc
parity and the `v1` tag move, so it is accurate-but-incomplete rather than wrong.

Close it with a comment that walks the issue's **own three acceptance criteria**, in order, each
with its evidence — not a summary of the work:

1. *"`grep -rn "basicConfig" --include=*.py` matches only `__main__` blocks"* — five calls, one per
   repo, at `alto/service/text_api.py:540`, `llm/service/api.py:531`, `nlp/service/api.py:558`,
   `pc/service/api.py:360`, `translator/service/api.py:510`. Every other match is a rule comment or
   the guard's own source text. Enforced by `tests/test_logging_contract.py:151`.
2. *"`LOG_LEVEL=DEBUG docker run …` visibly changes output volume for all five"* — proved in the
   WARNING direction, with a format control beside it, at `docker-tool.reusable.yml:415-450`
   (control) and `:553-602` (assertion). Green in all five on 2026-09-14; link the five runs from
   the table above.
3. *"Nothing a partner needs to diagnose a failed request is written only to a file inside the
   container"* — `nlp/service/enrichment.py:306-347` relays combined stdout and stderr to the
   service logger, at both call sites (`:449` dry-run, `:511` enrich). `processing.log` still exists
   (`:254`) and is now a per-job artifact rather than the only copy.

### B — Do not let the closing comment invite a "finish the job" sweep

Three statements belong in it precisely because a later reader will otherwise undo them:

- **The 41 remaining `print()` calls under `service/` are correct.** They live in
  `service/healthcheck.py` (×5, invoked by the Docker `HEALTHCHECK` — converting them breaks the
  health contract), `pc/service/api_client.py` and `nlp/service/test_api.py`. Their stdout *is*
  their output contract. `PRINT_ALLOWLIST` at `tests/test_logging_contract.py:80` is the enforced
  record of this; say so, so nobody "fixes" it.
- **Batch CLI entrypoints** (`run.py`, `run_pipeline.py`, `main.py`, `llm_run.py`, `entrypoint.py`)
  configure no root logger, and that is a decision, not an oversight. The guard is scoped to
  `service/*.py` by construction, so this is a structural boundary rather than a sentence someone
  has to remember.
- **The 4000-character tail contract is deliberately unchanged.** `_run_and_log()` still returns the
  exact `(returncode, tail)` pair every caller depends on, and is still `subprocess.run(...,
  capture_output=True)` underneath so that every fixture patching
  `service.enrichment.subprocess.run` keeps working. Its docstring (`:312-335`) says this; the
  comment should not contradict it.

### C — Leave the residual with its real owner

`API_JOBS_ROOT` is container-local, so `processing.log` is unreadable from any other replica however
well the relay works, and the workspace is still removed on a failed job unless
`API_KEEP_WORKSPACES` is set. That is the disk half, and it belongs to
[nlp\#35](https://github.com/ufal/atrium-nlp-enrich/issues/35). The relay closes #61's half without
touching it. Reference nlp#35 from the closing comment; do not decide it twice.

### D — Tell #53 that factor XI is done

Issue #53's own re-measurement already scores factor XI 🟢 and names #61 as closable. When #61 closes,
that row needs no further work — but #53's sub-issue list should show it closed, since #53 itself
closes only when every sub-issue except #55 has. This is the cheapest of the nine to retire.
