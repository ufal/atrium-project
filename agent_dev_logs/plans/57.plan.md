# Strategy — Issue #57: GitHub Pages documentation sites for all six repositories

> Issue [\#57](https://github.com/ufal/atrium-project/issues/57) · Labels: `documentation`, `enhancement` · Milestone: WP4 — Pre-Closure Architecture Review · **Status: 🆕 Opened 2026-09-09, scoped and planned same day**

## Context
~2.9 MB of markdown is spread across six repositories with no navigation, no search and no
cross-repo entry point, and GitHub Pages is disabled on all six. The issue asks for that corpus to
become published documentation — README content, the docs scattered through `service/`, `tools/`,
`prompts/`, `annotation/`, `schemas/` and `data_samples/`, and an `agent_dev_logs` summary per
repo — wired together as *one system of interlinked pages*.

The maintainer settled four boundaries before any work started: **nothing moves** (READMEs and
CONTRIBUTING files stay full-length and canonical, the sites are additive); `agent_dev_logs`
contributes **one summary page per repo**, not 44 digest pages; the generator is **MkDocs
Material** deployed through a hub reusable workflow; and each site publishes from its repo's
**default branch**, with `test` building but never deploying.

"Nothing moves" is what makes this non-trivial. Rendering an 89 KB README as one page is not a
system of interlinked pages, and copying its sections into `docs/` would create exactly the
duplication that every CONTRIBUTING's own "Repository Documentation Management" rule forbids —
`README.md` is named there as the single owner of the project overview. **The resolution is to
derive the page split at build time from untouched sources.** A hub-canonical assembler slices
`README.md`, `CONTRIBUTING.md` and the scattered docs into site pages on every build; the split is
regenerated, never stored, and so cannot drift from what it came from.

That choice also settles the hosting shape: the assembler lives once in `atrium-project/tools/docs/`
and a new `pages.reusable.yml` checks out both hub and caller to run it — the identical two-checkout
pattern `workflow-lint.reusable.yml` already uses, and for the identical reason ("a copy in six
places needs a para-drift parity step to stop it drifting"). No sixfold copy, no new parity step.

## Strategic actions

### A — Build the assembler, and make it fail loudly
`tools/docs/assemble_docs.py`, driven by a per-repo `docs/site.yml` manifest. Five capabilities,
each answering a defect the survey actually found rather than a hypothetical:

* **Split at declared depth.** Section sizes are wildly uneven — alto's `## 🛤️ Workflow Stages` is
  41 KB and five levels deep, llm-enrich's whole README has no section over 7.4 KB. The manifest
  declares depth per section; the assembler never guesses.
* **Carry footnote definitions.** Every README defines footnotes in one EOF block. The assembler
  collects it and re-emits, on each page, only the definitions that page references — otherwise
  every split page loses every `[^n]`.
* **Transpose the release table.** `## 📦 Release History` is 56–81 % of each CONTRIBUTING and one
  table with 728–1,335-character cells. It becomes a changelog page: one anchored `###` per
  version, newest first — 13–42 linkable releases per repo instead of a horizontal scroll.
* **Map anchors explicitly.** Emoji headings slug differently on GitHub and in MkDocs; translator's
  README embeds a badge image *inside* an `##` heading; page-classification carries the corpus's
  only `<a name="…">`. Build a GitHub-slug → site-slug map and rewrite inbound anchors through it.
* **Rewrite links by target class.** doc→doc to site paths; doc→code and doc→CI to absolute GitHub
  blob URLs at the built ref; the 6 links into `agent_dev_logs/` likewise, since those pages are
  unpublished; page-classification's 11 URL-encoded `result%2Fplots%2F…` image paths decoded.

Unresolved link, missing split heading, or a manifest entry naming a vanished file → non-zero exit.
Together with `mkdocs build --strict`, a future README refactor that would silently gut a page
turns the Pages build red instead of shipping a hollow site.

### B — Land the hub site first, as the pilot
`atrium-project` is the natural pilot: its README is 1 KB and its real bulk is `docs/` (307 KB), so
it exercises the scattered-docs path without the README-splitting path, and it is where the
assembler, theme and workflow all live anyway. Its site is the portal — Ecosystem (architecture,
pipeline, repository map) · Contracts (`document_schema`, `paradata_schema`, `rocrate_export`,
`skos_strategy`) · Agent Skills · Operations · Contributing standards · Development history.

Architecture and pipeline pages are **rewritten** from the narrative `project_state_2706/1307.md`
reviews and `plan_repo_review.md` §2 — those files are internal and are not published raw.

### C — Roll out the five tool sites in pipeline order
page-classification → alto-postprocess → translator → nlp-enrich → llm-enrich. Every tool site
takes the same shape — Home · Guide · Reference · Development · ATRIUM ↗ — so a reader who learns
one has learned all five. Repo-specific sections are additive, not shape-changing: alto gains
*Research* (`RULE_COVERAGE`, `SWEEP_NOTES`, `quality_model`), nlp-enrich gains *Annotation* and
*Vocabulary & prompts*, translator gains the backend evaluation.

**Single-source rather than copy.** The four byte-identical nlp-enrich/llm-enrich runbooks render
once and are cross-linked; the near-identical CONTRIBUTING middle sections render once on the hub
as the family standard, with each tool site linking to it and carrying only its own deviations.

### D — Make the interlinking structural, not editorial
A hub-canonical header partial gives all six sites the same six-site switcher; a pipeline strip on
each tool home highlights the current repo with live prev/next; every footer returns to the hub's
repository map. Theme, palette, CSS and partials live in `docs/templates/mkdocs/` and are pulled in
by the assembler — so the shared design system is enforced by the build, not by six people
remembering.

### E — Treat exclusion as a tested step
`docs/arub-p_contacts.md` (**partner email addresses**), `plan_repo_review.md`,
`docker_gha_roadmap.md`, the two nlp-enrich decision packages, `llm-enrich/digital_born/README.md`
and `tools/quality_model/EXPERIMENTS.md` are excluded, each with a recorded reason in its
manifest's `exclude:` block. Both acceptance runbooks lose their "Results log (fill in)" tables
section-wise. The built site is then grepped for every excluded path and for the partner addresses,
asserting zero hits — publishing PII is not a mistake worth making once.

### F — Deploy through the existing CI federation
`pages.reusable.yml` in the hub, thin `pages.yml` per repo, passing `tools/ci/workflow_lint.py` on
the same six policies as the other nine workflows: explicit least-privilege `permissions`,
`timeout-minutes` on every runner job, an event-scoped `concurrency` group, no `secrets: inherit`,
a unique workflow `name:`, caller/callee permission agreement. Pages is off everywhere and the
maintainer's token is `admin: false` on two repos, so the workflow turns Pages on itself via
`actions/configure-pages` (`enablement: true`) rather than requiring a settings change.

Triggers: push to default branch → build + deploy; push/PR to `test` → `--strict` build only;
`workflow_dispatch` → build + deploy.

## Verification / done-criteria
- `assemble_docs.py --repo-root <repo> --check` passes for all six: manifest resolves, every
  declared split heading exists, every link resolves.
- `mkdocs build --strict` green per repo — no broken internal reference, no orphan page.
- `workflow_lint.py --repo-root <repo> --hub-root .` green for all six new callers.
- `pytest tests/test_assemble_docs.py` — split depth, link rewriting, emoji-slug mapping, footnote
  carry-forward, release-table transposition.
- Built `site/` greps clean for every excluded path and for the ARÚP/ARÚB partner addresses.
- All six URLs load; the six-site switcher works from each; the pipeline prev/next chain traverses
  all five tool sites and returns to the hub.
- Issue #57's six checkboxes ticked, with the live URLs posted.

## Out of scope
- **Changing `atrium-page-classification`'s default branch** from `vit` to `master`. Publishing
  follows the default branch, so this is worth doing — but as its own change, not folded in here.
- **Restructuring the READMEs or CONTRIBUTING files.** They stay canonical and full-length; the
  only edit is a one-line docs-site link near the top. The single exception is
  page-classification's stale `DEVLOG.md` header, corrected because the history page derives from it.
- **Publishing the 44 per-issue digests, 44 plans and 42 issue exports.** One hand-written history
  page per repo instead, by maintainer decision; the raw records stay in-repo and on GitHub.
- **A custom domain or an `ufal.github.io` root site.** Six project sites under
  `ufal.github.io/<repo>/` is the delivery target.
- **DOG / Switchboard registration** — separate, tracked under **#56**.
