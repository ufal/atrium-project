**Why it matters now.** AMČR decides, per document licence, whether a document may go to external services. So the
licence each record derives (`provenance.license`, from `para_licenses.resolve_effective_license` over the
components in `para_config.txt`) has to be **complete**: a component that runs but is not declared makes the
derived licence wrong in the permissive direction, which is the direction that matters.

**D — page-classification: PyMuPDF (new, David's first finding).**
- The fact: `/predict_document` rasterises PDF pages with `import fitz` (`service/api.py:120`); `PyMuPDF>=1.28.2` is
  in `service/requirements.txt` and in the `base` stage, so in both published images. PyMuPDF is **AGPL-3.0** (or
  commercial). `setup/para_config.txt` `[components]` lists only `vit_models`, `lindat_dataset` and `ultralytics`, so
  a record made through `/predict_document` leaves it out of its derived licence.
- **Recommended: replace it with `pypdfium2`** (Apache-2.0 / BSD-3; PDFium is BSD-3), which alto-postprocess and
  llm-enrich already use and declare. The change is local to the page-rendering helper: render each page at
  `PDF_RENDER_DPI / 72` scale to a PIL image. Guard it with a regression run over the repository's PDF samples —
  top-1 labels before and after, disagreements listed — because rendering differs slightly between engines; the
  training pages came from `pdftoppm` (`data_scripts/unix/pdf2png.sh`), which neither engine reproduces exactly.
- Fallback, if the regression says the swap costs accuracy: declare `pymupdf = AGPL-3.0 ; conditional ;
  /predict_document PDF rendering` in `[components]` and log it on that path, so the record's licence is right.
- Ghostscript (AGPL-3.0, `57.findings.md` L242) is a host-side conversion tool, not in any image; it needs no
  component row, only a note in the tool's docs.
- *Done when* (David's): **`para_config.txt` declares it, or the service no longer installs it.**

**E — flexiconv: a licence file (new, David's second finding).**
- The fact: nlp-enrich's service README states flexiconv is GPL-3.0, and both nlp-enrich and llm-enrich declare
  `GPL-3.0; conditional` in `para_config.txt`, but [ufal/flexiconv](https://github.com/ufal/flexiconv) carries no
  licence file, so GitHub and licence scanners detect none.
- Action: ask the flexiconv maintainer (ÚFAL) to add `LICENSE` (GPL-3.0-or-later, matching what the ATRIUM repos
  declare). flexiconv is off AMČR's production chain (nlp-enrich#10, #38), so this is a correctness fix, not a
  blocker.
- *Done when* (David's): **the repository carries its licence file.**

## Context
The license inventory is **done** and has been propagated into two live surfaces: per-run
paradata (shared `atrium_paradata.py` / `para_licenses.py`, all four repos) and the SSHOMP
**tool** records (license tables appended to each description). The remaining work is
documentation-completeness and keeping the inventory honest as backends change — not new
research. The one genuinely open item is attaching the license list to the SSHOMP
**workflow** records (distinct from the tool records, which are done).

This plan exists because #6 is the canonical legal-constraint map for the whole ecosystem:
the **CC-BY-NC-SA** chain it documents (NameTag3 + CUBBITT + layoutreader) is the exact
constraint that translator [#4](https://github.com/ufal/atrium-translator/issues/4) is now
trying to lift, so #6 must stay in lock-step with every backend swap.

  (it currently resolves to maximally-restrictive on purpose).

### C — Record the "permissive output" recipe centrally
#6 should hold the one authoritative statement of what it takes to ship a **permissive**
output, because it spans repos:
- translation model permissive (EuroLLM / MADLAD, Apache-2.0), **and**
- FastText langid avoided (explicit `--source_lang`, since FastText is CC BY-NC), **and**
- permissive/empty glossary (AMCR/TEATER vocab are CC BY-NC).
This is already written in translator #4's `translation-backends.md` design — link it from #6
so the legal map and the implementation recipe never diverge.
