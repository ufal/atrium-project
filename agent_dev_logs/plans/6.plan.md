## Context

Issue #6 started as a compact inventory request with one explicit question: whether **CC BY-NC-SA** is required by UDPipe, NameTag, or other components.

That part is now answerable from the current production trees:

- `nlp-enrich` core runs use **NameTag3 models — CC BY-NC-SA 4.0** and **UDPipe2 models — CC BY-NC-SA 4.0** as always-on model components;
- the current translator's LINDAT/CUBBITT path is also **CC BY-NC-SA 4.0**, with UDPipe2 models contributing the same restriction;
- OCR post-processing may add **LayoutLMv3 / LayoutReader — CC BY-NC-SA 4.0** conditionally;
- FastText is **CC BY-NC 4.0**, not NC-SA;
- the AMCR `heslo` material and TEATER data are now **CC0** for current runs, following the rights-holder statement in #6;
- keyword extraction adds new conditional components (YAKE, KeyBERT, sentence-transformers and its embedding model) under the new `keyword-extract` owner;
- the translator now has conditional LLM/CT2 backends with backend-specific licences;
- the born-digital repository still needs its inherited LLM metadata stripped down to the actual `digital-convert` production stack.

The harder issue is conceptual. The existing `para_licenses` mechanism uses a most-restrictive union over declared components. The latest #6 discussion points out that an **execution tool's software licence is not automatically the licence of the record content it rendered or converted**. Therefore the plan must separate:

- **content-bearing components**: models, model weights, datasets, vocabularies, service outputs and other assets whose licensed material is actually represented in the produced record; and
- **execution-only components**: renderers, converters, parsers, runtimes and similar software whose own licence should remain visible for provenance/compliance but should not automatically change the record's effective content licence solely by being executed.

That separation is a proposed **paradata model**, not a statement that every software/tool licence is legally irrelevant. The maintainers and rights holder still need to agree the exact rule before it replaces the current resolver semantics.

## Strategic actions

### A — Separate output-affecting components from execution-only tools

This is the main new action implied by the latest #6 discussion.

1. **Define the two classes in the shared paradata vocabulary.**
   - `content` / `effective` components: model weights, datasets, vocabulary data, translation-service outputs, and other assets whose own licensed content/data materially contributes to the record.
   - `tool` / `execution` components: renderers, parsers, converters, libraries, runtimes and vendored utilities that execute the transformation but whose source code is not itself transferred into the produced record.
2. **Keep both classes in run provenance.** A tool must never disappear from the audit trail merely because it does not determine `provenance.license`.
3. **Change the effective-license resolver only after explicit agreement.** Its input should be the content/effective class; tool licences stay informational unless a separate compliance requirement says otherwise.
4. **Add regression cases that demonstrate the intended distinction.** For example, an otherwise MIT document-processing run that invokes a GPL renderer should not become GPL merely because the renderer ran; by contrast, a CC BY-NC-SA model that contributes generated content remains part of the effective licence calculation.
5. **Retain the conservative treatment of unknown model/provider terms.** `llm_api = LLM provider ToS` must remain clearly non-OSS/unresolved until the actual provider and terms are pinned.
6. **Do not rewrite historical paradata.** The resolver change applies to new runs only; existing labels document what the pipeline declared at the time.

**Decision gate:** maintainer/rights-owner confirmation that this is the desired metadata semantics. Until then, existing current-run resolver behaviour remains the implementation baseline and #6 records the proposal explicitly.

### B — Reconcile the current six repositories with the inventory

The source of truth for a repository's current declared components is its `para_config.txt`. The digest must stay synchronized with it.

#### B.1 page-classification — close the rendering acceptance loop

- Keep `pypdfium2` as the released PDF renderer.
- Run the documented AMCR label comparison from [`data_scripts/pdf_rasteriser_comparison.md`](https://github.com/ufal/atrium-page-classification/blob/test/data_scripts/pdf_rasteriser_comparison.md):
  ```bash
  python3 data_scripts/compare_pdf_rasterisers.py path/to/amcr_pdfs/ --labels --version all --out amcr_labels.md
  ```
- Record the top-1 agreement summary in #6 and #72.
- If the result shows a material regression, follow the existing fallback rule: record the training renderer and its actual provenance, rather than hiding the difference.
- Do not describe GPL/AGPL renderer licences as automatically applying to the PDF record; the open #6 decision above is now the correct framing.

#### B.2 ocr-postprocess — preserve the current detailed inventory

- Keep `fasttext`, `layoutlmv3`, Qwen/distilgpt2, GLM and reader components conditional/always exactly as their current `para_config.txt` declares.

- Keep old `alto-postprocess` records as historical producer identifiers; new runs use `ocr-postprocess`.

#### B.3 nlp-enrich — keep the current narrow scope

- Treat **NameTag3 models + UDPipe2 models** as the confirmed CC BY-NC-SA 4.0 core.
- Keep MPL-2.0 engine rows conditional and distinct from the model rows.
- Keep `flexiconv` conditional.
- Do not add the keyword/LLM rows back merely because older documentation references them.

#### B.4 keyword-extract — make the new owner authoritative

- Maintain the current rows for KER, YAKE, KeyBERT, sentence-transformers and `paraphrase-multilingual-MiniLM-L12-v2`.

#### B.5 translator — keep the backend matrix conditional

- Preserve LINDAT/CUBBITT + UDPipe2 as CC BY-NC-SA 4.0 for the current baseline backend.
- Keep FastText CC BY-NC 4.0 conditional, since it is only used for automatic source-language detection.

- Keep CT2 engine and model licences separate: e.g. CTranslate2 MIT + EuroLLM/MADLAD Apache-2.0; NLLB CC BY-NC; Opus-MT CC BY 4.0.
- Keep `llm_api` explicitly non-OSS/provider-terms until a specific provider/model is pinned.
- Treat the EuroLLM sample result as evidence for the current per-run mechanism, not as a final model-selection decision; translator #4 owns that selection.

#### B.6 digital-convert — rebuild the inventory around the actual production service

The current `test` branch still carries the old LLM service identity and is therefore the least reliable #6 source.

Before calling #6 current for this repository:

- change `para_config.txt` to `program = digital-convert` and the new repository fallback;
- remove LLM/vocabulary rows that disappear when the LLM engine leaves the repository;

The result should describe **the service that is actually released**, not the migration ancestry of the repository.

### C — Close the remaining upstream/evidence gaps

#### C.1 flexiconv

`ufal/flexiconv` currently declares `GPL-3.0-or-later` in `pyproject.toml`, but the repository has no `LICENSE` file. The action remains:

- upstream adds a GPL-3.0-or-later licence file; or
- the maintainer provides an explicit, citable upstream licence statement suitable for the project record.

Until then, keep the ATRIUM row explicit and flag the repository-level evidence gap. This is a metadata/compliance-cleanliness issue, not a claim that the package is unlicensed.

#### C.2 model/provider provenance

For model rows where the repository currently uses shorthand or provider-specific terms, record an exact source:

- GLM-4v-9b → exact model card/licence;
- translator `llm_api` → exact provider + model + applicable terms before any production use;
- future LLM backends in keyword-extract/digital-convert → model-specific row, never a generic “LLM” licence.

### D — Keep the inventory drift-proof

Use the current `para_config.txt` files as the machine-readable checklist and make drift visible before release:

1. every component declared in a production repository appears in #6's inventory;
2. every inventory row points back to a repository file, model card, upstream source or explicit rights-holder statement;
3. each row says **owner**, **licence**, **when used**, and **content vs execution** status;
4. a new backend, model or vocabulary cannot reach a release with an undocumented licence string;
5. renamed repositories move the inventory row with the code owner, rather than creating a second historical row for the same component.

The hub's production-image closure / `para-drift` machinery from [#72](https://github.com/ufal/atrium-project/issues/72) can be used to support the mechanical part. #6 remains the human-readable canonical interpretation.

### E — Keep external catalogue surfaces consistent

The existing #6 conclusion for SSHOMP remains **by link** rather than duplication:

- detailed licence tables belong on the tool records;
- workflow records point to the tool records;
- workflow-level versions/dates are not re-invented in #6.

As repositories move, update the tool record to the current successor identity and keep historical entries readable. This follows the same successor strategy already established for `ocr-postprocess`, `keyword-extract` and `digital-convert`.

- [ ] The new output-vs-tool licence semantics have been explicitly accepted by the relevant maintainers/rights owner, or #6 has a documented decision to keep the old resolver semantics.
- [ ] The implementation/tests match the accepted rule and still log execution tools in run provenance.
- [ ] Every current production `para_config.txt` component across the six repositories is represented in the digest with owner, licence, use condition and class.
- [ ] page-classification's AMCR PDF label comparison is run and recorded.
- [ ] `flexiconv` has a repository `LICENSE` file, or an equivalent citable upstream statement is attached to the issue.
- [ ] `digital-convert` has a current service identity and a cleaned `para_config.txt`; inherited LLM/vocabulary rows are gone from the production baseline.
- [ ] LibreOffice and every other actual `/reformat` production dependency are represented with their exact applicable licence metadata.
- [ ] `glm4v_9b` and any future arbitrary-provider backend have exact provenance/terms rather than unresolved shorthand.
- [ ] The CC BY-NC-SA chain is still recorded precisely: NameTag3 models, UDPipe2 models, LINDAT/CUBBITT, and conditional LayoutReader/other components where applicable.
- [ ] Historical paradata is preserved unchanged; current #6 corrections do not rewrite old records.
- [ ] SSHOMP tool-record links remain valid and workflow records continue to rely on those linked tool records rather than duplicating the tables.

## Closure rule
