## Strategic actions

### A — The output-licence semantics (decision, then code)
1. **Decision (stranak, motyc).** Do only the components whose content ends up in the record (models, data, vocabularies, translation-service output) decide its licence, with tools listed but not ranked?
2. **If yes,** split the component classes in the shared paradata vocabulary and change `para_licenses`. The tests:
   - a run that invokes a GPL converter stays MIT;
   - a CC BY-NC-SA model still decides;
   - `llm_api` stays conservative until the provider is pinned.

   Re-vendor with `scripts/revendor_shared.sh`. The change applies to new runs only, and historical paradata is not rewritten.
3. **If no,** record that the current resolver stays, and close the semantics question on the thread.

### B — Evidence gaps
1. **The PyMuPDF label run:** `python3 data_scripts/compare_pdf_rasterisers.py <amcr_pdfs>/ --labels --version all --out amcr_labels.md` in page-classification. Record the agreement here and on #72. If labels move, declare the training renderer, which A may make harmless.
2. **flexiconv:** ask upstream (ufal/flexiconv) for a GPL-3.0-or-later LICENSE file, or attach a citable statement.
3. **GLM-4v-9b:** cite the model card's licence for `glm4v_9b = glm-4`.
4. **keyword-extract:** add a model-specific row once a model is chosen (keyword-extract#2's shortlist names `qwen-3.8-27b-it`). Never add a generic "LLM" row.

### C — Keep surfaces consistent
- The SSHOMP tool records carry the tables, and workflows link them. `RER7Fw` and `CizIUW` are corrected through #4 (Appendices A, F).
- A new backend, model or vocabulary reaches a release only with its row in `para_config.txt`.
