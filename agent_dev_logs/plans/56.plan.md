# Strategy — Issue #56: Register with the Digital Object Gateway (DOG), then Language Resource Switchboard

> Issue [\#56](https://github.com/ufal/atrium-project/issues/56) · Labels: `documentation`, `enhancement`, `integration` · Milestone: Q3-27 [WP6: Conclusion of Service Interoperability] · **Status: 🆕 Just opened, no discussion yet**

## Context
This is an external registration process, not a code change — the deliverable is a JSON file per
service plus a successful PR review from an upstream maintainer outside this project. The main risk
is not technical difficulty but the **upstream review cycle latency**, which the issue itself
flags ("start November"). The five-repo checklist should not be read as five independent parallel
efforts; the first config will surface format questions the other four should learn from, so a
pilot-then-replicate sequence is cheaper than five simultaneous first-time submissions.

## Strategic actions

### A — Study the validation schema and one real example config
Before drafting anything, read `repo_config_validation_schema.json` from `clarin-eric/DOGlib`
directly and find at least one merged example `repo_config` from another project in that repo to
use as a template — reduces the number of upstream review round-trips.

### B — Draft and PR a pilot config
Pick the tool repo with the most stable, least-churning API surface as the pilot — page-
classification (0 open issues, mature releases) is the obvious candidate. Draft its `repo_config`
JSON, validate it locally against the schema before opening the PR, and open the PR against
`clarin-eric/DOGlib`. This first PR is expected to take longer — treat upstream review comments as
input to a shared template for the other four.

### C — Replicate for the remaining four services
Once the pilot config is accepted (or at minimum, once upstream review comments settle the format
questions), draft and PR the remaining four `repo_config` files using the pilot as a template.

### D — Register with Switchboard
Only after DOG has accepted at least the pilot config — the DMP and this issue both sequence
Switchboard strictly after DOG.

### E — Track review latency explicitly
Since the upstream cycle is external and slow, keep this issue (or a per-PR checklist inside it)
updated with PR status rather than letting it go quiet — this is exactly the kind of externally-
gated item that silently stalls if nobody's watching it.

## Verification / done-criteria
- All five `repo_config` JSONs pass local schema validation before submission.
- At least the pilot config is merged into `clarin-eric/DOGlib`.
- Switchboard registration started for the accepted service(s).
