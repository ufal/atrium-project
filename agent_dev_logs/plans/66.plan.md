## Phases

### A — Contract rules (settled)
- Pin a released `-api` image and call only its documented endpoint. Copy no processing code into the Galaxy repository.
- Keep scopes honest:
  - keyword-extract wraps the statistical kind (the controlled kind needs a model backend and is unevaluated);
  - the translator defaults to `replace`;
  - GPU is an option for page-classification.
- Use the successor names only.

### B — The external route (Mark A. Greenwood) — **blocking**
Send the consolidated request (three accounts: lutsai, stranak, novak@arup.cas.cz) and record the answers on #66:
1. which instance: DARIAH's or ssh.usegalaxy.eu;
2. which route: `DARIAH-ERIC/atrium-galaxy-tools`, ToolShed + `usegalaxy-eu-tools`, or both;
3. are GHCR images accepted, and how is an HTTP service image run;
4. network access (LINDAT, Hugging Face) or staged models;
5. GPU;
6. workflow metadata conventions.

If the request already went out, say so on the thread with the date.

### C — The hub pages as the Galaxy source
- **C1:** the translator and page-classification sheets are complete and on the `-api` images. Refresh their Sources lines to the current releases when the wrappers are written.
- **C2:** promote the four paragraph pages (ocr-postprocess `:98`, nlp-enrich `:89`, keyword-extract `:98`, digital-convert `:85`) to full sheets: image and tag, endpoint, datatypes, network and model needs, test data. digital-convert's paragraph says `pdf`/`docx` only; give its full input range.

### D — Wrappers
- **Wave 1 (translator, page-classification):** tool definition, pinned image, datatypes, `test-data/` from the repositories' samples, Planemo tests (the normal path plus one validation error), the `.ga` workflow, and links to `13eHAZ` and the page-classifier workflow record (#4).
- **Wave 2:** ocr-postprocess → nlp-enrich → keyword-extract (statistical), then digital-convert (`/reformat`). `/describe` stays out: it calls the other services, and Galaxy chains them itself.

### E — SSHOMP linkage
Source order: the repository's contract → the hub page → the Galaxy tool/workflow ↔ the SSHOMP workflow record. Records are created under #4, and Galaxy work does not wait on records that do not exist yet.

## Done-criteria
- **External:** instance, route, access, image policy, and network/GPU policy recorded.
- **Documentation:** six full Galaxy sheets on the `-api` images, with current Sources.
- **Wrappers:** for each published tool:
  - a pinned image;
  - Planemo tests green;
  - datatypes match the page;
  - a Galaxy-visible error path;
  - the `.ga` workflow linked to its SSHOMP record where one exists.

## Out of scope

- The controlled keyword kind as a Galaxy capability, before keyword-extract#2 evaluates it.
- GPU runners for CI (#40).
