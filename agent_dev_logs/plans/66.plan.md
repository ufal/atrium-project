## Strategic actions
### A — Ask (user)
One message to Mark A. Greenwood: access for the three accounts, and what ssh.usegalaxy.eu expects of a tool — a
Galaxy tool wrapper in a ToolShed, a container reference, test data, datatypes for inputs and outputs, resource limits
(GPU for page classification and the LLM stages), and how an SSH Open Marketplace workflow links to the Galaxy one.

### B — A requirements page on GHP (hub, docs only)
`docs_site/operations/galaxy.md` (proposed): per tool — image and entry point, inputs and outputs with their formats
(linking the format references above), parameters, test data, licences (and why flexiconv stays out), hardware.
Write it from the answers to A, not before.

### C — First two wrappers
Translator (XML in, XML out; remote LINDAT services by default, so no GPU) and page classifier (images/PDF in, CSV out;
CPU or GPU). Then a two-step workflow and its link from the translator's SSHOMP workflow record.

### D — The rest, in pipeline order
alto-postprocess (ALTO or any text input → line tables), nlp-enrich (line tables + ALTO → TEITOK), llm-enrich
(Markdown/TEITOK → enrichment); each needs the record-passing convention decided for Galaxy (the `atrium_document`
JSON as a dataset between steps).
