# Strategy — Issue #59: bring agent skill's `SHARED_FILES` up to the para-drift guard set

> Issue [\#59](https://github.com/ufal/atrium-project/issues/59) · Labels: `enhancement`, `development`, `github_actions` · Parent: [\#53](https://github.com/ufal/atrium-project/issues/53) (factor I, strategic action C)
> **Status: 🟢 Closed.** No digest or plan existed for this issue before this pass — the only issue in the #51–#64 band without either. Resolved in one sitting alongside #64 and #60.

## Context

`53.plan.md`'s strategic action C named this as "cheap, mechanical" — add `atrium_rocrate.py` to `tools/skill_drift_check.py`'s `SHARED_FILES` and move on. Measuring the actual state on 2026-09-14 found the gap larger and older than the issue's own body: the tuple was 5 entries against a guarded set that had grown to 16 (not the 13 the issue counted — two more sub-issues' canonical tests landed between filing and this pass), and the same hand-maintained-enumeration pattern existed in at least eleven more places the issue did not name.

The issue's own scope note 2 asked for exactly this if it turned out to be cheap: *"Derive the list from one place if cheap … A shared manifest turns the next omission into a diff instead of a silent gap."* It was cheap enough to do properly.

## Decision: full manifest, not the fallback cross-reference comment

The issue offered two scopes — a shared manifest (§2), or, failing that, a cross-reference comment on each of the three files (§3). Went with the manifest: the fourteen enumerations found (not three) make the comment-only fallback strictly worse than doing nothing, since a comment cannot be *checked*, and fourteen unchecked cross-references is a bigger surface for the next omission than five hand-tuples were.

## What was built

**`docs/templates/shared/MANIFEST.json`** — one row per canonical file. Fields: `canonical`, `dest` (repo-relative path a tool repo vendors it to), `selftest`, `ruff_format_exclude`, `isort_first_party`, `preconditions`, `issue`, `note`. 16 rows, exactly matching `para-drift.reusable.yml`'s guarded set.

**`tools/shared_manifest.py`** — the manifest's one reader. A `load_manifest()` function (validates no duplicate `canonical`/`dest`, every required field present) plus a `--tsv` CLI mode, since two of the three consumers are bash and cannot import a Python module.

**Four consumers rewired:**

1. **`tools/skill_drift_check.py`** — `SHARED_FILES` is now `tuple(entry["dest"] for entry in load_manifest(...))`. The `elif` at the old `:326-328` that decides whether an *absent* shared file is a finding was rewritten for two shapes 5→16 walked in that it could not previously express:
   - a `.schema.json` file's neediness is now checked against its *owning module* (strip `.schema.json`, check the closure) — the old test (`removesuffix(".py") in port_closure or startswith("service/")`) could never fire for these, so their absence was unconditionally tolerated;
   - a `tests/test_*.py` file's absence is *never* a finding (the trim is by design — `skill_ify.py`'s `TRIM_DIRS`), while its parity (present-on-both-and-differing) is still checked.
2. **`scripts/revendor_shared.sh`** — the three `declare -A`/array literals are now populated from `python3 tools/shared_manifest.py --tsv MANIFEST.json` in one `while read` loop. The header's "ADDING A FILE TAKES THREE REGISTRATIONS" comment now reads "ONE."
3. **`.github/workflows/para-drift.reusable.yml`** — sixteen hand-written `diff -u` steps + two selftest steps collapsed into one loop step that reads the same manifest via the same `--tsv` CLI. Also closes roadmap finding **D5** ("seven near-identical `diff -u` steps … over a hardcoded file list").
4. **`docs/templates/ruff.toml`** — cannot read JSON, so held in sync by a test instead of a fourth manual edit path (below).

**`tests/test_shared_manifest.py`** (10 tests, new) — the manifest's own guard, run by `hub-self-check.yml`'s existing `shared-tests` job (no new CI wiring needed):
- manifest loads and validates; a constructed duplicate-`dest` manifest is confirmed to raise
- every file in `docs/templates/shared/` has a manifest row and vice versa
- `ruff.toml`'s `[format] exclude` and `known-first-party` match the manifest exactly
- `para-drift.reusable.yml` is parsed (not grepped) to confirm it calls `tools/shared_manifest.py` and carries no reintroduced per-file `diff -u` step
- `revendor_shared.sh` carries no hand-written array literal
- the two remaining prose file-counts (`docs/templates/ruff.toml`, `atrium-page-classification/ruff.toml`) match `len(manifest)` — both were stale ("13", "eight") and fixed to 16 in this pass

**The orphan, resolved.** `docs/templates/shared/test_atrium_service.py` (396 lines, vendored in zero repos, registered in none of the required places — flagged for #59 by `60.digest.md`, `60.plan.md`, `61.digest.md` D7 and `61.plan.md`) is moved to `tests/test_atrium_service.py`. It tests `atrium_service.py`'s contract, already exercised centrally by `hub-self-check.yml`; vendoring it into five repos that already carry `test_logging_contract.py` and `test_env_contract.py` against the same module would add maintenance for no new signal. Its `sys.path` insert was updated to reach `docs/templates/shared/` (where `atrium_service.py` still lives) from its new location; all 17 of its own tests pass unchanged.

## Verification / done-criteria

- [x] `tools/skill_drift_check.py` reports a finding when any para-drift-guarded file is out of parity in one tool repo. **Verified by breaking it**, per the issue's own acceptance standard: on a disposable local branch built off `test`, deleting `atrium_document.schema.json` (while its owning module stays in the service's import closure) was flagged; deleting two `tests/test_*.py` entries was correctly *not* flagged (the trim is by design); corrupting a `tests/test_*.py` entry present on both sides *was* flagged. `scripts/revendor_shared.sh --check` was separately confirmed to go red on a corrupted `atrium_rocrate.py` and green again once restored.
- [x] Adding a 17th canonical file requires editing one list (`MANIFEST.json`) — `tests/test_shared_manifest.py` fails loudly (`test_every_shared_directory_file_is_in_the_manifest`) the moment a new `docs/templates/shared/` file lacks a row, and separately if `ruff.toml` falls out of sync with a manifest that already has the new row.
- [ ] **The `agent-skill` branches cannot be checked from this checkout.** No local clone has `origin/agent-skill` fetched; `skill_drift_check.py`'s default-vs-skill comparison needs `git fetch origin agent-skill` in all five repos first. All 80 canonical-file pairs are in byte parity in every default branch today, so nothing will surface there until the branches are fetched and actually diverge.
- [ ] **The retag.** `para-drift.reusable.yml`'s logic changed (the guarded set did not); per `docs/docker_gha.md`'s standing rule this must land in the hub and all five tool repos in one window before `v1` moves. Bundled with #60's already-committed, still-unretagged probe fix.
