## Why an umbrella

- **The open questions are motyc's and AMČR's, and they cross four repositories:**
  - the go-ahead;
  - where archive data may be processed;
  - AMČR's `dokument_typ` list;
  - annotators;
  - keyword-extract#2's D2 comparison.

  The hub is where cross-repository approvals are asked, as with #67 and #72.
- **The umbrella owns no code.** Each child owns its work, plan and results. The umbrella holds the answers, the
  shared client's governance and the overall outcome.
- **#58 stays the anchor of the method:** the candidates, the API, the client and the hardware. The umbrella does not
  restate it.

- **The wire format** is now taken from the Clef model card's `joint_schema_model.systemone`:

## The shared client

- **What it is:** `decision_client.py`, written in page-classification (#58 Phase 0). It is a single file with no
  torch, using the standard library and `requests`.
- **How it is pinned** (`docs/shared_components.md`):
  - **Rule 1:** one owner, page-classification. Consumers never edit the copy.
  - **Rule 2:** each consumer records `VENDORED` (the SHA-256) and `ADOPTED` (`owner`, `commit`, `release`) in
    `tests/test_vendored_decision_parity.py`.
  - **Rule 3:** adoption is a reviewed change, made in each consumer's own pull request.
- **The row it gets** in the table "Who owns what":

  | Component                                    | Owner               | Consumers                                         | Role in the consumer                                                                                                    | Adopted revision recorded in                                          |
  |----------------------------------------------|---------------------|---------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------|
  | `decision_client.py` (decision-model client) | page-classification | ocr-postprocess, digital-convert, keyword-extract | experimental: offline tools in ocr-postprocess and keyword-extract; the opt-in `document-type` stage in digital-convert | `ADOPTED` in each consumer's `tests/test_vendored_decision_parity.py` |

- **The client is a tool-to-tool copy,** not a hub-canonical file, so it is not in `docs/templates/shared/MANIFEST.json`.
- **In digital-convert** it enters the service image with the stage, so it is listed in that repository's
  `.github/production-image.json`. Elsewhere it stays out of the images.
- **Its class:** the client changes no record and no service response, so a client change is class (a).
  digital-convert's new report fields are class (b) for its `/describe` contract. A record field would be class (c).

**The first probe** (#58 Phase A, steps 1–2) uses public inputs only:
1. **The route.** The plans assume `POST /v1/systemone` (oMLX PR 4315). Pavel calls it "the decisions API", so record
   which path answers.
2. **The card's own example request.** Then one fold-1 training page through `images`, to see whether images are
   accepted at all.
3. **The build.**
   - Confirm that `oQ8e` is an 8-bit quantisation.
   - Record the server software and version, and the model's source revision.
   - Thresholds set on this build do not transfer to the bf16 one.
4. **Reach.** Can the cluster nodes reach it? CI never calls it: CI uses the stub (`--selftest`, `tools/stage_stub.py`).
5. **Load.** Measure latency and throughput while the generative model is resident too. It is one shared machine, so
   full-corpus runs are sized from these figures, not assumed.
6. **Privacy of the host.** It is never written in a public repository. It lives only in `DECISION_MODEL_URL` or a
   CLI flag.

## Out of scope

- A change to the pilot set, a production default or the record.
- Hosted inference on archive data: Workers AI, OpenRouter or any external API.
- Fine-tuning, including Cloudflare's tuning service, before a zero-shot result justifies it.
- Using the endpoint's generative model as a candidate. It can be a separate comparison in a child, if proposed there.
