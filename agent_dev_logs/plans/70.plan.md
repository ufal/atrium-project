### A — `--detail` (llm-enrich)
- **Profiles** (`api_util/layout_md.py`): `DETAIL_LEVELS`, `PROFILE_CUES` (minimal ⊂ standard ⊂ full), `BBOX_SCOPE` (line / block / none), `RESERVED = {cue: reason}`; `check_detail()` refuses an unknown value (never a downgrade).
- **Renderer**: `xml_to_md.rows_to_layout_markdown(..., detail)` (block union boxes, gated `DOC_META`/`OCR`/figure boxes, `LAYOUT_MARGIN` from a page's `margin`); `json_to_md` (emphasis kept out of `minimal`, `_page_margins` for `full`, `CONVERTER_ID = "json_to_md@1.1"`); `doc_to_visual_md` (`detail`, refused with `--legacy`/`--ocr`, `CONVERTER_VERSION` bump); `xml_to_md --detail`.
- **Pipeline**: `prepare_document_input(detail)` with `detail` in the cache stamp; both clients' `--detail`; the recipe's real `detail`; `renders_from_record()` so a `json_to_md` recipe is written only for a record that renders, else the `doc_to_visual_md` recipe from the converted source; the recipe's `from` is the record's own file (#68).
- **Tests**: catalogue coverage and nesting, schema-enum match, per-profile text identity and monotone size on synthetic records, the TEITOK writer sample and the digital fixtures; block unions; margins; cache, recipe, dispatcher and client flags.
- **Measured, not decided**: README table from `scripts/detail_budget.py` (off the image). #22 still decides a lighter default from quality.

### B — projection (nlp-enrich)
- **Encoding** (TEI P5 content models; `@score` a TEITOK-style attribute like `@bbox`): `pb@ana` + `classDecl/taxonomy[@id="tax-page-category"]/category[@corresp]/catDesc`; `textClass/keywords[@scheme="#tax-amcr-teater"][@resp="#app-llm-enrich"]/term[@type="teater-category"][@ref][@cert][@corresp]`; `keywords[@resp="#app-llm-enrich"][@lang]/term[@type="extracted-keyword"]`; `keywords[@resp="#app-kw"][@scheme="#kw-<method>"](@corresp="#pb-K")?/term[@type="statistical-keyword"][@n][@score]`; `application[@id]` and `change[@type="enriched"]`.
- **Pages**: record pages by `teitok_surface` → `page_index` → numeric key → `pb@n`; llm item labels through the record's page of that label → `pb@n` → number. Unresolved pages are reported.
- **Contract**: reads only the record; `<title>` must be `doc_id` or the id of `source.filename`; writer format `teitok-2` only (unless forced); input and output validated (`contract`); idempotent; the writer's header lines stay byte-identical (only whitespace beside new elements changes); atomic writes.
- **Per-page keywords**: per-page CoNLL-U from the TEITOK's own tokens (UDPipe's shape, MWT ranges), through `keywords.extract_keywords` with the run's method, top N clamped 5–20. This departs from the draft's `rows.tsv` source: the tokens are the ones the document-level keywords read, and every backend works unchanged.
- **Switches**: `run_pipeline.py --teitok-enrichment` / `TEITOK_ENRICHMENT` in `config_api.txt` (a `project` stage after `keywords`, reachable with `--start-from project`); `teitok_enrichment` on `/enrich`, `/enrich_text`, `/jobs`; `POST /project_record`; the module CLI (one file, or a directory). The knob lives in `config_api.txt`, not `.env.example`: that file's header keeps batch knobs out, and no Python reads it from the environment. `_parse_config` now understands `${NAME:-default}` — without that an exported `TEITOK_ENRICHMENT=true` never reached the runner.
- **In the pipeline** the stage pairs `<doc_id>.teitok.xml` with `<doc_id>.document.json` and takes that pairing as the identity (an AMČR seed keeps its own `doc_id`); a format-1 file left by a resumed run is skipped, not failed; the service pins `TEITOK_ENRICHMENT=false` in its derived config, so only the request's field switches it on.
- **Gate**: XSD grown additively; `ana`/`resp`/`scheme` join `_REF_ATTRS`; `lint_projection`; `CTX_projected` fixture + negative steps in `teitok-schema.yml`.
- **Not done**: line anchoring (llm line numbers ≠ `lb` numbering); a record `keywords` block (R5) does not exist, so statistical keywords come from the run; `enrichment.summary`/`topics` have no writer. A stage-4 regeneration drops the projection (documented).
