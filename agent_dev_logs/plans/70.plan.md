## Strategic actions

### A — `--detail` profiles and reserved cues: wait for #22, then decide from its numbers
- The profiles exist to cut prompt tokens.
- **Whether they are worth building** is what #22's token-cost bake-off measures. #22 is deferred until after the pilot, so this waits with it.
- **When #22 reports:**
  - if `standard`/`minimal` save enough at acceptable quality, implement them in `json_to_md.py`, and the reserved-cue emitters with them;
  - if not, **mark not planned** and narrow the CLI's `--detail` choices to `full`.
- The API and schema enum can stay: they already refuse an unimplemented level rather than downgrade it.

### B — TEITOK back-projection: needs a design before an owner
- **Two decisions come first:**
  - the TEITOK encoding: which elements or attributes carry keywords, TEATER categories and page categories;
  - the owner: nlp-enrich writes TEITOK, llm-enrich owns `enrichment`.
- ufal/flexiconv#1 asks for it, so the encoding should be agreed there.
- **Proposal:** hand the design to flexiconv#1 and keep here only the ATRIUM side, a writer once the encoding exists. If nothing downstream consumes TEITOK with enrichment after the pilot, mark it not planned.

### C — `entities[].translation_en`: pick one of three
The field is declared for the translator (`atrium_document.py:275`, schema `:345,366`, `document_schema.md:184`) but cannot be written in pipeline order: `entities[]` comes from nlp-enrich, after the translator. The options:
1. **Second translator pass:** read `entities` from an enriched record, translate each `surface`, `merge_block(..., own_fields=["translation_en"])`. `utils.py:853-857` already sketches it. Costs one more stage call per document.
2. **Reassign:** let nlp-enrich or llm-enrich write it, since both run after `entities[]` exists. This changes `BLOCK_FIELD_OWNERS`, which is a shared-module + para-drift round, and the schema description.
3. **Reserve:** keep the field in `doc-schema-v1` (removing it would be breaking), and document it as reserved and unwritten.

**Recommendation:** decide after the pilot, based on whether AMČR's keyword or search use needs English entity names. Until then, option 3's wording could go into `document_schema.md` at no cost.
