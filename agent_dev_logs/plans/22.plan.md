## 1. Strategic intent

One research question, answered with reproducible evidence:

> **On representative archaeological documents, how do exact-version out-of-the-box document-understanding models compare with the established ATRIUM pipeline on reading order, text, image regions and key-value fields, and how much representation detail do they need?**

This is a benchmark and evidence track, not a production stage. The production chain works without #22, and a benchmark result informs later decisions without rewriting the production route.

## 2. What is settled

- **Timing:** deferred until after the pilot. The blocker is the missing in-domain gold set, not code. Specifications may be written now; no model run counts toward the pilot.
- **Corpus:** an ATRIUM archaeological gold set is mandatory. Public benchmarks (OmniDocBench, CHURRO-DS) give context only.
- **Canonical record:** `atrium_document` is the record of truth. Markdown is a derived, regenerable model input and never carries earlier model answers (`json_to_md` does not read `enrichment`).
- **Harness:** `sample_stratify.py`, `bench_compare.py` and `eval_metrics.py` in digital-convert, as research tools kept out of every image (#72).
- **Detail profiles:** `full` (default), `standard`, `minimal`. The text is identical across the three; only the cues differ.
- **Boundaries:** the OCR-engine bake-off is AMČR's. The Docling/MinerU complex-layout bake-off is #22's, deferred with it (10-12).

## 4. Format decision (answers "MD vs JSON")

**Proposal:** JSON for gold and scoring, Markdown for model output, with one converter in each direction.

```text
                gold (OmniDocBench v1.7 page JSON + KV sidecar)  ◄── annotators
                          ▲
record ──► record→gold JSON (baseline)            scorer: compares JSON with JSON
                          ▲
model ──► Markdown (+ HTML tables) ──┬─► OmniDocBench evaluator (text, tables, order)
                                     └─► regions/KV parser ──► JSON (checks 3, 4)
```

1. **Gold format:** OmniDocBench v1.7's exact page JSON, checked at the source on 11-04:
   - per element: `category_type`, `poly`, `order`, `anno_id`, `ignore`, `attribute`, and `text`, or `html` for tables;
   - per page: `page_info` (`page_no`, `width`, `height`, `page_attribute`);
   - caption → figure/table links in `extra.relation`.

   ATRIUM additions go where the format already has room: the `script` attribute and region subtypes in `attribute`; the quality tier and the page-classification label in `page_attribute`; our region types (§5.2) map onto its `category_type` values. Key-value fields go in a sidecar (`field_id`, `label`, `value`, `value_type`, bbox) that mirrors the record's `forms` row, so the baseline maps across 1:1. Pin the OmniDocBench commit in the gold bundle. Its data is research-only, so it stays context and is never redistributed.
2. **Record → gold JSON:** a small benchmark-side converter, used only to score the baseline. Lines become text elements in `page_index`/`line` order; `tables` + `lines` become HTML tables (`rowspan`/`colspan`); `forms` becomes KV rows. ALTO `Illustration`/`GraphicalElement` boxes become untyped regions. They are not in the record today, so read them from the source ALTO, as `xml_to_md.py` does.
3. **Markdown → JSON, split in two:**
   - **Text, tables and reading order:** OmniDocBench's own end-to-end evaluator (Apache-2.0, pinned) matches one Markdown file per page against the gold JSON. We do not write this part.
   - **Regions and key-value fields:** a benchmark-side parser for what that evaluator does not score: `![alt](src) <!-- BBOX -->` figure placeholders and typed regions, and key-value lines. Boxes are corners, `[x_min, y_min, x_max, y_max]`; the `[x,y,w,h]` in `layout_md.image()`'s docstring (digital-convert `api_util/layout_md.py:383`) is wrong.

   The parser must also read `json_to_md`'s own output, which gives a round-trip test: record → MD → JSON → compare with record → JSON.
4. **HTML tables in our own Markdown:** `json_to_md` writes GFM tables, which cannot express merged cells. Propose an HTML-table option to digital-convert (default unchanged) rather than changing the renderer here.
5. **No schema change.** Regions and object segments have no record block. If the benchmark proves them useful, propose one as an additive change under `doc-schema-v1` (hub `docs/document_schema.md` § "Changing the schema after the freeze"):
   - one hub commit with the schema edit, its `POST_FREEZE_CHANGES` entry, a changelog and the producer shapes;
   - a new issue, shared with page-classification#58, that names the owning tool;
   - AMČR's agreement if it changes what the record asserts.

   #71, named on the thread on 10-29, closed on 10-07.

## 5. Benchmark design

### 5.1 Unit and stratification

The page is the primary unit. Quality statistics are per page, failures are often partial, and hard pages stay visible. Document-level aggregates are a secondary view.

Use the `sample_stratify.py` tiers unchanged:

| Tier        | Rule                                                   |
|:------------|:-------------------------------------------------------|
| `clean`     | `avg_quality_score` ≥ 0.85 and valid-line ratio ≥ 0.50 |
| `degraded`  | ≥ 0.60, not `clean`                                    |
| `hard`      | < 0.60                                                 |
| `text_poor` | no scoreable `Clear`/`Noisy` lines                     |

Changing a threshold after model runs start defines a new benchmark version.

### 5.2 Annotation layers

| Layer        | Content                                         | Pages                                                                                 | Metric (§7)                                           |
|:-------------|:------------------------------------------------|:--------------------------------------------------------------------------------------|:------------------------------------------------------|
| A. Text      | UTF-8 text per element, reading order preserved | all gold pages                                                                        | CER, WER, NED                                         |
| B. Order     | element ids in reading order                    | all gold pages (cheap once A exists)                                                  | order NED                                             |
| C. Regions   | typed regions with bbox/polygon                 | a subset, rich in `PHOTO*`/`DRAW*`/mixed pages; one batch with page-classification#58 | presence/count P/R/F1, area-share error; IoU P/R, mAP |
| D. Key-value | form fields (label, value, type)                | form-like pages (`LINE_*` labels from page-classification)                            | field F1, ANLS\*                                      |
| E. Tables    | HTML table structure + cell text                | pages with tables                                                                     | TEDS                                                  |
| F. Entities  | `TYPE<TAB>surface` sidecar, CNEC/TEATER types   | an agreed subset                                                                      | entity F1                                             |

**Region taxonomy (to agree in W0; revised 11-04):** start from the OmniDocBench and DocLayNet categories and keep only what ATRIUM acts on. A coarse list that annotators can apply consistently beats a fine one. The script is an attribute rather than a type, because page-classification's labels already keep graphics, script (`_HW`/`_P`/`_T`) and tabular layout apart, and the regions should keep them apart too.

| Type                                | `script` attribute | OmniDocBench `category_type`      | Record today (baseline coverage)                                           |
|:------------------------------------|:------------------:|:----------------------------------|:---------------------------------------------------------------------------|
| text                                | yes                | `text_block`                      | every line                                                                 |
| title                               | yes                | `title`                           | `style.heading_level` (born-digital only)                                  |
| table / form                        | yes                | `table` (+ `html`)                | `tables`, `forms`                                                          |
| photo                               | —                  | `figure`                          | — (untyped `Illustration` / `GraphicalElement` boxes from the source ALTO) |
| drawing / map                       | —                  | `figure`                          | as photo                                                                   |
| caption                             | yes                | `figure_caption`, `table_caption` | —                                                                          |
| header / footer (incl. page number) | yes                | `header`, `footer`, `page_number` | `style.region` (born-digital only)                                         |
| footnote                            | yes                | `page_footnote`                   | `style.region` = `footnote` (born-digital only)                            |
| stamp / label                       | yes                | — (ATRIUM extension)              | —                                                                          |

- `script` ∈ {printed, typed, handwritten} on text-bearing regions. A page's page-classification label can then be checked against its regions.
- "Label" is a physical tag or sticker (#58's "OCRed labels"), not the `_L` suffix.
- For public comparability, photo and drawing/map collapse to `figure`.
- Before freezing, compare with SegmOnto's zone list (the eScriptorium/Kraken vocabulary). It could not be fetched on 11-04.

### 5.3 Sampling protocol

1. Freeze the corpus snapshot and the quality-statistics snapshot.
2. Generate the tier manifest with a fixed seed and check that every tier the corpus contains is present.
3. Size the sample by annotation capacity, never by a desired outcome.
4. Annotate A and B first, then C–F on their subsets.
5. Checksum the manifest and the gold bundle.
6. Never swap pages after seeing results without recording a new benchmark version.

## 6. Baseline

The current deterministic path on the same manifest, frozen as named predictions:

```text
OCR/text input ─► atrium-ocr-postprocess ─► atrium-nlp-enrich (UDPipe + NameTag + TEITOK) ─► atrium_document
```

Born-digital fixtures enter through digital-convert. The baseline is scored through the record → gold JSON converter (§4.2). The baseline has no typed regions, so check 3 reports it as "untyped ALTO boxes only", not as zero. On born-digital pages it can still be scored on title, header/footer and footnote, from `style.heading_level` and `style.region` (§5.2).

## 7. Metrics (answers "scoring methods")

| Check          | Metric                                                                                                                                                                                                                                                         | Code                                                                                                                                                       |
|:---------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1. Order       | Two NEDs over matched element ids: (a) OmniDocBench's text-only order, for comparability; (b) an all-element order over text, titles, tables, figures and captions, without header/footer                                                                      | (a) OmniDocBench's evaluator; (b) new, reusing `eval_metrics.levenshtein()`; elements matched by text similarity, plus bbox IoU when both sides have boxes |
| 2. Text        | CER, WER, NED, by tier and overall; OmniDocBench's text NED alongside                                                                                                                                                                                          | `eval_metrics.cer/wer/normalized_edit_distance`; OmniDocBench's evaluator                                                                                  |
| 3. Regions     | **Primary:** per-type presence/count P/R/F1 per page, and the error of each type's area share (area ÷ page area), as the body asks. **Secondary**, where the output carries boxes: per-type P/R at IoU ≥ 0.5; COCO mAP@[.5:.95] where predictions carry scores | new                                                                                                                                                        |
| 4. Key-value   | field P/R/F1 on exact (key, normalised value); ANLS\* (arXiv:2402.03848) for values with OCR noise and for missing or invented keys; per-key breakdown                                                                                                         | new; ANLS\* from `deepopinion/anls_star_metric` once its licence is checked                                                                                |
| Tables         | TEDS and TEDS-structure                                                                                                                                                                                                                                        | OmniDocBench's evaluator; or `eval_metrics.teds_score()` once `table_teds.py` is vendored                                                                  |
| Entities       | micro P/R/F1 on (type, normalised surface)                                                                                                                                                                                                                     | `eval_metrics.entity_prf()`                                                                                                                                |
| Representation | characters, tokens with the exact model tokenizer, runtime                                                                                                                                                                                                     | `scripts/detail_budget.py` + run paradata                                                                                                                  |

Rules:
- Report every metric by tier and overall; a macro average must not hide a collapsed tail.
- Missing predictions are counted, never dropped (`bench_compare.py` already does this).
- Page-reference/citation validity stays a diagnostic until the output contract is fixed.
- Report OmniDocBench's component scores, never its Overall: Overall averages in formula CDM, which our pages rarely need.

## 8. Candidates and the representation bake-off

**Selection:** a small, interpretable matrix:
- one domain-relevant compact model;
- one general multimodal model;
- one lightweight model;
- the baseline;
- one large model only to test a stated hypothesis about the hard tiers.

The earlier names (CHURRO-3B, Qwen2.5-VL, SmolDocling) are starting points; re-validate them when #22 resumes. Each candidate must be:
- open-weight or locally runnable;
- pinnable;
- licence-compatible with the data;
- runnable on the hardware actually available: the cluster, the Grace Hopper machine via Viktor (stranak, 06-19), or a Spark-class unit (see page-classification#58).

**Per-run record:**
- model and tokenizer revisions;
- inference backend and version;
- prompt version;
- input representation (`image`, `full`, `standard`, `minimal`);
- image preprocessing;
- context limits and decoding parameters;
- hardware and batch settings;
- runtime and cost proxy;
- container and commit;
- licences.

All of it is written as paradata.

**`--detail` bake-off:** the same model, record, prompt and settings with `full` / `standard` / `minimal`; only the profile changes. The size half is measured (digital-convert `docs/reference/markdown.md`); the quality half needs the gold set. `full` stays the default until quality evidence says otherwise. Check 3 applies only partly here: a text-input run sees figures only as placeholders (`xml_to_md`; `json_to_md` writes none), and none with a box at `minimal`. For these runs, check 3 asks only whether the placeholders survive.

**Docling/MinerU:** on the born-digital subset, scored with checks 1, 3 and tables against the same gold. dc#5's heading counts are input evidence, not a result.

## 9. Outputs of a completed run

```text
benchmark/
├── manifest.csv, manifest.sha256
├── gold/          text/  order/  regions/  forms/  tables/  entities/
├── predictions/   baseline/  <candidate>/ …   (raw output + parsed JSON)
├── page_scores.csv, aggregate_scores.csv
├── report.md
└── run_paradata.json
```

The report contains:
- the sample summary;
- the benchmark version and checksum;
- per-tier and overall scores for each check;
- the representation cost;
- the run configuration;
- missing outputs and failures;
- licence and resource notes;
- qualitative failures linked to page ids;
- what the data do not support.
