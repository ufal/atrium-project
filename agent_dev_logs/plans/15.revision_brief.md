## 1. Evaluation: what the stored splits show

The repository keeps the five cross-validation splits of the `vX.3` generation in
`result/stats/20251005-0434_model_v93_FOLD_{1..5}_DATASETS.txt`. The per-revision fold rule (`model_registry.py`,
`REVISION_BEST_FOLDS`; seed = 420 + fold − 1) means the `vX.3` models of one fold share its split; the training
logs can confirm it. On those files (the appendix gives the commands):

| Finding                                                                                                | Value (fold 1; the other folds within ±1 %)                                 |
|--------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| Partition sizes per fold                                                                               | 38,625 train / 4,823 dev / 4,823 test; 48,271 pages per fold, 48,498 in all |
| The unit of the split is the page, stratified by category (`classifier.py:669`, `split_data_80_10_10`) | —                                                                           |
| Test pages whose document also has pages in training                                                   | 1,191 of 4,823 (24.7 %); 3,632 test pages come from unseen documents        |
| **Pages of the "5,449-page evaluation set" that are in the fold's training partition**                 | **4,296 of 5,449 (78.8 %)**; 581 in dev, 569 in test, 3 in none             |
| Documents of the evaluation set with at least one page in training                                     | 655 of 776                                                                  |
| A stored result table that gives 99.16 %                                                               | none: the eleven `*_5449_*_EVAL.csv` tables give 96.81–99.12 %              |

The labels of all 5,446 shared pages agree between the evaluation table and the fold folders, so the match is the
same page, not a name collision.

**What it means.** The 5,449-page set is not held out from the `vX.3` training data under any of the five stored
splits. A result on it measures agreement on mostly seen pages. The held-out figures are each fold's own test
partition (4,823 pages), which the README calls the "Evaluation set" for `vX.3`. The README table's
`Best_Acc` column, which picks the best of five folds per base model, probably comes from those partitions. That
is the figure to report, with the selection stated.

**The corrections.**

1. Report each base model's accuracy on its fold's test partition. Give the mean and range over the five folds,
   and the best fold only with the note that it was chosen on those results. Find the run behind 99.16 % in the
   training logs. If no log shows it, take the figure out.
2. Describe the 5,449-page set as what it is: a manually checked set that mostly overlaps the training data. It
   is useful for confusion patterns, not as a held-out score. Or drop it.
3. State that the split is by page. Report accuracy separately on the test pages from unseen documents (about
   3,630 per fold). This needs predictions on each fold's test partition from the existing checkpoints, with no
   training. `run.py --eval -rev vN.4 --folds_csv …` does this for the `v*.4` models; for `v*.3`, the fold files
   above give the page lists. Run it with the fix of
   [page-classification#61](https://github.com/ufal/atrium-page-classification/issues/61), then report the groups
   with the appendix's script.
4. The averaged models (`*a5`) average five fold models whose training partitions together cover every page, so
   no page is held out from them. Their tables
   (96.83–99.01 % on the 5,449 set) are not evaluation results.
5. Name the revision behind every number (`v4.3` and its siblings, not `v*.4`). The `v*.4` models were retrained
   later on the licence-compatible subset with the same folds (`--folds_csv`), and go in a separate sentence.

- **Datasets.** The experiments appear to have used the original annotated set,
  [LINDAT 1-5959](http://hdl.handle.net/20.500.12800/1-5959), with its 318 restricted pages: the fold files hold
  48,498 pages, and the README says 48,499. Confirm it. The public derivative
  [1-6184](http://hdl.handle.net/20.500.12800/1-6184) excludes those pages and is the one to cite for reuse.
- **Rights.** Code (MIT), model weights (their Hugging Face licences) and page images (the dataset licence) are
  three statements, not one "open source" claim. Each figure that shows an archival page needs a permission and
  an attribution.
- **Section 3.** Make clear that the deleted PDFs were temporary processing copies, if that is what happened.

## 4. Interpretation

- Differences of a few tenths of a point between the top image-only models are not shown to be significant. Give
  the range over folds from correction 1, and rank models only on differences larger than that range.
- CLIP was trained on one fold under its own protocol. Present it apart from the five-fold comparison.
- Agreement over the 649,508-page collection is consistency between models, not accuracy. CLIP's low agreement
  calls for caution; it does not prove overfitting.
- Replace "near-perfect" and "most efficient" with the measured figures. Present the runtime for hundreds of
  thousands of pages as an estimate, unless one timed run with its hardware is reported.

## Appendix: the split check

The check is `data_scripts/eval_by_document_overlap.py` in `atrium-page-classification` (with the next push; its
tests reproduce the 4,296 of section 1). It reads a split and one or more result tables and gives top-1 accuracy
for pages in training, held-out pages of documents seen in training, unseen documents, and pages outside the
split. From the repository root:

```bash
# the stored vX.3 split of fold 1 against the 5,449-page evaluation table (section 1)
python3 data_scripts/eval_by_document_overlap.py \
    --split result/stats/20251005-0434_model_v93_FOLD_1_DATASETS.txt \
    --results result/tables/20251020-1849_5449_model_v43_TOP-1_EVAL.csv

# a vX.4 re-run on fold 1's test partition, split read from the folds CSV
python3 data_scripts/eval_by_document_overlap.py --split licensed_crossval_folds_CUT.csv --fold fold1 \
    --results result/tables/<the re-run's TEST table>.csv --json
```
