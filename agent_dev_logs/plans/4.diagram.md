## digital-convert

### Input formats and how the code reads them

The type comes from the file's bytes, never from its name (`sniff()`, `api_util/digital_to_json.py:703`).

| Format                 | Recognised by                                | Read with                                          | What is taken                                                                                                                          | On the panel |
|------------------------|----------------------------------------------|----------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|--------------|
| PDF                    | `%PDF-` in the first KB                      | pdfplumber, pdfminer.six; pypdfium2                | pages with their labels, **lines with boxes**, fonts, columns, running header/footer, headings by size or bold, ruled tables           | yes          |
| DOCX, DOCM, DOTX, DOTM | ZIP with `word/document.xml`                 | python-docx, lxml                                  | pages from breaks, headings from outline level or style, bold/italic, header/footer, footnotes, tables with merged cells; **no boxes** | yes          |
| ODT, OTT               | ZIP whose `mimetype` says text               | the text reader shared with ocr-postprocess (lxml) | pages from page breaks, paragraphs and table cells as lines, footnotes; headers/footers not read; no styles, no boxes                  | yes          |
| ODS, OTS               | ZIP whose `mimetype` says spreadsheet        | same reader                                        | a page per sheet, a line per row, text cells only (numbers and dates dropped)                                                          | yes          |
| XLSX, XLSM             | ZIP with `xl/workbook.xml`                   | same reader (zip + lxml, not openpyxl)             | a page per sheet (hidden sheets too), a line per row, text cells only                                                                  | yes          |
| RTF                    | starts with `{\rtf`                          | same reader's own tokenizer                        | `\page` makes a page, `\par` a line; headers, footers and footnotes skipped                                                            | yes          |
| DOC                    | OLE2 file with a `WordDocument` stream       | headless LibreOffice to DOCX, then the DOCX reader | as DOCX; the original's name and hash stay in the record                                                                               | yes          |
| XLS                    | OLE2 file with a `Workbook` or `Book` stream | LibreOffice to XLSX, then the shared reader        | as XLSX                                                                                                                                | yes          |
| Seed record (JSON)     | the `document_json` part                     | JSON                                               | `doc_id` and `source`; its `sha512` must match the file, else 422                                                                      | yes, dashed  |
| PDF through Docling    | CLI `--engine docling`, local build only     | Docling layout model, TableFormer                  | reading order, headings, tables without rules                                                                                          | no           |
| Record, TEITOK, ALTO   | helper CLIs `json_to_md.py`, `xml_to_md.py`  | —                                                  | rendered as Markdown only                                                                                                              | no           |

**Refused**: PPTX, EPUB, ODP and other ZIPs, PPT, HTML, plain text and images (415); encrypted or corrupt
files (422); a PDF whose text layer is mostly an earlier OCR run (422 `ocr_text_layer`); DOC or XLS
without LibreOffice (501; the API image has it).

## nlp-enrich

### Input formats and how the code reads them

In the service, the `file` part is chosen by its name and a peek at its content

| Format                                                                                   | Recognised by                                                 | Read with                                    | What is taken                                                                                                                                             | On the panel |
|------------------------------------------------------------------------------------------|---------------------------------------------------------------|----------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|--------------|
| Line table, CSV                                                                          | extension `.csv`                                              | `csv`                                        | `text`, `page_num`, `line_num`; other columns (`categ`, `lang`, scores) ignored                                                                           | yes          |

| Plain text                                                                               | extension `.txt`                                              | —                                            | a line per row; a form feed starts a page. **Service only**: the CLI ignores `.txt`                                                                       | yes          |
| TEITOK XML (e.g. flexiconv's conversion)                                                 | name `*.teitok.xml`, or `<TEI` in the first 4 KB of an `.xml` | `api_util/teitok_read.py`                    | text from `<s>`, else `<lb/>` lines, else blocks; the page from `<pb>`. **Also the layout**                                                               | yes          |
| ALTO XML                                                                                 | `alto` part (with a CSV or XLSX), root element `alto`         | `api_util/teitok_alto.py`                    | **layout only**: measured `String` boxes, lines, blocks, figures, page size; its text is not used                                                         | yes          |
| Document record (JSON)                                                                   | `document_json` part                                          | `api_util/record_layout.py`                  | the record the entities go into; a layout when it has canvases and line boxes; the text when no `file` is sent (`lines[]` minus Garbage, Inverted, Trash) | yes, dashed  |
| Lines as JSON                                                                            | `/enrich_text` body                                           | pydantic                                     | strings, or objects with `text` and page and line; an optional inline record                                                                              | no           |
| PDF, DOCX, ODT, RTF, HTML, MD, TXT, EPUB, TEI, CoNLL-U, VERT, FoLiA, SRT, PAGE XML, hOCR | extension (`FLEXICONV_FORMATS`)                               | flexiconv, **CLI only** (`api_flexiconv.sh`) | converted to TEITOK first; boxes only from PAGE XML, hOCR and ALTO                                                                                        | no           |

| CoNLL-U, NE TSV from an earlier run                                                      | CLI `--start-from`                                            | —                                            | resume a stopped run                                                                                                                                      | no           |

**Layout precedence**: ALTO, then TEITOK, then the record, then rows only (no boxes).

## Found while reading the code

- **nlp-enrich does not filter the lines of a table.** Trash and Noisy lines from ocr-postprocess go to
  UDPipe. Only the lines of a record are filtered.
- **nlp-enrich's service drops `page_label`** from a CSV. The CLI turns it into `<pb n>`.
- **keyword-extract's legacy method (KER) cannot run on a record from the chain.** It needs
  `lines[].lemma`, and nlp-enrich writes lemmas only into `entities[]`: its `include_lines` switch does
  nothing (`api_util/document_hook.py:405`). The 422 message tells the caller to send a record "that
  nlp-enrich has annotated".
- **keyword-extract's batch CLI labels its paradata `nlp-enrich`** (`keywords.py:917`), and nothing reads
  `ker_data/`.
- **digital-convert reads less from ODT and RTF than from DOCX.** Headers, footers and RTF footnotes are
  not read.
- **digital-convert's `doc_to_visual_md.py` decides by extension.** It accepts only PDF, DOCX and
  records, although the converter reads eight kinds.
