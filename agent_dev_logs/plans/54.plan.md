# Strategy — Issue #54: Freeze `atrium_document` schema at v1.0 + add RO-Crate export

> Issue [\#54](https://github.com/ufal/atrium-project/issues/54) · Labels: `documentation`, `enhancement`, `development` · Milestone: Q4 [WP3: Conclusion of Semantic Harmonization] · **Status: 🆕 Just opened, no discussion yet**

## Context
The issue bundles two tasks that differ in kind: (1) tightening `required` is a small, low-risk
correctness fix — no behaviour change for any conforming producer, it only rejects records that
were already wrong; (2) the RO-Crate export is new packaging work with no prior art in any of the
six repos. Treating them as one ticket is fine for tracking, but they should be sequenced and
verified separately, and (1) should land well before (2) since it is the actual "freeze" gate.

## Strategic actions

### A — Tighten `required` first (the actual freeze gate)
Decide, per block, which are genuinely mandatory for *any* valid accreted record vs. which are
stage-dependent (a record before stage 3 legitimately has no `entities` block yet). The fix is
likely a conditional/`anyOf` shape keyed on `assembled.blocks`, not a flat `required` list — a
naive "require everything" would break every intermediate-stage record. Add a schema test that
pins the specific failure this closes: a stage that writes only `schema_version`/`doc_id` must now
fail validation.

### B — Design and implement the RO-Crate export
No prior art exists, so this needs a small design pass first: what becomes the RO-Crate root
entity (the document? the pipeline run?), which existing provenance fields map to RO-Crate
properties (tool version, runner image, licence, vocabulary build hash are all already captured
per the DMP's provenance mandate), and where the export is invoked from (a new
`atrium_document` method, or a separate packaging script). Cross-check against the DMP's WP3
standards column before finalising the mapping.

### C — Tag v1.0 once A lands
Do not wait for B — the schema freeze (A) is the WP3/T3.3 deliverable; RO-Crate (B) is DMP-mandated
but additive and can ship as a minor/patch release after the freeze.

### D — Confirm `atrium-llm-enrich#13` has nothing outstanding
The cross-reference suggests this issue may be closing out loose ends from #13. Read #13's current
state before assuming this issue is the only remaining schema work — if #13 tracked something this
issue doesn't cover, fold it in rather than letting two issues silently split one deliverable.

## Verification / done-criteria
- A schema test exists that fails on a stage-empty record and passes on every real intermediate
  stage shape actually produced by the five tool repos.
- RO-Crate export produces a crate that validates against the RO-Crate spec for at least one real
  pipeline run.
- `v1.0` tag exists and `para-drift` continues to pass across all five tool repos.

## Out of scope
- The full WP3/T3.1 vocabulary deliverable (D3.1) — separate, tracked under `atrium-nlp-enrich#6`.
- Any schema change beyond the `required` tightening — this is a freeze, not a redesign.
