## Strategic actions

### A — Pilot slice: B2 and B6 (tool repos, small diffs)
- **B2**, per the roadmap's §3.1 decision (adopt the CI form): change `image:` to `ghcr.io/ufal/atrium-<tool>-<target>:${ATRIUM_VERSION:-dev}`.
  - The four repos are alto-postprocess (`api`), page-classification (`api`, plus its `ATRIUM_RUNNER_IMAGE` build arg), nlp-enrich (`api`, `llm`) and llm-enrich (`remote`, `digital`, `llm`, `api`).
  - alto's `-gpu` overlay is a local build variant that is not published, and keeps its own local name.
  - The `ATRIUM_VERSION` default must also lose the `v` prefix (B3's compose half).
- **B6:** add `data/.gitkeep` in all five repos. The directory then exists in a fresh clone with the cloner's ownership. Keep translator's comment.
- **Acceptance:**
  - `docker compose pull` resolves every published `image:` at the current release in all five repos.
  - `docker compose run` writes to `./data` from a fresh clone.

### B — Pilot slice: B3 with #67 R2 (hub)
- **Change:** derive `ATRIUM_RUNNER_IMAGE` from the metadata action's output (§3.2, "one source of truth") instead of `github.ref_name`.
- **Why it rides R2:** R2's `CreateAction` names this image as its `instrument`, so R2 would otherwise record a tag that does not exist.
- **Acceptance:** a fresh tag's paradata image reference is a tag that exists in GHCR.

### C — Pilot slice: W5's image items, with #67 R7
- **H3:** pin alto's fastText weights to a Hugging Face revision plus a checksum, and rename the file honestly.
- **H4:** move test and sweep dependencies out of the production images: alto's `requirements-sweep.txt`, pc's `requirements-test.txt`.
- **H5:** extend the `.dockerignore` files.
- **Batching:** these change the images AMČR runs, so they land in one round with R7's slimmer images (nlp-enrich without `llm`).
- **Acceptance:** image sizes recorded before and after; no test/sweep packages in `pip list` inside a production image.

### D — Record W1 as landed, and finish or retire its two leftovers (hub)
- **Update the roadmap** to strike E1, E2, E4, E5, E6 (reusables) and E7 in §2.2, citing the lines in the digest.
- **Action-version floor:** add the rule, or retire it on the grounds that dependabot's `github-actions` ecosystem already bumps actions. The latter is a proposal to decide.
- **E11 `workflow_dispatch`:** a one-line add to three hub workflows. Cheap, so it can go in before the pilot ends.

### E — After the pilot: W3, W4, the rest of W5, W6, each executed or retired
- **W3:** an `:edge` channel and a parameterised E2E. Execute when a HEAD image is needed for testing; if the seeded E2E needs it before a release, pull it into the pilot.
- **W4:** the DRY collapse is the largest diff. Execute after the pilot, translator first, as the roadmap stages it. The GPU parts (`gpu-inference` reusable, `runner-labels`) are **candidates to retire** while the GPU runner is deferred with #40.
- **W5, remaining:**
  - H1 (lockfiles): a pilot on translator.
  - H2 (tooling pins).
  - H6 (`docker` and `pre-commit` dependabot ecosystems).
  - H7 (`pip-audit` as a gate).
  - arm64 (H8) stays retired, as the roadmap already records.
- **W6, remaining:**
  - compose `healthcheck:` asserted against a running container;
  - GPU overlays for `api` (with #40);
  - pc's shellcheck hook regex to cover `result/stats/*.sh`.
- **Closing the issue:** the roadmap gains a per-wave line: *executed (commits)* or *retired (why)*. That line is what closes #69.
