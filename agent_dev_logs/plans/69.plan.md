### Design rules (each checked against the 09-29 heads)
1. **B3 takes the tag from the step that makes it.** Use
   `ATRIUM_RUNNER_IMAGE=…:${{ steps.meta-release.outputs.version || steps.meta-immutable.outputs.version }}`.
   - On a tag this is `1.6.0-beta`, the semver rule's value (priority 900 over `raw`), which is what GHCR carries.
   - On a `test` push it is `test`.
   - With no release tag it is `sha-<short>`, the only tag such a build pushes.
   - **Not `sha-<short>` always.** That value changes every push and sits in the ENV layer the apt layer sits under,
     so every `test` build would re-run the apt upgrade. The Dockerfiles' *cache interaction* note relies on a value
     that is stable on `test` and unique per release; `test`/`<semver>` keeps both properties.
   - `ATRIUM_RUNNER_REF` stays `github.ref_name`: it is a git ref, and the `v` is correct there.
2. **One image name, published or local, never a third form.**
   - Every `ghcr.io/…` `image:` is `ghcr.io/<image-name>[-<target>]:${ATRIUM_VERSION:-dev}`, with the target in the
     caller's `build-targets` (`base` = no suffix).
   - A build-only image is a bare local name with `pull_policy: build`, so `docker compose pull` never asks the
     registry for it. That covers alto `-gpu` and llm `digital-docling`.
   - `ATRIUM_RUNNER_IMAGE` (build arg and env), where set, equals the service's `image:`. This is checked after
     `extends` and after an overlay is merged onto its base, the way compose itself resolves them. That catches
     alto's GPU overlay (CPU image in paradata) and alto `api`'s inherited batch build arg.
3. **B6 uses the OpenShift arbitrary-UID convention.**
   - Compose services that bind-mount anything under `./data` run as `user: "${ATRIUM_UID:-10001}:0"`.
   - The images make what they write group-0-writable (`chown -R atrium:0 … && chmod -R g=u …`) and set
     `HOME=/home/atrium`, so a host uid with no passwd entry still has a writable home.
   - The default runtime (uid 10001, the k8s template's `runAsUser`) is unchanged.
   - Each bind source under `data/` exists in the clone: `data/.gitkeep`, and pc's `data/output/.gitkeep`.
   - On Linux the operator sets `ATRIUM_UID=$(id -u)` in `.env`. Docker Desktop needs nothing.
   - Named volumes created by an older image stay `atrium:atrium` and are only owner-writable. An operator who sets
     `ATRIUM_UID` recreates them once (`docker compose down -v`); `.env.example` says so.
4. **H3 fails closed and costs one layer.**
   - `ARG FASTTEXT_REVISION=` and `ARG FASTTEXT_SHA256=` are empty by default, and the weights `RUN` exits naming the
     one-liner that reads both.
   - The URL is `…/resolve/${FASTTEXT_REVISION}/model.bin`. It checks the size (1,176,355,829 B) and then runs
     `sha256sum -c`.
   - `useradd` moves above the download, and the file is owned `atrium:0` in its own layer. The final ownership step
     prunes `$MODEL_DIR` and never dereferences the `/app/lid.176.bin` symlink, so the 1.18 GB file is no longer
     copied into a second layer.
   - **The rename is retired.** `lid.176.bin` is the default in `classify_TEXT.py:516`, `setup/config.txt:83`,
     `service/text_inference.py:83`, the tools and a test. The persisted `alto-models` volume is seeded only when
     empty, so a renamed file would never reach an existing volume. The Dockerfile and README say what the file
     really is (NLLB LID `model.bin`, 1.18 GB, CC BY-NC 4.0).
5. **H4 removes only what no ENTRYPOINT imports.**
   - The images stop installing `requirements-test.txt` (alto, pc, nlp base) and `requirements-sweep.txt` (alto).
   - The exact fastapi/pydantic pins stay in each `service/requirements.txt`.
   - pc's `test_service_runtime_deps.py` stops listing the test file as image-installed.
6. **The linter guards what round 5 fixes.** The new rules run in all five tool repos through
   `workflow-lint.reusable.yml` (the caller's `GITHUB_REPOSITORY` resolves `${{ github.repository }}`). Each rule
   must fail a purpose-built broken fixture and must fire on the *original* compose files.
