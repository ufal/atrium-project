## Context

The issue asked for a DARIAH Vocabs namespace so the harmonised AMCR+TEATER vocabulary could be
published as SKOS. @motyc's same-day answer removed that from this repo's plate — a dedicated
SKOSification project led by @petrpajdla owns it on an 18-month timeline — **and added the part
this plan now acts on**:

> "This does not prevent using SKOS as framework to align the data internally. It is definitely
> desirable."

This plan replaces its own previous version, which read that as §A *"Do nothing that anticipates a
namespace"* plus an optional, unscheduled §B. §A was right about the namespace and wrong about the
consequence: it treated "no namespace" as "no work", when the blocking dependency applied only to
**publication**. Everything @motyc affirmatively encouraged needed no namespace at all — and three
live defects were waiting in the gap. See [`../../docs/skos_strategy.md`](../../docs/skos_strategy.md) §6.

## Strategic actions

### A — The namespace question stays closed, and is now closed *by design*

No namespace is requested. The one constant that roots ATRIUM-authored URIs
(`atrium_vocab.SKOS_BASE = "https://w3id.org/atrium/"`) covers only the ~64 concepts ATRIUM itself
authors — page categories, line categories, quality bands, coarse entity types, harmonisation
themes. Every harvested concept keeps the source's own identifier. When the SKOSification project
ships, either the `w3id` redirect is repointed (zero data changes) or one string changes and the
artifact is regenerated.

Registering the `w3id.org/atrium` redirect is **optional and blocks nothing** — these are
identifiers before they are locations. It is also not a namespace request in the sense @motyc ruled
out: it reserves a redirect, not a vocabulary, and commits ARUP/ARUB to nothing.

### B — What was deliberately NOT done

Recorded because each looked like the obvious next step and each is wrong:

* **`exact_match` was NOT added to `_settings.nested_keep`.** `get_prompt_string()` serialises the
  whole nested structure into the model's system prompt, so that one config edit would inject 707
  Getty URIs plus 5,594 source URIs into every request — against a context budget this repo tracks
  in its own reviewer sheet, and a change to model behaviour in the name of a provenance field.
  The URIs reach runtime through `concept_index()` instead.
* **AMCR's `hierarchie_vyse` was NOT emitted as `skos:broader`.** All 1,176 edges cross heslář
  boundaries; `obývání` (an activity) declares 22 `areal` "parents". It is `skos:related`.
* **TEATER's ancestor chain was NOT emitted as 12 `skos:broader` links.** Only the direct parent is
  `skos:broader`; the rest are `skos:broaderTransitive`.
* **TEATER's AAT quotes were NOT promoted to `skos:exactMatch`.** They are citations
  (`dcterms:source`), not identity claims.
* **`same_as` was NOT serialised as `owl:sameAs`.** It is a label-shape scoring heuristic.
* **No `enum` was added** to `lines[].categ`, `pages[].category` or `page_categories`.
  `validate_document()` raises, and page-classification derives its labels from the filesystem at
  runtime — an enum would convert a naming slip into a pipeline failure.

### C — Check in with @petrpajdla's project when it has a namespace

Unchanged and still not urgent. The check-in is now cheaper than it was: the migration is a
redirect or a one-line constant, not a data model change.
