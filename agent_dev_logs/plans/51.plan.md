# Strategy — Issue #51: Request DARIAH Vocabs Service Namespace

> Issue [\#51](https://github.com/ufal/atrium-project/issues/51) · Labels: `question`, `beginning`, `integration` · Milestone: Q3 [WP8/WP7] · **Status: 🔵 Deferred to a separate 18-month project (per @motyc, 2026-09-04) — explicitly non-blocking**

## Context
The issue opened asking to coordinate a DARIAH Vocabs namespace request so the AMCR+TEATER
vocabulary (built out in `atrium-nlp-enrich`'s issue #6, mirrored in `atrium-llm-enrich`) could be
published as SKOS. @motyc's same-day answer changes the shape of this issue entirely: a dedicated
SKOSification project for AMCR and TEATER, led by @petrpajdla, already exists on an 18-month
timeline and owns this ground. This issue's job going forward is to **not duplicate or race** that
project, and to stay a lightweight pointer to it.

## Strategic actions

### A — Do nothing that anticipates a namespace
Don't build a SKOS export path keyed to a specific namespace guess, and don't restructure the
existing `(source, id)` vocabulary keys in `atrium-nlp-enrich`/`atrium-llm-enrich` in anticipation
of a future PID scheme. @motyc's framing is explicit: today's IDs *become* PID references later;
building toward a namespace now risks having to redo it once the real one exists.

### B — Optional, low-priority: an internal SKOS-shaped alignment
If it's ever useful for the vocabulary curation work in nlp-enrich's #6 (e.g., to reason about
broader/narrower term relationships more formally), an unpublished, internal SKOS-structured view
of the vocabulary is fine to build — this is the one thing @motyc affirmatively encouraged. Not
scheduled; opportunistic only.

### C — Check in with @petrpajdla's project periodically
No fixed cadence justified by the thread — @motyc explicitly said not to treat this as urgent. A
light-touch status check (e.g., every few months, or when the vocabulary work in #6 reaches a new
milestone) is enough to know when the real namespace becomes available and the PID migration can
happen.

## Verification / done-criteria
- This issue can close (or be downgraded to a pure tracking pointer) once @petrpajdla's
  SKOSification project either ships a namespace or is confirmed to have superseded the need for
  one here entirely.

## Out of scope
- The vocabulary content and governance decisions themselves (facets, exclusions, dedup) — owned
  by `atrium-nlp-enrich`'s **#6**.
- Any actual SKOS export implementation — not scoped until a namespace exists.
