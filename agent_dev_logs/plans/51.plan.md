## Strategic actions

### A — Finish the internal part
1. **The translator on the curated list (#72 B.2).** `load_vocab.py --from-release` keeps the flat rows whose pairs are in the asset's `vocabulary.csv`, and the committed CSV is regenerated (about 4,715 rows). This retires F3 and the last duplicate source of truth (V-3).
2. **The registry follows keyword-extract's taxonomy.** keyword-extract's `tests/test_vocab_theme_maps.py` (delivered 10-15) fails whenever `taxonomy_config.json` and the vendored `HESLAR_TO_THEME` / `TEATER_BRANCH_TO_THEME` disagree.
3. **Remove F8.** `git rm fixtures/e2e/VOCAB/teater_nested_vocab.json` makes `skos_strategy.md`'s F8 row and `fixtures/e2e/README.md` true. The crate fix ships with the six repositories' next tags (#72 E.2).

### B — Follow-ups that do not block
- **F7:** dispatch keyword-extract's `vocab-refresh.yml` (network). The weaker mappings (`close_match`, `broad_match`, `citation_uri`) then fill the committed flat data, and the next release carries them.
- **F4:** CNEC 2.0 glosses only from the reference, never invented.
- **F5:** register the `w3id.org/atrium` redirect when convenient.

### C — V-5 as an explicit contract decision
Producers write the source label into `enrichment.items[].teater_category`, and the schema now says so. The crate reads `teater_category_ids` and no longer depends on the label. The record-contract owner chooses between two options:
1. **Keep the source label:** the theme is derived through the registry when needed.
2. **Put the theme in the field:** the source label moves to a sibling field.

Whichever is chosen, the registry, schema description, validators and crate change together in one round. Nothing changes before the decision.

### D — Keep the semantic choices
- `hierarchie_vyse` → `skos:related`;
- TEATER → one `skos:broader` + `broaderTransitive`;
- AAT quotes → `dcterms:source`;
- `same_as` is not identity;
- facets are collections;
- provenance never enters the prompt (`resolve_pid()`, `teater_category_ids`).

### E — Hand over publication
When the external project sets its PID policy:
1. map the source concepts to the PIDs;
2. update the artifact metadata, not the historical records;
3. repoint `SKOS_BASE` or the redirect if needed;
4. re-run the drift and record gates.
