## 1. What is settled
- [x] All six `api` stages read `PORT`/`HOST`/`GRACEFUL_SHUTDOWN_S` from the environment. No `--port` is baked in, and `ENV PORT=8000` stays as the default.
- [x] `service/healthcheck.py` reads `$PORT`, so a container that reports `healthy` with `PORT=9000` proves both the listener and the probe.
- [x] The shared probes run on every pull request, push to `test` and tag (`docker-build-smoke`):
  - the default port;
  - `PORT=9000`;
  - `HOST=127.0.0.1`, which must be unreachable on the published port.
- [x] Green on all six current heads (the digest's table).
- [x] The `v1.9.2-beta` false red is explained, and fixed by `4cbf900`: a shared model cache, and an error that names the warm-up as the other possible cause.

## 2. Closing step — the deliberate red run
1. **Repository:** `atrium-translator`.
   - It has only `base` and `api` targets, and with the default `lindat` backend it loads no translation model at start-up. So the log reads as a port failure and nothing else.
   - nlp-enrich would do as well. Avoid page-classification, where warm-up dominates the log.
2. **Vehicle:** a pull request into `test`.
   - `docker-build-smoke` runs on pull requests.
   - `build-and-push` runs only on a push to `test`, a `v*` tag or a release, so nothing is published.
3. **The one-line break** in the `api` stage:

   ```dockerfile
   ENTRYPOINT ["uvicorn", "service.api:app", "--host", "0.0.0.0", "--port", "8000"]
   ```

   Keep `ENV PORT=8000 GRACEFUL_SHUTDOWN_S=20`, so the default-port step stays green and the `PORT=9000` step is the one that fails.
4. **Expected:**

   | Check                                                | Result | Why                                                                                               |
   |------------------------------------------------------|--------|---------------------------------------------------------------------------------------------------|
   | "Run container and wait for HEALTHCHECK (issue #55)" | 🟢     | the listener and the probe both use 8000                                                          |
   | "Run container on a NON-DEFAULT port (issue #58)"    | 🔴     | the probe asks 9000, the listener is on 8000; the container log shows uvicorn on 8000, no warm-up |
   | `tests/test_service_entrypoint.py` (fast lane)       | 🔴     | the static guard refuses a baked `--port`                                                         |

   The red arrives after the HEALTHCHECK budget (`start-period` 180 s + retries). Do not shorten it for this run.
5. **Record and close:** link the red run on #58, close the pull request unmerged (nothing to revert on `test`), and close #58. Then close #53 with its one line (see its plan §2).

## 3. Rules for later changes
- A new `-api` image adopts the same contract and joins `probe-targets` (as digital-convert did in `v1.1.0-beta`).
- A red `PORT=9000` step is a regression in the owning repository. The container log decides between port and warm-up.
- Making `docker-build-smoke` gate `build-and-push` is a separate change (the workflow comment sequences it), outside #58.
- Optional, small: give ocr-postprocess the `test_api_entrypoint_does_not_hardcode_the_port` guard the other five have (adapted to `service/text_api.py`). Its Docker probe already covers the case.
