## 2026-10-02 — current architecture baseline

The issue's implementation no longer needs to be designed. It has already landed.

The required deployment contract is now present in the five current production API images:

| Stage               | Repository                   | Listener form                |
|---------------------|------------------------------|------------------------------|
| OCR postprocess     | `atrium-ocr-postprocess`     | `python service/text_api.py` |
| Keyword extraction  | `atrium-keyword-extract`     | `python -m service.api`      |
| NLP enrichment      | `atrium-nlp-enrich`          | `python -m service.api`      |
| Page classification | `atrium-page-classification` | `python -m service.api`      |
| Translation         | `atrium-translator`          | `python -m service.api`      |

All five use:

```text
PORT                 -> listener + healthcheck target
HOST                 -> listener bind address
GRACEFUL_SHUTDOWN_S  -> uvicorn graceful-shutdown timeout
RELOAD               -> development reload mode
```

with the production defaults:

```text
PORT=8000
HOST=0.0.0.0
GRACEFUL_SHUTDOWN_S=20
RELOAD=false
```

The common Docker workflow already probes the current `api` target with:

```text
PORT=9000
HOST=127.0.0.1
```

The issue is therefore in **verification/closure mode**, not implementation mode.

## B — Perform the deliberate-breakage acceptance test

This is still the acceptance item explicitly requested by the issue and remains the cleanest proof that the Docker runtime guard is not vacuous.

### B.1 — Use `atrium-translator`

Use `atrium-translator` for the temporary regression because:

* it has only `base` and `api` build targets;
* it does not require page-classification's model-cache-heavy API lane;
* the old failure mode is deterministic;
* the current five include translator directly, so the test does not depend on a predecessor/successor rename.

### B.2 — Break exactly one line

In the temporary PR branch, replace the current API entrypoint with the historical bad form:

```dockerfile
ENTRYPOINT ["uvicorn", "service.api:app", "--host", "0.0.0.0", "--port", "8000"]
```

Do **not** remove:

```dockerfile
ENV PORT=8000 GRACEFUL_SHUTDOWN_S=20
```

This is important.

Keeping the default `PORT=8000` guarantees that:

* the default-port smoke step stays green;
* the `PORT=9000` smoke step is the one that demonstrates the regression;
* the workflow does not skip the interesting failure because an earlier default-port step failed.

### B.3 — Open a PR into `test`

Do this as a PR rather than pushing the bad commit directly to `test`.

The shared Docker smoke job accepts pull requests, while the publish path is gated separately. Therefore the intentionally broken image is exercised by CI but is not published as the normal `:test` artifact.

The PR should contain only the one-line regression.

### B.4 — Record all three expected signals

The expected result is deliberately redundant:

| Guard                           | Expected result | Why                                                                        |
|---------------------------------|-----------------|----------------------------------------------------------------------------|
| default-port container          | 🟢              | proves the accidental break does not destroy the ordinary `PORT=8000` path |
| `PORT=9000` container           | 🔴              | proves the non-default-port probe detects the baked listener               |
| static service-entrypoint guard | 🔴              | proves source-level regression detection also fires                        |

The non-default-port container step may fail by timeout. That is expected.

The listener remains on `8000`, while `service/healthcheck.py` reads:

```text
PORT=9000
```

and therefore probes the wrong port.

Do not shorten the smoke timeout merely to make the deliberate red run faster. The existing workflow budget is intentionally large enough for the standard API startup window.

### B.5 — Confirm no publication occurred

The deliberate-breakage PR must not publish the broken `:test` image.

Record the PR URL and the CI run in the #58 closure comment.

Then close the PR unmerged.

There is no code to revert on `test`.

## E — Preserve the manifest contract

The current Kubernetes manifest should not be redesigned.

The existing contract is:

```yaml
containerPort: 8000
name: http

env:
  - name: PORT
    value: "8000"
```

and all startup/readiness/liveness probes use:

```yaml
port: http
```

This is the important integration property: a partner changing the declared port changes the process listener and the Kubernetes probe target together.

The reference deployment document already explains this relationship.

No Helm/chart templating or values-file work belongs in #58.

## F — Preserve the healthcheck and para-drift boundary

`service/healthcheck.py` is already the canonical shared probe.

It reads:

```python
port = os.getenv("PORT", DEFAULT_PORT)
```

and always probes loopback.

Do not modify it as part of this closure.

Likewise, do not re-vendor or regenerate the shared healthcheck merely because the production repositories changed names. The repository split changes ownership of services, not the canonical runtime probe contract.

The OCR script entrypoint is also intentionally outside the `-m service.api` rule used by the other four services.
