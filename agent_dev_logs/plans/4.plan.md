Create one digital-convert record only if no equivalent already exists. Do not create a second converter record or a second full-chain workflow.
- Each tool record describes its newest **released** version, not features only present on `test`. A record must be revised only if the release changes the durable description, supported formats, endpoints, image names or component-license entries.
- Keep software/model/service terms separate from rights in derived documents or annotations. A component licence does **not** by itself determine output rights. For LINDAT-hosted models/services, name the model/software licence separately from [LINDAT Terms of Use](https://lindat.mff.cuni.cz/en/terms-of-use). The human-readable explanation is [Licences and paradata](https://ufal.github.io/atrium-project/ecosystem/licences/).
- The controlled-vocabulary keyword results must remain explicitly **experimental and not yet evaluated**. Distinguish statistical keywords (method, score, rank) from vocabulary-controlled results (term, Czech/English labels, confidence, vocabulary record IDs).
- For NLP/TEITOK, distinguish actual word boxes preserved from ALTO from positions estimated within born-digital line geometry. For digital conversion, distinguish PDF page/line geometry from office-document structure, which generally carries no page positions.
- Keep the born-digital branch inside `0xSpVP` (as step 6), not as a second full AMČR workflow. Preserve the step 6 PDF-extraction/GROBID context when its links/formats are updated.

### C. `jGxgQI` — Born-digital document converter

**Repository:** `https://github.com/ufal/atrium-digital-convert`
**Release:** `v1.4.4-beta`
**Changed since the 10-24/10-27 submission:** the table shape (the component rows are unchanged); the command line
gives the per-page assessment too; the Docling engine is command line only; the default engine needs no model or
network.

**Proposed fields:** category Tool or service; label `Born-digital document converter: PDF and office files into structured text without OCR`; accessible at the repository above; external ID GitHub `ufal/atrium-digital-convert`; activity Converting / Extracting (verify both concepts); keyword `ATRIUM catalogue`, born-digital documents, document conversion, PDF; language-independent; mode command line + API; input PDF, DOCX, ODT, ODS, XLSX, RTF, DOC, XLS; output JSON, Markdown; resource category Software Repository; licence MIT; version `v1.4.4-beta`; helpdesk `https://github.com/ufal/atrium-digital-convert/issues`; manual `https://github.com/ufal/atrium-digital-convert#readme`; see also `https://ufal.github.io/atrium-project/workflows/digital-convert/`; related `0xSpVP`, `RER7Fw`, `YParYU`, `j9fqxo`, `EMhu3X`. Do not add a standalone converter workflow; the born-digital branch belongs to `0xSpVP`.

**Description to paste:**

> Reads documents that were created on a computer rather than scanned, and writes their text with its structure into the ATRIUM document record (JSON), without OCR: pages, text lines in reading order grouped into blocks, and the headings, running headers and footers, footnotes and tables the format carries. The two kinds of input differ. From a PDF it takes the page geometry: the size of each page and the position of every line, with headings recognised from the size and weight of the type. From an office document (DOCX, ODT, ODS, XLSX, RTF, and the legacy DOC and XLS through LibreOffice) it takes the structure the format declares, with no positions on the page. The type is recognised from the file's content, not its extension.
>
> The text layer of every page is checked. A page without a text layer, with one that does not decode, or with one left by an earlier OCR run is flagged as needing OCR, with the reason, so that only such pages go to OCR; a PDF that is mostly an earlier OCR run is refused as not born-digital. Pages with substantial character loss from unmapped glyphs are also flagged as needing OCR and their text layer is marked as garbled. On request the record is also rendered as annotated Markdown in reading order.
>
> REST API container image (`ghcr.io/ufal/atrium-digital-convert-api`): `/reformat` returns the record; `/describe` adds a per-page assessment with the suggested next step (NLP, OCR or handwritten text recognition), asking the ATRIUM page classifier and OCR post-processor when they are available. The command line gives the same results, the per-page assessment included.
