## 4. Record-writing rules

1. **One current owner per tool.** Reuse `YParYU` and `j9fqxo`; create only the converter record.
2. **The newest release, not `test`.** Every sheet names a release tag; nothing that exists only on `test` is described.
3. **Research named as research.** A component that is not in the release's production surface is described as such, in
   the present tense, without promising when it will change.
4. **Licence rows from `para_config.txt` at that release**, in the July table shape (Component · License · Status ·
   Compliance Details; 🟢 Friendly, 🔴 Problematic, 🟡 Depends), followed by "The source document's own licence applies to
   its text" where the repository README says so.
5. **Durable wording.** No defaults, command-line flags, configuration keys, issue numbers or dates in a description; model
   names only where the model is the service (UDPipe, NameTag, CUBBITT) or in the licence table; the version field is the
   only release-bound value.
6. **No chain narrative in a tool record.** Relate `0xSpVP`; name neighbouring ATRIUM tools only where the tool calls or
   reads them.
7. **Lineage in one sentence**, only where a name changed (`YParYU`, `j9fqxo`); historical repositories never appear as
   current owners.
8. **Image names as published:** `ghcr.io/ufal/atrium-<tool>-api` (the hub's `docker-tool.reusable.yml`), not the
   `…:<version>-api` form some service READMEs still use.

**Description:**

````markdown

**Description:**

````markdown
Reads documents that were created on a computer rather than scanned, and writes their text with its structure into the ATRIUM document record (JSON), without OCR: pages, text lines in reading order grouped into blocks, and the headings, running headers and footers, footnotes and tables the format carries; for PDF also the position of every line. It reads PDF, DOCX, ODT, ODS, XLSX and RTF, and the legacy DOC and XLS through LibreOffice; the type is recognised from the file's content, not its extension.

The text layer of every page is checked. **Description:**

````markdown
Translates the text inside XML files and writes it back without changing the structure: tags, namespaces and OAI-PMH envelopes are kept. In ALTO mode each text block is translated as a whole and line by line, and the fluent translation is realigned to the original lines and word positions. In metadata mode the fields named by XPaths are translated, for example in AMČR records; the translation replaces the source text or is added beside it with language labels. The command line can validate the output against an XSD schema; AMČR's own schema accepts replaced records only.

The source language is detected per text block or field, or given. Domain terms can be held to their agreed translations from a vocabulary, matched as phrases or by UDPipe lemma; a helper harvests Czech–English term pairs from the AMČR vocabularies and the TEATER thesaurus. Backends: LINDAT Translation (CUBBITT), self-hosted CTranslate2 models, or an OpenAI-compatible language-model API. A reply that comes back empty, cut short or looping is requested again and never written. A CSV log beside each output pairs source and target text for review, and each command-line run writes a paradata JSON log.

Command-line tool, or REST API container image (`ghcr.io/ufal/atrium-translator-api`, `/translate`).
