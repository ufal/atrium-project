## Context
- **What goes wrong.** A tool opens its baseline under `<derived>.document.json`, where `<derived>` comes from the upload's filename. `DocumentRecord` keeps the baseline's `doc_id`. Left to its default, `finalize()` names the output after that id, so whenever the two ids differ, the file the tool reads back is not the file it wrote.
- **Why the pilot hits it.** An AMČR seed carries the AMČR file id, so every pilot call differs. The failure is silent: the response is a valid record, just without the tool's block.
- **Why it goes first.** It is #67's first item because the rest of R1 (seed profile, `sha512`, seeded E2E) builds on it.

## Strategic actions

### A — The fix ✅ (done, 2026-09-27)
**Rule:** a tool writes the record back to the file it read and returns that path; its callers read that path back. The record keeps the seed's `doc_id`.
- **Why "in place" and not just "read back what `finalize()` returns":** alto's CLI runs its stages as separate processes that find the record by name. With `finalize()`'s default name, every stage re-read the seed. nlp-enrich already accretes in place; the fix brings alto-postprocess and llm-enrich onto the same rule.
- **alto-postprocess:** `document_hook.write_document_block()` calls `doc.finalize(path)` after its Layer D gate and returns the path (`None` when nothing was written). `/process` reads `record_path or baseline_path`.
- **llm-enrich:**
  - `write_document_record()` returns the `finalize()` path, which fixes `/extract_keywords` and `--document-json-out` in both batch clients.
  - `enrichment` citations use the record's `doc_id`.
  - `/extract_keywords_text` uses `_inline_doc_id()`. It takes the sent record's `doc_id` when it is a printable, plain file name of at most 200 bytes, and otherwise falls back to `inline_text`.

### B — Close
Post the verification comment (draft in chat) and close as completed. #67's first pilot item is then done.

### C — Carry it to AMČR
The fix is on `test` only. It reaches the images AMČR runs with the next alto-postprocess and llm-enrich releases. Those ride #67's order: #40's immutable releases come first, for the tags AMČR builds from. No separate release for this fix alone, unless AMČR tests seeded calls before then.

### D — Follow-ups that are not this issue
- **#67 §C:** the seed profile and `source.sha512` (C.1-C.3), then the seeded E2E (C.4) with `e2e_assert.py` checking that `doc_id` survives every stage. The E2E is what keeps this fixed across all five images, not only in each repo's unit tests.
- **Translator path hardening:** `service/api.py:344` (baseline `doc_id`) and `:323` (upload name) are used in paths unchecked. The same guard as llm-enrich's `_inline_doc_id()` would fit. A small issue of its own, or a rider on the translator's next change.
