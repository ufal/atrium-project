## Context

The ecosystem reads configuration from the environment in ~180 places across six repos. ARÚP/ARÚB are handed `docs/k8s_deployment.md`, `docs/templates/k8s/atrium-service.deployment.yaml` and `docs/k8s_acceptance_runbook.md`, and are expected to deploy five services from them. #60 exists so they can find every knob without opening five source trees.

This is the least urgent of #53's findings and the one most likely to be done badly, because "write documentation" invites writing down whatever seems true rather than deciding what the contract *is* and checking it. That is not a hypothetical: it has already happened once inside this issue.

## The six findings that reshape the work

### 1. The deliverable has already drifted, inside 24 hours

|-------------------|--------------------------------------|------------------------|
| `MAX_UPLOAD_MB`   | **5** (`resolve_max_upload_mb(5.0)`) | `50`                   |
| `MAX_WORDS`       | **30000**                            | `200000`               |

This settles the ordering the issue leaves open: **fix the facts, publish them, then lock them.** A guard written after the files is a formality; a guard written first is the deliverable.

### 2. `.env` does not reach the container — and the new files promise that it does

No repo imports `python-dotenv`; no compose file has `env_file:`. Compose reads `.env` **only** to expand `${VAR}` inside the compose file itself, so a name reaches the container only if the api service's `environment:` block passes it through.

| Repo                | api-service keys fed from `.env`                                                      | `.env.example` rows |
|---------------------|---------------------------------------------------------------------------------------|---------------------|
| alto-postprocess    | `ALLOWED_ORIGINS`, `PORT`                                                             | 6                   |
| llm-enrich          | `LLM_BACKEND`, `OPENROUTER_*`, `OLLAMA_*`, `ALLOWED_ORIGINS`, `MAX_UPLOAD_MB`, `PORT` | **no file**         |
| nlp-enrich          | `PORT`, `UDPIPE_URL`, `NAMETAG_URL`                                                   | 20                  |
| page-classification | `ALLOWED_ORIGINS`, `PORT`                                                             | **no file**         |
| translator          | `PORT`, `TRANSLATION_URL`, `UDPIPE_URL`                                               | 22                  |

`HOST`, `GRACEFUL_SHUTDOWN_S`, `LOG_LEVEL`, `RELOAD` and `HEALTHCHECK_PATH` are passed by **zero** compose services in **any** repo — while three `.env.example` files document them under a header stating that compose picks them up. nlp-enrich is worse than inert: `docker-compose.yaml:44-45` hard-codes `MAX_CONCURRENT_JOBS: "2"` and `DEFAULT_KW_METHOD: "keybert"` as literals, *actively overriding* `.env`.

**This is the `PORT`-before-#58 bug class, reproduced inside the issue created to prevent it.** The variables are real for Kubernetes and for `docker run -e`; they are inert on the path the file's own header recommends. The repo with the best passthrough in the ecosystem (llm-enrich, eight names) is one of the two with no template at all.

### 3. A literal `os.getenv` scan under-counts, so the acceptance rule cannot be implemented as written

`processors/translator.py:104-126` defines `_env_float` / `_env_int` / `_env_str`. A grep for `getenv("LINDAT` / `environ.get("LINDAT` over `processors/` returns **nothing**, yet `LINDAT_MIN_INTERVAL_S`, `LINDAT_MAX_RETRIES` and `LINDAT_BACKOFF_BASE_S` are read at `:128-132`, and `TRANSLATION_URL`/`LINDAT_BASE_URL` at `:159`. translator's `.env.example:38-40` documents three of them — from a human read, not a scan.

A guard that only understands `os.getenv` would certify that file complete while blind to an entire variable class. The extractor must understand helper indirection, or it is theatre.

### 4. The scan boundary cannot be a directory

The acceptance bullet says "reads under `service/`". But the backing-service URLs the issue opens with are elsewhere — `nlp-enrich/api_util/call_udpipe.py:145`, `call_nametag.py:206`, and all of `translator/processors/` — while `nlp-enrich/api_util/summarize_nt_udp.py` holds ~15 batch-only names (`ALTO_DIR`, `SAVE_CSV`, `TEITOK_OUTPUT_DIR`, …) that must **not** be published.

`KOREKTOR_URL` (`alto/tools/quality_model/correct.py:337`, a fourth LINDAT service added by #63) is **correctly excluded**: the api entrypoint's import closure does not reach it, and the manifest lists only the three. It belongs to the batch/tools layer. The digest omits it — right answer, unstated reason.

### 5. A sixth enumeration already exists, already disagrees with the code, and cannot be deleted

All five repos carry an env table in `service/README.md` (alto `:396-402`, llm `:98-111`, nlp `:181-193`, pc `:308-314`, translator `:35-44`). Nobody counted these. alto's says `MAX_UPLOAD_MB` = 10; `service/text_api.py:79` is `resolve_max_upload_mb(25)`.

They are **normative** and cannot simply be deduped away: `docs/agent_skill_strategy.md:702` (Appendix D item 6) requires *"Configuration: env-var table (§4.5 subset)"*, and `.github/workflows/skill-validate.reusable.yml:41` has `service/README.md` in its checked doc set.

`MAX_UPLOAD_MB` has **five different effective defaults**, none of them at the `os.getenv` site — alto **25**, llm **10**, nlp **5**, pc **10**, translator **50** — and the manifest's commented `value: "10"` reads as universal while being right for two of five.

### 6. `.env` is not gitignored where it is about to matter

alto (`.gitignore:18`), llm-enrich (`:151`) and translator (`:6`) ignore `.env`. **nlp-enrich and page-classification do not** — and nlp-enrich's `.env.example:3` already says "Copy to `.env` and edit", while page-classification is about to receive its first template. llm-enrich's compose passes `OPENROUTER_API_KEY`.

## Strategic actions

### A — Fix the facts, publish them, lock them

Generate the variable/default/section skeleton from the code; hand-write only the comment prose. Land the guard **green** — a guard that lands red gets disabled.

### B — Declaring the scan boundary: compute the floor, allow only reasoned deltas

```
SCAN = {service/**.py}                    # hard floor, never declarable away
     ∪ import_closure(entrypoint_module)  # derived from the Dockerfile ENTRYPOINT
     ∪ EXTRA_SCAN.keys()                  # additive only, each with a written reason
```

`entrypoint_module` comes from the `Dockerfile` `ENTRYPOINT` line — the same source `tests/test_service_entrypoint.py` already reads in all five. `import_closure` is a stdlib AST walk over first-party imports. It is the one genuinely new mechanism and it earns its place: it makes `SCAN` impossible to shrink silently. Checked against the trees:

- **translator** — the closure reaches `processors/translator.py` (`LINDAT_*`) and `ct2_translator.py` / `llm_translator.py` (`CT2_*`, `LLM_*`), correctly, since `TRANSLATION_BACKEND` selects them at run time. No `EXTRA_SCAN` needed.
- **nlp-enrich** — the closure stops before `api_util/summarize_nt_udp.py`, so the batch variables stay out **by construction, not by suppression**. It also does not reach `call_udpipe.py` / `call_nametag.py`, which sit behind a subprocess boundary — the only two `EXTRA_SCAN` entries in the ecosystem.
- **alto** — the closure does not reach `tools/quality_model/correct.py`, so `KOREKTOR_URL` is excluded for a stated reason.

Per repo, a **data-only** `service/env_contract.py`, parsed with `ast` and never imported, holding four names: `EXTRA_SCAN` (unreachable-but-published paths, with reasons), `INTERNAL` (read-but-suppressed, with reasons), `COMPOSE_INTERPOLATED` (`ATRIUM_VERSION`, `ATRIUM_RUNNER_REF` — set by a partner, read by no Python), and `READERS` (repo-local helper signatures).

Logic hub-side, data repo-side. Adding a shared *file* costs three registrations (`scripts/revendor_shared.sh:24-33`), and `tools/skill_drift_check.py` has already fallen five names behind `para-drift.reusable.yml` — [\#59](https://github.com/ufal/atrium-project/issues/59)'s exact failure. This plan adds no sixth copy of anything.

**Anti-vacuity, all four enforced:** every `EXTRA_SCAN` path resolves to ≥1 file with ≥1 env read; every `INTERNAL` key is genuinely read; every `COMPOSE_INTERPOLATED` key appears as `${KEY` in a compose file; and `service/atrium_service.py` is in `SCAN` **with** `MAX_UPLOAD_MB` in the extracted read-set. Without that last assertion a broken extractor certifies all five repos clean.

### C — Check names **and** defaults

Names-only would have passed all four wrong nlp values and alto's README `10`. Three call shapes:

1. **Literal** — `os.getenv("NAME", "lit")` → `ast.literal_eval` of arg 1; no second argument means *unset*.
2. **Canonical helper, name fixed in the body, default at the call site** — `resolve_max_upload_mb(5.0)`. A hub-side table pins the name (`MAX_UPLOAD_MB`, deprecated alias `MAX_UPLOAD_BYTES`) and reads the call argument. It lives hub-side because `service/atrium_service.py` is byte-identical in all five and para-drift enforces that.
3. **Repo-local helper, name at the call site** — declared in `READERS`. `_env_str("TRANSLATION_URL", "LINDAT_BASE_URL", default=…)` is first-wins, which is also the precedence `processors/translator.py:143-159` documents.

**Never guess; fail only on contradiction.** A `Name` default resolves one hop against module-level literals; failing that, record it *unresolved*, check the name only, and emit a `::notice::` so creeping loss of coverage stays visible. `ALLOWED_ORIGINS` is the live example — `os.getenv("ALLOWED_ORIGINS", default)` where `default` is a parameter whose signature default is `"*"` — and it must degrade, not go red. Normalise before comparing (`5.0` == `5`; `false`/`0`/`no` equal; blank RHS means "matches unset"). A `# NAME=value` line parses as *documented but not set*, which is what `MAX_UPLOAD_BYTES` requires.

### D — `.env.example`: complete, and honest about which path honours each entry

- Every name in `SCAN`, with the **code** default.
- Each entry tagged `[compose + k8s]` or `[k8s / -e only]` — or `[OVERRIDDEN]` for nlp-enrich's two literals. This is finding 2 made visible to the person editing the file.
- `ALLOWED_ORIGINS` publishes the **code** default `*`, with the per-repo compose default noted separately. alto's and translator's current files publish alto's *compose* value as if it were the default.
- Credential-shaped keys get placeholders only, and a pointer to `secretKeyRef` rather than a manifest literal. Add `.env` to nlp-enrich's and page-classification's `.gitignore`.
- `MAX_UPLOAD_BYTES` stays commented and labelled **DEPRECATED** (§4.5, `docs/agent_skill_strategy.md:170-179`).

### E — Make the compose passthrough match the file

For each api service add `VAR: ${VAR:-<code default>}` for every published variable not already present, and convert nlp-enrich's two hard-coded literals. This is what turns each file's header from a claim into a fact. `RELOAD` is deliberately **not** wired — roadmap B8's subject; documented as development-only.

### F — One section in `docs/k8s_deployment.md`, cross-referenced from the manifest

**New `##` at `:120`, not a widening of `:88`.** `:110-116` is the `HOST=127.0.0.1` warning — *"reports healthy and serves nobody"* — the most operationally dangerous paragraph in the document; burying it inside a 30-row reference is how it stops being read.

- Rewrite `:117-118` from a deferral into a forward pointer; relabel the `:97-102` table "the four the reference manifest itself exposes".
- **Table A**, common to all five, with an "In the template manifest" column (set / commented / —).
- **Table B**, per repo, operator-facing deltas only, plus one sentence excluding algorithmic parameters by name.
- **A callout, "Two defaults, and which one applies to you"** — the tables give **code** defaults, which is what Kubernetes gives you; compose supplies its own per repo, and a variable compose does not pass cannot be set from `.env` at all.
- `MAX_UPLOAD_MB` stated once, per repo. Reword the manifest's `# value: "10"` to read as an example.
- **Secrets**: the manifest ships no `Secret`, and llm-enrich *requires* `OPENROUTER_API_KEY` (`service/api.py:128-131` raises without it) — so llm-enrich cannot be deployed from the reference manifest unmodified. Add a `secretKeyRef` stanza and a "Known limits" line.
- Both cross-references **name the test**, which turns them from a hope into a falsifiable claim.
- `k8s_acceptance_runbook.md` mentions neither `ALLOWED_ORIGINS` nor `MAX_UPLOAD_MB`, both of which a partner running real traffic will hit. Add them to its prerequisites.

### G — Where the guard runs

1. **Hub-local, land first** — `tests/test_env_contract.py`: the manifest's `env:` block (live *and* commented-out) against the doc's tables, plus an anti-vacuity test in the `tests/test_e2e_entrypoints.py:178-193` idiom. Picked up free by `hub-self-check.yml`'s `shared-tests` job, which already installs PyYAML. It cannot break a tool repo, and today both files are checked by nothing at all. Live entries come from `yaml.safe_load` cross-checked against the raw text; commented entries can only come from the raw text, since PyYAML drops comments — state that asymmetry in the docstring.

2. **Per-repo** — `tools/ci/env_contract_check.py`, invoked from `para-drift.reusable.yml`, which every tool repo already calls and which already checks out `tool-repo` and `hub-repo` side by side. Same invocation shape as `workflow_lint.py`. **Stdlib-only in phase 1**: para-drift has no `setup-python` and installs nothing (bare `python3` at `:101`, `:115`), so a PyYAML import there would break all five at once. The compose-passthrough assertion needs YAML and lands as phase 2 alongside `setup-python` + `pip install pyyaml`.

**The retag window.** All five pin `para-drift.reusable.yml@v1`. Adding a step makes it live in all five *the instant `v1` moves*, so the per-repo work must be complete everywhere before the retag or four go red simultaneously. Mitigation with machinery that exists: land on `test`, point one caller at `hub-ref: test` (the documented pre-release channel), verify green, then retag.

**Prove red before trusting:** add an `os.getenv` to a scanned module; change one default; add a stale `INTERNAL` key; add an `env:` entry to the manifest. Four deliberate breakages, four failures.

## Verification / done-criteria

- [ ] Each of the five repos has a repo-root `.env.example` whose names are a **superset** of its api-image configuration surface, with defaults equal to the code's.
- [ ] `docs/k8s_deployment.md` documents every variable the reference manifest sets or comments out, and every variable the acceptance runbook needs.
- [ ] The guard exists, runs in CI, and **fails** when a new `os.getenv` is added to a scanned module, when a default is changed, and when an `INTERNAL` suppression goes stale. Verified by doing each and watching it go red.
- [ ] No published variable is false at the time of publication — in particular `LOG_LEVEL` is absent until #61 is green in all five.
- [ ] No credential-shaped key in any committed `.env.example` carries a real value; `.env` is gitignored in all five.
- [ ] `MAX_WORDS=123 docker compose --profile api config` shows the value reaching the container — the claim in every file's header, tested rather than asserted.
- [ ] A reader with only the manifest and `k8s_deployment.md` can set an upload limit, a CORS origin and a self-hosted UDPipe endpoint without opening a source tree. Test on someone who has not read the code.
