## The one new finding

`docker-tool.reusable.yml`'s post-`healthy` probe asserts (#61) that at the default `LOG_LEVEL`, at least one record reaches `docker logs` in the agreed format — proof the root logger is wired correctly, not a coincidence of something happening to print. It was written and verified against services whose lifespan warmup always succeeds in CI. llm-enrich's `api` target is the first probed service (added this same round, alongside the env-contract work) where that's false by design: `OPENROUTER_API_KEY` is `[required, secret]`, genuinely absent in CI, and the failure path logs only a `WARNING`. The check, as written, cannot tell "nothing is logging" apart from "the one thing that logged used a level I didn't allowlist." nlp-enrich fails the same check for a separately-diagnosed, likely-timing reason.

This isn't a defect in the five `.env.example` files, the doc, or the static guard — all four of those are doing exactly what they were built to do. It's a gap in a *different*, older mechanism (#55's container probe, #61's extension to it) that nothing in this issue's scope was checking. It surfaced only because `v1` retagging is what makes both `.env.example`-driven work (this issue) and the container probe (someone else's, years earlier) run against the same commit at the same time.

**Fix, committed at hub `daf230c` (also on `origin/test`) — the retag is the one step still open:**
1. Widen the log-format check from `INFO`-only to any of the five standard levelnames (`DEBUG|INFO|WARNING|ERROR|CRITICAL`) — the actual invariant is "a correctly-formatted record reached stdout," which a `WARNING` satisfies exactly as well as an `INFO`.
2. Poll for up to 15s instead of a single `docker logs` grep immediately after `healthy`, to absorb the nlp-enrich timing gap regardless of its precise cause.
