That asymmetry is the whole point of this edition. The issue's own history is a sequence of *claims about the deliverable that turned out to be slightly false*: nlp's four wrong defaults (caught 09-11), the "COMPLETE ledger" that missed 95 names, the "byte-identical §1" the translator's active `HOST` broke, the "`env.example.template` fixes their layout" pointing at a file that is not there. Closing the issue on the strength of three green acceptance bullets, while the most-clicked link in the deliverable 404s, would repeat the pattern one last time on the way out the door.

## Strategic actions

### A — Do the rename the thread already announced

One command, in the hub:

```
git mv docs/templates/.env.example.template docs/templates/env.example.template
```

**No reference edits accompany it.** All 22 occurrences across the six repos already spell the path undotted; the rename is what makes them resolve. This is precisely the change the 11:37 comment described — it simply was not run.

Two consequences to handle in the same commit:

- **The file misnames itself** at `docs/templates/.env.example.template:93`. After the `git mv` that line becomes correct with no edit. Verify rather than assume.
- **The two clickable links are the acceptance surface.** `docs/k8s_deployment.md:127` is a relative markdown link; `docs/templates/skill/serviceREADME.template.md:88` is an absolute `blob/main/` URL that seeds every future `service/README.md`. Open both on GitHub after the rename lands on the default branch. A relative link resolving locally is not evidence.

### B — Correct the public record before closing anything

The 11:37 comment on #60 states *"Renamed; all 14 references now resolve."* It is on a public thread, it will be believed, and if #60 closes under it the defect becomes unfindable. Post a correction that says three things: the rename was not performed; it has now been performed (link the commit); and the reference count is **22 occurrences on 20 lines across six repos**, not 14 — the earlier figure undercounted, so anyone auditing against it would have stopped eight short.

While posting, carry the two genuinely good pieces of news that thread does not yet have: the probe fix shipped and `v1` moved, so the "What's Broken (Red)" section of the 08:22 comment is spent; and `env_file:` passthrough is confirmed in all five compose files, which its "Next Steps" still lists as unverified.

### C — Re-point the parity evidence

Several records still cite `para-drift.reusable.yml:144-156` with a tag of "issue #60" as the mechanism guaranteeing the vendored guard's parity. That citation is dead: #59 replaced the per-file `diff -u` steps with the `MANIFEST.json` loop, the workflow is now **90 lines**, and `grep -c "issue"` over it returns **0**.

The guarantee itself is intact and is in fact stronger than what it replaced. Cite it where it now lives: the `test_env_contract.py` row in `docs/templates/shared/MANIFEST.json`, which is the only one of the sixteen rows carrying a non-empty `preconditions` list (`["tests/env_contract_data.py"]`) — the mechanism by which a hub-vendored test may import a file that must *not* be vendored with it.

Worth recording in the same pass, because it looks like a hole and is not: the hub has **no** `tests/env_contract_data.py`, so the hub's copy of the guard skips at import (`tests/test_env_contract.py:68`). Enforcement lives in the five tool repos; the hub copy exists for parity. The file's own comment puts it better than a plan can — *"an honest skip beats a vacuous pass."*

### D — Fix the measurement methodology, not just the number

The issue body's "178 places (alto 50 · nlp 47 · translator 30 · llm 29 · pc 11 · hub 11)" has been quoted forward through three editions and is now wrong in a way that repeating a new number would not fix. Re-measured: **205** occurrences of `os.getenv(` / `os.environ` over tracked `*.py` excluding `tests/`, **259** including them (hub 17/25 · alto 45/58 · nlp 54/61 · llm 34/41 · pc 15/23 · translator 40/51).

State the method with the number, every time, because two caveats invert its meaning. It counts **occurrences, not distinct variables** — the published contract is ~40 service-layer names. And it **undercounts the real surface**: alto's ~95 `ATRIUM_TEXT_UTILS_*` / `ATRIUM_CLASSIFY_*` names are composed as f-strings inside `_get_float`/`_get_int`/`_get_str`/`_get_csv_set` and appear at no literal call site, so no grep finds them — which is exactly why the guard grew a resolver and why they are declared as two wildcard `NOT_PUBLISHED` entries at `alto/tests/env_contract_data.py:35-36` rather than 95 individual ones.

### E — Then close, with the evidence attached

Close only after A and B are on `test`. The closing comment should state each acceptance bullet and the evidence for it, rather than asserting completion:

1. *Five `.env.example` files, names a superset of the code's reads, defaults equal to the code's* — the five files, plus `test_env_example_documents_every_variable_the_code_reads` and `test_env_example_defaults_match_the_code`.
2. *`docs/k8s_deployment.md` documents every variable the manifest sets or comments out* — `:122-211`, guarded bidirectionally by `tests/test_env_doc_contract.py`.
3. *A deployer can find every knob without opening a source tree* — the two sections, the three tables, and (after A) two links that resolve.

Alto's ~95 `ATRIUM_TEXT_UTILS_*` / `ATRIUM_CLASSIFY_*` constants are tuned through `setup/config.txt` and are declared `NOT_PUBLISHED` with a written reason — the correct answer, not an omission.
- **`LANGID_CONFIG`'s two incompatible default shapes** across nine alto sites, and **`MAX_WORKERS`** overriding two independent config keys. Alto-internal, batch-layer, its own issue.
- **`RELOAD` wiring** — roadmap B8.
- **`atrium-nlp-enrich/annotation/env.example`** — the second template named in the 09-10 comment. Different stack, different audience; the repo-root `.env.example` was written not to collide with it, and that is the extent of the interaction.
- **Re-auditing the contract's contents.** Twelve tests in five repos plus three hub-local ones do this on every push. Re-derive by hand only if the guards stop running.
- **`docs/templates/shared/test_atrium_service.py`'s registration gap** — closed by #59, which moved the file to `tests/test_atrium_service.py` as a hub-local test. No longer anyone's open item.
