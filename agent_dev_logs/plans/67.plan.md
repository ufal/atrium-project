## 1. What this plan closes

Issue #67 should not become a parallel implementation tracker for every repository. It is the pilot umbrella that defines the integration contract and the order in which the concrete sub-issues are consumed.

The architecture execution flow is mapped as follows:

```text
AMČR seed
   │
   ├── scanned-document path
   │      page-classification
   │          ↓
   │      ocr-postprocess
   │          ↓
   │      nlp-enrich
   │          ↓
   │      keyword-extract
   │          ↓
   │      translator
   │
   └── born-digital path
          digital-convert
              ↓
          nlp-enrich
              ↓
          keyword-extract
              ↓
          translator
```

## 2. Phased Integration Strategy

### Phase 1: Architecture & Repository Consolidation (Issue #72)

* [ ] Split OCR post-processing into its own `atrium-ocr-postprocess` identity.
* [ ] Extract statistical and controlled vocabularies into `atrium-keyword-extract`.
* [ ] Establish `atrium-digital-convert` as the explicit owner of born-digital processing.
* [ ] Centralize and pin single governed implementations for reader, LLM, and vocabulary layers.
* [ ] Scrub all legacy branding (`alto-postprocess`, `llm-enrich`) out of current `test` READMEs.

### Phase 2: Baseline Identity and Paradata (Issue #71)

* [ ] Fix the seeded E2E read-back defect (Issue #68) to ensure `doc_id` / `source.sha512` identity preservation across all six stages.
* [ ] Reach production parity for typed `CreateAction` (paradata) responses across all six service implementations.
* [ ] Validate `atrium_rocrate.py` strictly against RO-Crate 1.2 and Process Run Crate 0.5 rules (fragment mode composition).

### Phase 3: Content Enrichment & Output Quality (Issue #73)

* [ ] Finalize `keywords` block in `atrium-keyword-extract`.
* [ ] Confirm statistical outputs (KeyBERT/YAKE) remain fully distinct from controlled AMČR/TEATER vocabulary elements.
* [ ] Formulate a document-level quality summary deterministically derived from `ocr-postprocess` page/line quality signals (preventing the invention of a second quality model).

### Phase 4: Born-Digital Stage Integration (`atrium-digital-convert#2`)

* [ ] Complete the `/reformat` (`api-digital`) production surface.
* [ ] Confirm born-digital outputs comply perfectly with the shared `atrium_document` record contract.
* [ ] Ensure the born-digital converter hands off to the OCR pipeline *only* when the `needs_ocr` parameter evaluates to true.

### Phase 5: Umbrella Validation & Closure (Issue #67)

* [ ] Validate that the full six-stage E2E pipeline reaches a green CI state from seed injection to translation.
* [ ] Prove that the AMČR trust gate can reproducibly pin release tags and service metadata across all containers.
* [ ] Close #67 and mark the pilot baseline completed.
