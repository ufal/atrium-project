### B — R1 first: the seed read-back bug (all other R1 work builds on it)
The shared module keeps the **seed's** `doc_id` (`atrium_document.py:494-534`) and `finalize()` writes
`<seed id>.document.json` (`:1002`). Two tools then read back the file named after the **filename-derived** id:

| Where                                                                                                        | Effect when the ids differ                                         |
|--------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------|
| alto-postprocess `service/text_api.py:502` (`baseline_path`), read back at `:527-528`                        | `/process` returns the seed, without alto's blocks                 |
| alto-postprocess `run_pipeline.py:346-377`                                                                   | the CLI collects the seed copy                                     |
| llm-enrich `llm_client_shared.py:1248` (`baseline`), returned at `:1319`, loaded by `service/api.py:351-398` | the API returns the seed, without `enrichment`                     |
| llm-enrich `service/api.py:516` (`doc_id="inline_text"`)                                                     | a seeded record through `/extract_keywords_text` is never enriched |

- **Fix:** take the path `finalize()` returns (it returns it) instead of re-deriving it; in llm-enrich return that
  path from the helper. For `/extract_keywords_text`, key the call by the seed's `doc_id` when a record is sent.
- **Test, in each repository:** a seed whose `doc_id` is an AMČR file id unlike the upload's name; the response
  record carries the tool's block **and** the seed's `doc_id`.
- The page-classification, translator and nlp-enrich paths write to an explicit path and are correct
  (`pc/service/document_json.py:126-136`, `tr/main.py:176-209`, `nlp/api_util/document_hook.py:389`); the test is
  added there too, so it stays true.
- A new hub issue carries this fix (body drafted in chat); it is a bug, not a pilot feature, and goes first.

### C — R1: accept a seeded baseline and keep it
1. **`source.sha512`** — optional, pattern `^[a-f0-9]{128}$`, beside `sha256`. It constrains a value that
   `additionalProperties` let through unchecked, so under the freeze rule it lands with a `POST_FREEZE_CHANGES`
   register entry, a changelog section in `docs/document_schema.md` and its producer shapes — additive, still
   `doc-schema-v1`, no `SCHEMA_VERSION` bump.
2. **A seed is valid input.** Today a bare seed is reported as an invalid baseline, because the schema requires
   `provenance` and `assembled` (`schema.json:7`). Define *seed* in `document_schema.md` — `schema_version`,
   `doc_id`, `source` and nothing else — and let `DocumentRecord.open()` judge a seed against that profile, filling
   `provenance` and `assembled` on the first write. Records a tool *emits* stay under the full schema.
3. **Keep what the seed says.** `set_source()` is already first-writer-wins (`:565-613`). Pin the rule: `doc_id`,
   `sha512`, `filename` and `media_type` from the seed are never changed; a tool adds `sha256` and `origin`; a tool
   that holds the original bytes (digital-convert; alto for a born-digital upload) **checks** `sha512` against them
   and refuses a mismatch with the harmonised error.
4. **E2E from a seed.** Add `fixtures/e2e/SEED/<AMČR id>.document.json` and a seeded variant of
   `e2e-pipeline-smoke.yml` (stage 1 gets the seed); `e2e_assert.py:147-195` gains a check that `doc_id` and
   `source.sha512` are unchanged after every stage. Same for `e2e-digital-smoke.yml` with `digital-convert` as the
   first stage.
5. *Done when* (David's): **the E2E smoke runs from a seeded baseline.**

### D — R4: align `atrium_rocrate.py` with the AMČR record crate (carries #54 §B)
1. RO-Crate **1.2** context and `conformsTo` (`:80-82`, `:497`), Process Run Crate **0.5** (`:88`, the pin the file
   itself asks to verify).
2. `version`, not `softwareVersion`, on every `SoftwareApplication` (`:386`, `:465`, `:622`).
3. **Stable identifiers.** Tool: its release URL,
   `https://github.com/ufal/atrium-<tool>/releases/tag/v<version>`. Run: a `urn:uuid:` minted when the run starts,
   carried in paradata as a new `run_uuid` field beside the second-resolution `run_id` (`atrium_paradata.py:86`),
   which collides across parallel workers.
4. **Authors per tool.** The ATRIUM authors move from the root's `author` (`:311`, `:541`) to each tool's `creator`.
5. **Fragment mode.** `--fragment` (and a `fragment=True` argument) emits the entities without the root dataset and
   metadata descriptor, so AMČR can embed them in its own record crate.
6. **Validator in CI.** A hub job runs `rocrate-validator` twice on the module's self-test outputs — once with
   `ro-crate-1.2`, once with `process-run-crate-0.5`.
7. *Done when* (David's): **the output passes rocrate-validator with both profiles, run separately.**

### E — R2: one `CreateAction` per service call
1. A shared builder in `atrium_rocrate.py`, `create_action(paradata, object, result, status)`, from a finished
   `ParadataLogger` run:
   - `instrument`: the tool's `SoftwareApplication` (with `version`), plus `containerImage` naming the image the
     service runs as (`ATRIUM_RUNNER_IMAGE`; the `sha-<short>` tag is the stable one);
   - `object`: the input file(s) and the seed record; `result`: the output file(s) and the record;
   - `agent`: from an `ATRIUM_RUN_AGENT` setting (the operator — AMČR in production), documented with the limits (#53);
   - `startTime`/`endTime` from the run, not the single `at` timestamp used today (`:417-446`);
   - `actionStatus`: `CompletedActionStatus` or `FailedActionStatus`, with `error` on failure;
   - the paradata 2.0 fields (`atrium_paradata.py:204-228`) as properties of the action.
2. Every service returns it in its JSON response as `paradata`:
   - **page-classification** — create a `ParadataLogger` in the service (it has none);
   - **alto-postprocess** — stop writing into the working directory's `paradata/` (`text_api.py:459`); return it;
   - **translator** — in the JSON part of the multipart response; an XML-only response gets it only when the client
     asks for multipart (to decide in review);
   - **llm-enrich** — return it, and stop pointing `paradata_ref` at a temp path that no longer exists;
   - **nlp-enrich** — wrap what `service/api.py:214` already returns.
3. The contract test (`tests/test_api_contract.py` or equivalent per repository) asserts the action's required keys.
4. *Done when* (David's): **each service's response carries it.**

### F — R3: record-only mode
One switch per tool — `--record-only` on the CLI, `record_only=true` on the API — that runs the tool's
`document_hook` over outputs that already exist, runs no model, and says so in the `CreateAction` (a `mode`
property).

| Tool                | Existing output it merges                          | Block(s)                    |
|---------------------|----------------------------------------------------|-----------------------------|
| alto-postprocess    | ALTO, first the PSNC ALTO AMČR imports in bulk     | `pages`, `lines`, `content` |
| page-classification | a predictions table (`atrium_document_adapter.py`) | `page_categories`           |
| translator          | a translated `metadata-en` file                    | `translations`              |
| nlp-enrich          | NameTag/UDPipe output or a TEITOK file             | `entities`                  |
| llm-enrich          | an enrichment JSON                                 | `enrichment`, `forms`       |

alto-postprocess goes first, because the bulk PSNC import is the pilot's first use; its nearest mechanism today,
`--skip-*`/`--start-from` (`run_pipeline.py:42-48,165-180`), writes no record block. *Done when* (David's): **a
record is built from existing outputs alone.**

- `sha512` (§C), `keywords` and `quality` land in **one** additive round: one changelog date, one register update,
