# Strategy — Issue #55: Add `HEALTHCHECK` and `SIGTERM` handling to all five tool-repo services

> Issue [\#55](https://github.com/ufal/atrium-project/issues/55) · Labels: `enhancement`, `development` · Milestone: Q3 [WP8 / WP7: Advanced Transnational Access & Curriculum Drafting] · **Status: 🆕 Just opened, no discussion yet**

## Context
This is a small, mechanical, cross-repo change — the same two edits repeated five times — rather
than a design problem. The risk is not difficulty, it's that five near-identical Dockerfile/service
edits drift from each other if done independently. Doing it once, as a pattern, and applying it
uniformly is cheaper than five separate reviews later finding five slightly different
implementations.

## Strategic actions

### A — Land the pattern in one repo first, then replicate
Pick one tool repo (page-classification is the simplest — zero open issues, no in-flight work to
conflict with) and implement both pieces there as the reference:
1. `HEALTHCHECK` directive in the Dockerfile calling `GET /health` (not `?deep=true` — a deep check
   inside the healthcheck itself risks the probe timing out on a slow dependency check).
2. A `SIGTERM` handler — for FastAPI/uvicorn services this is normally `--timeout-graceful-shutdown`
   plus, if any service holds long-running work (model inference, batch jobs), an explicit signal
   handler that stops accepting new work and waits for in-flight requests.

### B — Replicate across the remaining four repos
Apply the same two edits to alto-postprocess, nlp-enrich, llm-enrich and translator. While touching
alto-postprocess's entrypoint anyway, fix `docs/docker_gha_roadmap.md`'s B8 in the same PR — same
file, same review, avoids a second round-trip through the same code.

### C — Verify locally before publishing
`docker run` each image, send `SIGTERM`, confirm no in-flight request is dropped and the process
exits cleanly within a reasonable grace period. Confirm `docker inspect --format='{{.State.Health.Status}}'` reports `healthy` after startup and `unhealthy` if `/health` is made to fail.

### D — Request the partner acceptance check
Once published, ask ARÚP/ARÚB (per this issue's stated acceptance criterion) to confirm the images
run cleanly, unattended, on their Kubernetes — a liveness probe firing correctly and a rolling
restart not dropping requests are the two things to ask them to specifically check.

## Verification / done-criteria
- All five Dockerfiles declare `HEALTHCHECK`.
- All five services exit cleanly on `SIGTERM` with no dropped in-flight requests (tested locally).
- alto-postprocess's production entrypoint no longer runs `--reload`.
- ARÚP/ARÚB confirm clean unattended operation on their Kubernetes.

## Out of scope
- The remaining ten factors of #53's full twelve-factor checklist.
- Any change to what `/health` itself checks — this issue wires existing endpoints into Docker/K8s
  primitives, it doesn't change health-check logic.
