## Actions

### A — The approval question (motyc)
Ask on the thread whether the keyword-extract and digital-convert copies are approved. The 10-15 comment does this, with the facts the 10-13 comment lacked. Depending on the answer:
1. **Approved:** record it here with the date and the scope (which repositories, which licence; keyword-extract's `data_samples/LICENSE` is CC BY-NC 4.0, and digital-convert's directory has none). Add a licence line to digital-convert's `data_samples/README.md`.

   - remove or replace the two digital-convert#5 attachments;
   - for digital-convert, keep the run outputs on the cluster and commit only the aggregate report (`tools/samples_report.py` output).

### B — Keep the register current
On every refresh, check by data class (real source, derived real text, keys-only, synthetic, vocabulary):
- each product repository's `data_samples/` (and page-classification's `small_data_samples/`);
- the hub's `fixtures/e2e/`;
- the predecessor repositories until they are archived (#72);
- the ARUP-CAS forks (they do not hold the 10-12/10-14 files yet);
- the cluster paths under `/lnet/work/projects/atrium/` that runs name;
- issue attachments;
- deliveries outside GitHub (FileSender);
- the LINDAT dataset and publications (#21, closed).

### C — Keep the responsibilities apart
- #16 says where copies are.
- #21 (closed) holds the public dataset and its licence.
- #6 covers tool and model licences.
- #72 covers the archiving of the predecessors.

## Done-criteria (for each refresh)
1. Every location with real ARUP/B content (source or derived text) is listed, with its data class and date.
2. Every public copy has a recorded approval, or a withdrawal action.
3. Locations that left are kept in the history list, with the date and the mechanism (deleted, archived, history-rewritten).

#16 itself closes only at the end of the project, when AMČR confirms the removals.

## Risks
- **Derived files are easy to miss.** Records and Markdown carry the full text, so a "results" commit can be a data copy.
- **Git history and attachments outlive a deletion.**
- **Forks mirror later.** A copy withdrawn here can survive in a fork that synced before the withdrawal.
