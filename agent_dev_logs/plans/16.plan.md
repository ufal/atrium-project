## Strategic actions

### A — Maintenance cadence
Re-run the inventory whenever a repo's `data_samples/` (or equivalent) directory composition
changes materially: a new real-data fixture added (as happened 07-16 with the hub's own
`fixtures/e2e/`), a repo resolved from real to synthetic (as alto/nlp already did), or a new repo
added to the ecosystem. No fixed schedule — event-triggered.

### B — page-classification is the one repo not yet resolved
Unlike alto and nlp, page-classification's real-data footprint (84 tracked assets, thesis/IJDL
page samples, presentation slides) has not been audited for synthetic-substitution feasibility.
Whether it *can* be resolved the same way alto/nlp were is an open question for whoever owns that
repo's dataset work — not attempted here, just flagged as the natural next candidate if ARUP/B
withdrawal ever becomes time-pressured.

### C — Keep #21 as the single source of truth for licensing terms
This issue answers "where" (storage locations); #21 answers "under what license, if public." Don't
let the two threads duplicate licensing detail — #16 should link to #21 rather than restate it.

## Verification / done-criteria
This issue has no done-criteria in the normal sense. The check is: **is the inventory table above
still accurate?** Re-verify it against live repo state whenever this plan is re-read, the same way
the digest itself should be re-verified rather than trusted as a snapshot beyond its own date.
