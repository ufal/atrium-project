## Context

This is not a task with a finish line. The question is continuously: **where does ARUP/B's data currently live?** The answer needs to remain usable by the data owner while the project changes repositories, fixtures and deployment paths.

The main risk exposed by the 2026-10 repository split is not a new dataset; it is **inventory drift**: the same files may move from an old repository to a successor while the predecessor remains public, the path name changes (`data_samples/` → `small_data_samples/`), or an E2E fixture is copied into the hub. The strategy therefore distinguishes source data from synthetic fixtures, derived outputs, vocabulary artefacts and historical pointers.

## Strategic actions

### A — Keep #16 as the single living location register

Do not try to close the issue when a batch of copies is removed. The acceptance condition is instead: **the inventory remains accurate enough for the data owner to locate the copies that currently matter**.

Use event-triggered refreshes rather than a fixed calendar:

- a repository is split, renamed, archived, deleted or replaced;
- a `data_samples/`, `small_data_samples/`, `fixtures/`, demo or test corpus changes materially;
- a real-data fixture is added to or removed from CI;
- the public dataset, presentation or paper changes its linked dataset copy;
- the AMČR pilot introduces a new import/storage location;
- the physical UFAL collection/output layout changes.

### B — Audit the current six product repositories by **data class**, not by repository name

For every current product repository, inspect the live branch/tree and classify stored artefacts as exactly one of:

1. **REAL SOURCE DATA** — the actual ARUP/B or other licensed source document/page;
2. **SYNTHETIC FIXTURE** — deliberately fictional test/sample data;
3. **DERIVED OUTPUT** — processing result derived from a real/synthetic source;
4. **CONTROLLED VOCABULARY / LICENCE ARTEFACT** — separately governed vocabulary/material, not treated as an ARUP/B source-document copy here;
5. **REFERENCE ONLY** — a manifest, identifier list, URL or other pointer whose corresponding source files are not present.

This prevents two recurrent errors: counting synthetic `CTX000000001–3` fixtures as copyrighted source data, and treating a historical document identifier in a manifest as evidence that the document is still stored in the repository.

### C — Keep the known real-data locations explicit

#### C.1 `atrium-translator`

Keep `data_samples/my_documents/` as a named real-data location. The current test tree contains 16 source files, and the sample README documents both AMČR metadata inputs and the anonymized ALTO sample. Translated outputs and paradata remain part of the copy footprint because they are committed derivatives produced from those inputs.

Do not collapse this to "the source files" only; for removal/audit purposes, the associated translated-output and paradata directories must be checked together.

#### C.2 `atrium-page-classification`

Treat `small_data_samples/` as the current in-repository footprint. The current `test` tree contains 229 PNGs; the older #16 count (~245) should be treated as superseded by this refresh.

Keep the external LINDAT dataset as a separate location. The current README points to handle `1-6184` and documents 48,499 pages from 37,328 archival documents under CC BY-NC 4.0. Any future replacement/withdrawal of the public dataset must be reflected in #21 and then echoed here as a location change.

The Master's thesis, related paper and presentation/Zenodo copies should also remain on the public-reference side of the inventory until their actual public content changes.

#### C.3 `atrium-project/fixtures/e2e/`

Keep the hub fixture store explicitly split into:

- synthetic: `CTX000000001–3`;
- real: `CTX192100040`, `CTX192601143`.

The real fixtures are currently used in the E2E smoke workflow. If CI stops needing them, the preferred cleanup path is to replace them with synthetic or otherwise AMČR-cleared fixtures and then update #16.

### D — Maintain the synthetic/no-source classification of the successor repos

#### D.1 `atrium-ocr-postprocess`

The committed `data_samples/README.md` is explicit: the corpus is fictional and does not contain real archival records or restricted ARUP/ARUB data. Preserve this status when the predecessor `alto-postprocess` is eventually archived.

#### D.2 `atrium-nlp-enrich`

The current committed ALTO and categorized sample directories contain only the three synthetic `CTX000000001–3` files. `manifest.tsv` still mentions real historical IDs, but the source files are absent from the committed sample tree. Treat the manifest as a **reference residue**, not a present storage location.

If a future commit restores any of the historical real documents, that change becomes an immediate #16 inventory event.

#### D.3 `atrium-keyword-extract`

The current document sample footprint is derived from the synthetic `CTX000000001–3` corpus. Its `data_samples/vocab/` is different: those files are the AMČR/TEATER controlled-vocabulary artefacts that now move with keyword extraction. Keep their licence/ownership record under #6/#72 rather than treating them as ARUP/B source samples in #16.

#### D.4 `atrium-digital-convert`

The current `data_samples/` tree contains taxonomy configuration and vocabulary artefacts, not committed source PDFs, page images or other ARUP/B source documents. The repository is still in the transition described by `atrium-digital-convert#1`; the presence of old LLM code is an architecture/release concern, not evidence of an additional source-data copy.

### E — Handle predecessor repositories as public legacy locations until the lifecycle is actually complete

Do not remove `atrium-alto-postprocess` and `atrium-llm-enrich` from the inventory merely because the hub README calls the new repositories their successors. As of this refresh, GitHub repository metadata still reports both predecessors as **not archived**, and #72 still carries the explicit archival/moved-notice action.

Before declaring a predecessor no longer relevant to #16:

1. confirm the repository is archived or carries a durable moved notice;
2. inspect the final default branch/tag that remains publicly reachable;
3. confirm no real source-data copy was left behind;
4. record the successor mapping in this issue;
5. only then downgrade it from an active public-copy location.

### F — Track AMČR-controlled mirrors and pilot storage separately from UFAL code repositories

The repository split recreated these public AMČR forks:

- `ARUP-CAS/atrium-ocr-postprocess`
- `ARUP-CAS/atrium-digital-convert`
- `ARUP-CAS/atrium-keyword-extract`

Their current sample footprints mirror the UFAL successors and do not reveal a separate real source corpus, but their existence matters for copy visibility and should stay in the topology record while #16 is open.

The #67 baseline additionally names:

- `ARUP-CAS/aiscr-docs-pipeline`;
- the PSNC ALTO bulk import.

These are AMČR-side locations. #16 should record them and their owner, but not try to replace the owners' own storage-management records.

### G — Keep public licensing and location records separate

#16 answers **where**. Keep these other responsibilities in their owning issues:

- #21 — public dataset/release copy and its governing licence terms;
- #6 — licences of models, tools and controlled vocabularies;
- #71 — `atrium_document` identity, seed and paradata contracts;
- #72 — repository/service architecture, release hygiene and successor/predecessor lifecycle;
- #73 — discovery/keyword output ownership.

Do not duplicate long licence tables in #16 unless a licence change directly changes the classification of a storage location.

## Verification procedure for every future refresh

1. **Fetch current refs.** Record the current branch/tag/commit for every current product repo plus the hub.
2. **List storage-shaped paths.** At minimum inspect `data_samples/`, `small_data_samples/`, `fixtures/`, `data/` and any documented demo/test corpus.
3. **Inspect provenance docs.** Read the relevant `README`, `data_samples/README`, manifests and licence files before classifying a location.
4. **Classify by data class.** Use REAL / SYNTHETIC / DERIVED / VOCABULARY / REFERENCE ONLY.
5. **Reconcile successor/predecessor copies.** Do not assume that a moved repository means the predecessor is gone; confirm GitHub archival state.
6. **Cross-check public locations.** Compare #16 against #21 and the current page-classification dataset reference.
7. **Update the table, not the issue's historical trail.** Preserve the previous event history and change only the current-state inventory/strategy sections.
8. **Leave the issue open.** The only closing event would be a project-end decision after the continuous-reference period, not completion of one inventory pass.

## Verification / done-criteria

This issue has **no normal done-criteria**. The recurring check is:

> **Can ARUP/B look at #16 and identify the current real-data storage locations, the public references, and the still-public predecessor/mirror repositories without confusing synthetic fixtures for source data?**

A refresh is complete when the answer remains yes against the live repository state and the latest AMČR baseline.

## Risks

| Risk                                                                     | Effect                                                                      | Mitigation                                                                                               |
|--------------------------------------------------------------------------|-----------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------|
| Repository moves happen faster than the inventory is updated             | old and new repositories can both appear to be authoritative                | Event-triggered refresh on every repository split/move; keep predecessor status explicit until archived. |
| Synthetic fixtures look like source documents                            | unnecessary withdrawal work or false claims about copyrighted-data exposure | Require provenance README/manifest inspection before classifying a fixture as real.                      |
| A manifest keeps old identifiers after files are removed                 | false claim that real data is still physically stored                       | Distinguish REFERENCE ONLY from REAL SOURCE DATA; inspect the actual tree.                               |
| Public dataset links move while issue text remains historical            | data owner follows an outdated location                                     | Cross-check #21 and the current repository README on every refresh.                                      |
| Old repositories remain publicly reachable after a successor is released | users can still cite/build from stale copies                                | Keep predecessors in #16 until GitHub archival or durable moved notices are verified.                    |
| AMČR/PSNC storage is outside UFAL GitHub                                 | the GitHub inventory can be mistaken for the whole inventory                | Keep the AMČR-side locations from #67 as explicit external entries with owner responsibility.            |
