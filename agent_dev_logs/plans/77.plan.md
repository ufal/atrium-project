## Execution plan

### A — Runbooks
1. **The hub outline (a).** `docs/templates/skill/serviceREADME.template.md` and strategy Appendix D gain five sections:
   - **Start:** the published image first (`docker run -p 8000:8000 ghcr.io/ufal/atrium-<tool>-api:<version>`), then compose, then a venv.
   - **Models and caches:** what is fetched, from where, at which revision, into which directory (`HF_HOME`), and what happens without egress.
   - **Errors:** the existing table, plus a "What to do" column.
   - **Partial results:** `partial`, `limits_applied`, and the tool's own statuses.
   - **Known limits:** see B.
2. **A check (a).** `tools/runbook_check.py --repo ../atrium-<tool>`, in the style of `skill_drift_check.py`, run over the six checkouts. It checks two things: the five headings exist, and every error row has a "What to do" cell. It belongs in the hub, so no shared module changes.
3. **The six READMEs (a),** each in its repo's next release:

   | Repo                | Release                 | Beyond the outline                                                                                                                                                                                                                                                                  |
   |---------------------|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | digital-convert     | `v1.2.0-beta` (round 2) | only the fix column; it is the model otherwise                                                                                                                                                                                                                                      |
   | nlp-enrich          | `v1.1.0-beta` (round 2) | a LINDAT outage → 502 `upstream_unavailable`, and what to do                                                                                                                                                                                                                        |
   | page-classification | `v1.9.4-beta` (round 2) | a README.md link to `service/README.md`; `run.py --hf -rev` and the HF cache                                                                                                                                                                                                        |
   | translator          | `v1.5.0-beta`           | **bake FastText into the image** at a pinned revision and sha256 (ocr-postprocess's Dockerfile:109-139 does it for the same file) and read it from a path setting. A runtime `hf_hub_download` with no revision is not pilot-safe: it fails without egress and can change under us. |
   | keyword-extract     | `v1.4.0-beta` (round 3) | the KeyBERT cache; the controlled kind's key (already in `k8s_acceptance_runbook.md`)                                                                                                                                                                                               |
   | ocr-postprocess     | next                    | first-run downloads of LayoutLMv3 and Qwen: a pre-fetch command, or an `HF_HOME` volume; `partial` as a batch status                                                                                                                                                                |

   The three round-2 releases carry their part only if A.1 lands first; otherwise their next release does.
