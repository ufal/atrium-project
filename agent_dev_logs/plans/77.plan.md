## Execution plan

### A — Runbooks
1. **The hub outline (a).** `docs/templates/skill/serviceREADME.template.md` and strategy Appendix D gain five sections:
   - **Start:** the published image first (`docker run -p 8000:8000 ghcr.io/ufal/atrium-<tool>-api:<version>`), then compose, then a venv.
   - **Models and caches:** what is fetched, from where, at which revision, into which directory (`HF_HOME`), and what happens without egress.
   - **Errors:** the existing table, plus a "What to do" column.
   - **Partial results:** `partial`, `limits_applied`, and the tool's own statuses.
   - **Known limits:** see B.
2. **A check (a).** `tools/runbook_check.py --repo ../atrium-<tool>`, in the style of `skill_drift_check.py`, run over the six checkouts. It checks two things: the five headings exist, and every error row has a "What to do" cell. It belongs in the hub, so no shared module changes.
