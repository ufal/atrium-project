## Strategic actions

### A — Close the hub half of B7. This is the whole of what blocks the issue

Two files, both hub, both docs-class. No reusable workflow is touched, so **no retag**.

1. **`docs/templates/skill/server.template.sh:70`** — make the template resolve the compose extension at runtime instead of hardcoding the pair. It currently reads:

   ```
       gpu)   start_docker -f docker-compose.yml -f docker-compose.gpu.yml ;;
   ```

   Every other placeholder in this file is an angle-bracket token the generating repo fills in (`<venv-dir>`, `service.<module>`), so a token would be consistent with the file's own style — but a runtime probe is better here, because the template is copied into five repos that genuinely differ and a token is one more hand-maintained fact of exactly the kind §E just spent two tests eliminating. Pick the base and overlay by testing for each file, and fail with a readable message if neither exists.

2. **`docs/docker_gha_roadmap.md`** — three edits, in descending order of harm:
   - `:285` — *"normalise every compose file to `.yml` (B7), which also repairs `server.template.sh`"*. Replace the prescription with §D's decision: the split stays, the template stops assuming, and record why. This line is the reason a future reader will "fix" B7 by renaming five repos' compose files.
   - `:84` — the B7 row describes the nlp-enrich header as live (fixed since `b1a62e8`) and cites `server.template.sh:63` for a line now at `:70`. Re-scope the row to the hub half only.
   - `:117` — the D1 row still reads *"Translator is the ecosystem's only **Python 3.12** job (everything else, hub included, is 3.11)"*. Not since `fbb90e9`. The rest of the row — three semantics across five files, nlp/llm byte-identical, llm carrying nlp's header — still verifies and should stay.

   `grep -n "#64" docs/docker_gha_roadmap.md` currently returns nothing; after this action it should return at least `:285`.

### C — Fix `annotation/README.md`, the same bug in the file this thread used as evidence

`atrium-nlp-enrich/annotation/README.md:14` lists `` `.env.example` `` in its file table and `:28` prints `cp .env.example .env`. The file on disk is `annotation/env.example`, undotted — so the copy-paste line fails verbatim, which is precisely the failure mode B7 was filed for.

Both issue comments spell the undotted name correctly while the README beside the file does not. Two one-word edits. Do **not** rename the file to match the README: `annotation/env.example` is referenced from the 09-10 comment and from `docker-compose.yml` conventions in that directory, and #60 is separately carrying a dotted-template defect — adding a second dotted filename to the ecosystem is the wrong direction.

### D — Leave the extension split alone (unchanged, and vindicated)

Recommend explicitly **not** converging the ecosystem on one extension. Nothing has changed since 09-10 to weaken the argument, and one thing has strengthened it: the only surviving B7 breakage is a hub template that assumed a single extension. The fix is to stop assuming, not to make the assumption true across five repos heading into a pre-closure architecture review.

The single outstanding contradiction of this section is `docs/docker_gha_roadmap.md:285`, and §A resolves it in §D's favour.

### E — The version now sticks; finish the prose that still disagrees (unchanged, and done)

§E was marked optional in the 09-10 edition. It was implemented twice:

- `atrium-translator/tests/test_python_version_parity.py` — Dockerfile is the anchor; every `python-version:` in the repo's workflows and `ruff.toml`'s `target-version` are checked against it.
- `atrium-project/tests/test_hub_python_version_parity.py` — anchors on `docker-tool.reusable.yml:116` (the lane that builds and probes the published images, the closest thing the imageless hub has to production), checks every hub workflow *and* every `workflow_call` input `default:`, and asserts at `:107-120` that no such input is left defaultless. That covers the hole the 09-10 plan could not have named: caller lanes backed by a reusable carry no `with:` block, so a hub-side `default: "3.12"` would be invisible to all five tool repos' own parity tests.

What is left is prose the guards do not read:

- `atrium-page-classification/README.md:288` — *"Make sure you have **Python version 3.10+** installed"*.
- **`docs/templates/ruff.toml`** — all five tool repos now carry `target-version = "py311"` (alto `:15`, nlp `:3`, llm `:10`, pc `:9`, translator `:14`) but the template they derive from has none, and both parity tests read their own repo's root `ruff.toml`, never the template. The one file that would propagate the pin to the next repo is the one place it is missing. Add it.
