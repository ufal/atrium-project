## Context

The technical content existed and was mostly tested; what was missing was the order a reader meets it in. On 10-20:
- four READMEs were over 1,100 lines;
- most headings carried emoji;
- 26 in-page links were broken (GitHub keeps U+FE0F in heading ids);
- measurements, dated decisions and full service tables sat in the user path.

The work is editorial: move, shorten and link, keeping every fact.

Reused:
- the ownership rule in `docs_site/contributing-standards.md`;
- #77's service README outline as the operations layer;
- each repository's `service/openapi.json` as the one API contract;
- each CONTRIBUTING.md "Release History" as the changelog;
- `tools/runbook_check.py` as the model for `docs_check.py`.

## Execution plan

### A — The shared guide (done)
1. `docs/documentation-style.md`: the six reader layers, one-line editorial rules, suggested file names, and the PR checklist (behaviour and limits stated, a working example, each page in its layer, links and anchors checked, one source per contract, a relocation map when content moves).
2. `docs/templates/README.template.md`: seven sections (what and when; inputs and outputs; quick start with expected result; role in ATRIUM; limits and maturity; documentation map; licence, citation, acknowledgements).
3. The templates brought in line: `serviceREADME.template.md` and `templates/CONTRIBUTING.md`.
4. The guide linked from `docs_site/contributing-standards.md`; the hub README reworked to put the reader first.

### B — The ocr-postprocess pilot (done)
An inventory first, then the README cut to the skeleton. Step 4 became the five categories, the stages and the limits next to the instructions. `docs/categorization_logic.md` was rewritten as an explanation: the rules and generated examples went to `docs/reference/`, the decision record to `docs/decisions/`, and the measurements to `docs/evaluation/`, which says plainly that the walkthrough tests pin behaviour, not accuracy. Anchors were repaired and incoming links repointed.

### C — The five other tools (done)
Each repository: the skeleton; setup before reference; plain headings; links to the service README and `service/openapi.json` instead of copies; history and measurements moved to `evaluation/` or `decisions/`; the guide and `ci_policy.md` linked from CONTRIBUTING; a relocation map.

### D — Newcomer review (open)
For each repository, one person who does not work on it:
- follows the quick start from a clean checkout at the release tag;
- finds the API, configuration and limits pages;
- notes on #79 what was unclear, missing or hard to find.

The fixes land before the 11 November release choice. Tool changes ride the next code releases (no docs-only releases), and hub pages change directly.

### E — Keeping it readable (open: blocking switch)
`tools/docs_check.py` (stdlib):
- fails on emoji in headings;
- fails on broken relative links and anchors, U+FE0F included;
- fails when a README has no documentation map or no link to the guide;
- warns when a README runs over 250 lines.

Tested by `tests/test_docs_check.py`; advisory in Workflow Policy Lint. After D: remove `continue-on-error` and adopt it at the next pin bump.
