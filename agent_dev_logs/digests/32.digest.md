### What the design review found (2026-09-28)
A review of the design against the FastAPI and pydantic internals, and against oasdiff v1.32.1 fetched from the Go
module proxy.
- **oasdiff handles OpenAPI 3.1.** It is built on kin-openapi v0.149.0, which models `const`, `examples`,
  `prefixItems`, `if`/`then`, `$defs`, `$comment` and type arrays. **Three default severities would let a real break
  through `--fail-on ERR`:**
  - `response-optional-property-removed` is INFO;
  - `api-operation-id-removed` is INFO;
  - `response-non-success-status-removed` is INFO.
- **pydantic's `anyOf: [X, null]` is not recognised as nullable**; oasdiff only knows the two-branch `oneOf` form.
- **Mitigations:**
  - response fields a handler always emits get no default, so they are required and their removal is ERR;
  - a runtime `--severity-levels` file raises the three rules;
  - `anyOf`-null is normalised to `oneOf` before the diff;
  - the frozen record schema is compared by its sha, not diffed.
- **FastAPI:**
  - An explicit `response_model=None` is needed on routes annotated `-> Dict[str, Any]` (alto `:428`, nlp `:444`,
    llm `:600`). Otherwise an inferred free-form schema merges with the declared `$ref`.
  - An app-level `responses={422: …}` reaches every route, including those `attach_health` adds later, and suppresses
    `HTTPValidationError`.
  - A shared `responses` dict would be mutated across routes, so the helper returns fresh dicts.
  - `root_path_in_servers=False` keeps the spec's digest stable behind an ingress.
- **The record is typed as one `AtriumDocument` component** (a `RootModel` whose body is swapped for the vendored
  schema). A raw `$ref` inside `WithJsonSchema` fails in pydantic for required fields.
  - Only **responses** use it. A multipart record part stays `format: binary` with `contentType: application/json`.
  - A #67 R1 seed (`doc_id` + `source`) fails the full schema, so no request body is typed with it.
- **Versions must be pinned**, because the committed spec is a function of the code, fastapi and pydantic. The pins are
  `fastapi==0.141.1` and `pydantic==2.13.5`: today's latest, the repos' floors, and `requirements_llm.txt`'s existing
  pydantic pin, which the GPU lanes resolve in one pip call.
- **The release must check freshness itself.** `release.yml` runs as a separate workflow and cannot see the Docker
  smoke, so it checks that the committed spec is current before it publishes the asset. The baseline is the release
  with the **highest version below** the tag. An API error fails the gate: only "found none" is a bootstrap pass.
- **`invalid_record` stays narrow**: a record that does not parse, is not an object, or has an unsupported
  `schema_version` major. A baseline that fails the schema is still accepted, with `document_json_schema_error`.
- **alto `dependency_missing` is not a media type.** It becomes 501. alto's reader codes travel in an unregistered
  `cause` member instead of growing the registry.
