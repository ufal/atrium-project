## 🧠 Strategy (settled, unchanged)
Separate the **common ground** (reusable workflows, `on: workflow_call` — single source of truth in `atrium-project`) from the **per-repo differences** (thin caller workflows). Reuse rather than reinvent: `atrium_paradata.py` already reads `ATRIUM_RUNNER_IMAGE`/`REPO`/`REF`, so **GHCR-published, self-identifying containers** are the mechanism. motyc: orchestration to be discussed with rharasim; **no overall runtime wrapper needed** — containers are reachable via API. This scopes the issue to **packaging + CI**, not a runtime orchestrator.

## ✅ Caller-example templates corrected (2026-07-31)

`codeql.caller.example.yml` had been a byte-identical copy of the Docker example — fixed upstream in `79e2b70`. A follow-up sweep of all ten templates then found a **worse** defect in `docker.caller.example.yml`: its `build` job declared an *explicit* permissions block of only `{contents: read, packages: write}`, while `docker-tool.reusable.yml`'s `build-and-push` requests `security-events: write` for the SARIF upload. Copying that template reproduced the **Wave B `startup_failure`** verbatim. No live caller used it, so nothing was broken in practice — but it is the file that teaches the pattern. Fixed, along with the leftover `secrets: inherit` and a missing tag-exempt `concurrency` block.

The distinction worth keeping: an **explicit** permissions block that omits a scope fails at parse time; **no** block at all inherits the repo default and is fine. `skill-validate.caller.example.yml` has no block and is correct — it flags on a naive check and is a false positive.

## ✅ Reusable pins moved to `@v1` (2026-07-30)

26 references migrated: **20 live callers** (4 files × 5 repos) and **6 documentation examples**. Plus a 27th that a find-and-replace would have got wrong — `para-drift.reusable.yml` hardcoded `ref: test` for the hub checkout supplying the canonical `docs/templates/shared/*` files. Left alone, the pin would have been half-done: workflow *logic* from the immutable tag, the *files it enforces* still from a mutable branch. It now takes a **`hub-ref` input** (default `v1`), so `@test` callers pass `hub-ref: test` and stay self-consistent.

Two channels now: **`@v1`** is what every repo pins — a moving major tag only a maintainer advances; **`@test`** is for validating a hub change before moving `v1`. Documented in `docs/docker_gha.md` §1.

## 🧩 Things worth remembering
- **`codeql.reusable.yml` / `pre-commit.reusable.yml` are deliberately deferred** behind the `@v1` pin. They would collapse ~325 duplicated lines but raise mutable-branch coupling from 20 refs to 30. The Wave B regression — one hub-side permission change that took down `docker.yml` in all five repos simultaneously — is the standing argument for that ordering.
- **The `@test` pin enforces across every branch.** `para-drift.reusable.yml` checks the hub out at `ref: test` and its callers fire on default-branch pushes, so the newest templates are enforced against branches that may not have the matching vendored files. This nearly bit when `check_version.py` parity landed while no default branch had the file; the merge delivered both together. Keep it in mind when adding a parity step.
- **llm-enrich's `docker.yml` carries a long `build-targets` comment for a reason.** The line was briefly lost in an edit, silently falling back to the reusable's `["base"]` default — which would have published an unrunnable image (the `base` stage has no ENTRYPOINT) and never published `-remote`/`-llm`. Restored.
- **Check the doc templates whenever a reusable's permissions change.** The templates are not covered by CI — nothing parses or runs them — so a hub-side permission change silently invalidates every example that grants an explicit block. That is precisely how `docker.caller.example.yml` kept a Wave-B-shaped `startup_failure` for a week after the live callers were fixed. Grep is the wrong tool here: `secrets: inherit` appears in the explanatory comments, so the check has to parse YAML.
- **`release: types: [published]` is in 4 of 5 live `docker.yml` callers,** alongside `push: tags`. translator is the lone exception. Worth a deliberate decision at some point (the pair can double-fire), but do not "normalise" it away by looking at one repo.
