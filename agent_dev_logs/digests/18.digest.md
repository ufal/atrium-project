## 🎯 Goal
Provide a Docker-compose + GitHub-Action wrapper for the four ARUP-CAS CU repo forks. Opened by motyc.

## 🧠 Strategy (settled, unchanged)
Separate the **common ground** (reusable workflows, `on: workflow_call` — single source of truth in `atrium-project`) from the **per-repo differences** (thin caller workflows). Reuse rather than reinvent: `atrium_paradata.py` already reads `ATRIUM_RUNNER_IMAGE`/`REPO`/`REF`, so **GHCR-published, self-identifying containers** are the mechanism. motyc: orchestration to be discussed with rharasim; **no overall runtime wrapper needed** — containers are reachable via API. This scopes the issue to **packaging + CI**, not a runtime orchestrator.

## 🐞 Open findings — 2026-07-29 ecosystem audit

Full detail and sequencing in [`../plans/18.plan.md`](../plans/18.plan.md). Headline: **green does not mean covered.**

**P0**
1. **Mutable cross-repo pin + blanket secret inheritance.** All 20 caller refs point at `…@test`; `atrium-project` has only `main`/`test`, **neither protected**, and 4/5 callers pass `secrets: inherit`. One push reaches all five repos with every secret.
2. **`page-classification` release bundle is unrunnable.** `release.yml` ships `run.py` but **not the 6 first-party modules it imports** (`atrium_paradata`, `atrium_document_adapter`, `utils`, `model_registry`, `parallel_best`, `yolo_classifier`) — reproduced locally, `ImportError` on first launch. Same defect class fixed in translator in June, never revisited here.

**P1**
3. **The E2E `llm` stage has never executed.** It gates on `OPENROUTER_API_KEY`; the secret that exists is `OPENROUTER_KEY`, and it was added to llm-enrich/page-classification — **not to atrium-project**, where the E2E runs. Skips cleanly, reports green.
4. **Two no-op stub workflows** (`llm-enrich-execution.caller.yml`, `hf-model-sync.caller.yml`) call nothing, contain `# Insert … command here` placeholders and unresolved `[cite: 1, 2]` artifacts, and pass on every push.
5. **`atrium-project` has no `dependabot.yml`** — the repo hosting the shared pins is the only one whose pins never update. Hence live drift: `checkout@v7` in one reusable, `@v5` in another.
6. **Trivy/SBOM race the image they scan** — they run on tag push against `:latest`, published by a *separate* workflow with no ordering guarantee; `exit-code: "0"` means they never block.

**P2 — coverage gaps:** PR triggers narrower than push triggers in all 5 repos · page-classification's active `vit`/`clip` branches skip api-contract + para-drift · `llm-enrich/api-contract.yml` targets a nonexistent `master` · smoke failures notify nobody in llm-enrich/nlp-enrich · **no GPU runner exists, so every `slow`-marked test in the ecosystem has never run** · lint blocking in 3 repos, advisory in 2.

**P3 — hygiene:** `timeout-minutes` on **0 of 53** workflows · `concurrency` on 2 of 53 · ~360 lines of copy-pasted version-guard Python · floating/tag-only third-party pins · duplicate `requirements-test.txt` in page-classification · translator publishes on `v*.*.*` while everyone else uses `v*`.
