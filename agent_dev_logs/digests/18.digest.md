## 🎯 Goal
Provide a Docker-compose + GitHub-Action wrapper for the four ARUP-CAS CU repo forks.

## 🧠 Strategy (settled, unchanged)
Separate the **common ground** (reusable workflows, `on: workflow_call`) from the **per-repo differences** (thin caller workflows). Reuse rather than reinvent: `atrium_paradata.py` reads `ATRIUM_RUNNER_IMAGE`/`REPO`/`REF`, so **GHCR-published, self-identifying containers** are the mechanism. No overall runtime wrapper is needed — containers are reachable via API (motyc, 2026-06-12).

## 🔍 2026-08-04 audit — the four things that matter most

1. **The guardrails cannot see what they enforce.** `workflow_lint.py` has **no rule** for `timeout-minutes`, `concurrency`, workflow-level `permissions` or the action-version floor, and **no tests of its own** (~250 lines of policy logic; `check_version.py`, at 140 lines, has 16 tests). Worse, `hub-self-check.yml` documents itself as validating "the ref being pushed" but `workflow-lint.reusable.yml` checks the hub out at `hub-ref` (default `v1`) and runs the linter **from there** — so a linter change is never the code that runs on its own PR. `all-repos-smoke.yml`, added 2026-08-01, shipped with no timeout, no concurrency, no `permissions`, omitting `llm-enrich`, and running the model/network lane on a GPU-less runner. CI stayed green.
2. **Two published API images cannot start.** `uvicorn` appears in **no** requirements file in `page-classification` or `nlp-enrich`, yet both declare `uvicorn service.api:app` entrypoints. Nothing catches it — the contract test import-skips, and building a stage never invokes its ENTRYPOINT. Separately, **six compose `image:` refs are unpullable**: CI publishes a repo-name suffix (`…atrium-nlp-enrich-api:<ver>`), compose asks for a tag suffix (`…atrium-nlp-enrich:<ver>-api`).
3. **The E2E's own skip path can only fail.** With `OPENROUTER_KEY` unset — every PR, fork and push run — the workflow falls back to `4_nlp.json`, but `e2e_assert.py:49` asserts `enrichment` unconditionally, a block owned exclusively by llm-enrich. The gate and the assertion contradict each other.
4. **CI can only ever test the last release.** Images publish only on `refs/tags/v*`, so both smoke workflows exercise the last tagged image, never HEAD — the caveat that forced "run new source inside an old image" workarounds during the 2026-08-01 E2E rewrite.

## 🐞 Open — carried forward

_2026-09-26: every item below moves — 1 and the pinning note to #40, 2 deferred, 3–5 to the new CI-roadmap issue (table above)._

1. **Branch protection**: **zero of ~20 branches are protected in any of the six repos**, and `test` sits at the *exact same SHA* as the default branch everywhere — so every push runs the whole suite twice while protecting nothing (#40).
2. **No GPU runner** (#40). W4 removes the single-supplier dependency: a `runner-labels` input plus a `slow`/`gpu` marker split lets the network-integration tests run on `ubuntu-latest` today. Note **`alto` owns the ecosystem's only real GPU test and has no GPU workflow**, while `nlp` and `llm` have GPU workflows that collect zero tests.
3. **8 of 12 active weekly jobs land in Monday 05:00–06:00 UTC** — the deliberate CodeQL stagger was never extended to `security.yml`.
4. **Supply chain**: no lockfiles or hash pinning across 30 requirements files (8 installed by nothing); two floating `git+` VCS refs; an unpinned ~1.2 GB build-time weight fetch baked into the alto image; test and research dependencies in production images.
5. **`update_issues.sh`** exports an elided placeholder token that kills its own `-z` guard and overrides the caller's environment. Not a usable credential — but confirm GitHub-native secret scanning is enabled on all six repos.
