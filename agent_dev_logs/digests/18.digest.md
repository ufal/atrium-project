## ✅ Supply-chain pinning and the Trivy release gate

**SHA pins.** Every third-party action resolved through a mutable tag. `security.reusable.yml` already documented that `aquasecurity/trivy-action` tags ≤ 0.34.2 were force-pushed to credential-stealing malware on 2026-03-19 (GHSA-69fq-xp46-6x23, **76 of 77 tags**) and recommended pinning to the release commit — advice that had sat unacted-on. Now applied to the actions holding write scope: `docker/build-push-action` ×3, `aquasecurity/trivy-action` ×2, `peter-evans/create-pull-request` ×1 (all live on `main`), plus `softprops/action-gh-release` ×5 — **those five are still only on `test`.**

**Trivy `exit-code` policy — settled.** Rather than flip the existing step, a **separate gate** was added to `docker-tool.reusable.yml`: the SARIF step is unchanged (runs every build, never blocks, so the full CRITICAL+HIGH picture always reaches code scanning), and a new step blocks — placed **after** the SARIF upload so a blocked release still records its findings. Three narrowings: `if: startsWith(github.ref, 'refs/tags/')` (stops a *release*, not day-to-day pushes), `severity: CRITICAL` (HIGH stays report-only), `ignore-unfixed: true` (an unpatchable CVE cannot wedge releases). The weekly scan stays report-only. **Unfired — it needs a tag push.**

## 🧩 Things worth remembering

- **Green does not mean covered.** The organizing lesson. Stage 5 was dark for weeks while the run reported green; `test_para_licenses.py` has 36 passing tests that nothing invokes; a caller example was a copy of another file and still parsed, pinned and permissioned correctly.
- **Copy-paste clobbers are this repo's characteristic failure, and they pass every ordinary check.** Twice a file was overwritten with another's contents. Both results were *well-formed YAML*, correctly pinned, correctly permissioned. Parsing, pin, permission and secret checks all pass happily on a perfectly valid file that is simply **the wrong file**. The detectors are duplicate `name:` within a directory, and a template passing an input its callee does not declare.
- **Redundant checks hide broken ones.** `check_version.py` compares the tag against *both* `CITATION.cff` and `para_config.txt`; when those agree, either alone blocks a bad tag, so deleting one is unobservable. That mutation survived the first draft of the test suite. Isolating it needed fixtures where the two files deliberately **disagree**.
- **A pytest collection error is not a test failure and does not look like one.** A broken import reported one *error* and zero tests, which scans as "fine" far more easily than "16 failed". Watch the test count, not the pass/fail line.
- **`git fetch --tags` does not move a tag that already exists locally** — it needs `--force`. A stale local `v1` had this work reasoning about the wrong reusable for a whole session. Resolve against the remote when it matters.
- **Annotated tags need `^{}` to pin.** `git ls-remote refs/tags/v3` returns the tag *object*; the commit is `refs/tags/v3^{}`. Two of the four pinned actions are annotated.
- **The `@test` pin enforces across every branch.** `para-drift.reusable.yml` checks the hub out at a ref and its callers fire on default-branch pushes, so the newest templates are enforced against branches that may lack the matching vendored files. Adding a parity step for a file the tool repos do not yet have breaks `para-drift` in all five.
- **llm-enrich's `docker.yml` carries a long `build-targets` comment for a reason.** The line was briefly lost in an edit, silently falling back to the reusable's `["base"]` default — which would have published an unrunnable image (the `base` stage has no ENTRYPOINT).
