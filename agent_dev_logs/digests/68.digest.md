## 🎯 Goal
When a tool is handed a **seed** record whose `doc_id` differs from the upload's filename, the response must carry **both** the tool's own block **and** the seed's `doc_id`. AMČR seeds carry the AMČR file id as `doc_id`, so every pilot call hits this case.

## 🧵 Decision trail
- **2026-09-26, K4TEL (#67 R1 planning)**: found by reading the code, not yet reproduced.
  - The shared module keeps the seed's `doc_id` (`atrium_document.py` `_inherit_doc_id`, `:494-534`).
  - `finalize()` without `out_path` writes `<seed doc_id>.document.json` (`:1002`).
  - alto-postprocess and llm-enrich read back the file named after the id **they** derived from the upload's name.
  - Posted as a comment on #67.

  - **Done-when:** a seeded test in all five repositories that fails before the fix in alto-postprocess and llm-enrich and passes after it.

## 🔎 What reproducing it showed
- **The four rows of the issue's table hold.**
  - alto `/process` returned the seed without `lines`, and without alto's fields on `pages`.
  - llm-enrich `/extract_keywords` and `--document-json-out` returned the seed without `enrichment`.
  - `/extract_keywords_text` could never enrich a sent record, because it keyed every call `inline_text`.
- **alto's CLI was worse than the table says.**
  - `run_pipeline.py --document-json` runs five stages. Each stage re-read the **untouched** seed at `<derived>.document.json` and wrote `<seed>.document.json`, so each stage overwrote the one before.
  - Only the last stage's block survived. `_collect_document_json_output` then copied the seed.
  - Reproduced with two `write_document_block()` calls: stage 1's `lines` was lost.
- **"Read back the path `finalize()` returns" alone cannot fix the CLI.** The stages are separate processes and look the record up by name.
  - The fix therefore **writes back in place**: each tool finalizes to the file it read, returns that path, and its callers read that path.
  - nlp-enrich already works this way (`api_util/summarize_nt_udp.py`: `out_json = baseline_json`).
  - Both helpers' docstrings already promised "write it back in place".
  - The record inside keeps the seed's `doc_id`.
