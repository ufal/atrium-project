### The paradata wrinkle, and why "defaults unchanged" is literally true

`service/api.py:401-405`:

```python
if backend_name == "lindat":
    effective_url = getattr(models["translator"], "base_url", None)
    if not isinstance(effective_url, str) or not effective_url.strip():
        effective_url = resolve_translation_url()
    para_config["translation_api"] = effective_url.rstrip("/") + "/"
```

Three properties, in order of how easy they are to miss:

1. It reads the **effective** URL off the live backend instance — the same object that issues the requests — so the provenance record and the request cannot diverge. The comment at `:395-400` says exactly this.
2. It falls back to `resolve_translation_url()` only for a backend that exposes no `base_url` (a test double), and that fallback returns what the real backend *would* have resolved.
3. `.rstrip("/") + "/"` restores the trailing slash the field has carried since it was introduced. The resolver normalises the slash away; this line puts it back. **So an unconfigured run's paradata record is byte-identical to the pre-#63 literal** — which is what makes the issue's third acceptance bullet ("defaults unchanged") true at the byte level and not merely at the host level. Two tests assert it directly: `TestServiceParadata::test_default_record_is_byte_identical_to_the_pre_issue_literal` (`:256`) and its CLI twin (`:186`).

`main.py:87-90` applies the same guard to the CLI path — `if backend_name == "lindat":`, a function-local import of `resolve_translation_url`, and the same `.rstrip("/") + "/"`. The comment at `:80-86` gives both reasons: the provenance one (a record that is confidently wrong is worse than one that is absent) and the mechanical one (a module-level import would pull `requests`/`tqdm` into every run regardless of backend).

### The four surfaces beyond the issue's scope

**1 — `config_api.txt:30-31`, the `source` clobber.** Both endpoint lines now read:

```
UDPIPE_URL="${UDPIPE_URL:-https://lindat.mff.cuni.cz/services/udpipe/api/process}"
NAMETAG_URL="${NAMETAG_URL:-https://lindat.mff.cuni.cz/services/nametag/api/recognize}"
```

The header at `:20-29` explains why the form is load-bearing rather than stylistic: every stage script opens with `source "${ATRIUM_CONFIG:-config_api.txt}"` (`api_2_udp.sh:5`, `api_3_nt.sh:5`), and **bash keeps the export attribute of a variable that was already exported**, so a bare assignment here would overwrite a deployment-set value *and re-export it*. This is the finding that resizes the issue: without it, the issue's own acceptance criterion passes — it invokes `call_udpipe.py` directly, bypassing the shell — while the deployed pipeline stays unattachable. Both stages now also pass the flag explicitly (`api_2_udp.sh:39`, `api_3_nt.sh:42`) and record the resolved host in paradata (`:14` in each).
