## 🔎 What each record can truthfully say (newest release)

### `RER7Fw` — `atrium-page-classification` `v1.9.2-beta`

* 11 categories formed from archival documents of 1920–2020; the page image alone decides.
* Fine-tuned ViT, RegNetY and EfficientNetV2 models, singly or as an averaged ensemble, on the Hugging Face Hub (`ufal/vit-historical-page`); since `v1.8.0-beta` the default generation is `vX.4`, trained on a CC BY-NC 4.0 subset of 38,307 pages, so the 09-25 figure "48,499 pages" no longer describes the default models.
* API image `ghcr.io/ufal/atrium-page-classification-api`: `/predict_image` (JPEG/PNG), `/predict_document` (PDF). `service/README.md` §Shutdown still writes the image as `…:<version>-api`, which is never published (the hub's `docker-tool.reusable.yml` names it `…-api:<version>`).
* Licence rows: models and code MIT (always); LINDAT dataset CC BY-NC 4.0 (training); Ultralytics AGPL-3.0 (`--yolo`); **pypdfium2 Apache-2.0** (API PDF rendering).

### `YParYU` — `atrium-ocr-postprocess` `v1.9.1-beta`

* A new repository (not a GitHub rename) continuing alto-postprocess "with the pipeline, the scripts, the categories and the scoring unchanged"; program id `ocr-postprocess`.
* Inputs: ALTO, PAGE XML, hOCR, ABBYY FineReader XML, DjVuXML, Tesseract TSV, OCR JSON, and text-bearing files (PDF, office, EPUB, HTML, TEI, Markdown, CSV, e-mail, plain text, ZIP bundles).
* API image `ghcr.io/ufal/atrium-ocr-postprocess-api`: `/process` (also merges an OCR'd page into a born-digital record that flagged it), `/score_record`.
* Licence rows unchanged in substance: FastText CC BY-NC 4.0 (always), LayoutLMv3 CC BY-NC-SA 4.0, Qwen2.5-0.5B/distilgpt2 Apache-2.0, GLM-4v-9b GLM-4 licence, pypdfium2/charset-normalizer.

### New record — `atrium-digital-convert` `v1.1.1-beta`

* Born-digital PDF, DOCX, ODT, ODS, XLSX, RTF; DOC and XLS through headless LibreOffice; type recognised from the content.
* Per-page `text_layer` verdict; `needs_ocr` with a reason; a PDF that is mostly a prior OCR layer is refused (`ocr_text_layer`).
* `POST /reformat` (record, Markdown on request, `paradata`) is the production endpoint; `POST /describe` is optional and asks page-classification and ocr-postprocess only when their URLs are set. CLI `api_util/digital_to_json.py`; Docling is an opt-in local build, never published.
* Licence: light engine MIT; Docling's weights (Apache-2.0, CDLA-Permissive-2.0) still resolve to MIT; LibreOffice (MPL 2.0) is declared and never logged, as motyc accepted on atrium-digital-convert#4 (2026-09-26).
* The GitHub homepage setting still points at `https://ufal.github.io/atrium-llm-enrich/`; the record uses the README as the user manual.

### `EMhu3X` — `atrium-nlp-enrich` `v1.0.0-beta`

* UDPipe 2 (`czech-pdt` model) and NameTag 3 (multilingual OntoNotes model) through LINDAT; the service is Czech-pinned.
* Outputs: TEITOK XML (with word boxes when ALTO is supplied), CoNLL-U, entity tables, collection summary, document record, paradata.
* API image `ghcr.io/ufal/atrium-nlp-enrich-api`: `/enrich`, `/enrich_text`, `/jobs`, `/rescale`, `/project_record`.
* No keyword code, parameters or response fields since `v1.0.0-beta`; the archaeological NER model (#7 there) is not trained, so the record names no domain NER.

### `j9fqxo` — `atrium-keyword-extract` `v1.0.0-beta`

* Statistical kind released: KeyBERT, YAKE, legacy KER; per document and per page; method, score and rank; API image `ghcr.io/ufal/atrium-keyword-extract-api` (`/extract_keywords`, `/extract_keywords_text`) and the `keywords.py` batch CLI.
* Controlled kind: research target; `llm_run.py` batch (`ghcr.io/ufal/atrium-keyword-extract-llm`, GPU, transformers or vLLM, local models only). 24 files of the llm-enrich copy are still to be taken over (atrium-keyword-extract#2); the experiment itself is deferred until after the pilot.
* Licence rows: KER MIT; KeyBERT MIT + sentence-transformers and embedding model Apache-2.0; YAKE AGPL-3.0; vocabularies CC0; no model or provider row in `para_config.txt` — the record describes the model's own licence in words.

### `CizIUW` — `atrium-translator` `v1.3.1-beta`

* ALTO and metadata modes; replace or append; XSD validation in the batch CLI only (not in `/translate`); AMČR 2.2's schema validates replaced records only.
* Backends LINDAT (CUBBITT), CTranslate2 (EuroLLM, MADLAD-400, NLLB-200, OPUS-MT), OpenAI-compatible API; every reply checked, retried and never written when degenerate.
* Licence rows: vocabularies **CC0**; the permissive recipe now needs only a permissive self-hosted model and an explicit source language.
