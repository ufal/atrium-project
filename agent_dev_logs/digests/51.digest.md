Publish the harmonised AMCR+TEATER vocabulary as SKOS, which the issue assumed required a DARIAH
Vocabs namespace first. `vocab_sources.py` already captured the AMCR `odkaz skos:exactMatch` URIs
and nothing exported them.

## ✅ What's settled

- **No namespace request from here.** Unchanged.
- **Current IDs are stable, and now stable by construction.** ATRIUM mints no URI for any harvested
  concept, so there is nothing to migrate off when the real PIDs arrive.
- **The publication dependency applied only to publication.** Everything @motyc encouraged —
  internal alignment — needed no namespace, and is now built: a hub-canonical controlled-label
  registry (`atrium_vocab.py`, 6 schemes / 64 concepts / 75 mappings) and a SKOS view of the
  harvested vocabularies (`vocab_build.py --skos` → 5,594 concepts, 55,188 triples), both
  drift-gated by the mechanisms already in place.
- **The mid-September date is met** in the only sense left open to this repo: the URI policy is
  decided (`https://w3id.org/atrium/`, one swappable constant), and it commits nobody to anything.

## 🔎 What's already in place (verified against the tree, not from this thread)

- 707 `skos:exactMatch` URIs on 668 AMCR concepts (555 Getty AAT, 143 n2t.net) — harvested since
  issue #6, read by one reviewer column, **now exported and resolvable at runtime**.
- `entities[].pid.{wikidata,geonames,aat,amcr}` — declared in schema 1.0 as *"the ARIADNE/GoTriple
  hook"*, owned by llm-enrich, **written by nothing**. 432 labels now resolve to a Getty AAT concept
  via `vocab_manager.resolve_pid()`.
- Three live defects found in the gap, all from uncontrolled labels crossing repo boundaries — most
  notably **V-1**: `lines[].categ`'s two originators emit disjoint label sets and the only consumer
  filters on one, so `DROP_CATEGORIES` matched nothing on the OCR path. Documented on 2026-09-08 and
  deliberately not fixed then, because it changes what text reaches the model. ✅ **Fixed 2026-09-16**
  once the owner took that call; V-2 with it. A fourth, **V-5**, was found on the same pass — see
  Open below.

## ⏳ Open

- The namespace itself, and the eventual PID migration — @petrpajdla's project, unchanged, not
  urgent, and now a redirect rather than a data change.
- **Five of the eight follow-ups were taken on 2026-09-16**: F1 (the V-1 fix — it changes what
  text reaches the model, and the owner took it), F2 (V-2), F6 (`teater_category_uri`, so the 707
  captured URIs finally have somewhere to go), F8 (orphan fixture), and the half of F3 that removes

  names, worth a second look if those terms matter.
- Still open: **F4** (needs the CNEC reference), **F5** (register the `w3id.org/atrium` redirect —

- **New: defect V-5.** `enrichment.items[].teater_category` holds a SOURCE label (`kostel`), not one

  `w3id.org/atrium/theme/kostel`, an ATRIUM-authored identifier for an AMCR concept, against §3.
  Mitigated (the crate now prefers the source URI); the contract question needs an owner.
  See [`../../docs/skos_strategy.md`](../../docs/skos_strategy.md) §6-§7.
