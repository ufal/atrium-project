## 🔎 What the 2026-09-25 research found
_Galaxy's own sites are unreachable from the agent session; everything below was read from the public GitHub
repositories behind them. Claims about live servers are therefore about their configuration, not a visit._

### ATRIUM already has Galaxy tools — at DARIAH
- [`DARIAH-ERIC/atrium-galaxy-tools`](https://github.com/DARIAH-ERIC/atrium-galaxy-tools) (created 2026-07-03, pushed
  2026-09-22, mostly Mark Greenwood) holds Galaxy wrappers for other ATRIUM components: `atrium_pdf_text_extraction`,
  `gate-cloud-client`, `atrium_t4_1_2_ie`, `ATRIUM_T4_1_3_IE`, `atrium_t_4_5_2_ner`, `ATRIUM_T3_4_Temporal_IE`.
- They are **local tools** listed in `tools/atrium_tools.xml` (a section "ATRIUM"), with **conda requirements** and
  planemo-style tests; the README runs them on a Docker Compose Galaxy (`quay.io/bgruening/galaxy:26.0`). The
  repository also restarts a Kubernetes deployment, which suggests DARIAH's own Galaxy server rather than
  ssh.usegalaxy.eu.
- **The narrative ↔ Galaxy pairing is already practised:** `workflows/README.md` links the Galaxy workflow
  `T4.2.1-Vocab_Driven_IE.ga` to its SSH Open Marketplace narrative
  [`IrpmkB`](https://marketplace.sshopencloud.eu/workflow/IrpmkB) (*Vocabulary-driven Information Extraction*, four
  steps). The `.ga` itself has an empty annotation, no creator and no licence.

### ssh.usegalaxy.eu
- A branded **subdomain of usegalaxy.eu** with the same toolbox; its welcome page points to tools tagged
  "Humanities". The EU panel has a **Digital Humanities** section (Kraken segmentation/OCR, ketos); also installed:
  `tesseract`, `stanza_nlp`, `grobid` (PDF → TEI), `markitdown`, `llm_hub`, `chatgpt_openai_api`, `image_learner`,
  `doclayoutyolo`.
- **No Galaxy tool translates, runs UDPipe/NameTag, extracts keywords, identifies language or scores OCR quality.**
- Tools reach usegalaxy.eu through the ToolShed (IUC standards, planemo lint/test) and a PR to
  `usegalaxy-eu/usegalaxy-eu-tools`; there is no separate tool list for the `ssh` subdomain.

### What Galaxy offers our formats
- Datatypes exist for `alto`, `tei`, `page.xml`, `hocr`, `xml`, `json`, `csv`/`tabular`, `txt`, `pdf`, `png`, `jpg`,
  `docx`, `markdown`. **There is no CoNLL-U datatype** (`stanza_nlp` writes it as `tabular`).
- usegalaxy.eu honours an explicit `<container type="docker">`; custom images run there today (grobid,
  doclayout-yolo, a goeckslab GPU image). GPU jobs are routed by tool (`gpus: 1`). Tools that call external services
  exist (openalex, chatgpt with Galaxy's `<credentials>`).
- Workflow best practice (IWC/planemo, GTN): annotation, creator with ORCID, licence, release, labelled inputs and
  outputs, step annotations, `-tests.yml` + `test-data/`, README and CHANGELOG; a Workflow RO-Crate on WorkflowHub.

### Our constraints
- Neither production image contains its models: page-classification downloads its weights from the Hugging Face Hub;
  the translator calls LINDAT (translation, UDPipe) and downloads FastText. A Galaxy job needs **outbound network** or
  **staged models** (Galaxy's shared `huggingface` data table).
- The images are on GHCR (`ghcr.io/ufal/atrium-<tool>:<version>` for the command line, `-api` for the service).
  DARIAH's wrappers use conda instead; our tools are not conda packages.
- Test data exists: page-classification `small_data_samples/`, translator `data_samples/`.

## 🧭 What already exists that the Galaxy work reuses
- **Workflow narratives** (hub site, `docs_site/workflows/`): purpose, steps with formats and activities, outputs,
  licence, and a Galaxy sheet per tool — datatypes, container, compute, network, test data, closest Galaxy tools. The
  overview maps each narrative section onto the `.ga` fields.
- **SSH Open Marketplace records**: five tool records (#4) and, planned in #4, the translator workflow `13eHAZ`
  (rebuild) and a page-classifier workflow record — the narratives a Galaxy workflow links back to.
- **Container images** for every tool, run in sequence by the hub's E2E test.
- **Licences** per component in each repository's `para_config.txt`; flexiconv (GPL-3.0) stays out of every service
  image, which also holds for any Galaxy container.
