Mark's answers remove the need to wait for a choice between the DARIAH sandbox and `ssh.usegalaxy.eu`, but the access request for three accounts is not confirmed on the thread, and the execution/model/network details are not fully decided.

- **Short term:** contribute wrappers to [`DARIAH-ERIC/atrium-galaxy-tools`](https://github.com/DARIAH-ERIC/atrium-galaxy-tools) and test them on the DARIAH Galaxy instance (a sandbox with limited job-runner resources).
- **Long term:** migrate/publish tools through ToolShed for broader reuse and aim at [`ssh.usegalaxy.eu`](https://ssh.usegalaxy.eu/) for visibility/resources.
- **GHCR images:** Mark says using the Docker image requirement *should* work, and is available on the DARIAH instance and believed to be available on `ssh.usegalaxy.eu`; it is not guaranteed on every Galaxy instance. This confirms likely support, not the exact run pattern for an HTTP `-api` image.
- **Models/network:** Galaxy can potentially fetch models from Hugging Face, stage/cache models once on the instance, or call external APIs. The deployment choice is tool-specific and still needs testing.
- **GPU:** not available on DARIAH's instance; `ssh.usegalaxy.eu` may have attached GPUs, but Mark has not verified them.
