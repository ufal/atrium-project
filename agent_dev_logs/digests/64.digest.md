Keep what CI runs and what ships the same. Two mechanical divergences, both cheap, one of which has a way to go wrong.

## 🔎 Finding 1 — the 3.12 lane (confirmed, unchanged)

`atrium-translator/.github/workflows/scheduled-smoke.yml:51` pins `python-version: '3.12'`. Grepping `python-version` across all six repos' workflows returns **exactly one** non-3.11 value, and this is it. Every image is `python:3.11-slim`.

The compounding detail is real: that same job runs `pytest tests/ -rs` — the whole suite — rather than the slow subset it exists for (roadmap **D1**). So the single lane that differs from production also has the widest blast radius. A 3.12-only failure reads as a product bug; a 3.12-only pass hides one.

## 🔎 Finding 2 — the sweep changes the shape of B7

The issue describes B7 as an nlp-enrich typo. The sweep says otherwise: **the ecosystem is split on the file extension itself.**

| Repo                | Compose files on disk                            | GPU overlay header       | State        |
|---------------------|--------------------------------------------------|--------------------------|--------------|
| alto-postprocess    | `docker-compose.yml`, `docker-compose.gpu.yml`   | says `.yml` (`:1`)       | ✅ consistent |
| page-classification | `docker-compose.yml`, `docker-compose.gpu.yml`   | says `.yml` (`:6`)       | ✅ consistent |
| translator          | `docker-compose.yml`                             | — (no overlay)           | ✅ n/a        |
| llm-enrich          | `docker-compose.yaml`, `docker-compose.gpu.yaml` | says `.yaml` (`:1-2`)    | ✅ consistent |
| nlp-enrich          | `docker-compose.yaml`, `docker-compose.gpu.yaml` | **says `.yml`** (`:1-3`) | 🔴 **B7**    |

So: three repos use `.yml`, two use `.yaml`, and **llm-enrich — the other `.yaml` repo — has its header right**. nlp-enrich is the only broken one, and the sweep the issue asks for returns exactly one fix. That is the good news.

**The trap.** nlp-enrich contains a genuine `.yml` file that must not be touched: `annotation/docker-compose.yml`, the standalone Label Studio / Doccano campaign deployment (with its own `annotation/env.example`, referenced from `annotation/README.md:14`). A global find-and-replace of `docker-compose.yml` → `docker-compose.yaml` in that repo breaks a working deployment. The fix is four path references in one header comment, not a rename and not a sweep.

## ⏳ Open
- **Should the ecosystem converge on one extension?** Docker Compose accepts both, and `compose.yaml` is upstream's current preference. Three-vs-two is not causing failures today; B7 was caused by a header not matching its own directory, not by the split. Recommend: fix nlp-enrich's header, leave the split alone, and note the convention per repo. Converging would touch five repos' docs and CI for no functional gain — but if it is going to happen, it should be decided here rather than drifting.
- **D1's second half is a separate decision.** Changing `scheduled-smoke.yml:51` to 3.11 is unambiguous. Whether that job should also narrow from `pytest tests/ -rs` to `-m slow` is a scheduled-job-scope question the issue explicitly defers ("decide separately"). It should be answered in the same PR, even if the answer is "stay broad, here is why" in a comment — a scheduled job whose scope nobody can justify is how D1 got filed.
- **Nothing enforces the version.** After this fix, `python-version` is 3.11 everywhere by convention only. The next workflow added can differ silently. A one-line check (grep the workflows, compare to the image base) would keep it — the same argument [\#59](https://github.com/ufal/atrium-project/issues/59) and [\#60](https://github.com/ufal/atrium-project/issues/60) both make about hand-maintained facts.
