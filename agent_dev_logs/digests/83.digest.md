## 🔄 What changed on 11-09

- **The rule (K4TEL, in session):** terms about a document's form and terms about its content are two groups, never
  mixed. Each tool decides only what its input shows:

  | Tool                | Sees        | Decides                                                                  |
  |---------------------|-------------|--------------------------------------------------------------------------|
  | page-classification | page images | form; in Track 2 also the depicted objects (Artefact, Material, Feature) |
  | digital-convert     | page images | form: AMČR `dokument_typ`                                                |
  | keyword-extract     | OCR text    | content: a vocabulary term, or meta-text                                 |
  | ocr-postprocess     | OCR text    | text quality                                                             |

  Written in the plan's new section "Form and content".
- **Applied (prepared, not pushed):**
  - **digital-convert:** the text layer is never sent. The list v3 has a view per level: a page's `group` and
    `image_type` (25 picture types), a document's `group` and full type (32, the written genres included). No tool
    vendors it now.
  - **keyword-extract:** `--doc-type`, its list copy and pin removed. 22 form-like TEATER terms (`dokumentace` and
    its kinds, `nálezová správa`, `fotografie`, `kresba`, 7 kinds of map, 3 remote-sensing products) are withheld
    from the decision tree, not from the vocabulary or the prompt.
  - **ocr-postprocess:** the quality set v2; `f_mirrored` and `f_handwriting` asked about the page, and become the
    text symptoms `f_inverted_letters` and `f_script_misread`.
  - **page-classification:** Track 2 from the image alone: no linked text; AMČR picture types in place of
    `capture_context`; terms from the visual facets; labels transcribed and handed on as text.
- **`docs/shared_components.md`:** the list's row is removed (no consumer); the client's row names the three CLIs.
- **Questions 3 and 4 narrow:** the list is digital-convert's alone, read from images; annotators label form from
  images.

## 🔄 What changed on 11-08

- **page-classification (#58), image only:**
  - **Triage:** seven content elements; the tags OCR, HTR, tables and graphics computed from them; one primary
    processor. A page may need all four.

## ⚠️ Limits

- **Benchmarks are vendor-reported.** Only local results on archive data decide anything.
- **The output is constrained, not correct.** A decision model cannot leave its option list, but it can pick the wrong
  option. Every child counts `invalid` answers and timeouts, and sets its thresholds on dev.
- **The internal endpoint is one shared machine running an 8-bit build.** Its figures are not the card's bf16 figures,
  and a full-corpus run is sized from measured throughput.
- **No record field exists for any result.** #71 is closed, so any field is a new hub issue and a class (c) change
  with AMČR's agreement.
- **The meeting of 11-11 also carries the pilot's approvals** (#77, #78, #79). If there is no time for these five
  questions, they can be answered in writing on the issue.
