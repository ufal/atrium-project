### Nine structural findings that shape any solution

1. **The READMEs cannot simply be rendered.** `alto-postprocess`'s `## 🛤️ Workflow Stages` is **42,775 B
   — 72 % of its README** — and nests five heading levels; `nlp-enrich`'s LLM-enrichment section is
   29,907 B. Meanwhile `llm-enrich`'s README is already flat (17 `##`, none over 7,345 B). A single
   uniform split rule fits none of them.

2. **A naive `^## ` splitter shatters the hub's own pilot.** **218 heading-looking lines sit inside
   fenced code blocks** corpus-wide. At split depth that costs `docs/agent_skill_strategy.md`
   **5 phantom `##` and 3 phantom `###`** — the SKILL.md skeleton quoted in Appendix A — and
   `llm-enrich/README.md` one phantom `##`. The splitter must track fence state, and this bites the
   pilot repo before it bites any tool repo.

3. **Every CONTRIBUTING is mostly one table, and that table is the least shareable thing in the
   corpus.** `## 📦 Release History` is **62.4–81.1 %** of each file — **195,371 B, 75.9 % of all
   CONTRIBUTING bytes** — one 3-column table per repo with cells **799–1,694 characters** wide
   (alto: 40 release rows, 56,510 B). Rendered verbatim it is one horizontally-scrolling page.
   Transposed to one anchored `###` per version it yields **133 linkable releases** across the five.
   *It is 0 % shareable:* five distinct changelogs that must render five times.

4. **Footnotes are defined only at EOF** — 30 in nlp-enrich, 19 in page-classification, 9 in alto
   (numbering skips `[^3]`), 8 each in translator and llm-enrich. Any split orphans every `[^n]`
   reference in the file.

5. **The link-rewriting job is dominated by *intra*-file anchors, not inter-file links.** The
   publishable docs carry **92 relative links, 14 of them anchor-bearing**. But every tool README also
   carries a **hand-maintained Table of Contents** — 33 / 24 / 28 / 28 / 19 in-page anchors,
   **132 total** — which a split turns into cross-page links. Those TOC blocks then duplicate the
   generated nav and must be suppressed, not rendered.
   One link is **already broken**: `alto-postprocess/service/README.md:93` targets
   `../README.md#composite-quality-score`, but the only `## Composite Quality Score` heading is at
   `docs/categorization_logic.md:214` — the README merely links to it (line 619). Emoji headings make
   GitHub's slugs and a generator's slugs disagree, so anchors need an explicit map, not a convention.

6. **The duplication the TODO asks about is real but small, and concentrated in one place.**
   Measured, not assumed:
   - **READMEs: essentially nothing to share.** Whole-file similarity between any two of the five is
     **0.012–0.108**; exact shared blocks ≥80 B total **~2,400 B (0.7 %)** of 326 KB. There is no
     common install / Docker / env / licence section to centralise — most of those sections do not
     exist in most of the five.
   - **CONTRIBUTING: ~62 KB outside Release History, of which 17,636 B is exact duplication** across
     25 blocks ≥60 B. The clean wins: `## 🔁 Contributor Workflow` (**413 B, byte-identical ×4**),
     `## 📋 Pull Request Format` (**688 B, byte-identical ×4**), the 659 B commit-type table
     (**identical in all six, including the hub template**), `## 🌿 Branches & Environments`
     (~970–998 B ×5, similarity 0.75–0.91 — the only deltas are each repo's 3 example branch names and
     `master` vs `main`).
   - **Four files are byte-identical between nlp-enrich and llm-enrich** (**75,525 B**):
     `data_samples/vocab/RUNBOOK.md` (28,939), `prompts/RUNBOOK.md` (19,948) and the two decision
     packages (16,520 + 10,118). **The two decision packages are already excluded from publication**,
     so the recoverable figure is **48,887 B**.
   - **Total recoverable: ~67,700 B.** Worth doing — and worth saying plainly that it is *not* the
     "duplication everywhere" the corpus's size suggests.

7. **Not all of it is publishable.** `docs/arub-p_contacts.md` is 6 lines holding **5 personal email
   addresses of named ARÚP/ARÚB partners**; `plan_repo_review.md` carries the maintainer's personal
   email and self-declares as stale; two `nlp-enrich` decision packages are open memos addressed to
   named individuals; `llm-enrich/digital_born/README.md` calls itself a "Phase 0 exploration scratch
   space"; `tools/quality_model/EXPERIMENTS.md` is an unfilled results table; `docker_gha_roadmap.md`
   (97 KB) is an internal roadmap. Exclusion has to be an explicit, tested step.
   **But the exclusion grep must be scoped precisely:** all five tool READMEs and CONTRIBUTING files
   carry a contact address of their own (one shared maintainer address, **zero overlap** with the five
   partner addresses), and those files are published deliberately. A blanket "no email addresses in the
   built site" assertion fails on day one against content that is public by design.

8. **Assets are 94 % noise.** `atrium-page-classification` holds **266 image files (~59 MB)**; exactly
   **17 are referenced from markdown** (11 confusion-matrix plots under `result/plots/`, 6 figures
   under `supplementary/figures/`). The remainder is `small_data_samples/` training imagery. A
   directory copy would bloat the site ~20×; the site needs an allowlist derived from parsing image
   references. Those 11 plot references are also **URL-encoded** (`result%2Fplots%2F…`) — GitHub's
   renderer tolerates it, a static generator will not; there are 60 `result%2F` and 134 `%2F`
   occurrences in that README to decode.

9. **There is not one pipeline, and the one everybody draws is wrong.** Every diagram in the corpus —
   `plan_repo_review.md`, `skills_catalog.md`, `project_state_1307.md`, `fixtures/e2e/README.md` —
   draws five boxes with arrows between them. The file topology disagrees, and the disagreement is
   verifiable:
   - `nlp-enrich` reads `DOC_LINE_CATEG/` and the **original** `ALTO/` (`config_api.txt:2,15`), never
     the translator's output;
   - **no repo reads `TRANSLATED/`** — 0 hits across all four downstream repos. The translator is a
     **terminal branch**: its output is recorded in `derived_from.translated_xml` and read by nothing;
   - `alto-postprocess` never consumes `page_categories` (its only occurrences are in the vendored
     schema files, i.e. deep-copy pass-through), so page-classification → alto is a **human routing
     decision, not code**.

   What *is* linear is the **record**: `atrium_document` accretes block by block, each stage writing
   only its own block and deep-copying the rest. Only `docs/document_schema.md:16` states this, and
   only about the record, never about the file topology. Beyond the canonical OCR chain there are a
   dozen further workflows — the born-digital two-stage path (`e2e-digital-smoke.yml`), the
   containerised service path, agent skills, vocabulary harvesting, training/evaluation, alto's
   parameter sweep, the llm-enrich benchmark, flexiconv adaptation, annotation, and the RO-Crate
   export.

### Scope settled with the maintainer

READMEs and CONTRIBUTING files stay **full-length and canonical** (the sites are *additive*, nothing
moves); `agent_dev_logs` contributes **one history page per repo**, and — new this round — that page is
**derived from `DEVLOG.md`** rather than hand-written, so it cannot go stale the way
page-classification's header once did; the generator is **MkDocs Material**; de-duplication is
**site-only**, the sources are untouched; and the topology is **hybrid** — one aggregate hub site
carrying all six repos' documentation, plus a minimal stub site per tool repo that lands the reader in
that repo's section of the hub.

**The design consequence** of "nothing moves" is that pages must be *derived* at build time rather than
authored: a hub-canonical assembler slices the untouched sources into pages on every build, so the
split can never drift from the README it came from. **The design consequence of the hybrid topology**
is that every cross-repo link becomes *internal*, and therefore checkable — which is the whole reason
to prefer it. Both are the core of the plan.

## 🧩 What the 2026-09-17 TODO changes

1. **De-duplication is a measurement problem before it is a design problem.** Finding 6 says where the
   ~67,700 recoverable bytes are and, just as importantly, where they are not: no README machinery, no
   Release-History sharing. The plan builds dedup only where the bytes justify it.
2. **The external-tools page has ~60 entries in 7 categories.** About 60 % can lift existing prose —
   `skos_strategy.md`, `rocrate_export.md`, `translator/docs/translation-backends.md` and
   `k8s_deployment.md` are tutorial-grade. About nine are **used across the ecosystem and explained
   nowhere in it**: the Handle System / PID (the LINDAT handle is the project's primary dataset
   citation), LINDAT/CLARIAH-CZ as an institution, OAI-PMH, Dublin Core (`dcterms:` is emitted; the
   string "Dublin Core" appears in zero files), Korektor (a live API call in
   `tools/quality_model/correct.py`, absent from every Acknowledgements section and the licence
   inventory), **ARÚP / ARÚB / AISCR — acronyms never expanded anywhere** — the work packages and the
   DMP, the CI security stack (Trivy / CodeQL / SARIF / Codecov), and DOG / Switchboard.
3. **The pipelines page must correct the ecosystem's own diagrams,** per finding 9 — two layers, a file
   DAG and a record chain — and it has almost nothing to start from visually: **there is not one
   Mermaid block in the entire corpus.** Every diagram is ASCII box-drawing inside a fence (358 such
   lines in page-classification's README, 258 in alto's). The only real figures anywhere are
   page-classification's six `supplementary/figures/*.png`, of which `architecture.png`,
   `use-case.png`, `page-sort.png` and `dataset_timeline.png` are directly reusable.
