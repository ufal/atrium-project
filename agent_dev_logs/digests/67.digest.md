## 🔄 Repository-set change and what it means for #67

### `atrium-ocr-postprocess` replaces `atrium-alto-postprocess`
The OCR stage is no longer identified by the old repository name. The new repository keeps the ALTO-specific implementation where it is genuinely specific, but the service is now intended for OCR outputs more broadly: ALTO XML, PAGE XML, hOCR, ABBYY XML and OCR JSON. The new image/service identity is `atrium-ocr-postprocess`.

For #67 this means:
- R1/R2/R3/R7 must name the OCR stage as `ocr-postprocess`;
- the PSNC ALTO corpus remains an input, not a reason to keep the production service named `alto-postprocess`;
- old `alto-postprocess` issue numbers may remain as historical provenance, but are not current stage owners.

### `atrium-keyword-extract` takes ownership of R5
The 30 September split moved statistical keyword extraction out of `nlp-enrich` and into the new `keyword-extract` repository, together with the controlled-vocabulary/LLM implementation inherited from `llm-enrich`.

The current `test` README is explicit:
- statistical keywords are **KeyBERT by default**, with **YAKE** and legacy KER selectable;
- the service is `POST /extract_keywords`;
- the statistical and controlled kinds are kept as separate concepts;
- every produced keyword carries method, score and rank;
- the controlled kind is still a research target in the current tree and reports `skipped`/501 from the service until its production path is completed;
- the record-level `keywords` block is tracked by #73 and is not yet landed.

Therefore the old R5 wording “keywords block owned by nlp-enrich” is obsolete. The canonical owner is `atrium-keyword-extract`.

### `atrium-digital-convert` takes ownership of the born-digital stage
The old `llm-enrich` repository contained several unrelated production concerns. The born-digital converter is now its own repository. The intended production role is a stage that turns PDF/DOCX/ODT/RTF/XLSX/ODS and related born-digital inputs into the same `atrium_document` record used by the scanned-document chain.

The service and integration work are tracked by `atrium-digital-convert#2`. The current repository, however, still contains substantial inherited LLM-enricher branding and code paths, so the repository move is not the same thing as production-stage completion.

For #67:
- the born-digital stage is a first-class sixth production stage;
- it must feed the same record contract;
- it must hand off to OCR only when `needs_ocr` says so;
- it must not become a second home for the keyword/LLM production service;
- its production API (`api-digital`) remains an open implementation item.

### `atrium-nlp-enrich` becomes CPU/LINDAT/TEITOK
The current README states that keyword extraction is no longer part of `nlp-enrich`. The repository is now the LINDAT-oriented NLP stage: UDPipe, NameTag, TEITOK and the record projection around those outputs.

That removes the old architectural ambiguity in R7: `nlp-enrich` is not the production home for the LLM engine, vocabulary code or statistical keyword extractor.

## 🎯 Goal

#67 now has one integration-level goal:

> **Make the AMČR pilot contract executable across the six-stage production architecture, while keeping #71, #72 and #73 as the concrete work packages.**

The pilot contract is not a second schema. `doc-schema-v1` remains the frozen record baseline. The work is to make the existing record move through the whole chain with stable identity, machine-readable provenance, explicit stage ownership and a validated crate.

### R1 — seeded identity
AMČR supplies before the first processing stage:
- `doc_id` = AMČR file id;
- `source.sha512` = Fedora digest;
- source file name;
- media type.

`source.origin` is owned by the tool that actually reads the source, because that determines the page/layout interpretation. Every stage must accept the seeded record and preserve `doc_id` and `source.sha512`. The #68 seed read-back bug is fixed, but the integration gate remains incomplete until the processed record—not the untouched seed—reaches the final stage.

### R2 — paradata
The common response already has a typed optional `paradata` slot. The intended unit is one Process Run Crate `CreateAction` per service run, with:
- tool identity and version;
- container image;
- object/result/agent;
- start/end times;
- `actionStatus`;
- agreed paradata properties.

Current implementation is ahead in some repositories and still only on `test` in others. The integration requirement is six production services, not “all repositories that happen to contain a related helper”.

### R3 — record-only mode
This remains intentionally deferred. It was requested in the original #67 proposal, including the PSNC ALTO bulk-import use case, but the post-meeting split did not turn it into a required S1/S2 production path. Do not let R3 re-introduce per-tool alternate contracts while R1/R2 are being closed.

### R4 — RO-Crate
The common utility follows the AMČR S1 baseline:
- RO-Crate 1.2;
- Process Run Crate 0.5;
- `version` for software, not `softwareVersion`;
- stable run and tool identifiers;
- tool authors as the tool `creator`;
- file size information;
- fragment mode without a second root.

The remaining task is integration proof: a real seeded chain must produce a crate that validates and is composable by AMČR.

### R5 — keywords
The owner is now `atrium-keyword-extract`. The intended record design keeps two kinds distinct:
- **statistical** keywords from KeyBERT (default), YAKE or legacy KER;
- **controlled** vocabulary terms from AMČR/TEATER selected by the LLM path.

Every statistical result must expose at least method, score and rank. Controlled enrichment keeps its own semantically distinct fields (`enrichment`, entities, vocabulary/category information) rather than silently becoming another copy of the statistical block. The current service is already able to return statistical results. The controlled path is still a research target in the current repository, and #73 owns the production record projection.

### R6 — quality summary
This is deliberately last. Page-classification and OCR line/page outputs already provide quality information; #73 should derive a document summary from those signals rather than introducing a new document-quality model or replacing the existing line categories. The summary is optional and should not become a prerequisite for the core seeded-chain contract.

### R7 — architecture
The post-meeting architecture is six production stages, with shared layers governed separately:

| Shared concern                                | Canonical owner / rule                                  |
|-----------------------------------------------|---------------------------------------------------------|
| `atrium_document` and common contract modules | hub, vendored into services, checked with `para-drift`  |
| source/document reading                       | OCR-stage reader ownership; one governed implementation |
| born-digital record construction              | `digital-convert`                                       |
| TEITOK consumption / projection               | `nlp-enrich`                                            |
| LLM engine and vocabulary runtime             | `keyword-extract`                                       |
| vocabulary release artifact                   | `keyword-extract`                                       |
| translation backend                           | `translator`; consumes the agreed inputs                |
| release/runtime conventions                   | all services under #72 / #32 / #40 / #53 / #55 / #58    |

The point of R7 is not to make all repositories identical. It is to stop production images from duplicating the same responsibility under different names.

## ⚠️ Current inconsistencies that #67 must not hide

1. **The #67 issue body is historically named.** It still says `alto-postprocess`, `llm-enrich`, and `nlp-enrich` in places where the successor repositories are now canonical.
2. **`digital-convert/test` contains stale inherited `atrium-llm-enrich` branding and LLM-first documentation.** This is a real migration gap, not merely a cosmetic README issue.
3. **`keyword-extract/test` is ahead of #67's old wording but not yet complete:** statistical extraction is implemented, while the controlled kind is still a research target and the record `keywords` block is owned by #73 and still pending.
4. **The seeded E2E exists but is not green.** Do not close R1 on the existence of unit/service tests alone.
5. **Not every service is yet at the same release stage for `CreateAction`.** The closure criterion is production parity across the six services, not “some current branches have it”.
6. **Release immutability, vocabulary artifact publication, shared-reader pinning and licence cleanup remain integration concerns.** They belong to #72/#6/#40, but #67 should not be considered closed while the pilot trust gate cannot pin the stage set reproducibly.

## ✅ What “done” should mean for #67

#67 can be treated as the pilot umbrella being satisfied when all of the following are true:

- the six current production stages are the identities used by the AMČR integration;
- an AMČR-seeded document enters the first stage and the processed record reaches the final stage without losing `doc_id` or `source.sha512`;
- every production stage returns its own machine-readable Process Run Crate `CreateAction`;
- the RO-Crate utility validates against the agreed S1 profiles and supports fragment composition;
- `keyword-extract` owns the record `keywords` block and keeps statistical and controlled results distinct;
- any document-level quality summary is derived from existing quality signals and does not create a second quality model;
- the born-digital path exists as a real service and uses the same `atrium_document` chain;
- shared reader/LLM/vocabulary layers have one governed production owner each;
- release tags and service metadata are reproducible enough for the AMČR trust gate to pin them;
- the six-stage seeded E2E is green.

> **Closure rule:** #67 is an integration umbrella, not a seventh implementation. Once #71, #72, #73 and the born-digital service close their stated acceptance criteria and the six-stage seeded E2E is green, #67 should be reduced to a short record of the agreed baseline and closed.
