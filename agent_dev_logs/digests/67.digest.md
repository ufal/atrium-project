## 📋 The seven requests
Each is copied down to its checkable core; the plan carries the code state, the gap and the work.

| #  | Request                                        | Tools                                                                     | *Done when* (David's)                                                                               |
|----|------------------------------------------------|---------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|
| R1 | **Seeded baseline record**                     | all five, and `digital-convert`                                           | the E2E smoke runs from a seeded baseline                                                           |
| R2 | **Paradata from every service**                | page-classification, alto-postprocess, translator, llm-enrich; nlp aligns | each service's response carries it                                                                  |
| R3 | **Record-only mode**                           | all five                                                                  | a record is built from existing outputs alone                                                       |
| R4 | **`atrium_rocrate.py` aligned**                | hub (shared module)                                                       | its output passes rocrate-validator with `ro-crate-1.2` and `process-run-crate-0.5`, run separately |
| R5 | **A `keywords` block owned by nlp-enrich**     | nlp-enrich (schema in the hub)                                            | — (none given; the plan proposes one)                                                               |
| R6 | *Optional:* **document-level quality summary** | alto-postprocess (schema in the hub)                                      | — (optional)                                                                                        |
| R7 | **Tool architecture cleanup**                  | all; shape is ÚFAL's                                                      | `para-drift` covers the shared layers, and each image does only its stage                           |

- **R1.** AMČR creates the record before the first stage: `doc_id` = the AMČR file id; `source` with `sha512` (the
  Fedora digest), the file name and the media type; `source.origin` left to the tool that reads the document. Every
  service accepts it on its first call and keeps `doc_id` and `source.sha512` unchanged.
- **R2.** One RO-Crate Process Run Crate `CreateAction` per run: `instrument` (the tool, with `version`, and its
  container image), `object`, `result`, `agent`, start and end times, `actionStatus`; the paradata 2.0 fields as
  properties of the action.
- **R3.** Merge an output that already exists into the record without running models — first example: the PSNC ALTO,
  which AMČR imports in bulk, into alto-postprocess.
- **R4.** RO-Crate 1.2 with Process Run Crate 0.5; `version` on each `SoftwareApplication`, not `softwareVersion`;
  stable run and tool identifiers; tool authors as `creator` of each tool, not of the root; a fragment mode without a
  root entity, so AMČR can embed it.
- **R5.** Statistical keywords with their method and score — KeyBERT by default, YAKE selectable — next to the
  controlled keywords from llm-enrich.
- **R6.** A document-level quality summary, next to the page aggregates.
- **R7.** One production service per stage; shared layers governed like the contract modules under `para-drift`
  (one document reader, one LLM engine and client, one versioned vocabulary artifact); nlp-enrich without its `llm`
  stage and vocabulary code; llm-enrich research kept off the release line.

The four thread-specific requests are in their threads and pairs: born-digital in llm-enrich#10, release hygiene in
#40, configurable limits in #53, licences in #6.

## 🔎 What the code says today (2026-09-26, the six clones above)
- **R1 — one bug, two gaps.**
  - *Bug:* alto-postprocess `/process` and llm-enrich read back the record from the path named after the
    **filename-derived** id (`service/text_api.py:502,527-528`; `llm_client_shared.py:1248,1319` →
    `service/api.py:351-398`), while `finalize()` writes it under the **inherited seed** id
    (`atrium_document.py:1002`, `_inherit_doc_id` `:494-534`). With an AMČR file id as the seed, the response
    carries the untouched seed. Found by reading, not yet reproduced. The same shape is in alto's
    `run_pipeline.py:346-377`. llm-enrich's `/extract_keywords_text` hardcodes `doc_id="inline_text"` (`api.py:516`).
  - *Gaps:* no `sha512` anywhere (the schema keys on `source.sha256`, `schema.json:64-67`); a bare seed (`doc_id` +
    `source`) fails the schema, which requires `provenance` and `assembled` (`schema.json:7`); the E2E smokes run
    the CLI images and start unseeded (`e2e-pipeline-smoke.yml:263-275`).
- **R2.** Only nlp-enrich returns paradata in its response (`service/api.py:214`). page-classification's service has
  none; alto writes it into a relative `paradata/` folder; translator and llm-enrich into temp folders that are
  gone when the response leaves. A `CreateAction` exists only in `atrium_rocrate.py` (`:417-446`, `:585-606`),
  which no tool imports, and it has no `agent` or `actionStatus`.
- **R3.** Nothing. The nearest is alto's `--skip-*`/`--start-from` (`run_pipeline.py:42-48,165-180`), which writes
  no record block.
- **R4.** RO-Crate 1.1 (`atrium_rocrate.py:80-82`); `softwareVersion` (`:386,465,622`); run ids are timestamps
  (`:256-265`); authors on the root (`:311,541`); no fragment mode; no validator run anywhere.
- **R5.** KeyBERT/YAKE live in nlp-enrich's `keywords.py` and reach the API response and CSV only; the schema has no
  `keywords` block and `BLOCK_OWNERS` has no entry (`atrium_document.py:108-118`). The API defaults to KeyBERT, the
  CLI to YAKE.
- **R6.** Quality exists per page and per line only (`schema.json:187-188,261`).
- **R7.** `MANIFEST.json` governs 19 files; the LLM engine (`llm_run.py`, `prompt_template.py`, `vocab_*`), the
  vocabulary artifact (`union_nested.json`) and the readers are duplicated between llm-enrich and nlp-enrich and not
  governed; nlp-enrich still publishes an `llm` image (`Dockerfile:124-139`); llm-enrich's and nlp-enrich's images

## ✅ What's settled
- **The baseline is adopted by ÚFAL** as written, pending only what the 30 September meeting changes.
- **The record is the intermediate format** (llm-enrich#13), frozen as `doc-schema-v1` (`544298b`, #54).
- **OCR is outside the tool repositories.** AMČR brings its own OCR connector and backup engine; the tools receive
  ALTO for pages flagged `needs_ocr` (llm-enrich#10, #24, #25).
- **flexiconv stays off the AMČR production chain** (nlp-enrich#10, #38); born-digital documents reach the pipeline
  through `digital-convert` (llm-enrich#10).
- **The translator's production mode is `replace`** for AMČR records; AMČR keeps English metadata as a separate
  `metadata-en` file (translator#46).
- **Fork checks move to `ARUP-CAS/aiscr-docs-pipeline`**; the ARUP-CAS forks stay plain mirrors of release tags (#18).
