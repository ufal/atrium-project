## ❗ Two corrections to the previous refresh

### 1. "A small, low-risk correctness fix — no behaviour change for any conforming producer"

**Half right, and the wrong half is load-bearing.** No *producer* is affected: every record goes
through `DocumentRecord.to_dict()`, which emits `schema_version`, `record_type`, `doc_id`,
`provenance` and `assembled` unconditionally. But the ecosystem also feeds **hand-built baselines**
to that same validator — in tests, and over the service APIs — and there is a second-order effect
nobody had traced: five repos **demote the own-output gate from `raise` to `warn`** when the
baseline was invalid (`alto-postprocess/document_hook.py:92,119`; `translator/main.py:119,180`;
`page-classification/atrium_document_adapter.py:153,217`; `llm-enrich/llm_client_shared.py:1177,1229`;
`nlp-enrich/api_util/document_hook.py:340`).

So tightening `required` without a fixture pass would, for those runs, **weaken the exact gate
the freeze exists to strengthen**. At least nine hand-built minimal records need updating across
six repos, two of which (`test_atrium_document_adapter.py:285`,
`nlp-enrich/tests/test_document_hook.py`) explicitly assert the *un*-demoted behaviour and will
flip. One of the nine is the vendored `test_document_originators.py:304`, so that edit lands in
six repos and must go through `revendor_shared.sh`.

### 2. The obvious way to express "a stage that produces nothing" breaks the pipeline at stage 1

The natural reading is *require `assembled.blocks`, non-empty* — `_stamp()` runs only where a
payload is written, and `finalize()` already prints `WARNING – <program> contributed no block`.

**`set_source()` deliberately does not stamp.** `source` is not a tool's block; it is the
first-writer handshake, and `RESERVED_KEYS` excludes it from tool ownership. So
`atrium-alto-postprocess/page_split.py:540-553` — the scanned pipeline's **originator, stage 1** —
emits `schema_version, record_type, doc_id, source, provenance, assembled` with **no `blocks` key
at all**, and hands it to a hard gate. A blanket `blocks` requirement would make the originator
refuse to emit its own first record.

The rule that is actually true: **a record must carry either `source` or at least one stamped
block.** Written as a two-branch `anyOf`, it keeps `page_split` valid and rejects exactly the
shape the issue is about.

## ✅ What was drafted and verified this pass

### The schema

`required` → `["schema_version","record_type","doc_id","provenance","assembled"]`, plus the
`anyOf` above and an `allOf` of eleven `if`/`then` clauses giving **stamp/payload coherence**
(every name in `assembled.blocks` must have a top-level payload).

Executed against `jsonschema` 4.26.0 — the version the repos pin — over every per-stage record
shape traced from production code. **16 cases, 0 mismatches:**

- **Valid, unchanged (11):** the committed `fixtures/atrium_document.example.json` · alto
  `page_split` (source only) · alto `extract` (`pages`+`content`) · alto `classify_TEXT` (`lines`)
  · alto `aggregate_STAT` (`pages`) · page-classification standalone · translator standalone ·
  nlp-enrich standalone (`entities: []`) · llm-enrich standalone · digital-convert originator ·
  `merge_document_records()` output.
- **Newly rejected (5), all defects:** today's two-key minimum · a floor record with neither
  `source` nor a stamp · a stamp naming a block the record does not carry · floor-minus-`record_type`
  · floor-minus-`provenance`.

The table is delivered as an executable test, `tests/test_document_required.py`, with every
positive case annotated with the production call site it was traced from. **18 passed** against
the tightened schema; against the current schema exactly the five negative cases fail — so the
test discriminates rather than passing vacuously.

**One live call site falls into the newly-rejected set, and it is a genuine bug.**
`atrium-alto-postprocess/classify_TEXT.py:1109` calls the document hook *outside* the
`if not df.empty` guard, so an empty CSV produces `merge_blocks={"lines": []}` — truthy enough to
pass the hook's own guard, empty enough to write nothing — and emits a five-key record. Only bites
a standalone run; fix at the call site, not in the schema.

### The RO-Crate module

`atrium_rocrate.py`, hub-canonical, **stdlib only** and deterministic, modelled on
`atrium_vocab.to_jsonld()` (`:954-999`) — the same house rules that module states explicitly ("an
RDF library is deliberately not introduced"; byte-stability is drift-gated). Two functions:
`document_crate()` (the primitive) and `run_crate()` (references the per-document crates rather
than re-describing them, so it stays the same size at 1.2M-page scale).

Verified: `--selftest` clean, byte-identical across processes, and it turns the committed example
fixture into a **46-entity crate** — 5 `CreateAction`s (one per tool), 5 `SoftwareApplication`s,
4 ORCID `Person`s, 4 `File` parts, 8 `DefinedTerm`s, 1 root `Dataset`.

The record's reference discipline maps exactly onto RO-Crate's own hard rule: `derived_from` →
`hasPart`; `regenerable` → contextual entities, **never** `hasPart` (they are recipes for files
that do not exist); `source` → root `isBasedOn`, contextual (archive-managed, no path).
`datePublished` comes from the record's newest block stamp, not the clock, so re-exporting an
archived record reproduces the crate it shipped with.

## 🐞 Found while verifying — a new defect, and two unimplemented declarations

### V-4 has a second home nobody fixed

`fixtures/atrium_document.example.json` carries **four controlled values `atrium_vocab` does not
know**:

| Field                                | Value in the fixture | Registry says                                                      |
|--------------------------------------|----------------------|--------------------------------------------------------------------|
| `page_categories`                    | `"Text"`, `"Plate"`  | `TEXT`, `DRAW`, `PHOTO`, `LINE_*`, … (11 concepts)                 |
| `lines[].categ`                      | `"Text"`             | `Clear`/`Empty`/`Noisy`/`Non-text`/`Trash` or `Garbage`/`Inverted` |
| `enrichment.items[].teater_category` | `"kostel"`           | 11 themes, all English title-case                                  |

This is exactly defect **V-4** from `skos_strategy.md` §6 — *"schema examples contradicted the
label set" ✅ fixed* — in its **other** file. That pass corrected the schema's `examples` and left
the fixture, which is what a maintainer actually reads and what `tests/test_fixture_schema.py`
pins. Nothing catches it: the fixture test checks schema validity, and the schema deliberately
carries no `enum`. Surfaced here because the RO-Crate exporter mints a URI per controlled term,
so a value outside the registry becomes a URI that resolves to nothing.

**Fix the fixture. Do not add the enum** — the reason recorded on 2026-09-08 still holds
(`validate_document()` raises; `page-classification/utils.py` derives its labels from the
filesystem at run time).

### The coherence rule fires on a real, accidental shape — in this repo's own test suite

Running the hub suite with the tightened schema (`190 passed, 1 failed, 1 skipped`) turned up
`tests/test_e2e_assert.py::test_schema_invalid_record_fails_on_the_schema_first`. It deliberately
breaks a record twice and asserts the schema is what reports it; `del record["pages"]` leaves
`assembled.blocks["pages"]` behind, so the new stamp/payload rule reports that too, and the test's
final assertion — which used the bare word `"pages"` as a proxy for the block-missing error — no
longer holds.

**The behaviour under test is intact**: ordering is enforced by the exception type
(`assert_schema_valid()` raises `SystemExit`, block assertions raise `AssertionError`), not by
string matching. Only the proxy broke.

What makes this the best available evidence for the rule: that file deletes a block in **eight**
places, and **seven of them already delete the stamp too** (95/96, 103/104, 155/156, and 147 doing
the deliberate opposite). Its author treated "payload without stamp" and "stamp without payload" as
distinct, meaningful shapes and built them on purpose everywhere except line 205 — the one place
the pairing was forgotten. The freeze made that slip visible. Nothing else in the six repos orphans
a stamp.

Fix is three lines in the test (`test_e2e_assert.patch.md`); the whole hub suite is then green,
192 passed.

## ⏳ Open

- **Nothing has landed.** Both halves are drafted, neither is committed, and the fixture pass of
  the tightening has not been started. That pass is **ten** hand-built baselines across six repos,
  plus the one `test_e2e_assert.py` edit above — the tenth
  (`atrium-llm-enrich/tests/test_digital_to_json.py:262`) surfaced on a second sweep and is the
  only hand-built `assembled.blocks` map in any tool repo.
- **The `v1`-tag ordering is the real rollout risk.** `para-drift` reads the hub at `hub-ref`
  default `v1`, and all five callers pin `@v1` with no override, so hub and vendored copies must
  land in one window and `v1` must move *after*. The #13 digest records the live incident where a
  four-minute gap turned `para-drift` red.
- **The E2E gates run published `:latest` GHCR images**, and `:latest` only moves on a version
  tag — so a tightening any published image violated would cost a release cycle per repo to
  green. The floor is safe because every image carries the same `atrium_document.py`, but this is
  the constraint that decides how far the tightening may go.
- **`e2e-pipeline-smoke.yml` is already red for an unrelated reason** — `'enrichment' block missing
  from llm-enrich stage` on the CLI/`-remote` path, tracked as #49 whose guidance text is stale.
  Do not attribute a red E2E to this change without reading the traceback.
- **`atrium-llm-enrich#13` is open, not closed** — correcting the previous refresh, which called
  it "already settled". Two of its carried-over items sit under this freeze: `canonical_doc_id()`
  exists but is called by no tool (P2.1), and `entities[].translation_en` (P2.3).
- **The freeze tag is not `v1`.** `v1` is the moving reusable-workflow tag; the freeze needs its
  own immutable marker or it becomes un-referenceable the next time `v1` moves.
