## 🎯 Goal
Close out `atrium_document` as our WP3/T3.3 syntactic-interoperability deliverable: tighten the
schema so it can no longer validate a malformed record, add the RO-Crate export the DMP names for
WP3, then tag v1.0 and treat the schema as a compatibility obligation rather than a design surface.

## 🔎 What's already in place (verified against the tree, not from this thread)
- `SCHEMA_VERSION = "1.0"` is already set (`docs/templates/shared/atrium_document.py:63`).
- `migrate_document()` exists with a MAJOR-version-refuse guard.
- `docs/document_schema.md` documents the accretion contract and a block-ownership table.
- `para-drift` already enforces byte-identity of `atrium_document.py`/`.schema.json` across all
  five tool repos.
- **The gap named in the issue is real and unfixed**: `atrium_document.schema.json`'s top-level
  `required` is exactly `["schema_version", "doc_id"]` against 17 declared properties, so a stage
  that writes nothing still produces a schema-valid record.
- **RO-Crate**: zero occurrences of `RO-Crate`/`rocrate` in any of the six repos today. The DMP's
  WP3 standards column names it explicitly (alongside CIDOC CRM, SKOS, PeriodO, Getty AAT, TEI,
  DataCite, IIIF) — this is a new commitment, not something already partly built.
