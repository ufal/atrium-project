## 3. Why an owner's `test` branch can turn an unchanged consumer red

Each sibling parity test file contains two test functions with very different failure modes:

- **`test_vendored_copy_matches_its_pin`** hashes the consumer's in-tree file against the local `VENDORED` SHA-256 dictionary. It is self-contained, independent of the owner repository, and runs in every standard `pytest` job. This check is sound.
- **`test_vendored_copy_matches_sibling_checkout`** is run in CI by the `vendored-parity` job in `.github/workflows/para-drift.reusable.yml:120-175`. That job clones each owner repository at `inputs.vendored-ref`, which defaults to the moving `test` branch (`para-drift.reusable.yml:34-40, :149`). To prevent silent misconfiguration, `:168-171` fails the job if `pytest` reports any skipped tests.
- The owner commit SHA checked out by `vendored-parity` is printed only to the workflow log (`para-drift.reusable.yml:150`). Because the comparison targets the owner's moving `test` head rather than the revision the consumer actually adopted, **any owner commit to `test` that touches a pinned file immediately turns an unchanged consumer's CI red**.
- **Precedent in the ecosystem:** `ocr-postprocess`'s `alto_tools.py:70-73` records `UPSTREAM_COMMIT` as an explicit constant, and `tests/test_alto_tools.py:168` asserts it directly.

- **The single recorded owner revision is stale:** `digital-convert/tests/test_vendored_reader_parity.py:30-31` has a comment naming `atrium-ocr-postprocess` commit `6707320` (2026-09-27). ### What is missing

- **No impact-class rule:** No policy maps the nature of a shared-component change — **(a)** internal/cosmetic, **(b)** backward-compatible additive contract extension, or **(c)** breaking / record-meaning change — to the exact contract tests and gates that must be updated in the same PR.
- **No hub rule requiring AMČR agreement for semantic changes:** `docs/document_schema.md:458-487` defines a purely technical procedure for schema changes. The commitment that changes altering archival record meaning require agreement from AMČR (`ARÚP`) exists only in issue threads and digests ([#54](https://github.com/ufal/atrium-project/issues/54) (closed; its digest is retired), `agent_dev_logs/issues/2026-09-26.67.issue.open.md:78`), even though issue #6 (`agent_dev_logs/issues/2026-03-13.6.issue.open.md`) already plans a change of that class.

## 7. Runtime self-containment holds

- **Container builds copy local tree only:** Every tool `Dockerfile` uses `COPY . .` (matching `docs/templates/Dockerfile`).
- **Zero startup/runtime GitHub fetches:** No service downloads code, schemas, or vocabularies from GitHub when starting or handling requests.
- **Bundled vocabulary in `translator`:** The vocabulary CSV ships inside the container image; `VOCABULARY_PATH` is unset by default and only overrides the built-in path when explicitly configured.
- **Out-of-band fetches are build/release/setup only:** Remote downloads happen only during Docker image build, GitHub release packaging, standalone operator CLI invocation, or local developer setup. The only unpinned `git clone` in the ecosystem is in `ocr-postprocess`'s local setup script (cloning `alto-tools` for local dev).
