## 🔦 The one red run since the last comment
- **Run:** page-classification `v1.9.2-beta` tag run ([37269822039](https://github.com/ufal/atrium-page-classification/actions/runs/37269822039)), red at "Run container on a NON-DEFAULT port (issue #58)".
- **Cause:** model warm-up, not `$PORT`. Each probe container downloaded the service's five models into an empty `HF_HOME` again. The `PORT=9000` container, the second of the job, was still loading the fifth when the HEALTHCHECK budget ran out (`start-period` 180 s + 3 × 30 s).
- **Not gating:** `docker-build-smoke` is not in `build-and-push`'s `needs:`, so the images were still promoted. The workflow comment explains why the job does not gate publishing.
- **Fix:** hub `4cbf900` (in `v1`).
  - The probe containers of one job share a named volume at the image's `HF_HOME`; an image without `HF_HOME` is unchanged.
  - The `PORT=9000` failure message now names both causes ("Either `$PORT` is not being honoured, or the service had not finished starting … the container log below shows which").
- **First page-classification run on the fixed `v1`:** [37298437914](https://github.com/ufal/atrium-page-classification/actions/runs/37298437914), green.
