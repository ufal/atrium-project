## 🎯 Goal

Make `PORT` and `HOST` real deployment knobs for every current production API image, so the common Kubernetes deployment template and the Docker images have one coherent binding contract.

The invariant is:

```text
PORT/host configuration
        ↓
service __main__
        ↓
uvicorn listener
        ↓
service/healthcheck.py
        ↓
Docker HEALTHCHECK
        ↓
docker-build-smoke / Kubernetes probes
```

A service must never read one value while its listener uses another.

For the current five production images this means:

| Stage               | Repository                                                                                   | Production image                              | API entrypoint               |
|---------------------|----------------------------------------------------------------------------------------------|-----------------------------------------------|------------------------------|
| OCR postprocess     | [`atrium-ocr-postprocess`](https://github.com/ufal/atrium-ocr-postprocess/tree/test)         | `ghcr.io/ufal/atrium-ocr-postprocess-api`     | `python service/text_api.py` |
| Keyword extraction  | [`atrium-keyword-extract`](https://github.com/ufal/atrium-keyword-extract/tree/test)         | `ghcr.io/ufal/atrium-keyword-extract-api`     | `python -m service.api`      |
| NLP enrichment      | [`atrium-nlp-enrich`](https://github.com/ufal/atrium-nlp-enrich/tree/test)                   | `ghcr.io/ufal/atrium-nlp-enrich-api`          | `python -m service.api`      |
| Page classification | [`atrium-page-classification`](https://github.com/ufal/atrium-page-classification/tree/test) | `ghcr.io/ufal/atrium-page-classification-api` | `python -m service.api`      |
| Translation         | [`atrium-translator`](https://github.com/ufal/atrium-translator/tree/test)                   | `ghcr.io/ufal/atrium-translator-api`          | `python -m service.api`      |

The deliberate exception is `ocr-postprocess`: its service is intentionally launched as `python service/text_api.py` because `text_api.py` contains the repo-root `sys.path` bootstrap needed for that script form.

## 🧪 Current shared CI contract

The current `atrium-project/.github/workflows/docker-tool.reusable.yml` still has the two runtime probes introduced for #58.

### PORT probe

The shared step:

```bash
cid=$(docker run -d -e PORT=9000 -p 18080:9000 "$IMAGE")
```

waits for Docker `HEALTHCHECK` to report `healthy`, then curls:

```text
http://127.0.0.1:18080/health
```

The important property is that `service/healthcheck.py` itself reads `$PORT`. Reaching `healthy` with `PORT=9000` therefore tests the listener and the in-container health probe at the same time.

### HOST probe

The next shared step starts:

```bash
cid=$(docker run -d -e HOST=127.0.0.1 -p 18081:8000 "$IMAGE")
```

It first requires the container to become healthy, then requires the published interface to be unreachable.

That ordering matters: a failed container must not satisfy the negative curl assertion by accident.

### Caller coverage

All five current production repositories point at:

```yaml
ufal/atrium-project/.github/workflows/docker-tool.reusable.yml@v1
```

and expose their `api` target through `probe-targets`.

The current callers are:

* page-classification;
* translator;
* nlp-enrich;
* ocr-postprocess;
* keyword-extract.
