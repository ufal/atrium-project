## 🎯 Goal
Turn the tool set into independently deployable production services, each image carrying its stage and approved
shared components only. The issue's scope, condensed:
1. one production service per stage;
2. governed shared layers: one document reader, one LLM access layer, one versioned vocabulary artefact;
3. no duplicate LLM/vocabulary code in nlp-enrich; llm-enrich's research outside the release line;
4. para-drift over the shared layers;
5. PyMuPDF (AGPL-3.0, undeclared) replaced in page-classification after a comparison;
6. the AMČR vocabularies and TEATER declared CC0 in nlp-enrich and llm-enrich;
7. the `/health`, `/info`, limits and error conventions kept;
8. branch protection and immutable release tags; the GPU runner deferred.

Acceptance, in full: production images contain only their stage plus approved shared components; shared components
are drift-checked; no production image depends on the undeclared AGPL library; vocabulary and licence metadata match
the AMČR baseline; release tags cannot be silently retargeted; the resulting layout is the baseline of the processing
trust gate. Dependencies: #32, #53, #55, #58, #40.

## ✅ What's settled
- **The six stages** after the meeting: page-classification, ocr-postprocess, digital-born-convertor (`api-digital`),
  nlp-enrich (LINDAT only), keyword-extractor, translator.
- **The three shared layers**, now with owners: the document reader (ocr-postprocess, vendored by the converter), the
  LLM access layer and the vocabulary artefact (both keyword-extractor, by moving, not copying).
- **PyMuPDF → pypdfium2** after a label comparison (ÚFAL's proposal, report item 5).
- **CC0** — done.
- **Branch protection and immutable release tags** are present-time work; the GPU runner is deferred (#40 split).
- **The service conventions of #32/#53/#55/#58** are consumed, not reopened.
