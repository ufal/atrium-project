## 🎯 Goal
Turn the tool set into independently deployable production services, each image carrying its stage and approved shared components only.

The issue's scope:

1. one production service per stage;
2. governed shared layers: one document reader, one LLM access layer, one versioned vocabulary artefact;
3. no duplicate LLM/vocabulary code in `nlp-enrich`; `llm-enrich` research outside the release line;
4. `para-drift` over the shared layers;
5. PyMuPDF replaced in page-classification after comparison;
6. AMČR vocabularies and TEATER declared CC0 in nlp/llm enrichers;
7. established `/health`, `/info`, limit and error conventions retained;
8. branch protection, immutable release tags and trusted workflow references; GPU runner deferred.

Acceptance: production images contain only their intended stage + approved shared components; shared layers are drift-checked; no production image carries the undeclared AGPL dependency; vocabulary/licence metadata match the AMČR baseline; release tags cannot be silently retargeted; the resulting service layout is the baseline consumed by the processing/trust gate.

## 🔎 `atrium-ocr-postprocess` refresh

The new repository is materially more than an empty shell: its current `master` tree includes a production API target, health handling, the shared record/paradata stack, document readers and the OCR-quality pipeline. That makes it the intended home of the OCR stage.

However, it is **not yet an identity-clean successor**:

- Docker provenance defaults still fall back to `https://github.com/ufal/atrium-alto-postprocess`.
- README/CONTRIBUTING material still describes the old project name/repository in places.
- The service's program identity and release metadata need to be reconciled with the `alto-postprocess → ocr-postprocess` successor rule.
- The new repository therefore cannot yet be treated as the final immutable production identity for #71/#72's acceptance gate.

The correct interpretation is **move exists; migration is unfinished**.

## ✅ What's settled
- **Six production stages** are the post-meeting architecture; `docs/k8s_deployment.md` carries the map.
- **Shared document reader owner**: `ocr-postprocess`; consumers vendor it with explicit pins.
- **LLM access and vocabulary owner**: `keyword-extract` (not `-extractor`: the name AMČR kept), by moving the existing implementation rather than keeping copies.
- **Repository moves** ✅ for OCR (ocr-postprocess v1.8.0-beta) and keywords (keyword-extract v1.0.0-beta, nlp-enrich v1.0.0-beta); the release gate accepts a declared rename (`x-atrium-service-previous`).
- **Tool-to-tool vendoring is drift-checked** ✅ (`vendored-parity`; pins in keyword-extract and digital-convert).
- **PyMuPDF → pypdfium2** released in page-classification v1.9.1-beta.
- **CC0** is done; the vocabulary declarations now live in keyword-extract.
- **ARUP-CAS forks** follow the new repositories; future name changes are renames, not new repositories (AMČR's request).
- **Common service conventions** are consumed, not reopened.
