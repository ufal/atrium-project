## 🛠️ What was built

**`docs/templates/shared/MANIFEST.json`** — one row per canonical file: `canonical` (filename), `dest` (path relative to a tool-repo root), `selftest` (bool), `ruff_format_exclude` (bool — false only for the two `.schema.json` entries, which ruff never formats), `isort_first_party` (module name or null), `preconditions` (list), `issue`, `note`. 16 entries, matching `para-drift.reusable.yml`'s guarded set exactly.

**`tools/shared_manifest.py`** — the manifest's one reader (new). `load_manifest()` validates structure (no duplicate `canonical` or `dest`, every required field present) and is imported directly by `tools/skill_drift_check.py` and `tests/test_shared_manifest.py`; a `--tsv` CLI mode is the bridge for the two consumers written in bash, which cannot import a Python module.

**Four consumers, one manifest:**

| Consumer                                    | Before                                                                                  | After                                                                                                                                                  |
|---------------------------------------------|-----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| `tools/skill_drift_check.py`                | 5-entry hand-written `SHARED_FILES` tuple                                               | `SHARED_FILES = tuple(entry["dest"] for entry in load_manifest(...))` — 16 entries                                                                     |
| `scripts/revendor_shared.sh`                | three `declare -A`/array literals (`SHARED_FILES`, `PRECONDITIONS`, `SELFTESTS`)        | all three populated from one `tools/shared_manifest.py --tsv` call; the "THREE REGISTRATIONS" header comment now reads "ONE"                           |
| `.github/workflows/para-drift.reusable.yml` | 16 hand-written `diff -u` steps + 2 selftest steps (156 lines)                          | one loop step reading the manifest (90 lines total) — also closes roadmap **D5** ("seven near-identical `diff -u` steps … over a hardcoded file list") |
| `docs/templates/ruff.toml`                  | `[format] exclude` and `known-first-party` hand-typed, independently of the other three | cannot read JSON directly — held in sync by `tests/test_shared_manifest.py` instead, checked every hub CI run                                          |

**`tools/skill_drift_check.py`'s absence-detection logic, corrected for the new shapes.** The pre-existing `elif on_test and (path.removesuffix(".py") in port_closure or path.startswith("service/"))` was written for 5 root-level/`service/` `.py` files and silently mishandled two new shapes 5→16 introduced:

- **`.schema.json` entries** — `.removesuffix(".py")` is a no-op on them and they are never under `service/`, so the absence-is-a-finding branch could *never* fire; a schema file's absence was tolerated unconditionally. Fixed: a `.schema.json` file's need is now checked against its *owning module* (`atrium_document.schema.json` → `atrium_document`) in the service's import closure, the same test a `.py` module gets.
- **`tests/test_*.py` entries** (6 of the 16) — `skill_ify.py`'s own `TRIM_DIRS` trims `tests/` from every skill branch by design, so absence must *never* be a finding for these. Fixed: `dest.startswith("tests/")` now skips the absence check entirely while keeping the parity check (present-on-both-and-differing is still flagged).

**`tests/test_shared_manifest.py`** (new, 10 tests) — the manifest's own guard. Asserts: every file under `docs/templates/shared/` has a manifest row and vice versa (making an orphan like the old `test_atrium_service.py` structurally impossible); `docs/templates/ruff.toml`'s `[format] exclude` and `known-first-party` sets match the manifest exactly; `para-drift.reusable.yml` is parsed (not grepped) to confirm it invokes `tools/shared_manifest.py` and carries no reintroduced hand-written `diff -u` step; `scripts/revendor_shared.sh` carries no hand-written array literal; and the two remaining prose file-counts that cite this set by number (`docs/templates/ruff.toml`, `atrium-page-classification/ruff.toml`) match `len(manifest)`.

- **`tools/skill_drift_check.py`**, run against a disposable local branch built off `test` with one file altered at a time (no `agent-skill` branch exists in any local clone to compare against for real, so this pass constructed the three specific scenarios the new logic exists for):

  2. Deleting two `tests/test_*.py` entries entirely → **correctly silent** (no finding — the trim is by design).
  3. Corrupting a `tests/test_*.py` entry that *is* present on both refs → **correctly flagged** as an out-of-parity file, proving the parity check still runs for files the absence-check now skips.
- **`tests/test_shared_manifest.py`**: 10/10 pass against the landed tree; each of the manifest-loader validation, ruff-sync and structural-step checks was deliberately broken (a duplicate `dest`, a deleted ruff.toml row, a reintroduced hand-written `diff -u` step) and confirmed to fail before being trusted.
