## 🩺 Three defects nothing was checking for

**1. The endpoint check has been half-off on every repo since it landed.** All five callers
passed only `client-script`. `app-import` therefore defaulted to `service.api` — wrong for
alto-postprocess, whose app is `service.text_api` — so alto's step 4b import-skipped on *every*
run, emitting the `::warning::` that exists precisely to stop a skip reading as a pass. And
`primary-endpoints` defaulted to `""`, so the primary-endpoint assertions in **both** 4a and 4b
never ran anywhere. The hub's own caller template already carried both inputs; the live callers
were simply never brought up to it, and the previous digest recorded the situation **backwards**
— asserting the template was stale and the callers correct. All five callers are now regenerated
from the template.

**2. alto-postprocess's skill-branch API container could not start.** `test` had fixed
`service/text_api.py` to put the repo root on `sys.path` before importing `atrium_document` /
`atrium_paradata` / `document_hook`; the skill branch still imported them at line 21 with only
`service/` ever added, and after the fact. `python service/text_api.py` — the exact entrypoint
`docker-compose.yml`'s `api` service overrides to — died at
`ModuleNotFoundError: No module named 'atrium_document'`. Reproduced, then fixed by the port.
`skill-validate` could not have caught it: 4b import-skips there for unrelated reasons, and 4a is
static.

**3. The issue-#55 container contract was lost on all five.** Every `test` `api` stage declares
`STOPSIGNAL SIGTERM`, `--timeout-graceful-shutdown 20` and a `HEALTHCHECK` against
`/app/service/healthcheck.py`. No skill branch declared any of it — so `service/healthcheck.py`
shipped inert on four branches, was **missing entirely** on nlp-enrich (the actual cause of that
repo's red run), and nlp-enrich's `service/README.md` documented the behaviour as live throughout.
`Dockerfile` and `docker-compose*` are content-allowlisted in the drift tool for good reasons,
and that allowlist is what hid it.

- **Frontends** — translator and llm-enrich now actually mount `/frontend`, via an
  `.exists()`-guarded block that is a no-op on any branch without the directory, so it is
  forward-mergeable rather than a fork. llm-enrich's page was **broken against its own API** —
  it POSTed `{lines, top_k, backend}` to an endpoint that takes `{text, document_json}` (422 on
  every submission) and rendered a `data.lines` the response no longer carries — and has been
  rewritten against the live envelope, output now HTML-escaped.
- **Container contract** — restored: Dockerfile `api` stage on nlp-enrich and llm-enrich;
  compose `healthcheck:` + `stop_signal:` on the three single-stage branches, where the API is
  an entrypoint override rather than a build target.
- **Tooling** — `skill_drift_check.py` gained a missing-`service/`-file check (it had called
  nlp-enrich clean while CI failed on exactly that), an issue-#55 container-contract check, and
  a `DOCUMENTED_DIVERGENCES` table so a clean run means "nothing unexamined".
- **Docs** — strategy §5's claim that CI catches a false `/frontend` mount corrected: it cannot,
  and did not.
