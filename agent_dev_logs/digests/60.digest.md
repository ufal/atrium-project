## ⚙️ The four findings this pass adds

### 1. The deliverable drifted inside 24 hours

nlp-enrich's day-old `.env.example` against `service/api.py:43-46`: `MAX_UPLOAD_MB` **50** vs code **5**; `MAX_WORDS` **200000** vs **30000**; `API_JOB_TIMEOUT` **3600** vs **600**; `MAX_RESCALE_DIM` **4000** vs **100000**. Its own `service/README.md:181-193` carries the correct values throughout.

The issue's acceptance bullet — *"check this with a script and keep it, or the tables rot within a release"* — is not advisory. The rot is already measurable, in the file written to fix it, before the issue closed.

### 2. `.env` does not reach the container

No repo imports `python-dotenv`; no compose file has `env_file:`. Compose reads `.env` only to expand `${VAR}` **inside the compose file**, so a variable reaches the container only if the api service's `environment:` block passes it.

`HOST`, `GRACEFUL_SHUTDOWN_S`, `LOG_LEVEL`, `RELOAD` and `HEALTHCHECK_PATH` are passed by **zero** compose services in **any** repo — while three `.env.example` files document them under a header saying compose reads `.env` automatically. nlp-enrich is worse: `docker-compose.yaml:44-45` hard-codes `MAX_CONCURRENT_JOBS` and `DEFAULT_KW_METHOD` as literals, so compose *overrides* `.env`.

**This is the `PORT`-before-#58 defect, reproduced inside the issue raised to prevent it.** The variables are real for Kubernetes and `docker run -e`; they are inert on the path the file recommends. The irony worth recording: llm-enrich has the best passthrough in the ecosystem (eight names, including `MAX_UPLOAD_MB`, which no other compose passes) and was one of the two repos with no template at all.

### 3. A literal scan cannot implement the acceptance rule

`processors/translator.py:104-126` defines `_env_float` / `_env_int` / `_env_str`. Grepping `getenv("LINDAT` over `processors/` returns nothing, yet `LINDAT_MIN_INTERVAL_S`, `LINDAT_MAX_RETRIES`, `LINDAT_BACKOFF_BASE_S` (`:128-132`) and `TRANSLATION_URL`/`LINDAT_BASE_URL` (`:159`) are all read there. translator's `.env.example` documents three of them from a human read.

A guard that only knows `os.getenv` certifies that file complete while blind to a whole variable class. Same trap in the other direction for defaults: `resolve_max_upload_mb(5.0)` puts the value at the call site, and `allowed_origins(default="*")` puts it in a signature.

### 4. The scan boundary is not a directory — and there is a sixth enumeration

"Reads under `service/`" misses the backing-service URLs the issue opens with (`api_util/call_udpipe.py:145`, `call_nametag.py:206`, all of `translator/processors/`) while `api_util/summarize_nt_udp.py` holds ~15 batch-only names that must not be published. The boundary is the api entrypoint's **import closure**, plus a declared, reasoned delta for the two subprocess-reached modules.

`KOREKTOR_URL` (`alto/tools/quality_model/correct.py:337`, added by #63) is correctly **excluded** — the closure does not reach it and the manifest lists only three URLs. This digest's earlier revision omitted it; right answer, unstated reason.

And: **all five repos already carry an env table in `service/README.md`** (alto `:396-402`, llm `:98-111`, nlp `:181-193`, pc `:308-314`, translator `:35-44`). Nobody counted these. alto's says `MAX_UPLOAD_MB` = 10 against code 25. They are **normative** — `docs/agent_skill_strategy.md:702` requires them and `skill-validate.reusable.yml:41` checks them — so they cannot be deduped away, only brought under the same check.

### 5. Two repos do not gitignore `.env`

alto (`.gitignore:18`), llm-enrich (`:151`) and translator (`:6`) do. **nlp-enrich and page-classification do not**, while nlp-enrich's template already says "Copy to `.env` and edit" and llm-enrich's compose passes `OPENROUTER_API_KEY`.

## 🛡️ The guard, and where it can actually live

Two halves, both on machinery that exists:

- **Hub-local** — `tests/test_env_contract.py`, manifest `env:` ↔ doc table, in the `tests/test_e2e_entrypoints.py` idiom (parse, don't grep; explicit escape hatch with a written reason; anti-vacuity test). Picked up free by `hub-self-check.yml`'s `shared-tests`, which already installs PyYAML. Cannot break a tool repo.
- **Per-repo** — a hub script invoked from `para-drift.reusable.yml`, which all five already call and which already checks out both trees. Same shape as `workflow_lint.py`'s `--repo-root tool-repo --hub-root hub-repo`. **Stdlib-only in phase 1**: that workflow has no `setup-python` and installs nothing (bare `python3` at `:101`, `:115`), so a PyYAML import would break all five at once.

Vendoring a test into five repos was rejected: it costs the three registrations `scripts/revendor_shared.sh:24-33` enumerates, and `tools/skill_drift_check.py` has already fallen five names behind para-drift — #59's exact failure, which this issue must not reproduce.

**The retag window.** All five pin `para-drift.reusable.yml@v1`, so a new step goes live everywhere the instant `v1` moves. Land on `test`, point one caller at `hub-ref: test`, verify, then retag.

## ⏳ Open

- **`LOG_LEVEL` is withheld from every deliverable** pending #61. Its code landed in all five, but in page-classification it is **inert**: `service/inference.py:21` calls `logging.basicConfig` at import, `service/api.py:16` imports that module at the top of the file, and `api.py:360`'s own call has no `force=True`. The comment directly above it asserts the invariant being broken — *"The library modules only getLogger()"*. Publishing a knob that works in four images and silently does nothing in the fifth is precisely what the `PORT` constraint existed to prevent. #61's digest still reads 🟡 Open; this is why.
- **`ALLOWED_ORIGINS` has two defaults and the committed files publish the wrong one.** Code default is `*` (`service/atrium_service.py:367-370`); compose supplies narrower per-repo values — alto `localhost:8080,localhost:5500`, page-classification `localhost:8080,127.0.0.1:8080` (note `localhost` and `127.0.0.1` are *different origins* to a browser), llm-enrich `*`, and nlp-enrich and translator declare it not at all, so those two serve every origin under compose. Kubernetes never reads compose, so the k8s table must carry the code default.
- **The manifest ships no `Secret`, and llm-enrich requires one.** `service/api.py:128-131` raises at startup without `OPENROUTER_API_KEY`. A partner cannot deploy llm-enrich from the reference manifest unmodified — this belongs in "Known limits" with a `secretKeyRef` stanza.
- **`OLLAMA_HOST`'s code default is wrong inside a container.** Code says `http://localhost:11434` (`ollama_client.py:61`); compose says `host.docker.internal:11434`. Anything run outside compose with `LLM_BACKEND=ollama` silently targets the container's own loopback.
- **`k8s_acceptance_runbook.md` mentions neither `ALLOWED_ORIGINS` nor `MAX_UPLOAD_MB`**, both of which a partner pushing real traffic through a Service in step 4 will hit.
- **Named, deliberately not folded in**: `LANGID_CONFIG` is read at nine alto sites with two incompatible default shapes (`classify_TEXT.py` does both, at `:481` and `:1133`); `MAX_WORKERS` overrides two independent config keys; and `docs/templates/shared/test_atrium_service.py` is registered in **none** of the three places `revendor_shared.sh`'s own header says are mandatory — the silent miss that header warns about, already present, and #59's to fix.
