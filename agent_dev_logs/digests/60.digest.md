Two observations the issue does not make:

- **alto is not merely "the template" — it is the only repo with an operator-facing set at all.** `HOST`, `LOG_LEVEL`, `RELOAD`, `GRACEFUL_SHUTDOWN_S` exist in exactly one repo. #58 adds `HOST`/`GRACEFUL_SHUTDOWN_S` to the other four and #61 adds `LOG_LEVEL`; both land variables into this table. That is the dependency ordering, and it is stronger than the issue's "land this after #63".
- **page-classification has the smallest surface in the ecosystem** — four variables, all shared. Its `.env.example` will be nearly a copy of the common block, which is a good sign, not a gap.

## ✏️ Corrections to the issue text

1. **`PORT` is read in all five `service/` trees, but only alto's *server* honours it.** The issue's premise — that a partner "cannot discover `HOST`/`PORT`" — understates it: in four repos the variable is *read by the health check and ignored by the server*, so documenting it as a working knob would document a bug. See [\#58](https://github.com/ufal/atrium-project/issues/58)'s Finding 1. **The env table must not claim `PORT` is supported until #58 lands.** This is a hard ordering constraint, not a preference.

2. **"Exactly one `.env.example` exists in the ecosystem" is true for that exact filename, and misleading.** `atrium-nlp-enrich/annotation/env.example` exists — five lines, Doccano/Label Studio admin credentials for the standalone annotation deployment. It is a genuine second template, differently named and differently scoped. Worth knowing for two reasons: it establishes the house comment style ("Copy to `.env` and edit before `docker compose up -d`. Do not commit `.env`."), and a repo-root `.env.example` in nlp-enrich must not be confused with it.

## ⏳ Open
- **`MAX_UPLOAD_MB` vs `MAX_UPLOAD_BYTES` is settled in code but not for partners.** The shared canonical `service/atrium_service.py:350-359` resolves it: `MAX_UPLOAD_MB` is preferred, `MAX_UPLOAD_BYTES` is a **deprecated** fallback kept for existing callers (§4.5), and `service/api.py:51-52` derives the byte value from the MB one. So the table should document `MAX_UPLOAD_MB` only, and name `MAX_UPLOAD_BYTES` as deprecated rather than as a second knob. Listing both as equals would be the documentation introducing an ambiguity the code does not have.
- **The drift problem this issue creates.** Five `.env.example` files plus one table in `k8s_deployment.md` is six new hand-maintained enumerations of the same facts — the exact shape [\#59](https://github.com/ufal/atrium-project/issues/59) exists to fix elsewhere. The issue's own acceptance bullet ("check this with a script and keep it, or the tables rot within a release") is right and should be treated as required, not advisory.
- **Secrets in the template.** `OPENROUTER_API_KEY` and the annotation file's `*_PASSWORD` entries mean at least two `.env.example` files carry credential-shaped keys. They need placeholder values and an explicit "do not commit `.env`" line — nlp-enrich's existing file already models this.
- **File-based config is named but not resolved.** `atrium-nlp-enrich/config_api.txt:19-20` (`UDPIPE_URL`/`NAMETAG_URL`) and `atrium-translator/config.txt` (`input_path`, `output`, `translation_backend`) hold deployment-varying values. #63 moves the URLs; the translator's three are unclaimed by any issue.
