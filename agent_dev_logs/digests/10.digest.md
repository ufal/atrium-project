### 2 · Two safety mechanisms the hub had built but nobody had adopted

* **`canonical_doc_id()` — ~0 % adoption.** Introduced (issue #13) precisely to stop four independent filename derivations forking one document; every repo still hand-rolled its own. **~20 call sites** routed through it, *composing* where a repo legitimately needs more (pc must also split the page-number suffix an image filename carries).
* **`validate_document()` — 0 call sites.** The Layer D gate existed, was documented as normative, and ran nowhere; `jsonschema` was not even a declared dependency in three repos. Now on **every** production write path under one agreed policy: warn on an invalid *inherited* baseline, **raise** on invalid *own* output, one loud warning if `jsonschema` is missing — never a silent no-op.

* pc and nlp services had **no `document_json` wiring at all** (rule 1 was CLI-only), and both shipped a `service/requirements.txt` with **no `uvicorn`** — the documented `docker compose --profile api up` path could not start. ## 🔁 Three follow-on defects — each surfaced *by* a gate this round installed

The round's most useful signal: **every mechanism, once actually wired, immediately caught something real that had been invisible.**

**(a) Formatting split the vendored canonical file.** Vendoring `test_document_originators.py` byte-identically turned `para-drift` **red in pc, alto and translator**. Cause: tool repos run `ruff-format` on pre-commit while the hub deliberately does not, and `line-length` is not uniform (**100** in nlp/llm, **120** elsewhere) — so a shared file's bytes were a function of *which repo committed it last*. Each variant is a fixed point of its own config, so re-vendoring alone would not have held. Fixed with `[format] exclude` **plus `force-exclude = true`** — the flag is load-bearing, because pre-commit passes explicit paths and ruff otherwise honours exclusions only while walking directories (measured: "6 files would be reformatted" without it, all 7 skipped with it). The hub is now the sole formatting authority for the enforced set.

**(b) The schema gate caught a *released* image.** It rejected `entities[].type_cnec: null` against a `{"type": "string"}` schema — a real defect in nlp-enrich **v0.18.2**, invisible until something validated. The fix was already on `test`, but `:latest` moves **only on a version tag**, so no source change could green the nightly. Two consequences addressed: `e2e_assert` now reports **every** violation, each attributed to the owning repo (one-at-a-time would serialise a release cycle per field), and a moving **`:test`** image tag is published on branch pushes so the E2E can be asked "does what we are about to release satisfy the contract?". Cleared for real by the 08-06 release wave.

**(c) The cross-stage `doc_id` assertion caught a third fork — from a derivation that was *correct*.** Run `31076188660`: the translator emitted `CTX000000003-1` while the other four stages said `CTX000000003`. Its input really was `PAGE_ALTO/<doc>/<doc>-1.alto.xml`, a page alto had split out, so `canonical_doc_id()` answered accurately **for that file** and wrongly **for that record**. No filename heuristic can close that gap (a document may legally be named `sbn.2019-1`). The resolution is architectural and now in the canonical module: **`DocumentRecord` inherits the baseline's `doc_id`** — the originator names the document, every later stage inherits, and `canonical_doc_id()` decides only when there is no baseline (rule 3). Divergence is noted, never fatal, unlike `merge_document_records()` where two independent records disagreeing genuinely means two documents.

> The lesson worth carrying: **(c) could not have been found by deriving harder**, and no single repo's test suite could ever see it. It took an assertion that compares all five stages of one document.
