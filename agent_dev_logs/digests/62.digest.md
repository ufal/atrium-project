harmful work. That is why a two-line deletion read like a workflow rewrite.

## 🔭 The successor finding — restated precisely, and now with a dated proof

**Four of the five stages set the container's working directory to a fresh `actions/checkout` of the
tool's default branch rather than the image's `/app`**, so a source change that never reached the
published image still passes E2E:

| `-w`   | points at                                      | checked out by |
|--------|------------------------------------------------|----------------|
| `:298` | `/workspace/work/atrium-alto-postprocess-main` | `:272-275`     |
| `:348` | `/workspace/work/atrium-translator-main`       | `:304-307`     |
| `:370` | `/workspace/work/atrium-nlp-enrich-main`       | `:356-359`     |
| `:414` | `/workspace/work/atrium-llm-enrich-main`       | `:377-381`     |

None of those four `actions/checkout` steps declares a `ref:`, so each takes the tool's default
branch. Stage 1 has no `-w` and no source checkout.

**The proof, which this refresh found rather than reasoned about.** Stage 2 pulls
`ghcr.io/ufal/atrium-alto-postprocess:latest`, built from alto's newest release **`v1.4.7-beta`
(2026-09-09)**. The vendored `alto_tools.py` that alto#50 introduced landed in **`6ddabf7`
(2026-09-10)** and **does not exist at that tag** — fetching `alto_tools.py` at
`refs/tags/v1.4.7-beta` returns *does not exist in the repository*. Stage 2 nevertheless runs green
at 57 s, because `-w` puts the checkout's copy in front of the image's. **The published alto image
has never executed the vendored module.** alto#50's closing comment records the same caveat in
prose; this is the version with the tag and the commit date attached.

**The fix already has a working model in this repository.** The sibling lane
`e2e-digital-smoke.yml` starts its containers with **zero** `-w` flags — it mounts `/workspace` for
data only and lets each image run from its own `/app`. The pipeline lane has four.

This round is a prerequisite for closing the gap, not a partial fix: once `-w` goes,
`ENTRYPOINT ["python", "main.py"]` resolves `/app/main.py`, which is the desired end state. It is
also **why the overrides looked harmless for so long** — with `-w` on the checkout, the forced
interpreter and the real entrypoint resolved the same relative script.

`docs/docker_gha_roadmap.md` §9 (`:559`) names it under *The successor finding — not closed here*
(`:651`) and says *"It needs its own issue."* **It has none.** Hub numbering stops at
[\#64](https://github.com/ufal/atrium-project/issues/64); `#65` returns 404.
