## 🎯 Goal
Make the record AMČR seeds, and the provenance and packaging that leave the chain, one contract that holds from the first stage to the archived crate:

1. **Identity.** An AMČR-seeded `atrium_document` enters the first stage and comes out of the last with `doc_id`, `source.sha512`, file name and media type unchanged; `source.origin` stays with the tool that reads the source.
2. **Provenance.** Every production service returns its own run as a Process Run Crate `CreateAction`.
3. **Packaging.** `atrium_rocrate.py` writes RO-Crate 1.2 with Process Run Crate 0.5, with stable identifiers, tool `version`, tool authors as `creator` and an embeddable fragment; the validator runs in CI.
4. **Proof.** One end-to-end integration test covers all of it, not only per-service tests.

Out of scope, by the issue: **record-only mode** (#67 R3), deferred until a concrete use needs it. AMČR's own side remains tracked by `aiscr-webamcr` issues.

## ✅ What's settled
- **The record is the intermediate format**, with the current `doc-schema-v1` tag treated as the pilot/beta baseline for the current round.
- **Seed and origin rules exist in code**: first-writer-wins `source`, one originator per document. The work is to pin the rules in the schema/docs/tests.
- **AMČR writes the final paradata file** until services return their own run provenance; the service response is the input to that composition.
- **RO-Crate 1.2 + Process Run Crate 0.5** is the agreed pilot pair.
- **Record-only is out** of this issue.
- **Successor ids must be additive**, not destructive: `alto-postprocess` → `ocr-postprocess` and `llm-enrich` → `keyword-extractor` must coexist through one successor/alias map until the final contract freeze.
- **Each tool owns its own record block(s)**; shared `source` remains first-writer-wins.

## ⏳ Open
1. `source.sha512` and the seed profile must land in the schema round shared with #73.
2. The successor map must cover all old/new program comparisons, including the OCR hand-off path.
3. Every production service must return a populated `CreateAction` with stable run/tool identifiers.
4. `atrium_rocrate.py` must emit RO-Crate 1.2 / Process Run Crate 0.5, use `version`/`creator`, support fragments and include the agreed file metadata.
5. The hub must validate both RO-Crate profiles against real seeded production output.
6. The seeded E2E test must traverse the actual production-stage map, including the renamed OCR producer.
7. The `atrium-ocr-postprocess` repository needs its old `alto-postprocess` identity references removed or explicitly declared as successor compatibility metadata before the new producer can be treated as contract-complete.
8. AMČR decisions remain needed on failed-run `CreateAction`, fragment validation via a stub root, `contentSize`, `ATRIUM_RUN_AGENT`, and the final pilot/freeze date.
