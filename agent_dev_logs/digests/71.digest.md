## 🎯 Goal
Make the record AMČR seeds, and the provenance and packaging that leave the chain, one contract that holds from the first stage to the archived crate:
1. **Identity.** An AMČR-seeded `atrium_document` enters the first stage and comes out of the last with `doc_id`, `source.sha512`, file name and media type unchanged; `source.origin` stays with the tool that reads the source.
2. **Provenance.** Every production service returns its own run as a Process Run Crate `CreateAction`.
3. **Packaging.** `atrium_rocrate.py` writes RO-Crate 1.2 with Process Run Crate 0.5, with stable identifiers, tool `version`, tool authors as `creator` and an embeddable fragment; the validator runs in CI.
4. **Proof.** One end-to-end integration test covers all of it, not only per-service tests.

Out of scope, by the issue: **record-only mode** (#67 R3), deferred until a concrete use needs it. AMČR's own side (the single write, the record crate around the archived record, the paradata of the original) is [aiscr-webamcr#2590](https://github.com/ARUP-CAS/aiscr-webamcr/issues/2590), [#4316](https://github.com/ARUP-CAS/aiscr-webamcr/issues/4316) and [#4315](https://github.com/ARUP-CAS/aiscr-webamcr/issues/4315).

## ✅ What's settled
- **The record is the intermediate format**, frozen as `doc-schema-v1`; changes are additive.
- **Seed and origin rules exist in code**: first-writer-wins `source`, one originator per document. The work is to pin them in documentation and tests, not to invent them.
- **AMČR writes; services do not.** The service response is what AMČR composes its paradata file from, until services return it themselves.
- **The version pair is chosen**: RO-Crate 1.2 with Process Run Crate 0.5.
- **Record-only is out** of this issue.

## ⏳ Open
1. **Dates** for report items 1-3 (the meeting).
2. **`sha512` in the schema**: it belongs in the same additive round as [#73](https://github.com/ufal/atrium-project/issues/73)'s block, which is one changelog date and one re-vendor.
3. **How to validate a fragment**: a fragment has no root, so the validator can only judge it inside a stub root.
4. **Reconcile the docs**: `rocrate_export.md` §8 forbids what the acceptance criteria require; the hub CI job satisfies both if the validator stays out of the tool repositories.
