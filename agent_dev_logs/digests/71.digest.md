## 🎯 Goal
Make the record AMČR seeds, and the provenance and packaging that leave the chain, one contract from the first stage to the archived crate:

1. **Identity.** An AMČR-seeded `atrium_document` enters the first stage and comes out of the last with `doc_id`, `source.sha512`, file name and media type unchanged; `source.origin` stays with the tool that reads the source.
2. **Provenance.** Every production service returns its own run as a Process Run Crate `CreateAction`.
3. **Packaging.** `atrium_rocrate.py` writes RO-Crate 1.2 with Process Run Crate 0.5, with stable identifiers, tool `version`, tool authors as `creator`, an embeddable fragment; validated in CI.
4. **Proof.** One end-to-end integration test, not only per-service tests.

Out of scope: **record-only mode** (#67 R3).

### What the seeded E2E proves, and what not
- **It proves:**
  - the AMČR seed survives page-classification → ocr-postprocess → translator → nlp-enrich, checked by `e2e_assert.py` on every stage's record;
  - the final crate (record + the stages' paradata files) validates under both profiles;
  - keyword-extract's API returns `paradata`.
- **Not yet:**
  - It runs the batch/CLI images of the first four stages, so their API responses' `paradata` is not asserted. Only keyword-extract's `-api` is called (`e2e-pipeline-smoke.yml:473`).
  - It ran at 10:32 UTC, before ocr-postprocess `v1.9.1-beta` (10:48) and digital-convert `v1.1.1-beta` (10:54), so `:latest` was ocr-postprocess `v1.9.0-beta`.
  - The W3/W4 stamp checks and the `text_layer` check sit in `e2e_assert.py`'s born-digital branch. The seeded lane does not reach it, and the digital lane runs digital-convert alone on an image that predates `text_layer` (`fe494cd`), so no stamp or `text_layer` was present. These checks are covered by `tests/test_e2e_assert.py` only.
  - The born-digital branch is a separate workflow on the CLI image; `-api` and `/reformat` are not exercised (digital-convert#2 H.1).
  - Neither lane chains digital-convert into the downstream stages.

## ✅ What's settled
- The record is the intermediate format; `doc-schema-v1` is the pilot baseline; additive changes are registered post-freeze (`source.sha512`, `run_uuid`, `pages[].text_layer`).
- Seed contract, keep rule and successor ids, in code and in `docs/document_schema.md`.
- One `CreateAction` per call, built by `atrium_rocrate.create_action()`.
- RO-Crate 1.2 + Process Run Crate 0.5 with `version`, `creator`, release-URL tool ids, fragments and `contentSize`; validated in CI and on the E2E output.
- Co-contributions on a born-digital record are exactly two: scoring (W3) and the per-page OCR hand-off (W4). Every other foreign write is refused.
- AMČR writes the final paradata file, composed from the services' `CreateAction`s.
- Record-only mode is out of this issue.
