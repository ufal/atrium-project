## 🔄 Refresh 2026-09-24 — the 2026-08-01 decision this digest missed
The thread did not stop at 07-02: on **2026-08-01** (5151928504) K4TEL recorded the preliminary decisions from atrium-llm-enrich #13 — the ecosystem's three formats:
1. **JSON** — everything about the document from every step (OCR/HTR text, page category, line quality, NER + UDPipe + KeyBERT, LLM + TEATER keywords, links to other records).
2. **Markdown (+HTML/CSS)** — the full text without trash lines, tables with simplified layout, figure regions (size only), comments for visual context; not strictly aligned to the page.
3. **TEITOK XML** — visually correct text strings and figure regions that can be rendered over the PNG/JPG page image, with NER + UDPipe by default; keywords, topics, page classification and line quality are **not** recorded (at the moment); boxes aligned to the image and calibratable for the image used for rendering.

**TODO:** make sure the JSON-2-MD and TEITOK-2-MD pipelines work with fully and partially enriched JSON records and complex page XMLs.

**State of that TODO (2026-09-24):** both pipelines exist in atrium-llm-enrich and are tested case by case — `api_util/json_to_md.py` (20 tests) and `api_util/xml_to_md.py` (25 tests, rebuilt on TEITOK format 2's page model on 2026-09-24, with the real writer sample `CTX000000002` pinned as a fixture). A stress suite on fully enriched inputs does not exist yet; it is atrium-llm-enrich #11's 2026-08-02 task (shape proposed in that issue's plan). The TEITOK half of the decision is now nlp-enrich's format 2: boxes calibrated to the displayed page image (`INPUT_PAGES_DIR` or `IMAGE_DPI`), a contract gate before the file is used, and the pitfalls that still produce valid but misaligned files listed in its README (§ "TEITOK XML" → *Pitfalls*). The hub E2E checks the record against the TEITOK file (run 35990199050, green).
