## 🎯 What #6 is now the canonical record of

Issue #6 is the cross-repository licensing inventory used to answer two different questions that must not be conflated:

1. **What licences actually apply to the material/model/service output that a run depends on?**
2. **What software/tools are executed during the run, and under what licences are those tools distributed?**

The current paradata implementation historically merged these into one most-restrictive `provenance.license` calculation. The latest thread proposes separating them: keep execution tools visible in provenance, but let the effective output licence be driven by components whose licensed content/data/model actually contributes to the produced record. The proposal is technically motivated by the GPL-renderer discussion and is **pending agreement**, not a settled legal conclusion.

Historical paradata must remain unchanged: a record written when a vocabulary was declared CC BY-NC 4.0 keeps that recorded licence. #6 updates the current inventory and the rules used for new runs; it does not rewrite old evidence.

## 🧩 Paradata / output-licence semantics — the open design decision

The current implementation uses a most-restrictive licence resolver fed by `para_config.txt`. This was useful for catching undeclared components, but it also causes execution-only tools to look like output-licensing constraints.

The latest #6 proposal is therefore:

> **Keep all tools visible in paradata, but let `provenance.license` be determined by components whose licensed content actually contributes to the produced record.**

Examples:
- a GPL/AGPL PDF renderer or converter should remain visible as an executed tool, but its software licence should not automatically relabel the document record's content licence solely because it rendered the pixels;
- a NameTag/UDPipe model, translation model, vocabulary, or other model/data asset actually contributing to the record remains a candidate for the effective output licence;
- an unknown provider ToS should continue to be explicit and conservative rather than silently mapped to a permissive OSS licence.

This distinction still needs maintainer/rights-owner agreement and implementation. Until that is accepted, do **not** restate the current most-restrictive resolver as a legal rule.
