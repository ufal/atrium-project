# Glossary

The words these pages use, explained in a sentence or two each. Each entry links to the page that holds
the full description. Tools, models, standards and institutions have longer entries on
[External tools & services](external-tools.md).

| Term                                  | Meaning                                                                                                                                                                                                                                                     |
|---------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **accretion**                         | How the record grows. Each step adds its own blocks and fields and passes every other part on unchanged ([The document contract](ecosystem/document-contract.md)).                                                                                          |
| **actionable workflow**               | A workflow on the SSH Open Marketplace that can also be run, for example as a [Galaxy](external-tools.md#galaxy) workflow.                                                                                                                                  |
| **AIS CR**                            | The Archaeological Information System of the Czech Republic, the infrastructure behind AMČR and TEATER, at `aiscr.cz` ([more](external-tools.md#ais-cr--aiscrcz)). It also runs the ATR.                                                                    |
| **ALTO**                              | An XML format for OCR output that keeps every word with its position on the page image ([more](external-tools.md#alto-xml)). The AMČR pilot neither produces nor stores ALTO; the tools read it for batch and research use.                                 |
| **AMČR**                              | The Archaeological Map of the Czech Republic (*Archeologická mapa České republiky*): the national archaeological database of ARÚP and ARÚB, and the partner that runs the ATRIUM pilot.                                                                     |
| **AMČR pilot**                        | AMČR running the ATRIUM services on its own infrastructure, on real documents, from December 2026. The steps join the chain one by one ([Production pilot](pilot.md)).                                                                                      |
| **ARÚP, ARÚB**                        | The Institutes of Archaeology of the Czech Academy of Sciences in Prague and in Brno. They hold the collections the tools were built for ([more](external-tools.md#arúp-and-arúb)).                                                                         |
| **ATR**                               | Automated text recognition: OCR for printed and typed text, HTR for handwriting. In the AMČR pilot it is AIS CR's own text-recognition service (`aiscr-atr`), which reads whole documents and writes docproc ([Pipelines](pipelines.md)).                   |
| **block**                             | One top-level part of the record, such as `pages`, `lines`, `page_categories` or `keywords`. Each is written by one step, or by one tool for its own fields.                                                                                                |
| **born-digital**                      | A document created on a computer, so its text is already stored in the file: a PDF exported from Word, for example. The opposite of a scan. digital-convert reads these.                                                                                    |
| **category (page)**                   | One of the eleven page types page-classification assigns, such as `TEXT_T` (typed text) or `PHOTO` ([the definitions](https://github.com/ufal/atrium-page-classification/blob/test/docs/reference/categories.md)). It describes a page; it never routes it. |
| **CNEC 2.0**                          | The entity types of the Czech Named Entity Corpus, used by NameTag's Czech model. nlp-enrich reads them in older outputs; its default model uses OntoNotes types.                                                                                           |
| **CoNLL-U**                           | A plain-text table with one word per line: its lemma, part of speech, grammatical features and syntax ([more](external-tools.md#conll-u-and-universal-dependencies)).                                                                                       |
| **CUBBITT**                           | The Czech–English translation model behind LINDAT's translation service, the translator's default ([more](external-tools.md#cubbitt)).                                                                                                                      |
| **distribution**                      | One stored output of an AMČR file under its name, such as `atr/docproc-json`, `atrium/document-json`, `atr/teitok-xml`, `metadata-en` or an office document's rendered PDF (`rendered-pdf`, a stand-in name). Each has its own paradata, `paradata/<distribution>`. |
| **`DOC_LINE_CATEG/`**                 | ocr-postprocess's per-line table of a batch run: every text line with its line category. nlp-enrich and keyword-extract can read it outside the pipeline.                                                                                                   |
| **docproc**                           | The layout format that digital-convert and the ATR both write (`atr/docproc-json`): each page with its verdict, and blocks of text with their type, position and reading order. One is stored per document, and the record is built from it.                |
| **end-to-end test (E2E)**             | The test that runs the tools one after another on sample documents and checks what each passes on ([W6 on Pipelines](pipelines.md#w6--e2e-smoke-the-integration-contract)).                                                                                 |
| **ensemble**                          | page-classification's five `vX.4` models scoring the same page, with their scores averaged. It is the service's default. It has no held-out accuracy figure of its own.                                                                                     |
| **FAIR**                              | Findable, Accessible, Interoperable, Reusable: the principles research-data publication aims at. RO-Crate export is ATRIUM's route to them.                                                                                                                 |
| **FastText**                          | The language-identification model ocr-postprocess and the translator use to tell which language a line is in ([more](external-tools.md#facebookfasttext-language-identification)).                                                                          |
| **flexiconv**                         | ÚFAL's converter of PDF, office files, PAGE XML, hOCR and other formats into TEITOK. nlp-enrich runs it on the command line only; it is MIT-licensed.                                                                                                       |
| **fold**                              | One of five ways the annotated pages were divided into training (80 %), development (10 %) and test (10 %) parts. Each published page-classification model was trained on one fold.                                                                         |
| **forced pages**                      | The pages of a document that digital-convert found without usable text: in a PDF, a text layer that is missing or cannot be used; in an office document, a page with no running text that shows an object (a pasted scan, a chart or a table alone). The whole document goes to the ATR, with these pages marked for recognition. |
| **gold set**                          | Lines or pages labelled by hand and used to measure how often a tool's labels are right. ocr-postprocess's has 2,067 lines.                                                                                                                                 |
| **GraphQL**                           | A query language for web APIs, in which the client names exactly the fields it wants. TEATER is queried this way.                                                                                                                                           |
| **held-out**                          | Pages, or other data, a model never saw in training. Accuracy is only honest when it is measured on held-out data.                                                                                                                                          |
| **image (container)**                 | A packaged program, published on GitHub's container registry. Each tool ships at least two: a batch image for the command line and an `-api` image for the service ([Operations](operations.md#images-and-tags)).                                           |
| **keyword (statistical, controlled)** | A statistical keyword is a word the text itself makes prominent (YAKE, KeyBERT, KER). A controlled keyword is a term a language model chooses from a fixed vocabulary (AMČR, TEATER). keyword-extract writes both.                                          |
| **language model**                    | A model trained to predict text. keyword-extract's controlled kind asks one to choose terms from the vocabulary; the translator can use one instead of LINDAT.                                                                                              |
| **lemma**                             | A word's dictionary form: *domy* (houses) has the lemma *dům*. UDPipe finds it, and nlp-enrich writes it for every word of its TEITOK and CoNLL-U files.                                                                                                    |
| **LINDAT/CLARIAH-CZ**                 | The Czech research infrastructure for language data. It hosts the services nlp-enrich and the translator call: UDPipe, NameTag and translation ([more](external-tools.md#lindatclariah-cz)).                                                                |
| **line category**                     | The label ocr-postprocess gives each text line: `Clear`, `Noisy`, `Trash` (illegible), `Non-text` or `Empty`.                                                                                                                                               |
| **`metadata-en`**                     | The English version of an AMČR record's metadata. The translator writes it when the record is archived; it is a distribution of its own, with its own paradata.                                                                                             |
| **named entity**                      | A name in the text: of a person, a place, an organisation, a date. NameTag finds them, and nlp-enrich lists them per page.                                                                                                                                  |
| **NameTag**                           | LINDAT's named-entity recogniser. nlp-enrich uses NameTag 3 to find names of people, places and organisations.                                                                                                                                              |
| **NMT**                               | Neural machine translation: a model trained to translate whole sentences, such as CUBBITT.                                                                                                                                                                  |
| **OAI-PMH**                           | A protocol for harvesting metadata records from a repository. AMČR's records and its vocabulary are read through it ([more](external-tools.md#oai-pmh)).                                                                                                    |
| **OCR / HTR**                         | Optical character recognition (printed or typed text) and handwritten text recognition. Together they are ATR.                                                                                                                                              |
| **OntoNotes (entity types)**          | The entity types of NameTag's multilingual model, such as `PERSON` and `GPE` (countries, cities, states). nlp-enrich's default model uses them.                                                                                                             |
| **OpenAPI**                           | A machine-readable description of a service's endpoints. Each tool commits it as `service/openapi.json`; it is the API's one contract.                                                                                                                      |
| **originator**                        | The older name of the record builder, still found in some code names (`test_document_originators.py`).                                                                                                                                                      |
| **`PAGE_ALTO/`**                      | ocr-postprocess's batch output folder: one ALTO file per page, `<doc>/<doc>-N.alto.xml`. The translator's ALTO mode can read it, for research and batch use; it is not part of the pipeline.                                                                |
| **page verdict**                      | digital-convert's judgement of each page's text layer: whether its text can be used and, if not, why. A page whose text cannot be used needs the ATR; an empty page is routed `empty`.                                                                      |
| **paradata**                          | Data about the process: which program, version and settings made an output, when, from which inputs, and with which components and their terms. Each distribution has its own paradata file ([Licences and paradata](ecosystem/licences.md)).               |
| **perplexity**                        | How surprising a line is to a language model. ocr-postprocess uses it, with Qwen2.5-0.5B, as one sign that a line is garbled.                                                                                                                               |
| **provenance**                        | The history of how an output was made. In ATRIUM it is kept in the paradata, never in the record ([The document contract](ecosystem/document-contract.md#where-the-run-history-is)).                                                                        |
| **quality score**                     | A number from 0 to 1 that ocr-postprocess gives each line, built from nine measurements of its text. The line category is decided from it and a short list of rules.                                                                                        |
| **reading order**                     | The order in which a person reads a page's lines. On a page with columns it differs from the order in which they are stored. docproc carries it; for batch ALTO input, ocr-postprocess can restore it.                                                      |
| **record**                            | The ATRIUM document record: one JSON file per document, `<doc_id>.document.json`, that ocr-postprocess builds and the later steps add to. It holds content only ([The document contract](ecosystem/document-contract.md)).                                  |
| **record builder**                    | ocr-postprocess's role in the pipeline: it builds the record of every document from its stored docproc, and scores every line.                                                                                                                              |
| **revision (model)**                  | A named version of a model on the Hugging Face Hub, such as `v4.4`. Name the revision you mean: the Hub's default can point to an older one.                                                                                                                |
| **RO-Crate**                          | A standard way to package research data with its description, so a repository can publish it ([RO-Crate export](contracts/rocrate.md)).                                                                                                                     |
| **routing**                           | Deciding which pages go to the ATR. It follows digital-convert's page verdicts: if any page needs the ATR, the whole document goes there, with those pages marked. Page categories never route.                                                             |
| **runbook**                           | A service's `service/README.md`: how to start it, what it downloads, what its errors mean and what to do, and its known limits.                                                                                                                             |
| **seed record**                       | What AMČR passes with a document: its file id (`doc_id`), the SHA-512 of the original, its file name and its media type. Every step keeps these.                                                                                                            |
| **SKOS**                              | A W3C standard for publishing vocabularies. ATRIUM's label lists, such as the page categories, are published as SKOS concepts ([SKOS](contracts/skos.md)).                                                                                                  |
| **SSH Open Marketplace**              | The European catalogue of humanities tools and workflows. Each ATRIUM tool has a record there ([more](external-tools.md#ssh-open-marketplace)).                                                                                                             |
| **TEATER**                            | A thesaurus of archaeological terms with Czech and English names, published by AIS CR. keyword-extract's controlled keywords come from it and from AMČR's keyword lists ([more](external-tools.md#the-teater-thesaurus)).                                   |
| **TEI, TEITOK**                       | TEI is the standard XML for encoding texts in the humanities. TEITOK is a corpus format and platform built on it, keeping every word linked to its place on the page. nlp-enrich writes TEITOK.                                                             |
| **text layer**                        | The text a PDF stores beside the page image. A born-digital PDF has a usable one; a scan has none, or an earlier OCR run's. digital-convert gives each page a verdict on it.                                                                                |
| **top-1, top-3**                      | The share of pages whose correct category is the model's first answer (top-1), or among its first three (top-3).                                                                                                                                            |
| **UDPipe**                            | LINDAT's tool for words, lemmas, parts of speech and sentence structure. nlp-enrich uses UDPipe 2 ([more](external-tools.md#udpipe-2)).                                                                                                                     |
| **vocabulary (controlled)**           | A fixed list of terms that a keyword must come from: here, AMČR's keyword lists and TEATER. A controlled keyword is one of these terms; a statistical keyword is a word taken from the text.                                                                |
| **warm-up**                           | A service loading its models when it starts. Until it ends, the service answers no request, or answers `/ready` with 503; the first start may also download the models.                                                                                     |
| **workflow narrative**                | A tool's workflow told step by step, with the formats in and out of each step. Its SSH Open Marketplace record is built from it ([Workflows](workflows/index.md)).                                                                                          |
| **XPath**                             | A way to point at parts of an XML document. The translator's metadata mode names the AMČR fields it translates as XPath expressions, sent with each request.                                                                                                |
